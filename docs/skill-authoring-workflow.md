## Skill 编写、提炼与维护协作

本文记录 2026-10-08 确认的职责划分与维护取舍，供后续调整 skill 时参考。**采用独立维护、按场景引用的组合方式**：保留社区版 `skill-creator`，由自有 skill 补充多来源提炼、实战补丁与真源分发能力。

本文是维护决策说明。实际执行时读取对应 skill 的当前正文、项目规则及有效用户授权；本文不新增操作权限，也不替代各 skill 的具体执行规范。

### 职责与关联

四个 skill 围绕同一生命周期协作，但主要输入、判断依据和交付物不同。

| Skill | 主要输入 | 核心职责 | 主要输出 |
|---|---|---|---|
| [reference-to-skill](../skills/reference-to-skill/SKILL.md) | 多份参考文档、不同模型/版本报告、目标 skill | 比较独有贡献、区分证据、审查目标现状、裁决冲突与规则落点 | 采纳/未采纳依据、候选规则、可审阅的新建或改进文件 |
| 社区版 `skill-creator` | 目标能力、草稿、反馈、评估任务 | 需求澄清、编写、行为评估、基准对比、迭代与触发描述优化 | skill、评估产物、反馈与改进结论 |
| [skill-patcher](../skills/skill-patcher/SKILL.md) | 真实逃逸实例、旧规则缺口、实战复盘 | 将已发生的问题修成小范围、项目无关的补丁 | 简短规则、对应自检与未纳入内容说明 |
| [skill-authoring-sync](../skills/skill-authoring-sync/SKILL.md) | 已完成或待分发的 skill | 真源管理、README 索引、链接分发及同步验证 | 真源实体、正确链接与治理检查记录 |

`reference-to-skill` 判断材料中哪些内容值得进入目标；`skill-creator` 提供通用编写与评估方法；`skill-patcher` 修补实战暴露的具体缺口；`skill-authoring-sync` 负责实体管理与分发。创建、修改和评估能力存在交集，应按主要问题选择入口，而非每次加载全部流程。

### 保持独立的理由

1. **社区更新边界清楚。**将本地方法并入社区正文会形成维护分叉；上游更新时需要处理覆盖与冲突。保持外部 skill 原样，自有规则在真源维护，方便分别升级和回滚。
2. **证据要求不同。**`skill-patcher` 针对真实逃逸，参考材料提炼则允许可定位的文本矛盾和待验证设计建议。合并后容易要求为文献建议虚构事故，或把未经验证的建议记作实战结论。
3. **流程成本不同。**多文档分析可以只交付建议；小补丁可以只做相关检查；能力评估可进入完整对照与反馈循环。统一成一个强制流程会造成无关步骤和重复执行。
4. **上下文按需加载。**来源裁决、补丁规范、评估脚本和分发规则分别读取，能保持入口聚焦，也减少同一等级、状态或模板的多处定义。

后续若实际使用证明两个自有 skill 的触发、输入和执行步骤长期相同，且重复内容明显多于独有决策，再评估共享 reference、收敛入口或合并。单次任务同时用到多个 skill，不足以证明应合并；减少入口也不应以复制社区实现为代价。

### 按场景选择入口

| 任务 | 主入口 | 按需协作与交付边界 |
|---|---|---|
| 比较一批材料，判断是否值得改进 skill | `reference-to-skill` | 仅建议时给出贡献、冲突与取舍，不修改目标 |
| 从参考材料新建或整体改进 skill | `reference-to-skill` | 借助 `skill-creator` 的编写/评估能力；实体与分发走 `skill-authoring-sync` |
| 从零描述一种能力，缺少明确参考材料 | `skill-creator` | 明确目标、编写及验证；真源落地走 `skill-authoring-sync` |
| 复盘一次真实漏验、误判或执行失败 | `skill-patcher` | 小步修补；影响行为较大或需证明效果时用 `skill-creator` 评估 |
| 判断新版是否更有效、做对照或优化触发 | `skill-creator` | 使用相应评估流程、评分依据和原始输出，不以单次成功代替对照 |
| 只有安装、链接校验或跨机器同步 | `skill-authoring-sync` | 沿用已有实体，不重复提炼与编写 |
| 仅总结、合并或润色普通文档 | 对应文档 skill | 只有用户要求产出 skill 时才进入 skill 编写流程 |

参考材料驱动的任务先完成来源提炼与冲突裁决，再按任务需要编写、评估和分发。实战补丁从实际问题进入，不需要为了补一句规则重新进行完整资料调研。

### 引用约定

**skill 引用表示代理按需读取并采用相关指引，不是程序自动调用、自动安装或权限传递。**仅写出另一个 skill 的名字不能保证其正文已读取、指定流程已执行或依赖工具可用。

引用应说明以下内容：

| 要素 | 写法要求 |
|---|---|
| 触发条件 | 明确何时需要协作，例如需要对照评估或触发描述优化 |
| 身份与位置 | 明确社区版、系统版或自有真源；根据当前安装定位，不依赖机器专属绝对路径 |
| 使用部分 | 指明采用编写、评分、运行器、查看器或分发流程，避免含糊地要求“全部参照” |
| 交接内容 | 传递用户目标、原始资料、候选规则/草稿、预期场景和已执行事实 |
| 完成证据 | 报告实际读取、执行、产物及限制，不能把引用本身记作验证 |

`reference-to-skill` 保留来源提炼、证据分类、目标审查和规则裁决。采用社区版评估时复用它的运行器、评分格式与结果查看器，避免另抄一套实现；只采用轻量结构校验时如实写明采用范围。

`skill-patcher` 的“真实逃逸”条件限定于实战补丁，不传播成所有新 skill 的准入条件。参考材料中的案例描述、文本矛盾和设计候选分别标注依据类型，不用杜撰事故来满足补丁模板。

引用只在需要的方向建立：来源提炼或补丁可以使用创建/评估能力，完成实体后再使用治理流程。社区版不必反向依赖本仓库的自有 skill，也不要求创建新的总调度 skill。缺少可选协作工具时，完成可执行部分并注明限制；关键能力确实缺失时记录阻塞，不静默降级。

### 两份同名 skill-creator

本地曾同时存在社区版与 Codex 系统版 `skill-creator`。**名称相同不代表内容、工具或流程相同。**实际采用时说明来源与所用能力，不假设当前环境自动选择了某个版本。

| 项目 | 社区版 | Codex 系统版 |
|---|---|---|
| 维护归属 | 社区来源，独立安装与更新 | 随环境提供，按环境版本维护 |
| 已阅读版本的重点 | 创建—评估—反馈—迭代；有/无或新旧对照、评分与查看器、触发优化 | 适度约束、保持任务范围、渐进披露、结构校验及适用前向验证 |
| 常见定位示例 | 默认用户目录中的 `%USERPROFILE%/.agents/skills/skill-creator/SKILL.md` | 默认用户目录中的 `%USERPROFILE%/.codex/skills/.system/skill-creator/SKILL.md` |
| 使用记录 | 标明“社区版”以及实际执行的评估/编写部分 | 标明“系统版”以及所用校验器或指引 |

上述路径是当时默认布局的环境变量示例，不是跨机器安装契约；存在自定义目录时按实际安装位置查找。社区上游地址和版本号以安装元数据为准，本文不推定未核验的来源版本。

社区文档中的 Claude CLI、子代理、脚本及查看器需要与当前环境能力核对。采用完整评估时按对应流程执行，并根据本仓库治理约定存放过程产物；只运行结构检查或前向样例时，不宣称执行了完整社区评估流程。

### 维护原则

- **唯一权威定义。**等级、状态、模板和权限边界指定维护位置，其他文件引用；发现重复矛盾时修正调用关系，不只增加覆盖条款。
- **来源有边界。**实际观察、文本矛盾、来源主张和设计候选分开记录。同一输入产生的多个报告可补充思路，但不作为独立事实核验。
- **规则按适用性决定强度。**先修错误判据和过度约束，再补真缺口。MUST 用于必需底线，领域细节下沉 references，项目专值留在项目。
- **正文保持聚焦。**不复制社区评估手册、脚本或完整协议，不将所有材料求并集；较大变化分批审查，保留采纳与未采纳理由。
- **授权沿用。**文档引用不扩大授权；已授权工作不反复请求。额外安装、生产操作和提交推送按会话与治理规则处理。
- **更新可核对。**社区或系统 skill 更新后核对所用流程、工具和格式；涉及自有 skill 的触发/职责变化时同步 README。本文同步更新职责关系，不另维护正文规则副本。

目录分工遵循现有真源规范：

| 位置 | 保存内容 |
|---|---|
| `skills/<name>/SKILL.md` | 对代理生效的核心规则与按需引用入口 |
| `skills/<name>/references/` | 该能力的详细矩阵、实例、诊断及验证说明 |
| `docs/` | 维护决策、协作关系和适用边界说明 |
| `.workspaces/<skill-name>-workspace/` | 本地评估输入、输出、对照及过程记录；Git 忽略，不分发 |
| `README.md` | 人类检索入口与治理文档入口 |

社区版与系统版原文不复制进自有 skill。真源唯一、链接分发、提交权限及过程产物的具体规则以 [skill-authoring-sync](../skills/skill-authoring-sync/SKILL.md) 为准。

### 历史验证边界

2026-10-08 的 `reference-to-skill` 初版使用 Codex 系统版 `quick_validate.py` 做结构校验，并完成两次独立上下文的隔离执行：一次只提建议、一次创建通用 skill。输入保持只读，实际产物经核对；本机三 harness 的链接校验通过。

这些结果证明所选样例中的执行与边界处理，**没有执行社区版完整有/无 skill 基准、触发优化循环或统计提升率**。生成的样例 skill 也没有再次用于真实业务任务。历史过程产物留在本地工作区，不作为跨机器必备链接；未来变化应补自己的验证证据。

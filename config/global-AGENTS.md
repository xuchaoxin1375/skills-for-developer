# 全局偏好

> 标准主文件在真源仓库 `config/global-AGENTS.md`；本文件是本机自定义副本。
> 改通用标准先改主文件，改本机定制只改本文件；动本文件时核对主文件有无新增标准需跟进。

任何会话开始前请务必确认:

- 加载skill `user-profile`(初次被加载提示用户"已注入"),只有问候类的任务允许跳过加载。
- 不发起会产生费用的真实模型/搜索/API 请求,也不自行抓包/回显代理,除非用户明确要求;
  配置与排障先走文档给出的最短路径与静态检查,不跳过必做步骤。
- 写脚本/小工具 CLI 时:长选项是主名(可读、写在文档与补全里),**条件允许时同时给短选项**——
  给最高频的几个开关(输出文件、代理、模式、引擎之类)配一两个字母的短选项;短选项与既有字母
  冲突、或含义会歧义时宁可不加,长选项始终保留。
- 路径书写优先用 `/`(如 `C:/repos/scripts`、`./work/update-cron.cron`):PowerShell、.NET 文件 API
  与文档示例都认,跨系统可复用,反斜杠还要多一层转义。例外保留反斜杠——UNC 与 `\\?\` 长路径
  (`\\server\share`)、注册表与 provider 路径(`HKLM:\...`)、`cmd.exe` 内建命令与把 `/` 当选项
  前缀的原生工具,以及目标程序明确只接受反斜杠时。
- 文档示例中的占位路径统一用 `/path/to/...`(如 `-Path /path/to/update-cron.cron`),不要拿某台机器或
  仓库内的真实路径当占位;只有需要照做执行的命令才写真实路径。
- 用户对文档与代码的手工改动优先保留(优先级高于自己的整理与统一);仅在违反基本原则或正确性时
  才改回,并在回复里说明原因和被改掉的内容。
- 文档与注释的并列列举(功能点、用例、示例、选项、待办)不用任何数字编号——阿拉伯数字(1.、2.)、
  中文数字(一、二、三)与带圈数字(①②③)都不用,改用无序列表或小标题;有序列表只留给有先后
  顺序的步骤,插入新条目时不必调整既有序号。
- 批量覆盖/下发类脚本的写入前检查只做可证实的判定；脚本名或子串匹配只能提示，不能阻断下发，且必须留 `--force` 一类强制覆盖入口（是否备份另设开关）。
- 需求简单时先给能完成目标的最小方案；不为完整性顺手加幂等进阶、回滚、预检等附加能力。有多个各有优势的候选方案时，列出差异与取舍交用户决定，不自行跳过方案确认；用户明确授权代决时才直接选定。
- 提交:任务完成即按仓库既有风格提交(含仓库内部的小项目/子目录),不反复提醒确认;仅当
  `.gitignore` 规则本身不合理、或怀疑文件含不宜入库的私密信息时才停下确认。仓库既往提交信息
  (类型前缀、标题与正文体例)是决策输入之一,沿用其风格。
- 推送:提交后默认同步——先 `fetch` + `merge --ff-only` 对齐远端再 `push`(多远端逐个推);
  推送或拉取失败(无凭据、网络、非快进、远端拒绝)就跳过并如实报告,不阻塞交付,不擅自 `--force`。
- 本机 skill 以真源仓库 `C:\repos\skills-for-developer` 为准(harness 侧是链接,内容随真源即时更新);
  查 skill 现状先看真源仓库的 `git status`/`log`/`diff`,不以 harness 目录或本机副本的时间判断。
- `user-profile` 只在明确要求时才改,且保持简洁(只存最常用最重要的常驻默认值);其余长期偏好写在
  本文件或对应 skill 正文,不放进 user-profile。

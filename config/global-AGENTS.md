## 全局偏好

可分发真源为仓库 `config/global-AGENTS.md`。本机定制留在目标文件，通用变更回写真源；同步时对比合并，不直接覆盖。
**这里是全局规则,具体的偏好请按需查阅`user-profile`这个技能.**

### 会话入口与规则归属

- 除纯问候外，会话动手前加载 `user-profile`，初次加载提示“已注入”。
- 本文件只维护跨任务协作与授权底线；个人工具偏好在 `user-profile`，领域流程在对应 skill。按 skill 的 description 选择入口，不在这里复制细则或技能地图。
- 修改 skill、全局偏好或同步配置时加载 `skill-authoring-sync`；真源定位、差异核对与分发按其流程。
- 维护或同步 skill、全局偏好与 harness 配置时，顺路比对真源与本机副本的结构和内容差异，能对齐的当次对齐；差异较大或存在冲突时先询问用户，不让偏差长期累积。

### 协作底线

- 保留用户的手工改动；仅在违反基本原则或正确性时改回，并说明原因及被改内容。
- 中断、自动重试或用户要求继续时，先核对已有产物与可见执行记录，只续接未完成部分；记录缺失不等于未执行，不因此重做可能收费或有副作用的操作。无法确认时先说明缺口，沿用原渠道与费用上限，不将“继续”视为重跑授权。
- 需求含糊、存在不同合理形态，或与既有开关/命名不一致时，先确认目标、默认行为与组合关系再实现。多个方案各有优势时说明取舍，由用户决定，明确授权代决除外。
- 分析覆盖可预见的边界与失败情形，实现聚焦核心，其余说明取舍与缺口。技术选型撑不起要求时先调整选型；环境限制导致能力削减时明说，不含糊承诺。
- 脚本、部署与自动化方案按跨设备复用沉淀：新设备应能直接照做，平台差异与未实测项写清，不把本机验证当作全平台结论。

### 费用与外部操作授权

- 未经明确授权，不发起收费的真实模型/搜索/API 请求，不自行抓包或回显代理。配置与排障先走文档最短路径和静态检查。
- 子代理或辅助任务需转订阅/付费渠道时，先核实可用替代，说明回退原因、任务是否执行、供应商/模型、订阅或按量费用(未知就说明)、任务范围与调用/费用上限，申请本轮授权。
- 授权只覆盖本轮获准的渠道、范围与上限，失败尝试也计入；范围内不重复询问，换渠道、扩范围或超上限前重新申请。免费授权不含付费，订阅授权不含按量计费；未获批则完成可执行部分或报告阻塞。
- 目录可见不代表余额或调用可用，启动即失败不算任务已执行；临时限流不等于额度耗尽，不切渠道绕过冷却，不自动购买套餐、改全局默认或保存新凭据。

### 工具与文档默认

- Windows 首次发出 PowerShell 调用前加载 `powershell-pitfalls`，单行 `curl`/`Get-Content`/`python` 片段与多段链式管道同样算。
- 写脚本/小工具 CLI 默认按 `scripting-best-practices` 交付；覆盖写入前的检查与 `--force` 入口、方案取舍留档以该 skill 为准，本文件不复制清单。
- 文档与注释：并列列举用无序列表或小标题，不用任何数字编号（阿拉伯数字、中文数字、带圈数字），只有确有先后顺序的步骤才用有序列表；命令示例中的占位路径写 `/path/to/...`，不拿真实路径当占位。细节见 `markdown-style`。

### 提交与同步默认

- 任务完成即按仓库既有风格提交，包括仓库内子项目，不反复确认；仅当 `.gitignore` 规则不合理或疑有不宜入库的私密信息时停下确认。
- 提交后默认同步：先 `fetch`、`merge --ff-only` 对齐远端再 `push`，多远端逐个处理。拉取或推送失败就跳过并如实报告，不阻塞交付，不擅自强推。

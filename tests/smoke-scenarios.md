# Skill 行为冒烟场景

结构校验（`check-skills.py`、`check-links.py`、链接脚本）只证明文件齐全，不证明规则会被采纳。改动所列 skill 的 `SKILL.md` 或 `references/` 后，用本文件的场景走一遍：把“任务原话”交给独立上下文（子代理或新会话），不提示该用哪个 skill，看回答是否落在“期望行为”上。

- 记录：把最近一次通过的日期写进“上次通过”；失败先修规则，不改日期。
- 未执行的场景写“未验证”，不按日期填。
- 新增场景取真实任务原话，一条只验一个判断；与[触发评测](../skills/skill-authoring-sync/references/trigger-eval.md)分开——那边查 skill 是否被加载，这里查规则是否被采纳。
- 场景失败时先判断是规则缺失、表述歧义，还是场景本身不成立；只有前两种才进入补丁流程。

## network-access

| 场景（任务原话） | 期望行为 | 上次通过 |
|---|---|---|
| “pip 装包太慢，帮我多配几个国内源” | 只配一条 index；说明 `extra-index-url` 没有优先级、多源会拖慢解析并放大依赖混淆；不堆公共镜像 | 2026-11-17 |
| “这个镜像站现在能用吗” | 用固定版本分别测索引段与文件段，取 2～3 次中位数；按约 2 倍阈值给常驻/备选/不可用，并声明结论只描述当次网络 | 2026-11-17 |
| “GitHub raw 又超时了” | 先走已核验加速前缀；约 3 秒无首响即改路，不原样重发同一 URL；说明镜像不覆盖 API、网页与推送 | 未验证 |
| “私有仓库拉不下来，能用镜像站吗” | 私有资源不交公共加速；先核验凭据与代理路线，再判断是网络还是权限 | 未验证 |

## scripting-best-practices

| 场景（任务原话） | 期望行为 | 上次通过 |
|---|---|---|
| “帮我写个批量下载脚本” | 默认跨平台 Python；`main()` + argparse、`--help`、非零退出码、UTF-8；不默认输出 Shell 与 PowerShell 两份 | 2026-11-17 |
| “这脚本跑几分钟一点输出都没有” | 开始前给计划，过程给逐项进度，结束给汇总与重跑命令；进度走 stderr，结果走 stdout | 未验证 |
| “给这个功能加个开关” | 同时给停用与卸载入口、回落行为，并列清启用、状态查询、失败边界等衍伸面 | 未验证 |
| “顺手把这两个脚本合并成一份” | 先审原设计的参数语义、默认值与失败路径，再给合并方案与取舍，不默认保持原样也不默认合并 | 未验证 |

## 维护本文件

- 新增 skill 条目只在它进入高频使用后建立，不为全覆盖而铺场景。
- 场景数量按经验控制在每个 skill 3～5 条；某条长期不失败且不再对应真实任务时删除。
- 修改本文件后跑一次 `python scripts/check-links.py`，确认相对链接有效。

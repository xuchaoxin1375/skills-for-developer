# 布局：栅格、间距与模式

> 何时读：Step 2。先选模式，再定栅格，最后画线框。

## 间距 scale（4pt 基准）

只用这 7 个值：`4 / 8 / 12 / 16 / 24 / 32 / 48`。对应关系：

| 用途 | 取值 |
| --- | --- |
| 图标与文字、紧凑元素间 | 4 / 8 |
| 段落、表单项、卡片内边距 | 12 / 16 / 24 |
| 区块之间、页面边距 | 24 / 32 / 48 |

页面左右边距桌面 ≥24，手机 ≥16。禁止 13px、17px 这类魔法数字。

## 栅格

- 桌面内容区 12 列，gutter 16–24；正文最大宽 1200–1440 居中，超宽屏不拉满。
- 工具型后台：左侧导航 220–260px + 右侧主区；导航收起态 64px 只留图标。
- 对齐铁律：同一屏所有卡片、按钮、标题左对齐到同一条垂直线；居中只用于空状态与登录这类单焦点页。

## 信息层级

一屏只允许一个视觉焦点（主按钮或核心数据）。层级手段按强度排序：位置与尺寸 > 留白 > 字重 > 颜色。不要同时用四种手段强调同一元素。

## 四种成熟布局模式（只许选，不许发明第五种）

1. **仪表盘**：顶栏（标题+全局操作）+ 左侧导航 + 卡片网格（2–4 列，卡片等高、操作右下对齐）。适合总览+入口。
2. **表单页**：单列，宽 480–640，标签在上、输入框在下；主按钮左对齐与表单同宽或定宽 120–160。超过 7 项必须分组或分步（见渐进式披露）。
3. **列表+详情**：左列表（320–400px）+ 右详情；手机上拆成两页（列表页 → 详情页，带返回）。
4. **设置页**：左二级导航 + 右内容；危险操作（删除、重置）单独成区放底部，用红色次级按钮。

## 页面可返回性与出口设计（多页路由，SHOULD）

页面较复杂、具有多页路由时：进来容易回去不能难，任何页面都不许孤立,源码文件存放也不要过于分散或随意。

- 每页至少一条回首页的路：页眉 Logo/首页入口、常驻侧边栏、面包屑三者至少有其一，并且统一应用内鼓励共用一致的页眉或侧边栏。
- 面包屑规则：当前位置高亮不可点，上级可点；深链接直达的页面也要能逐级回退，不依赖浏览器后退键。
- 详情/弹窗类次级页：明确出口（返回按钮、关闭×、Esc、点遮罩），关闭后焦点回到触发点。
- 验收：从任意页面出发，两次点击内回到首页；新开深链接也能找到回去的路。

## 多页一致性（SHOULD）

同一个应用内有多个页面时，各页面的设计和风格应当一致或相似：同一套 token（字体/色彩/间距/圆角/阴影）、同一套导航与页眉页脚、同一套按钮/表单/空错态语言。用户的学习成本只付一次。

- 例外：页面来自第三方项目或 vendor（嵌入的外部文档、第三方登录页、外链 vendor 控制台），允许风格不同，但跳转处必须明示（新标签页图标 + "即将前往第三方"提示），且提供明确的回来路径。
- 验收：任意两页并排截图，换页不产生"像换了个产品"的感觉。

## 线框要求

输出前先给线框：每块区域写"是什么+多宽+里面有什么"，ASCII 框图或文字均可。线框确认前不许写一句 CSS。

## 防挤压与溢出

- flex/grid 子项默认加 `min-width: 0`（纵向加 `min-height: 0`），否则内容把容器顶出。
- 长串（URL/token/无空格英文）：`overflow-wrap: anywhere`，宁可断行，不许撑破容器。
- 省略策略：单行用 `nowrap + hidden + text-overflow: ellipsis` 并加 `title`；正文最多 2 行（line-clamp），不许截断 3 行以上藏信息。
- 按钮定宽、文字先缩文案（≤6 字）；按钮不变形、不换行顶高。
- 图片/头像定 `aspect-ratio` + `object-fit: cover`，加载前灰底占位防布局跳动。
- **异步槽位定高**：懒加载/分批渲染的槽位（图片、内嵌页、"点我加载"占位、骨架屏），占位和最终内容必须同高。占位矮一截的话，每渲染一批页面就跳一下，滚动条跟着漂。静态内容长短不一（标题/描述行数）没关系——那是一次性渲染的；要防的是**渲染后**的高度变化。
- 横向滚动只允许出现在表格区；页面级出现横向滚动= bug，直接打回。

## 宽控件是布局坏味道

异常宽的按钮/下拉框不是"大气"，是空间利用失败的信号：**控件宽度远超内容所需、同区还剩大片留白**，说明线框没排好，不许用"拉满"掩盖，必须回去重排。

- 按钮按内容宽（`inline-flex`，不随容器 stretch）；flex 列里用 `align-self:flex-start` 收住。操作组左对齐换行，不靠拉满凑满行。
- 下拉框给 `max-width`（桌面 240–320）或收进栅格列；筛选项多时进下拉（见渐进式披露），而不是把下拉拉宽装下长文案。
- 验收尺：按钮宽度超过文案 3 倍且无布局理由，打回重排。
- 例外（仅这三处允许全宽）：表单单列 480–640 的输入类控件；移动端主按钮/底弹主操作；面板列内次要按钮（主按钮仍定宽，次按钮全宽只许在列内且视觉弱一级）。

## 对齐：基线、等高与多列陷阱

高低不齐和挤压一样是布局坏味道，先看对齐机制，再看间距数字。

- **机制分层**：统一控件高（各控件 padding 可为光学对中让路，但渲染高度必须一致）> 端部对齐（同行 `align-items` 取顶/居中/底其一，混用即错位）> 间距刻度。评审对齐先看前两条。
- **多列等高**：卡片网格靠默认 stretch 等高 + 操作区 `margin-top:auto` 沉底；标题/元信息按内容顺序自然对齐，不许定死高度裁文案。
- **`:first-child` 清零陷阱**：`xxx:first-child{margin-top:0}` 这类规则在单列转多列（媒体查询改 grid 列数）时会只作用于第一列，导致整列错位 8px 级。作用域必须限定到对应断点（如包进 `min-width` 媒体查询），多列下各列标题边距完全一致，行节奏只靠网格间隙。
- **验收**：双断点截图，量同行元素的顶边/底边（标题行、控件行、按钮行各一条线）；多列布局逐列量标题基线。差 1px 的光学补偿（如 pill 内边距）可接受，差出一个边距级（4px+）打回。

## 浮层层叠与召唤关闭

卡片内下拉菜单常死于两种盖法，修之前先用穿透点名定性（被点元素中心打 `elementFromPoint`，命中非自己即被盖），再动手：

- **视口出界**：面板相对触发键的一侧展开，`min-width` 会顶出视口（看着像被遮挡，实为出界，祖先链无 `overflow` 裁剪可证）。对策：触发键在行尾用右对齐，行首用左对齐；断言面板矩形完全落在视口内。
- **层叠上下文囚笼**：`transform`/`filter`/`opacity<1` 的祖先自带层叠上下文，子级 `z-index` 再大也出不了卡片——后兄弟整层盖上来，键全在但点不了。对策：提层提整卡（如开菜单的卡 `:has([open])` 加 `z-index`，关即收回），不要只加面板的 `z-index`。
- **召唤必有四种关闭**：触发键再点、点空白、Esc、执行任一动作后收。原生 `details` 只自带第一种，其余三种手写（document 点空白、Esc 链、动作入口顺手关）；一次只开一个，重渲染即收。验收四路全点一遍。
- **跨引擎收纳不用 `<details>+display:contents` 展平**：闭合态隐藏在部分引擎盖过作者 `display`（移动端展开态正常、桌面端被收的键全灭，症状按端切分即是它）。改用 checkbox 方案（label 包 input 做点击转发，显隐/提层/单开/四关全走 JS + 祖先 class，无 UA 语义可打架；注意 input 藏进 label 后 `input:checked ~ 面板` 因隔代永远匹配不上——显隐必须挂共同祖先的 class）。门禁加"开盖穿透"断言（面板矩形非零 + 键中心命中自己）。

# 动效：交互目的与设计预算

> 何时读：Step 4。动效解释状态变化、空间关系或等待过程；不为每次点击添加装饰。

## 职责与规则来源

本文件是 `frontend-design` 工具界面的反馈预算与动效令牌维护位置。项目 `DESIGN.md` 记录实际令牌与必要例外；其他前端参考只引用这里。
技术选型、可运行示例、进出场清理、性能与减弱偏好策略由 `web-animation-guide` 维护：按需读取其 `references/selection.md`、`references/snippets.md` 与 `references/performance-a11y.md`。
未安装该 skill 时使用已有组件或简单 CSS 透明度/变换过渡；语义状态、键盘和无动画路径仍须正确，不照猜复杂实现。

## 工具界面动效预算

| 场景 | 默认预算 |
| --- | --- |
| 按压、开关、轻提示 | 120–200ms |
| 下拉、菜单 | 约150ms 出现，约120ms 退出 |
| 列表载入、分组开合 | 约200ms；不逐行拖延大列表显示 |
| 页面切换、抽屉、弹窗 | 200–320ms；退出通常更快 |
| 常规过渡上限 | 320ms；必要例外写入项目令牌并说明收益 |

基础令牌为 `120/200/320ms` 与 `cubic-bezier(0.2,0,0,1)`。令牌模板是起点，不是另一套规范。
工具界面避免弹跳、弹性与无限循环装饰；只在有助于理解空间关系时添加微位移。进入和退出都须覆盖，减弱偏好或不支持动画时允许瞬时切换。
默认动效必须保持中间帧视觉稳定，优先淡入淡出、短位移或克制等比缩放；有明确交互收益或个性化需求时可升级，但仍须验证全过程。例：详情窗口关闭时整块退场，正文不挤成长条。
列表刷新保留旧数据，骨架与真实内容保持结构连续；不要为了淡入先把已就绪内容长时间藏起来。

## 等待与忙态

| 等待 | 反馈 |
| --- | --- |
| ≤100ms | 直接完成，不造等待 |
| 100–300ms | 必要的状态过渡，不闪 spinner、不人为延迟结果 |
| 约300ms–2s | 延迟出现局部等待指示，其他区域可操作 |
| >2s | 阶段说明、已用时间、取消/离开出口；能缩小范围时给入口 |

忙态与视觉等待指示分离：请求一开始就防重入，spinner 可以延迟出现；短任务也不能重复提交。
能预知布局的载入用骨架，提交/计算用局部文字与指示；未知总量不伪造百分比。不可中止的事务说明边界，区分取消请求与停止等待，不承诺不存在的撤销能力。

## 体验验收

- 双向进出场和列表开合是否连续，瞬时回退时主任务是否仍可完成？
- 默认动效的中间帧是否稳定，复杂形变是否有明确目的并通过过程验证？
- 忙态是否立即防重入，失败是否恢复并给重试，短任务是否没有指示闪烁？
- 快速反复开关、Esc、动画取消与减弱模式下，终态、焦点与隐藏内容是否正确？

加载信息不能只靠运动或颜色；静态图标与文字应能表达等待、成功和失败。技术检查统一引用动画指南的验证矩阵。

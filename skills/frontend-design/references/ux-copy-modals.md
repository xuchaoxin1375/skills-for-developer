# 长等待、弹窗与按钮文案规范

> 何时读：Step 4（表单/弹窗/二级页面动笔前）。原则：**用户永远知道"在等什么、要多久、能做什么"；按钮文字即操作说明书。**

## 一、长等待的诚实反馈

等待分级、忙态与取消边界统一见 `motion.md`；本节只维护文案。阶段以真实任务状态为依据，不按已用时间编造“连接/拉取”等阶段。

1. **阶段说明**：写实际在做什么（如“正在连接…”“正在分页拉取…”）；未知进展就说明仍在等待，不许只有转圈。
2. **已用时间**：显示 `Ns` 计时，让用户自己判断去留。
3. **取消/离开出口**：支持中止时提供取消；不可中止时说明离开是否继续处理，不把停止等待说成撤销任务。
4. **缩小范围的出口**：任务支持时提供搜索、分页提示或数量统计，让用户能调整范围。
5. 首次加载慢要解释原因（一句话 tip："首次加载需向服务端分页拉取全量数据"）。

## 二、按钮文案直观性（动词 + 对象 + 后果）

| 反例（黑话） | 正例 |
| --- | --- |
| 刷新 / 提交 / 所选送操作页 | 重新加载 / 预览（只看不改）/ 把所选加入操作目标 |
| 预览执行 / 正式执行 | 预览（只看不改）/ 确认执行（会改动） |
| 下载失败清单 CSV | 下载未完成清单 |
| 清空 / 关闭（弹窗主按钮） | 清空选择 / 用所选账号执行 |

规则：危险按钮标后果（括号注明"会改动"）；数量进文案（"加入操作目标（3）"）；状态门按钮二选一：隐藏，或真禁用 + 原因可见（`0` 时禁用 + 旁边说明，见 `interaction.md` 状态门）；禁伪装可用（看着能点、点了才说不能用）。

## 三、弹窗操作设计

1. 标题说清后果，副标题给操作路径（"双击查看记录；勾选多个加入目标"），隐藏操作（双击）必须有可见的等价按钮。
2. footer 主次分明：主按钮动词化（"用所选账号执行"），次按钮（"清空选择/关闭"）弱化。
3. 弹窗内列表同样要有数量、搜索、空/错/加载态（见 `icons-motion.md` 第三节）。

## 四、二级页面（历史/审计/明细）

1. 不许裸文本堆砌：结构化行（状态徽标 + 关键字段 + 时间），支持空状态。
2. 审计行回答"谁在何时做了什么"：操作图标按类型区分（执行/新增/修改/删除）。
3. 历史行支持重跑入口（ID 可复制，终态可据此重跑）。

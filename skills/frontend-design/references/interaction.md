# 交互（SHOULD为主，注明MUST的除外）

## 异步视图状态机

待机→加载→成功/空/失败。失败→重试回到加载。成功→刷新时保留旧数据+小指示，不许整页闪回骨架屏。空态要有引导文案与主操作。错误态必须有重试/返回，不许只有一行红字。

- **首屏同步防闪跳**：持久化是同步的，读完立刻摆 DOM，不要等异步数据回来再纠正——"先错后对"看着像 bug。异步才能拿到的数据（如选项列表）仍后填，但开合/勾选/输入值这类本地就有的状态必须一步到位。
- **并行淘汰**：多路并行加载时，失效淘汰只认已加载成功的一路；没回来的一路不判死刑，否则启动时序一变就误删用户选择。
- **持久化带版本 + 自动迁移**：状态形状升级时（如单值改多选集） bump 版本，老形状自动转新形状，用户无感；非法值由加载后的淘汰逻辑处理，不在读取时抛错。

## 反馈时延预算

- ≤100ms：直接变化，不转圈。
- 100–300ms：用过渡动画掩盖，不弹spinner（会闪）。
- 300ms–1s：延迟约300ms后出局部指示（按钮内spinner、进度条），不整页。
- 1–10s：骨架屏或进度条，界面其余部分保持可操作，提供取消。
- >10s：给百分比与预计时间，允许离开并通知。
- 低风险操作可用乐观更新，失败回滚或给撤销。

## 动效（经验值，非标准）

微交互100–150ms，中等元素200–250ms，大面积300–400ms；超过500ms几乎总是太慢。进入用`ease-out`、退出用`ease-in`。只动`transform/opacity`，禁`top/left/width/height`，禁`transition: all`。尊重`prefers-reduced-motion: reduce`。动画可打断；自动播放超过5s必须有暂停/停止/隐藏。

## 表单（MUST）

每个输入必须有可见`<label>`。`type/inputmode/autocomplete`要正确。失焦验单字段、提交时汇总；首字输入不报错，修正即消错。错误紧贴字段、`aria-describedby`关联、给修复建议；提交失败焦点移到首个错误。保留已填数据，多步表单可回退且数据不丢。密码框允许粘贴与显示/隐藏。破坏性确认写清对象名与后果，按钮是动词（“删除”而非“确定”）。

## 按钮可用性：状态门（MUST）

按钮功能取决于某项状态（未选行、无数据、未连接、权限不足、前序步骤未完成），当前状态下点了也不会成功 → 不许呈现为正常可用态。只许二选一：

- **隐藏**：该状态下用户不需要知道此操作，或操作只在特定上下文有意义（如选中行后才出现的批量操作）。隐藏后入口仍可发现（选中即出现）。
- **真禁用 + 说清原因**：需让用户知道有这功能但现在不可用。视觉明确禁用（降对比 + 禁用样式，不只靠颜色）+ 真不可点（`disabled` / `aria-disabled` + 阻止操作）+ 原因可见（旁边文字、`title`/Tooltip、或文案带数量如"加入操作目标（0）"）。

禁止第三种：**伪装可用**——看着能点，点了静默无反应、只弹"请先选择"、或点了才告诉不能用。点了才说不能用 = 欺骗。

与"禁用提交代替校验"的边界：表单字段填错 → 提交保持可点，点了定位首错（表单 MUST 不变）；只有前置状态缺失才允许禁用/隐藏。可访问性：`disabled` 按钮移出 Tab 序；需解释原因时用 `aria-disabled="true"` 保留可聚焦，点击/回车给出原因，或在旁边放可见文字说明。

## 导航（MUST）

URL反映筛选/分页/标签/详情，可分享可还原。后退前进正常，列表进详情返回后恢复滚动，新页面滚到顶部。当前位置有标记（`aria-current="page"`、面包屑、随路由变的`<title>`）。一次只开一个弹窗；要堆叠改抽屉或分步。移动端输入字号≥16px防iOS缩放；列表超约50项做虚拟滚动。

## 国际化与本地化

用于产品要面向不同语言或地区用户，或同一产品要在多个市场复用时。国际化（i18n）是让代码和内容能适配不同 locale；本地化（l10n）是为具体市场准备语言、格式和内容。两者都要在界面结构和数据契约阶段考虑，不能等页面做完再补翻译。接口的 locale 协商、错误消息和邮件模板属于跨端契约，按[架构与契约](../../swe-gov/references/architecture-and-contracts.md)处理；本页聚焦界面呈现、文案和格式。

单语言内部工具不需要完整翻译流程，但仍应设置页面 `lang`，用标准库格式化日期、数字和货币，避免写死格式。

### 先定 locale 模型

- 语言和地区分开：`zh-CN`、`zh-TW`、`en-US`、`en-GB` 不是同一个 locale；同一语言在不同地区的日期、货币、地址和用词可能不同。
- 确定支持列表、默认 locale 和回退链：用户选择 → 账号/租户默认 → 浏览器 `Accept-Language` → 产品默认。不要只按 IP 猜测，必须允许用户切换并记住选择。
- 明确哪些内容翻译：界面文案、错误信息、邮件/通知、法律页面、帮助内容；用户生成内容默认不自动翻译。
- 明确缺失翻译的行为：显示回退语言并记录缺口，不要显示空字符串或 key 名。
- 多租户产品要确认：locale 是用户级、租户级还是两者都有；切换后哪些缓存和邮件模板要失效。

### 文案与布局

- 所有用户可见字符串外部化，不拼接句子。词序、性别、复数在不同语言中不同，拼接会直接产生病句。
- 用 ICU MessageFormat 或同类能力处理 plural/select/占位符；不要用 `if (count === 1)` 覆盖所有语言。波兰语、俄语、阿拉伯语等有更复杂的复数规则。
- 给译者提供上下文：出现在哪个页面、什么角色、按钮还是标题、最大长度、语气、截图。只给一句孤立文本，译者只能猜。
- 预留文本膨胀：德语、芬兰语等可能比英语长 30% 以上；按钮、标签、表头不要固定窄宽，允许换行和高度变化；窄屏下优先保操作可见。
- CJK 与拉丁文混排：设置合适行高、字体回退和标点；不要对中文使用斜体或两端对齐；数字和英文保持可读。
- RTL（从右到左）：用逻辑 CSS 属性（`margin-inline-start` 等），镜像布局和方向性图标，但数字、URL、代码保持 LTR；单独走查，不能只靠 `dir="rtl"`。
- 截断要谨慎：关键按钮、错误信息、表单标签不要用省略号藏住；需要截断时提供完整文本入口。

### 格式与数据

- 日期时间：用 `Intl.DateTimeFormat` 等标准能力；存储用 UTC，展示按用户时区；不要假设 `YYYY-MM-DD` 或 `MM/DD/YYYY`。
- 数字和货币：用 `Intl.NumberFormat`；小数分隔符、千分位、货币符号和代码因 locale 而异；不要写死 `$` 或固定两位小数。
- 姓名和地址：不要假设“名 + 姓”或西方地址顺序；字段和校验按目标市场调整；电话号码带国家码。
- 排序和搜索：使用 locale 感知的排序（collation）；大小写折叠和音译按需求处理。
- 单位：长度、重量、温度、纸张尺寸等按市场选择；必要时同时显示公制和英制。
- 法律/税务/医疗等受监管内容需要当地复核，不能只靠机器翻译。

### 翻译工作流

- 确定源语言和唯一字符串源；key 用稳定命名和命名空间，避免重复和歧义。
- 流程至少包含：提取 → 翻译 → 审校 → 伪本地化/QA → 发布；记录缺失和过期翻译。
- 伪本地化：用加长、带标记的假翻译提前暴露布局和截断问题，不要等真翻译回来才发现按钮放不下。
- 翻译可以滞后于功能，但不能静默缺失；按 locale 用功能开关控制发布，不要让一个语言的延迟阻塞所有市场。
- 明确谁维护术语表、谁审校、翻译更新 SLA，以及源文案变更后如何让旧翻译失效。

### 测试与验收

- 伪 locale 和每个真实 locale 的关键路径：注册/登录、核心任务、错误、空态、支付/提交。
- 复数边界：0、1、2、5、11、21 等；日期/时间/时区/夏令时；货币和数字格式。
- 长文案、长姓名、长地址、窄屏、RTL、字体回退、屏幕阅读器语言。
- 关键页面截图对照；高风险内容由母语者或当地同事复核。
- SEO：多语言页面用 `hreflang`、本地化 URL、canonical 和 sitemap；不要只靠 IP 自动跳转而没有手动切换入口。
- 分析事件带 locale 属性；口径按[产品度量与埋点](../../swe-gov/references/product-measurement.md)定义。比较不同 locale 的转化时注意样本量和渠道差异。

### 常见坑

- 用字符串拼接组织句子，翻译后词序错误。
- 页面布局完成后再翻译，长文案撑破按钮和表格。
- 写死日期、货币、电话号码、地址和姓名格式。
- 用简单的单复数判断覆盖所有语言。
- 译者没有上下文，术语前后不一致。
- 缺失翻译回退到英文却没有任何提示，用户以为功能坏了。
- 只做 `dir="rtl"`，没有处理图标、间距和数字方向。
- 只按 IP 判断语言，用户无法切换。
- 机器翻译法律、医疗、金融文案后直接上线。
- 翻译 key 重复或废弃，旧翻译覆盖新文案。

### 最小检查清单

- [ ] 支持 locale、默认值、回退链、切换与持久化明确。
- [ ] 用户可见字符串已外部化，无拼接；plural/select 使用 ICU 或同类能力。
- [ ] 日期、数字、货币、时区使用标准格式化，存储与展示分开。
- [ ] 长文案、窄屏、RTL、字体回退和截断策略验证过。
- [ ] 翻译流程、缺失 key、过期翻译和 owner 明确。
- [ ] 每个上线 locale 的关键路径和截图完成验收。

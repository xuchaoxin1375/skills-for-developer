## 前端界面设计

两种模式：**生成**（按步骤1–6）与**交付验收**（只走验收清单）。另有可选**协助式**模式（多方案出稿 + 用户参与选择）与**重设计**模式（改版默认推倒重来 + 保留举证，见文末）。标准依据：`prompts/前端设计合并版.md`。分工：存量页面缺陷深查（按编号根因/复现/验收）与CI门禁转 `frontend-ux-qa`，本 skill 不重复其编号体系；后台控制台/管理面板骨架（外壳侧边栏/数据表格/表单设置向导）转 `admin-console-design`，本 skill 只留通用主张/线框/令牌。

本 skill 维护任务、信息层级、页面结构、视觉令牌、通用交互与无障碍基线，以及整体交付。空间变化时的重排、操作收纳、视口/容器实现与专项验证由 `adaptive-responsive-guide` 维护，入口见 `references/responsive.md`。线框阶段识别约束，实施时只读相关专项，验收合并为一份报告，不重复执行两套完整流程。

### 步骤1——任务与渐进披露

用一句话说清：用户是谁、主要任务是什么、下一步操作是什么。信息不明时记下假设，绝不用装饰掩盖需求缺失。
改存量功能时，先书面还原它为什么是现在这样；说不清的疑点先问用户，不靠猜推进。
然后读 `references/progressive-disclosure.md`：首屏只做一件事、主操作不超过3个；表单超过7项必须分组或分步；危险操作远离首屏并二次确认；空状态只给一件事加一个主按钮。
同一动作多入口做同一件事时，推荐合并为一个（各端一致；有正当理由可保留多入口）。
按条件显隐时保留已填值（藏起不等于清空）。

### 步骤2——先定主张，再画线框，最后写样式

先读 `references/taste.md` 定主张（小工具默认一句话主张+一处记忆点+减法一遍；落地页/改版走三方向，三方向仍无辨识度时转 `distinctive-design-director` 方向模式定调，本 skill 只做落地），主张链写进线框顶部；主张不落 token 的不许开画。再读 `references/layout.md`。四种布局模式四选一（仪表盘 / 表单单列480–640 / 列表+详情 / 设置页），不许自创第五种。后台控制台类（Topbar56＋Sidebar折叠/peek/抽屉＋数据表格＋设置/向导）不套本节四模式，直接转 `admin-console-design` 步骤0–1定页型与外壳，本 skill 只做视觉主张与令牌。间距组件内只用 `4、8、12、16、24、32、48`，`64`只允许页面级大间距。
在线框阶段读 `references/responsive.md`，写清窄屏与窄容器中的重排、操作收纳和滚动归属；不要等样式完成后才补适配。例：同一卡片进侧栏时，次要动作移进更多菜单。
增长列表先确定滚动归属：页面列表默认随页面滚动，弹窗、日志或受限面板可使用限高内容区；具体边界见响应式专项 [page-patterns.md](../adaptive-responsive-guide/references/page-patterns.md)“滚动归属与浮层形态”。
整页长列表默认分页（条数固定、筛选页码联动、换页回到顶）。
分页须可回退（刷新返回不丢页码筛选）。
设置页内容多时用面板风：左导航＋单页切换（一次一节）＋按钮栏常驻。
切页窗口可保留稳定高度以维持连贯，须受可见视口约束；字体放大、窄屏与软键盘下仍能访问全部内容和操作。
先出线框（每块区域写清是什么+多宽+装什么）并经确认，再写一句CSS。底线读 `references/a11y.md`（WCAG 2.2 AA：全键盘可达、焦点可见且不被遮挡、目标≥24px/触屏≥44px、文字对比4.5:1/大文字与非文字3:1、320px回流、中文`lang`、行高≥1.6、CJK不用斜体与两端对齐）。

### 步骤3——视觉先写进令牌

读 `references/visual-tokens.md` 与 `references/tokens.md`。所有视觉决策先写进令牌（项目缺 `DESIGN.md` 时从 `assets/DESIGN.md` 复制）：三层令牌、组件只用语义层；字号档≤7档；圆角≤4档；阴影≤3级且带色相；只用一套图标库。`oklch()`可用但要给老WebView留sRGB回退；合规看WCAG对比率，APCA只作设计参考。
文字/图标与背景配对、透明叠层、状态及阅读质量统一读 [对比度与可读性](references/contrast-readability.md)，设计与验收共用；例：按钮hover后仍测字色对hover填充。

### 步骤4——交互、动效、文案

读 `references/interaction.md`、`references/motion.md`、`references/icons-motion.md`、`references/ux-copy-modals.md`。异步视图必须有加载/空/错/成功态且可恢复；刷新保留旧数据。
诊断/探测类结论必须标明测量条件（走的是哪条路、相对什么基线），不把 A 路结论用于 B 路决策。
显示与操作分离：只读状态不做成可点样。
配置类收进设置入口，操作留独立入口。
状态门按钮二选一：隐藏，或真禁用 + 原因可见，禁伪装可用（看着能点、点了才说不能用）；表单字段填错不禁用提交（点了定位首错）。反馈预算与工具界面动效令牌统一见 `references/motion.md`，项目 `DESIGN.md` 记录实际取值。

- 弹窗/抽屉/菜单默认提供双向过渡，列表载入与分组开合保持视觉连续；减弱偏好或兼容回退可瞬时切换。例：关窗也有退出反馈，减弱模式仍能立即关闭。
- 耗时操作同步进入忙态并防重入，完成或失败后恢复；动效不阻塞业务状态与焦点管理。例：保存未返回前再点击，不会重复提交。

本 skill 决定反馈目的与设计预算；`web-animation-guide` 集中维护技术选型、代码、清理、性能与减弱处理。实现进出场、尺寸变化或 JS 动画时按需读取其对应参考，不在本 skill 复制实现规则。按钮文案=动词+对象+后果。一次只开一个弹窗；破坏性确认写清对象名。

### 步骤5——响应式与状态

按 `references/responsive.md` 的路由落实线框约束：响应式阈值写入项目 `DESIGN.md`，基础宽度与专项验收读取 `adaptive-responsive-guide/references/acceptance.md`；`scripts/screenshot.mjs` 是基础截图助手，不能代替容器与交互验收。表单：可见标签、正确`type/inputmode/autocomplete`、失焦+提交两级校验、内联可修复错误（`aria-describedby`）、首错聚焦、保留已填数据、允许粘贴。控制台表单要 12栅/草稿/脏保护/危险区细节时，查 `admin-console-design/references/forms.md`（两级校验与设置/向导同一套，不断重写）。
内容区用 `flex:1＋min-width:0` 保收缩（`flex:none` 按内容撑开致溢出）。
长行（URL/命令）断行不断窗。

### 步骤6——审查与交付

先跑 `scripts/scan.py` 扫低级违例，再按 `assets/design-review-checklist.md` 与 `references/checklist.md` 逐项打勾（含 `taste.md` 主张项），顺序：任务→主张→恢复→键盘窄屏→视觉→装饰。需按编号深查缺陷根因/复现/验收时，转 `frontend-ux-qa` 的 catalog（`L/C/S/V/A/F/N/I/D/P/G/H`）；动效缺陷深查方法见 `web-animation-guide` 的验证清单。结论分三级：阻断（MUST/NEVER违反）/建议（SHOULD）/细节，每条注明文件与规则。交付物：线框、令牌差异、实际视口/容器验证记录与截图、清单打勾、已知问题；响应式专项合并到同一报告，未执行项明确记录。
可增长列表按滚动归属验：页面列表可自然增长，受限弹窗/面板条目翻倍也不突破可见高度；诊断结论验条件标注。
浮层类（fixed/overlay/portal）页面级断言查不到，须单列断言。
换元素类型必查元素前缀选择器；dialog 保留原生关闭隐藏机制，退出所需布局不能只依赖 `[open]`，写法见 `web-animation-guide/references/interactions.md`。
大改/新 UI 加交互态截图（开/关/空/满/错）并经人眼确认；DOM 断言只拦错位溢出，不代替视觉验收。
截图先全景定结构，再特写验细节；交互态用特写。
浮层用视口截图（元素截图裁掉溢出部分）。
假按钮/伪装可用、虚假进度、键盘陷阱、对比度失败一律不许放行。

### NEVER（两种模式通用）

无替代的`outline:none`、`div onClick`按钮、仅hover功能、`window.alert`、素按钮/素开关（按钮与开关必须带图标，纯文字按钮不得放行；动态生成的按钮同样适用）、禁用提交代替校验（表单场景；状态门见 `references/interaction.md` 二选一）、禁粘贴/禁缩放、未经主张检验的纯装饰渐变/满屏毛玻璃/标题emoji/卡片套卡片（有主张支撑且通过减法检验的见 `references/taste.md`，可用）、任何欺骗模式。详见 `references/anti-patterns.md`；需按编号深查时转 `frontend-ux-qa`。

### 协助式模式（可选）

用户要求"多给几个看看/我来选"时启用，不默认进入。

1. **多方案出稿**：同一需求出 2–3 个 HTML 稿（同一目录，如 `draft-a/b/c.html`），布局/主张/密度至少其一不同，只换配色不算新方案。
2. **标出最推荐**：必须明确标注最推荐的一稿 + 一句话理由；其余各稿标注 2–3 条优缺点（优点讲体验收益，缺点讲代价），不写"各有千秋"式空话。
3. **用户参与选择**：用户直接看稿点选；选定后按选定稿继续步骤 3–6，未选中稿保留不删，供回退。
4. **跨稿拼合**：用户说"A 的布局 + B 的配色"时允许拼合，但拼合后重过一遍主张检验与减法。

### 重设计模式（改版/重做，MUST）

被要求"重新检查/重新设计"时默认旧设计**总体是糟糕的**，除非用户只点了特定部分。

1. **默认推倒，不打补丁**：大模型基于旧稿渐进小改，做不出大改变。不许在旧稿上小修小补，必须回到步骤2从主张重做（新主张链 + 新线框 + 新 token）。
2. **保留举证倒置**：凡主张保留的旧有部分，逐项书面回答三问，答不上来就重做——
   - 为什么值得保留：它已达到独特级/非凡级美学特征了吗（遮住 logo 可识别、有好记的手法，而非品类默认值）？
   - 为什么不做得更好：不做的代价是什么，理由成立吗？
   - 是否对照过灵感指南：`taste.md` 第2/5条（转译原理、截图对标）走过吗？方向仍无辨识度时转 `distinctive-design-director` 定调了吗？
3. **交付**：改版交付物在步骤6基础上加"保留清单"（保留了什么 + 三问答案）；无论证保留 = 阻断，不许放行。

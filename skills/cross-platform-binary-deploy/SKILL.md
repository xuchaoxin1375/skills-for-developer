# Skill: cross-platform-binary-deploy

## 适用范围

- 适用：单文件或静态链接、无系统服务、无共享库与插件依赖的 CLI 工具，例如 `ripgrep`、`fd`、`btop`、`carapace`、`fzf`、`zoxide`、`yq`。
- 不适用：系统服务、驱动、内核模块、需要特定运行时或浏览器内核的软件、依赖自动安全更新的基础设施。这类软件使用系统包管理器或官方安装器。
- 安装前先查已装：同一命令可能来自包管理器、旧目录或别的版本。先运行 `Get-Command <name>`（Unix 可用 `command -v`）与 `<name> --version`，确认是否真的需要下载。

## 核心用例

- 新机器装一个没有包管理器的 CLI：固定版本下载、校验、安装到用户目录，再验证版本与 PATH。
- 包管理器版本太旧或平台没有对应包：用二进制通道取上游最新版或指定版本，包管理器保留为回退。
- 审查现有安装脚本：检查资产矩阵、校验、解压边界、原子替换、PATH、卸载与失败提示是否齐全。

## 最短路径

1. **判断通道**：按下方决策表选择二进制下载、包管理器或官方安装器；不把二进制方案当万能替代。
2. **确定目标**：列出 OS、CPU 架构、Linux libc/ABI；按上游 release 的实际资产命名映射，未知组合直接失败，不猜测回退。
3. **确定版本**：默认解析 latest；需要可复现时固定版本。已有版本高于目标时默认拒绝降级，要求显式允许。
4. **取回制品**：API 与资产 URL 分开处理；代理、镜像、超时与回退按 `network-access`，不在安装器里另写一套选路。
5. **校验完整性**：优先官方 `checksums.txt` 或签名。同源 checksum 只能证明传输完整，不能证明发布者可信；没有校验值时明确告知用户，不编造。
6. **安全解压**：解到临时目录，只取预期可执行文件；拒绝绝对路径、`..` 与符号链接条目，不整包解到系统目录。
7. **原子安装**：先写同目录临时文件，设置执行权限后重命名覆盖；失败时清理临时文件。
8. **配置 PATH 并验证**：加入用户级 PATH，运行 `<tool> --version` 并检查退出码；确认解析到刚安装的路径。
9. **记录与善后**：给出升级、卸载与回滚方式；不要静默修改 shell 配置或终端键绑定。

完成标准：`<tool> --version` 退出码为 0，`Get-Command`/`command -v` 指向目标路径，且安装脚本在重复运行、已有版本、未知平台与校验失败时都有明确结果。

## 通道决策

| 条件 | 优先选择 |
|---|---|
| 单文件、静态链接、release 资产覆盖目标平台 | 二进制下载 |
| 需要固定版本、快速跟进上游、包管理器版本过旧 | 二进制下载 |
| 目标平台没有包管理器或没有管理员权限 | 二进制下载到用户目录 |
| 需要共享库、插件、运行时或系统集成 | 包管理器 |
| 系统服务、驱动、内核模块 | 系统包管理器 |
| 依赖自动安全更新与系统级卸载 | 包管理器 |

二进制方案要自己承担依赖解析、升级、卸载、签名与系统集成。只对已经有共同模式的少量工具抽公共层；不要先做“万能安装器”。

## 资产矩阵

不要用 `uname -m` 临时拼资产名。为每个工具记录 OS × 架构到资产名的映射，并以 release 实际文件为准。

| 发布方式 | 常见命名 |
|---|---|
| GoReleaser | `tool_<版本>_windows_amd64.zip`、`tool_<版本>_darwin_arm64.tar.gz`、`tool_<版本>_linux_amd64.tar.gz`、`tool_<版本>_checksums.txt` |
| Rust target triple | `tool-x86_64-pc-windows-msvc.zip`、`tool-aarch64-unknown-linux-gnu.tar.gz`、`tool-x86_64-apple-darwin.tar.gz` |
| 单文件直出 | `tool_windows_amd64.exe`、`tool_linux_arm64` |

- 架构名统一映射：`x86_64`/`AMD64` → `amd64`，`aarch64`/`ARM64` → `arm64`。
- Windows 资产通常带 `.exe`；macOS/Linux 通常无扩展名，压缩包多为 `.tar.gz`。
- Linux 要区分 glibc 与 musl；静态链接的 Go 或 Rust 二进制通常不受影响，动态链接程序按发行版选择。
- 资产列表来自 API 时，缺目标资产就列出当前平台可用项后失败，不发“可能可用”的 URL。

## 版本与安装布局

- latest 查询失败时允许用固定版本重试；固定版本可以跳过 API，降低限流影响。
- 同版本默认跳过，`--force` 才重装；降级必须显式允许，并在输出中打印新旧版本。
- 安装目录优先用户级：Windows 可用 `%LOCALAPPDATA%\Programs\<tool>` 或 `%USERPROFILE%\.local\bin`，Unix 用 `~/.local/bin`。系统目录只在用户明确要求时使用。
- 单文件工具可以直接替换；需要回滚时用“版本目录 + current 指针”，保留上一版并在失败时切回。
- 记录安装来源、版本、校验值、目标路径与时间，供升级与精确卸载使用。

## 完整性与安全

- 优先独立可信的校验值或签名；只有同源 checksum 时，说明它防的是传输损坏，不防上游被替换。
- 下载走 HTTPS；Windows PowerShell 5.1 需要显式启用 TLS 1.2。
- 解压前建立独立临时目录；解压后按预期文件名查找可执行文件，不执行压缩包内的其他脚本。
- 安装后不要用 `rm $(which tool)` 卸载：该路径可能属于包管理器；按记录的安装路径删除。

## PATH 与优先级

- Windows 写用户级 PATH，避免要求管理员权限；同时更新当前会话。
- Unix 只更新当前会话，并打印可直接照抄的 `export PATH="<目录>:$PATH"`，由用户决定写入哪个 shell 配置。
- 安装后重新解析命令；若仍命中另一个版本，打印两个路径与优先级，提示用户移除旧版本或调整顺序。
- 不要修改 profile、Tab 键绑定或 shell 别名；只打印启用方式。

## 更新、卸载与回滚

- 更新前比较本地版本与目标版本；同版本跳过，高于目标拒绝降级。
- 包管理器与二进制通道可能同时存在；卸载时先确认当前命令归属，不静默卸载包管理器版本。
- 回滚优先切回上一版目录或指针；没有保留旧版时，明确说明只能重装指定版本。
- 卸载后清理 PATH 条目与安装清单，不只删除单个可执行文件。

## 常见坑

- 用 `$env:OS` 判断 Windows 在部分宿主或容器中会失效；PowerShell 7 用 `$IsWindows`，5.1 用 `PSEdition` 兜底。
- GitHub API 与资产 URL 的代理/镜像规则不同；API 地址不能直接塞进文件加速前缀。选路交给 `network-access`。
- API 限流时改用固定版本；不要在脚本里无限重试。
- Windows 10 以下可能没有 `tar`；缺少解压工具时给出包管理器或手工解压入口。
- macOS 未签名二进制可能被 Gatekeeper 拦截；优先改用 `brew`，或说明 `xattr -d com.apple.quarantine <文件>` 放行方式与风险。
- Git Bash/MSYS 等兼容层的 PATH 使用 `:`，而 Windows 程序常输出 `C:/...;...`；直接放进 PATH 会让首项失效，按平台分隔符修正后再继续。
- 同一二进制被多个 shell 使用时，补全注册与启动文件彼此独立；安装器不要用 PowerShell 组件开关推断 Git Bash、WSL 或其他 shell 已生效。
- 正在运行的旧进程可能锁住可执行文件；Windows 上需关闭会话后重试，不要反复强制覆盖。
- 安装目录不在 PATH 或排在其他目录之后时，“安装成功”但命令仍解析到旧版本；必须检查实际解析路径。

## 审查清单

- 目标平台与架构是否逐个映射，未知组合是否明确失败？
- 版本策略是否覆盖 latest、固定版本、同版本跳过与降级保护？
- 是否有可信校验值与失败即停的行为？
- 解压是否限定在临时目录，是否只取预期文件？
- 安装是否原子替换，失败是否清理临时文件？
- PATH 是否可逆，是否提示而不是静默修改 shell 配置？
- 是否验证 `<tool> --version` 与实际解析路径？
- 是否给出升级、卸载与回滚方式？
- 网络失败是否给出包管理器或手工下载的回退入口？

## 验证协议

- 先跑 dry-run 或 `-WhatIf`，确认动作清单与目标路径。
- 覆盖已有版本、同版本、指定低版本、未知平台、资产缺失与校验失败。
- 在至少一个真实平台完成下载、校验、解压、安装与 `<tool> --version`；其他平台只声明已验证资产命名或 release 列表，不声称已实机安装。
- 二进制同时服务多个 shell 时，分别在目标 shell 中验证补全注册与 PATH，不只验证 `--version`。
- Bash 中多候选第一次 Tab 只补公共前缀或响铃，第二次才列候选；超过 `completion-query-items` 会询问 `y/n`。不要以一次 Tab 无列表判定补全失效。
- 检查重复运行是否幂等，失败后是否留下半成品或错误的 PATH 条目。

## 与相邻 skill 的边界

- `network-access`：决定“怎么取回”，包括代理、镜像、超时与错误分流；本 skill 决定“取回后怎么安装与维护”。
- `scripting-best-practices`：CLI 参数、`--help`、退出码、覆盖预检与文档契约。
- `resource-inventory`：安装前盘点本机已有工具与版本，避免重复下载。
- `lightweight-app-builder`：从模糊需求选择程序形态与分发方式；进入具体发布资产与安装器实现后再使用本 skill。

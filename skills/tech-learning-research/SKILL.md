## 技术学习、信息调研与方案探索

目标是以足够证据回答目标读者的问题，并交付可理解、可使用的结果。先定产物与成功判据，再复用材料、补足取证、综合成文；不先写确定结论再寻找支持。

## 职责与协作

- **研究与综合**：本skill决定研究问题、覆盖范围、方案权衡和报告详略。
- **检索执行**：[agentic-web-search](../agentic-web-search/SKILL.md)维护渠道、查询、证据核验、预算、限流与停止机制；本skill不另设调用次数要求。
- **教学成文**：教程、解释型讲解或读者理解困难时，按需读[教学设计与理解对齐](../doc-rewrite-review/references/tutorial-design.md)；只采用相应教学规则，不重启改写、合并或落点确认流程。
- **其他产物**：已有正文改写归[doc-rewrite-review](../doc-rewrite-review/SKILL.md)，项目配套文档规划归[project-docs](../project-docs/SKILL.md)，脚本实现归[scripting-best-practices](../scripting-best-practices/SKILL.md)。需要归档定稿时再交[note-blog-archivist](../note-blog-archivist/SKILL.md)。
- **表现形式**：新写与改写均采用[markdown-style](../markdown-style/SKILL.md)的适用排版规则，不套用其纯排版任务的“内容零改动”判据。

## 输入与交付约定

复用请求和会话已明确的信息；有默认值的缺项直接采用默认，仅当真实歧义影响目标、风险或交付时提问。

| 输入 | 处理方式 |
| --- | --- |
| **话题与目标** | 必需；明确要回答的问题、适用范围及读者合理期待但不覆盖的内容 |
| **产物职责** | 区分教程、操作指南、解释、参考与研究报告；能从请求确定时不重复询问 |
| **读者能力** | 分别考虑领域知识、工具熟练度和任务经验；对未声明的必要背景按主题初学者处理，不抹去会话中已知能力 |
| **详略等级** | 默认`1` full，见“详略等级”；完整是目标范围内充分，不是穷举相关知识 |
| **搜索深度** | `正常`为常规取证，`深度`为多轮迭代意图；未指定时按时效、争议、候选数量与答错代价判断，具体力度归检索skill |
| **取证边界** | 判断是否需要新外部依据；已有材料充分的稳定概念可直接综合，时效或关键事实有缺口时定向核验 |

**报告交付方式**：生成调研报告且用户未说明交付方式时，开始调研前询问：“报告直接在对话中输出、写入文档，还是两者都要？”已有选择不重复询问；普通简短问答不增加此提问。写入文档时复用给定路径与格式；缺失时提出建议并确认，不擅自创建或覆盖文件。

## 最短工作路径

1. **定义成功**：用一句话对齐读者、问题与产物。教程确定要获得的能力，指南确定任务与验证，研究报告确定需回答的关键问题；不把所有产物都套成教程。
2. **盘点依据**：读已有资料并区分已证实事实、来源主张和设计建议。仅对缺口安排检索；首次有必要时说明工具能力、限制与费用边界，不重复自报角色、身份或工具清单。如被询问模型身份，应如实回答，不确定则说明。
3. **研究取证**：需要新依据时，先列相关维度、子问题与期望来源，再按检索skill执行。长任务只在范围、关键发现、取舍或阻塞变化时反馈进度。
4. **综合判断**：检查关键主张的支持范围与反例；方案场景给明确推荐、依据和不适用条件。缺口按“证据不足时的交付”处理。
5. **组织成文**：按读者和产物组织主线，而非照抄研究计划。必要解释就地呈现，非必要深度放选学或参考；关键示例在正文可见，完整代码可链接用户可访问的文件或公开资源。
6. **验证交付**：检查引用、概念依赖、关键示例和承诺范围。按已确认方式输出正文或实际写入文件；写文件时回复摘要与位置，两者都要时同时交付。未运行的示例不能称为实测。

## 按问题选择研究维度

下表是研究候选，不是每篇都必须填满的目录；无关维度省略，主题专属问题补入。

| 维度 | 待回答的问题 | 优先依据 |
| --- | --- | --- |
| 引入动因 | 解决什么问题，此前做法卡在哪里 | 官方设计、提案、作者文章 |
| 适用判断 | 适合谁、前置能力、实施成本和限制是什么 | 文档、实践案例、社区经验 |
| 现状与替代 | 当前状态、主要替代、迁移与退出代价是什么 | 发布记录、仓库、独立评测 |

- 每个纳入范围的问题都要有相应依据；可复用资料或直接读取一手页面，不以独立搜索次数代替覆盖。
- 选型任务核查替代方案；对容易过度乐观、争议或高影响的结论补反向验证，不要求每个维度机械搜索竞品。
- 对比表中的每个实体分别核验所声称的能力。产品能力、价格、额度与状态不得凭记忆补齐；未证实项明确列为缺口，不混入确定事实。
- 引用支持当前主张的来源，区分研究证据、作者经验与本文建议；教育或其他领域的研究迁移到新情境时说明适用边界。

## 深度调研与过程记录

多轮依据新线索、矛盾或证据缺口调整，不把预先写好的查询分批发送冒充迭代。继续取证与停止按检索skill执行；规划额度不是硬限制，也不扩大费用授权。

保留可核对的分类、实际查询与每轮新增线索。普通成品简述研究范围、主要来源和限制；用户要求审计、复现检索或详细研究过程时，在附录或指定记录中展开轮次与查询。不得虚报迭代、工具调用或核验结果，也不让完整搜索日志挤占教程主线。

## 证据不足时的交付

先判断缺口会影响哪条结论，不以扩写正文掩盖缺证，也不因独立的扩展缺口阻断全部结果。

| 缺口影响 | 交付方式 |
| --- | --- |
| 可能改变核心结论、推荐排序或关键操作安全性 | 暂停确定推荐或可照做的危险步骤；说明已覆盖内容、阻塞依据、待核实问题及下一步取证目标 |
| 与已证实结论可独立分离 | 交付明确限定范围的结果，显式列出排除项和影响，不称为完整覆盖 |
| 仅缺可选深入，不影响已承诺目标 | 完成主线，标注该扩展未核验；不强行补写 |

配额、期限或权限阻塞只说明执行状态；篇幅与证据状态独立。用户要求全范围完整交付而未满足时，应明确“部分完成”或“阻塞”，不能擅自缩范围后宣称完成。下一轮关键词仅在确有后续取证需要时给出。

## 方案与环境边界

- 比较方案时覆盖可靠性、成熟度与现代化程度，并按任务补成本、维护、兼容与退出代价；不把这些维度机械套给纯概念解释。
- 优先考虑免费、开源、跨平台、易用的候选，兼顾国内外与新兴方案，但以目标约束和证据为准，不为凑地域配额纳入不相关方案。
- 按声明的平台、终端和版本写必要差异，区分支持范围与实际验证范围。单平台任务不强加全平台命令；无部署内容时不加入网络配置章节。
- 环境未指定且确实影响任务时，可采用国内试验、海外生产的默认假设并说明；代理与镜像按[network-access](../network-access/SKILL.md)，不保证海外必然可达，不为教程擅改全局配置。
- 中文路径、编码等问题仅在目标工具存在相关限制或尚未验证时说明具体边界，不泛称国外工具不支持中文。
- 安装部署方案优先可自动化、可复用的路径；依赖与成本不适合初学者时，调整推荐而不是增加一整套无关工具链。

## 详略等级

| 等级 | 名称 | 表达范围 |
| --- | --- | --- |
| `1` | full | 目标范围内充分解释概念、依据、关键示例、边界和必要推导，主线与选学分层 |
| `2` | rich | 覆盖相同关键问题与边界，保留代表性示例，压缩次要推导与重复背景 |
| `3` | common | 突出核心结论、理由、必要步骤或示例，细节按需链接 |
| `4` | lite | 简练概括结论、适用条件与关键风险，不展开完整长文 |
| `5` | mini | 最短可用答案，保留决定性条件、必要风险与来源；证据充分时直接作答 |

等级只控制表达，不减少取证底线，不表示额度或执行状态。用户指定等级优先；确需调整时说明理由，不把完整档理解为无限扩展范围。

## 自检

- [ ] 产物、读者已有能力、目标与范围明确；是否误套了其他类型的模板？
- [ ] 已复用有效材料，只对需要新证据的部分取证；关键事实、建议和未核验项可区分？
- [ ] 关键缺口按影响处理，未以部分覆盖冒充完整，也未因无关扩展拒交已成立结果？
- [ ] 主线自足，必要概念、动作与判断有解释，选学深度和过程记录没有喧宾夺主？
- [ ] 推荐与环境承诺有边界，未验证示例和平台未被写成实测？
- [ ] 篇幅等级与证据状态独立；交付方式已确认并实际履行，没有重复提问或只承诺写文件？

## 验收清单与规范边界

> 何时读：流程步骤 5。先按下面的范围表选择检查项，再读取命中项的专项；独立交付四件套，与主设计流程同用时合并报告。

### 验证范围

本文件维护响应式验证范围；基础宽度是点检样本，不是设计断点，也不等于真机。纯文案且不影响几何或交互状态的变更可复用有效证据；未执行与不适用项分别说明。

| 范围 | 适用变更 | 验证内容 |
| --- | --- | --- |
| 基础点检 | 新建界面、页面或响应式布局变更 | 320/390/768/1440 CSS像素宽；检查主任务、内容回流、触控/键盘与页面级非必要横滚，记录实际视口 |
| 容器与阈值 | 可复用组件收纳、容器查询、导航或浮层跨宽度变化 | 实际使用的侧栏/弹窗/抽屉宽度、阈值两侧、最长标签与字体；页面截图不能代替窄容器验证 |
| 溢出与挤压 | 修复越界、裁切、压扁、隐藏操作 | 按 `overflow-squeeze.md` 连续扫描与探针，检查内容可达性及按钮几何 |
| 极窄复用 | 产品实际支持小于320px的容器 | 按 `extreme-narrow.md` 验 floor、P0、阈值 ±1px；不把约104px下限强加给所有页面 |
| 字号、主题、视口高度与输入 | 新建界面或改变对应行为 | 200%缩放、已支持的浅/深/系统主题、reduced-motion；按影响追加横屏、键盘、安全区或 forced-colors |
| 目标环境 | 新特性、最低支持变更或已知平台风险 | 按 `compat-testing.md` 验目标引擎/真机、字体与滚动条；未实测平台明确列出 |

布局、交互与状态变化的关键态先自动化断言再查看截图；已有页面深查与 CI 门禁按需使用 `frontend-ux-qa`。动效正常模式与中间帧验证引用 `web-animation-guide/references/performance-a11y.md`，不以减弱模式静态截图证明正常过渡。

### 设计验收

- [ ] 写清哪个最常用、哪几个低频，依据是什么。
- [ ] 标明所选策略的适用条件、空间成本、额外交互成本、失败边界。
- [ ] 选中浮层定义了触发、取消、切换实例、菜单关闭、遮挡处理。
- [ ] 宽窄两态标签完整或整体隐藏，无缩窄截断省略号；顺序语义一致。
- [ ] 图标只给语义稳定动作，新用户可经可见标签或焦点提示理解。

### 前端验收

- [ ] 按范围表完成基础与适用专项，实际视口/容器宽、已覆盖状态及未执行项有记录；裁切不能代替溢出修复。
- [ ] 页面级无非必要横向滚动；滚动归属按 `page-patterns.md` 选择，受限面板可限高滚动。
- [ ] 目标环境、缩放/横屏/键盘/字体影响按 `compat-testing.md` 验证，不宣称覆盖未实测平台。
- [ ] 全语义按钮/链接，无 `div onClick`。
- [ ] 容器宽度决定组件布局；容器查询不可用时有可操作回退。
- [ ] hover 被输入能力媒体条件包裹；focus-visible/focus-within 与触屏点击等价。
- [ ] Esc、点外、焦点返回、弹窗焦点、切换态已验证；反馈不遮焦点。
- [ ] 本次变更涉及的主题对比、缩放与 reduced-motion 达标；新建界面覆盖项目支持的主题。
- [ ] 改变选中态、进度、边框或自绘控件时，加验 `forced-colors` 下仍可辨，不只靠背景色。

### 宽度验证法（demo3 + demo1 做法）

- 预设点检 320/390/768/1440 + 连续滑块（300–800px 卡片级，或 320–1440px 页面级），只标“当前可用宽”，不宣称预设 = 真机。
- 记录调试信息：容器实测宽、可见按钮数、换行行数；窄屏逐项核对：`320px → 1带文字+更多 / 4图标 / 单行可滚` 等按所选策略如实记录，阈值以实测为准。
- 读数最短实现：列数 `getComputedStyle(el).gridTemplateColumns.split(' ').length`；流体字号实际落地
  `parseFloat(getComputedStyle(el).fontSize).toFixed(1)+'px'`；断点命中 `matchMedia(q).matches` 逐条打点——
  读数分档要与真实命中的规则一致，别用另一套档位（560/768/…）去解释 980px 的规则。
- 浮层形态按 `page-patterns.md` 选择；检查限高后的正文、关闭与操作可达，涉及固定底部面板时加验安全区与键盘。
- 性能门禁（拖滑条必查）：一次全程拖动菜单 DOM 变更数 ≤30（只许集合切换点重建）；任一可见按钮恒满足
  `scrollWidth <= clientWidth + 1`；`relayout` 内部禁注册 `fonts.ready.then` 自链（见 `js-apis.md` 五坑），回归用无头+截图双验。
- 收纳对等验收（折叠即移除，必须覆盖）：宽态页脚有效名序列 == 窄态（页脚可见 + 菜单项，去掉取消）有效名序列，
  有效名 = 可见文本，无文本取 `aria-label`（图标态），顺序一致；300–800 逐 2px 扫，任一宽度按钮右缘不得超出操作区内容右缘、
  `scrollWidth - clientWidth <= 1`（横滑对照方案自身条内滚动除外）。

### 产品验收

- [ ] 低频动作可发现，收纳不漏关键动作。
- [ ] 选中态（当前上下文）与批量态清晰区分，有计数与清空。
- [ ] 错误说明修复法，校验失败保留输入并聚焦首错。
- [ ] 生产行为（新标签/重命名/放大/对比）与演示一致，失败场景有设计。

### 规范边界（对外表述禁错）

- 通用 WCAG 要求与目标尺寸例外由 [frontend-design/references/a11y.md](../../frontend-design/references/a11y.md) 维护；本指南的44×44是产品基线，不能写成AA要求。合规声明须按完整条文及例外评估，不因几张截图通过就宣称合规。
- 回流与局部二维内容的场景边界见 `page-patterns.md`；响应式形态变化后复核正文对比、焦点可见与名称，不另设标准数值。
- 依据：W3C WCAG 2.2（2.5.8/2.5.5/1.4.10/2.4.7/1.4.3）、Material Design 3 Buttons/Cards、MDN any-hover/container queries/prefers-reduced-motion。来源给依据，不替代产品可用性测试。

### 交付四件套

1. 决策结论（主次+策略+为什么不用其它）。
2. 关键代码 diff（容器查询+菜单/浮层+回退）。
3. 验证记录（按范围表给出实际视口/容器宽、关键态截图与断言结果、未执行项）。
4. 已知问题（修不掉的列清单，不隐瞒）。

与 `frontend-design` 同用时，四件套归入主报告，不重复生成一份方案。客户需要交互式自验清单时，可用稳定 `data-key` 记录勾选与进度；普通交付不额外构建验收应用。

# 验收清单与规范边界

> 何时读：流程步骤 5。验收模式只读本文件 + 输出四件套。

## 设计验收

- [ ] 写清哪个最常用、哪几个低频，依据是什么。
- [ ] 标明所选策略的适用条件、空间成本、额外交互成本、失败边界。
- [ ] 选中浮层定义了触发、取消、切换实例、菜单关闭、遮挡处理。
- [ ] 宽窄两态标签完整或整体隐藏，无缩窄截断省略号；顺序语义一致。
- [ ] 图标只给语义稳定动作，新用户可经可见标签或焦点提示理解。

## 前端验收

- [ ] 320/390/768/1440 + 窄侧栏复用态 + <320 极限（受窗口限制态）可用；再验同一组件进侧栏/弹窗/抽屉的态。溢出/挤压按 `overflow-squeeze.md` 探针法验收，不用 `hidden` 掩盖。
  极窄（约 104–320px）按 `extreme-narrow.md` 加验：阈值 ±1px 双侧成立、floor 下限可点、P0 可达、截断有恢复出口、200% 字号与最长语言复核。
- [ ] 页面级无非必要横向滚动；列表走页面纵向滚动。
- [ ] 页面级宽度/缩放/横屏/键盘/字体族验收清单在 `compat-testing.md`，验收模式别漏读那份。
- [ ] 全语义按钮/链接，无 `div onClick`。
- [ ] 容器宽度决定组件布局；容器查询不可用时有可操作回退。
- [ ] hover 被输入能力媒体条件包裹；focus-visible/focus-within 与触屏点击等价。
- [ ] Esc、点外、焦点返回、弹窗焦点、切换态已验证；反馈不遮焦点。
- [ ] 深色/浅色/系统主题对比达标；reduced-motion 被尊重。
- [ ] 强制颜色（`forced-colors`，DevTools Rendering 可模拟）下选中态/进度/边框仍可辨，不只靠背景色。

## 宽度验证法（demo3 + demo1 做法）

- 预设点检 320/390/768/1440 + 连续滑块（300–800px 卡片级，或 320–1440px 页面级），只标“当前可用宽”，不宣称预设 = 真机。
- 记录调试信息：容器实测宽、可见按钮数、换行行数；窄屏逐项核对：`320px → 1带文字+更多 / 4图标 / 单行可滚` 等按所选策略如实记录，阈值以实测为准。
- 读数最短实现：列数 `getComputedStyle(el).gridTemplateColumns.split(' ').length`；流体字号实际落地
  `parseFloat(getComputedStyle(el).fontSize).toFixed(1)+'px'`；断点命中 `matchMedia(q).matches` 逐条打点——
  读数分档要与真实命中的规则一致，别用另一套档位（560/768/…）去解释 980px 的规则。
- 移动端弹窗变底部全宽页（`align-items: flex-end`，`max-height: 90vh`），动作面板行高 ≥50px 且含 `safe-area`。
- 性能门禁（拖滑条必查）：一次全程拖动菜单 DOM 变更数 ≤30（只许集合切换点重建）；任一可见按钮恒满足
  `scrollWidth <= clientWidth + 1`；`relayout` 内部禁注册 `fonts.ready.then` 自链（见 `js-apis.md` 五坑），回归用无头+截图双验。
- 收纳对等验收（折叠即移除，必须覆盖）：宽态页脚有效名序列 == 窄态（页脚可见 + 菜单项，去掉取消）有效名序列，
  有效名 = 可见文本，无文本取 `aria-label`（图标态），顺序一致；300–800 逐 2px 扫，任一宽度按钮右缘不得超出操作区内容右缘、
  `scrollWidth - clientWidth <= 1`（横滑对照方案自身条内滚动除外）。

## 产品验收

- [ ] 低频动作可发现，收纳不漏关键动作。
- [ ] 选中态（当前上下文）与批量态清晰区分，有计数与清空。
- [ ] 错误说明修复法，校验失败保留输入并聚焦首错。
- [ ] 生产行为（新标签/重命名/放大/对比）与演示一致，失败场景有设计。

## 规范边界（对外表述禁错）

- 触控：本指南 44×44 是产品设计基线。WCAG 2.2 SC 2.5.8（AA 最小）是 24×24，SC 2.5.5（AAA 增强）才是 44×44，各有例外。**不许把 44 写成 WCAG AA 要求**，合规声明须按完整条文与例外评估。
  2.5.8 五类例外：间距足够（Spacing）、有等效大目标（Equivalent）、行内文字链接（Inline）、浏览器原生控件（User-agent control）、尺寸本身至关重要（Essential）。
- 回流：WCAG 2.2 SC 1.4.10（AA）要求 320 宽纵向滚动回流，支持“避免页面级二维滚动”，但真正需二维的内容区例外仍可局部滚动。
- 对比焦点：正文按 WCAG AA 4.5:1 目标检查；焦点指示与非文本边界独立检查。
- 依据：W3C WCAG 2.2（2.5.8/2.5.5/1.4.10/2.4.7/1.4.3）、Material Design 3 Buttons/Cards、MDN any-hover/container queries/prefers-reduced-motion。来源给依据，不替代产品可用性测试。

## 交付四件套

1. 决策结论（主次+策略+为什么不用其它）。
2. 关键代码 diff（容器查询+菜单/浮层+回退）。
3. 验证记录（三断点以上截图或宽度记录 + 键盘全通记录 + 主题/reduced-motion）。
4. 已知问题（修不掉的列清单，不隐瞒）。

清单给客户自验时做成可勾选、带进度、跨会话保留（`data-key` 稳定键 + `localStorage` 逗号串），比发一张静态表更容易闭环。

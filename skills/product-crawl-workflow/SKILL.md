# 商品采集工作流

本 Skill 管“先做什么、按什么证据升级、何时停止”，不替代具体抓取库、浏览器或解析工具。它面向公开商品页与目录；不登录、不付费、不绕过访问控制，不采订单、账户或个人数据。

## 适用边界

- 适用于：新站可采性分析、采集方案规划、商品网址发现、分页与目录排查、详情页字段来源选择、抓取难度分级、字段漏采定位；也覆盖单品、变体、型号／零件、系列／套装等多层产品目录。
- 不适用于：大规模分布式调度、私有接口逆向、反爬对抗研究、登录态采集、下单或账户操作。
- 业务数据标准、导出列和验收口径由所在项目定义；本 Skill 只提供采集侧判断，不复制项目的价格、税价或字段规则。

## 核心原则

- **覆盖率优先于解析**：先证明发现路径、商品身份和去重，再优化字段；只抓第一页或只调选择器容易得到“字段很全但样本不全”的假完成。
- **证据决定工具**：静态 HTTP → 公开 JSON → 浏览器 → 有界挑战处理；一次只改一个变量，不用“换工具”掩盖字段或样本错误。
- **结构化数据优先**：JSON-LD、嵌入 JSON、公开商品接口优先于 CSS 选择器，选择器优先于文本兜底；记录每个字段实际使用的来源。
- **2xx 不等于有效内容**：商品身份、报价上下文、正文完整性和最终 URL 要分别核对，空壳页、软错误页和挑战页都可能是 200。
- **预算与停止条件先行**：先定商品页上限、时间上限、并发和重试；请求数、网址数不等于商品数，没有可靠分母时不编造百分比。
- **失败要分类**：访问、渲染、提取、规范化、范围外分别记录；字段缺失先查主商品容器和模板差异，不要直接升级到浏览器或代理。
- **先定实体与层级**：先明确“一个商品”是单品、变体、型号、零件还是套装，父子关系是什么，跨页面用什么稳定身份去重；目录页、型号页、详情页不能混算。
- **浅层优先**：字段已在列表或型号页出现，就不为同一字段下钻详情页；详情页只补独有字段和缺失字段。
- **先估规模再定深度**：用抽样页面数、页面大小、延迟和有效并发估算请求量与时间；预算不够先调整深度或范围，而不是只提高并发。
- **发现与判型分离**：发现阶段先扩大候选并保留导航页，再按内容判型；导航页不是商品，但可能是商品的主要入口。
- **URL 形态只是假设**：`/products/`、数字 ID、浅路径和无扩展名都可能是商品；型号目录里 `/<brand>-parts/<category>/<slug>` 也可能直接是商品页，不能只按 `/model-parts/detail` 一类规则判型。抽样验证后再定规则。
- **按产出率分配发现预算**：记录每个入口新增了多少实体 URL，优先高扇出导航，低产出的重复入口降级。

## 工作流

### 一、站点分诊

用少量请求回答“这个站该怎么采”，不要一上来写全站选择器。至少检查：

| 检查项 | 看什么 | 用途 |
| --- | --- | --- |
| robots.txt | 禁止路径、`Crawl-delay`、sitemap 声明 | 决定可访问范围和速率 |
| sitemap | 索引还是 urlset、商品 URL 形态、数量、更新时间 | 首选发现入口与分母线索 |
| 平台线索 | Shopify、WooCommerce、Magento、BigCommerce、Shopware、SFCC、自建 | 缩小公开数据与模板假设 |
| 入口／分类／详情样本 | 原始 HTML 是否含名称、价格、正文；渲染后是否变化 | 决定静态 HTTP 还是浏览器 |
| 公开数据 | Network 中的 JSON、嵌入状态、公开商品接口 | 可能绕过渲染，优先于 DOM |
| 实体层级 | 目录、型号、零件、文档的父子关系与 URL 形态 | 决定计数单位、去重键和采集深度 |
| 规模线索 | 站点自称数量、列表页成员数、是否有全量列表、单页大小 | 估算总请求与时间，决定样本还是全量 |
| 访问边界 | 403、429、挑战页、地区／语言／币种分支 | 决定限速、会话和停止条件 |

分诊输出一张卡：路径类型、发现入口、获取方式、字段来源、难度级别、单站上限、停止条件。样本不足时写“待验证”，不把平台猜测当结论。

发现网址前先写清三件事：

- **商品单位**：单品、变体、型号、零件、套装或文档；哪些对象是父子关系。
- **身份键**：SKU、零件号、型号＋变体、canonical URL；哪一个跨页面稳定。
- **页面层级**：入口／目录 → 列表／型号／系列 → 详情；每层能提供哪些字段，哪层是主数据源。

多层目录站常见的“品牌 → 分类 → 型号 → 零件”结构，不能把型号页或零件行直接当一个单品，也不能把同一零件的多个型号上下文算成多个商品。

### 二、网址发现

按可靠性从高到低尝试，前一层足够就不要重复造轮子：

| 优先级 | 入口 | 适用与注意 |
| --- | --- | --- |
| 1 | XML sitemap／公开 feed | 商品 URL 集中、可分页；检查索引和分片，不只看开头几条 |
| 2 | HTML sitemap／站点索引 | 无 XML sitemap 时优先；路径名不一定叫 sitemap，也不要请求 robots 明确禁止的路径 |
| 3 | 分类／全量列表页 | 一次给出几百个型号或商品的 `-list`、`all` 页；确认是否真全量，不因没有分页就判不完整 |
| 4 | 分页／加载更多／游标 | 按实际机制处理，不假定统一 `?page=` |
| 5 | 站内搜索／公开查询接口 | 仅作有界补充或定点核验，不把搜索结果当全量目录 |

发现规则：

- **商品判型**：主商品标题＋价格／购买控件、Product 结构化数据、唯一商品身份是正向证据；目录和列表页不能仅凭路径形态排除，浅层数字路径也可能是商品。型号页上的多行零件表通常是入口，不聚成一个商品；零件行有独立编号和报价时，按零件身份进入候选。
- **列表全量页**：页面没有下一页但成员很多时，先用成员数、重复集合和分类覆盖判断它是不是该分类的完整入口；不要凭“没有分页”断定不完整。
- **无 XML sitemap 不等于不可采**：HTML 索引、分类全量列表和公开 feed 可以组合使用；记录实际入口和覆盖范围。
- **分页终止**：以“没有新商品身份”“游标／下一页重复”“达到预算”为停止依据，不用固定页数；最后一页和倒数第二页要实际核对。
- **身份与去重**：用 canonical URL、商品 ID／SKU 或稳定路径归一化；同一商品的多网址、多变体、多次请求只算一个商品。品牌、系列、型号等父级要随成员一起记录；URL 只是定位，不是身份。
- **分母与剩余**：记录分母来源、数值、观测时间，以及已覆盖、待处理、未知；sitemap 数量是线索，不是永远可信的全站真值。
- **语言与市场**：URL 前缀是发现线索，不单独证明报价市场或币种；模糊分支保留并说明。

发现与判型分开做：

| 候选类型 | 典型页面 | 处理 |
| --- | --- | --- |
| navigation | 首页、品牌、分类、分页、筛选、站点索引 | 保留并优先抓；通常扇出最高 |
| listing | 型号列表、集合页、搜索结果、全量列表 | 保留；抓行级字段和下一页 |
| entity | 商品、型号、零件、文档、图纸 | 目标实体；后续按业务键去重 |
| asset | 图片、PDF、CSS、JS | 记录必要引用，不抓正文 |
| transactional | 购物车、结算、账户、订单 | 收集链接但不抓；遵守 robots |
| external | 其他域名 | 记录，不默认抓取 |

- **sitemap 条目不等于商品**：可能混合分类、商品、政策和图片；用页面内容或结构化数据确认，不只看 `<loc>`。
- **sitemap 格式先验证**：可能是 index、urlset、`.xml.gz` 或命名子图；解析失败先查状态、`content-type` 和压缩，不要直接判“无 sitemap”。子图未取全时标“部分枚举”。
- **没有 JSON-LD 仍可能是商品**：用标题、价格、购买区、重复卡片和父子关系综合判断。
- **多入口交叉验证**：分别记录 XML sitemap、HTML 索引、分类／全量列表、分页、搜索的贡献和重叠；用并集扩大召回，不把单一入口当全量。
- **客户端差异先比较一个变量**：同一 URL 在 200／406／403 间变化时，区分 UA、headers、HTTP 客户端和访问控制；不把一次失败当站点不可采，也不靠伪装绕过。
- **robots 按 UA 组匹配**：`Crawl-delay` 可能只属于特定 user-agent 组；按实际 UA 组和更保守值执行。

发现预算按“每抓一页新增多少实体 URL”分配：首页／索引、分类／全量列表优先，详情页主要用于补字段。记录入口产出率、实体占比、重复率、入口重叠和部分枚举；只存唯一 URL 集合无法计算重复率。详细策略见 [references/discovery-strategy.md](references/discovery-strategy.md)。

### 三、获取有效内容

先判断字段是否已在原始响应里，再决定是否渲染：

| 证据 | 默认动作 | 避免 |
| --- | --- | --- |
| 原始 HTML 已含名称、价格、正文 | 静态 HTTP ＋ 解析 | 为“更稳”无条件上浏览器 |
| 原始 HTML 是空壳，Network 有公开 JSON | 直接读公开 JSON，核对字段与商品归属 | 把需要认证的接口当公开接口 |
| 字段由 JS 渲染或交互后出现 | 浏览器，等待稳定容器或短文本 | 只等固定秒数就判定失败 |
| 403／挑战页 | 先区分网络、权限、挑战和资源不存在，再做有界尝试 | 一见 403 就叠浏览器或换出口 |
| 429 | 遵守 `Retry-After`，降速、有限退避 | 换出口绕过冷却或无限重试 |
| 200 但内容为空／通用错误页 | 查标题、主容器、商品身份和最终 URL | 把状态码当成功 |

内容有效性至少核对：商品标题、当前价格上下文、主图、正文主容器、最终 URL。批量获取时保持并发克制，默认并发 1、请求间隔不小于站点要求；会话复用和挑战处理按 `resilient-browser-fetch`，浏览器交互按 `browser-automation`，网络选路按 `network-access`。

### 四、字段提取与页面层级

先按页面层级选源，再按来源类型选源：

| 页面层级 | 典型字段 | 默认动作 |
| --- | --- | --- |
| 列表／型号／系列 | 名称、编号、价格、状态、缩略图 | 先取；字段足够就不下钻 |
| 详情 | 正文、规格、兼容关系、结构化报价 | 只补缺失或独有字段 |
| 搜索／公开接口 | 编号查找、定点核验 | 有界使用，不当全量目录 |

同一字段在多层都有时优先浅层；深层值用于校验或补缺，不重复抓取。

字段来源按稳定性排序，允许不同字段使用不同来源：

| 优先级 | 来源 | 典型位置 | 注意 |
| --- | --- | --- | --- |
| 1 | JSON-LD | `script[type="application/ld+json"]` 的 Product／Offer | 可能只是摘要或只覆盖当前变体；核对 `@type`、`offers` 和商品归属 |
| 2 | 嵌入 JSON | `__NEXT_DATA__`、内联 state、`application/json` | 结构与字段名随框架变化，按实际响应核对 |
| 3 | 公开商品接口 | 商品 JSON、目录 JSON | 只使用无需认证的公开响应；不猜管理员接口 |
| 4 | DOM 选择器 | 主商品容器内的标题、价格、图片、正文 | 选择器锚定主商品，避免推荐位和导航误命中 |
| 5 | 文本兜底 | 页面可见文本 | 记录来源和限制，不把摘要当完整正文 |

逐字段核对：

- **名称**：唯一商品标题，清理站点名和无关分隔符；不把店铺口号当名称。
- **价格**：当前主商品最低公开展示价，包含缺货有价变体；排除划线原价、分期、运费、附加服务差价和推荐商品。
- **币种**：与同一报价绑定；货币符号、域名或地区不能单独证明币种。
- **状态**：可售、缺货、停售、无价格、未知分开；停售可能仍有价格，不能因价格存在就当可售。
- **主图**：商品主图，不取 Logo、占位图、`none.jpg` 等占位资源或推荐图；处理相对路径。
- **正文**：优先完整主描述和分散规格；JSON-LD 描述常常是摘要；清洗后保留结构，区分完整、部分、摘要回退、原站未提供和提取失败。列表或型号页只有标题、没有正文时，不算完整正文。
- **选项与变体**：只保留公开选择维度和值；不枚举全部组合，不把变体当多个商品。
- **分类、品牌、库存**：原站有明确依据才填；未提供与漏采分开。
- **身份与 canonical**：canonical 只是证据，不是所有站点都有；URL 带父级上下文时，按稳定业务键去重，不按路径硬切。
- **来源网址**：保留实际商品 URL 和必要的重定向追溯，不丢商品身份。

每个字段记录来源类型和页面层级；同一模板的多个商品复用规则，模板差异分别保留，不用一条宽选择器覆盖所有页面。

### 五、采集深度与效率

先算再做，不把“先跑跑看”当规模估算。

- 按页面层级列出候选：入口／目录、列表／型号、详情、搜索或公开接口。
- 抽样 10–30 个页面，记录平均响应大小、延迟、字段命中率和重复率。
- 估算：请求数 ≈ 各层候选数之和；下载量 ≈ 请求数 × 平均页面大小；墙钟时间 ≈ 请求数 × 平均延迟 ÷ 有效并发。有效并发受站点限流、解析、重试和资源约束，不等于配置的 RPS。
- 预算超出时，优先减少深层请求、收窄范围或降低字段目标，不先提高并发。

| 深度 | 适用 | 代价 |
| --- | --- | --- |
| 只取列表／型号层 | 价格、库存、目录、型号关系 | 正文、兼容关系可能缺失 |
| 列表层＋按需详情 | 核心字段＋部分正文或规格 | 请求量取决于缺失字段比例 |
| 全量详情 | 字段要求完整，详情页确有独有字段 | 请求、存储和时间成倍增加，需单独预算 |

无法确认详情页的增量价值时，先抽 20–50 个详情页对比字段完整度，再决定是否全量下钻。价格／库存变化频繁的站点，重扫列表／型号层；详情页按内容指纹或字段变化触发，没有 `lastmod` 不代表不能增量。

效率记录至少包括：每有效商品请求数、每有效商品下载字节、各层请求占比、浅层字段命中率、重试率和墙钟时间。

### 六、校验与交付

- **样本矩阵**：入口、分类第一页、分页最后一页、列表／型号页、商品详情、多层目录的父子层级、多变体商品、缺货／停售商品、零价／缺价、长正文和非 ASCII 文本。
- **计数**：已发现网址、商品候选、已处理、有效、排除、失败、待处理、在途；终态在途必须为 0，候选与处理数满足守恒关系。按页面层级分别统计请求，不把目录或型号行直接算成商品。
- **覆盖**：有可靠分母时记录分母来源和覆盖数；没有分母时只报阶段与剩余入口，不显示伪百分比。
- **停止原因**：自然结束、预算、访问受限、质量阻塞、环境或方案错误、用户取消分别记录。
- **状态与降级**：可售／缺货／停售／无价格／原站未提供分开；占位图、部分字段和未补详情有明确标记。
- **证据**：方案版本、实际命令、样本网址、字段来源、页面层级、错误分类、复跑结果；不保存整页原文、密钥或 Cookie。
- **完成口径**：有界样本只能证明相应路径，不能写成全站完成；失败站点和未测项保留。

## 难度分级

| 级别 | 信号 | 默认策略 | 升级或停止 |
| --- | --- | --- | --- |
| L1 静态＋站点地图 | 原始 HTML 有字段，sitemap 可用 | HTTP ＋ JSON-LD／DOM | 只在字段缺失时查模板差异 |
| L2 分类／分页 | 目录和下一页稳定，详情可静态取得 | 分类发现＋分页＋去重 | 分页重复则修游标／终止条件 |
| L2+ 多层目录 | 品牌／型号／零件等多层，列表全量或型号页含多行 | 浅层取核心字段，详情按需 | 先估规模；详情全量超预算就收窄或标部分 |
| L3 JS 渲染／公开 JSON | 原始 HTML 空壳，Network 有数据或需渲染 | 公开 JSON 优先，否则浏览器 | 等待条件失败再查交互或会话 |
| L4 限流／挑战 | 429、挑战页、地区限制 | 降速、会话复用、有界挑战处理 | 超出重试上限就停止，不绕过访问控制 |
| L5 登录／付费／访问控制 | 必须登录、订阅或明确授权 | 停止 | 不把技术问题包装成可采 |

## 故障分流

| 现象 | 先查 | 动作 |
| --- | --- | --- |
| 403／挑战／空壳 | 最终 URL、响应正文、客户端、出口 | 区分网络、权限、挑战；有界比较，不盲目叠引擎 |
| 429 | 并发、速率、`Retry-After` | 降速、退避；耗尽预算报告访问受限 |
| 状态码 200 但无商品内容 | 标题、主容器、商品身份、最终 URL | 判为无效内容，不把空壳当原站缺字段 |
| 网址多但商品少 | 导航／商品判型、去重、待处理与失败 | 先对账，不把请求数当商品数 |
| 列表／型号页已有字段仍逐条抓详情 | 字段来源层级、详情增量字段、每有效商品请求数 | 改为浅层取数或按需详情，停止重复抓取 |
| 停售／无价格／占位图被当失败 | 状态语义、图片占位特征、数据标准 | 分开记录可售／缺货／停售／无价格／原站未提供，不混入技术失败 |
| 同一实体多个网址或父级上下文 | 业务键、canonical、父子关系 | 按业务键合并，不把型号上下文当多个商品 |
| 页面很大但有效行少 | 主容器、列表行密度、是否整页解析 | 只取主容器和行级片段，避免重复导航与脚本 |
| 分页重复或过早停止 | 游标、下一页、加载更多、去重集合 | 修终止条件，保留停止依据 |
| 价格错误 | 商品归属、原价／分期／差价、币种、税价 | 按项目数据标准修来源和口径 |
| 正文不全 | 摘要、展开区、规格表、清洗误删 | 优先补齐；难取区块有界尝试后标部分 |
| 选项漏采 | 控件、嵌入 JSON、当前商品公开选项 | 修公开选项，不采集全部组合价 |
| 模板变化 | 失败字段、影响模板、旧数据 | 阻止错误扩散，标明有效性，修复后重新试跑 |

## 反模式

- 只抓第一页或用固定页数，声称目录已完成。
- 用请求数、网址数或 HTTP 200 当商品产量和成功证据。
- 用货币符号猜币种，用划线价或分期价当当前价。
- 把 JSON-LD 摘要当完整正文，或把目录卡片当商品详情。
- 把型号页的多行零件表聚成一个商品，或把同一零件的多个型号上下文算成多个商品。
- 详情页优先，列表或型号页已有字段仍逐条下钻。
- 没有估算页面数和时间就承诺全量。
- 把停售、无价格或占位图当提取失败。
- 把 URL 当唯一身份，忽略型号／零件上下文。
- 把搜索接口或推荐 feed 当全量目录。
- 一见 403／429 就叠浏览器、换代理或无限重试。
- 选择器跨站复用，或为单个站点修改公共引擎。
- 没有可靠分母却显示百分比、剩余时间或“全站覆盖”。
- 失败样本被删除、被改期望或被排除出报告。

## 交付清单

- 站点分诊卡：路径类型、发现入口、获取方式、字段来源、难度、上限、停止条件。
- 实体与深度：计数单位、身份键、页面层级、主数据源和详情补全策略。
- 发现记录：实际入口、商品判型依据、身份去重、分母来源、已覆盖与待处理。
- 获取记录：静态／JSON／浏览器路径、请求数与状态、错误分类、会话与资源回收。
- 规模与预算：各层候选数、抽样页面大小／延迟、预计请求与时间、实际并发和停止边界。
- 字段记录：每个字段的来源、页面层级、缺失／部分原因、模板差异。
- 结果与报告：有效、排除、失败、部分、待处理、覆盖、停止原因、复跑命令。
- 状态与降级：可售／缺货／停售／无价格／原站未提供，以及占位图和未补详情。
- 复用说明：方案版本、依赖与兼容条件、已知限制。

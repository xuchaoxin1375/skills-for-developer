# 网址发现策略

目标不是“先判断哪些是商品再抓”，而是**先扩大公开候选、保留导航路径，再用内容证据判型**。导航页、列表页和搜索结果即使不是商品，也可能通向商品，不能在发现阶段按 URL 名称提前删掉。

最短路径：尝试 robots 只取 `Sitemap:` 行和入口 → 收集首批链接 → 抽样验证 URL 形态 → 比较 sitemap／HTML 索引／分类的贡献 → 高扇出页面优先 → 达到停止条件 → 输出候选、来源和入口贡献。

覆盖率和召回率是进阶审计项。结构清晰、入口和身份稳定时，优先证明路径完整性、样本代表性和停止条件，不默认计算全站百分比。

## 候选分类

| 类型 | 典型页面 | 默认处理 |
| --- | --- | --- |
| navigation | 首页、品牌、分类、分页、筛选、站点索引 | 保留并优先抓；通常扇出最高 |
| listing | 型号列表、集合页、搜索结果、全量列表 | 保留；抓行级字段和下一页 |
| entity | 商品、型号、零件、文档、图纸 | 目标实体；后续按业务键去重 |
| asset | 图片、PDF、CSS、JS、字体 | 记录必要引用，不抓正文 |
| transactional | 购物车、结算、账户、订单 | 收集链接但不抓；遵守访问控制与 ToS |
| external | 其他域名 | 记录，不默认抓取 |

发现阶段可以保留 `asset`、`transactional`、`external` 的链接用于分析，但只对允许的公开 HTML 发起请求。不要把“非商品”直接等同于“无价值”。

## 发现与判型分离

- **URL 形态只是假设**：`/products/`、数字 ID、浅层路径、`.html`、无扩展名都可能对应商品；先抽样 1–3 个页面，核对标题、Product 结构化数据、价格／购买区和主内容，再写判型规则。
- **sitemap 条目不等于商品**：sitemap 可能混合分类、商品、政策页和图片；用页面内容或结构化数据确认，不只看 `<loc>`。
- **保留来源与父级**：每个候选记录 `source`、`depth`、链接文字和所在页面类型；后面才能判断哪条入口真正贡献了商品。
- **不要过早去重成“商品”**：先按 URL 去重，再按业务身份（SKU、零件号、型号＋变体）归并；两者不是同一层。
- **Marketplace**：搜索／列表结果是 offer 集合，item canonical 常指向商品页；用 canonical 分组，但商品与 offer 分开计数。

## 入口阶梯与贡献

按证据顺序尝试：

| 顺序 | 入口 | 观察 |
| --- | --- | --- |
| 1 | XML sitemap／sitemap index／公开 feed | 可能是全量、子集或纯分类；先看索引、分片和条目形态 |
| 2 | HTML sitemap／站点索引 | 无 XML sitemap 时优先；路径名不一定叫 sitemap；robots 只用来取 `Sitemap:` 行，不据此排除路径 |
| 3 | 分类／全量列表页 | 有些页一次返回数百个成员，没有分页；用成员数、重复集合和覆盖判断是否完整 |
| 4 | 分页／加载更多／游标 | 按实际机制处理，不假定统一 `?page=` |
| 5 | 站内搜索／公开查询接口 | 适合定点查找或有界补充；`total` 可能只是当前关键词的结果数 |

多入口要**交叉验证**：分别记录 XML sitemap、HTML 索引、分类、分页、搜索的贡献和重叠。用并集扩大召回，用重叠和页面证据判断哪个入口更完整。不要因为一个入口缺失就判定站点不可采。

### 下一页状态是否 URL 可寻址

看到“加载更多”或无限滚动时，先做一次交互观察，但不要默认继续模拟点击／滚动。很多站点在追加商品后通过 `history.pushState` 把地址栏更新为 `?page=2`、`/page/2` 或类似状态；如果这个 URL 能直接打开对应页，按 URL 分页采集更稳定、更省浏览器。

判断顺序：

1. 交互一次，记录地址栏或 `pushState` 后的 URL。
2. 用新会话／普通 HTTP 直接打开该 URL，比较标题、商品数、首尾商品 ID 和正文，不只看状态码。
3. 直接打开得到对应页 → 用 `page_param`、`next_link` 或 URL 模板逐页取；交互只用于发现 URL 形状。
4. 直接打开回到第 1 页、返回空壳／403，或内容只在虚拟列表里逐批替换 → 才保留点击／滚动，并记录原因。
5. `?utm_*`、`#fragment` 或无关筛选参数的变化不算分页 URL。

证据记录：交互后 URL、直接打开的状态与条目数、重复率、请求数和耗时。不要因为页面看起来是“无限滚动”就跳过这一步；反过来，也不要把所有滚动站都假设成 URL 可寻址。

### sitemap 不是一种格式

- sitemap 可能是 `urlset`、`sitemapindex`、命名子图，也可能是 `.xml.gz` 压缩文件；先看状态、`content-type` 和文件头，再决定解析方式。
- 解析失败不等于“没有 sitemap”：可能是 403 的 HTML、挑战页、编码问题或 gzip 未解压。先记录状态、内容类型、字节数和首字节。
- sitemap index 可能有上百个子图；只取前几个时必须标“部分枚举”，不能把子图计数当全站总量。
- **多门店／多市场 index**：子图常按门店或市场分片（如 `fooddepot15ftvalley_1_sitemap.xml`），商品 URL 带门店前缀；先枚举子图并记录已覆盖门店，不要只取第一个。跨店合并前先验证身份键：URL UUID、slug、catalogue ID 可能是门店级或分组级，优先 UPC／EAN／GTIN／MPN；门店作为价格与可售状态的上下文。
- 命名子图本身是发现地图：按名称识别 `product.entity`、`category.product-list`、`variant`、`review`、`qna` 等类型，优先取商品实体图，不盲目抓全部。
- 无 sitemap 时，HTML 索引、分类页和公开目录是主路径；商品与分类 URL 可能共用路径形态，必须按内容判型。
- 没有 Product JSON-LD 仍可能是商品页；用标题、价格、购买区、重复卡片和父子关系综合判断。

### 公开 JSON 目录

- 先读分页元数据：`skip`／`take`、`page`／`limit`、`total`／`TotalNumberOfRecords`；空页或 `skip >= total` 是可靠停止信号。
- 列表对象可能已含名称、价格、可售、图片等基础字段；先列表层取数，详情只补描述／规格。
- sitemap 商品数与 API total 不一致时记录差异和观测时间，不强行解释为缺失或全量；两者是不同口径。
- 公开 JSON 可能单独 429；退避或换出口，不因 API 429 判站点不可采；单品 JSON／HTML 可兜底。

## 产出率与 frontier

发现预算按“每抓一页新增多少实体 URL”分配，而不是按页面类型平均分配：

| 优先级 | 页面 | 理由 |
| --- | --- | --- |
| 1 | 首页、品牌／分类索引、HTML sitemap | 扇出高，快速扩大候选 |
| 2 | 分类、全量列表、型号列表 | 一行多个实体，适合批量发现 |
| 3 | 型号／系列页 | 连接子实体和详情 |
| 4 | 商品／零件详情 | 主要做字段补全，发现新实体较少 |
| 5 | 静态页、政策页、其他 | 低产出，最后处理 |

记录：

- 每 100 个请求新增多少唯一实体 URL。
- 每个入口的贡献占比、重叠率和重复率。
- 页面平均大小、平均链接数、平均响应时间。
- 是否还有未访问的高扇出分支。

发现阶段先报 URL 候选、页面类型和入口贡献；商品候选和有效商品在判型后另计，不把 URL 数或请求数当商品数。

停止依据是“没有新实体身份”“高扇出分支已覆盖”“达到预算／访问边界”，不是固定页数。没有可靠分母时只报阶段和剩余入口。

## 指标口径

发现指标要能解释“入口值不值得继续抓”，不能把 URL 数当商品数：

| 指标 | 计算 | 用途 |
| --- | --- | --- |
| 入口产出率 | `unique_entity_urls / fetched_pages × 100` | 每 100 个请求新增多少实体候选 |
| 实体占比 | `entity_candidates / discovered_urls` | 候选池里有多少可能是目标实体 |
| 重复率 | `1 - unique_target_urls / target_url_occurrences` | 同一 URL 在一个或多个页面中重复出现多少 |
| 入口重叠 | `|A ∩ B| / |A ∪ B|` | 两个入口是否互补；接近 0 表示必须并用 |
| 部分枚举 | `children_fetched / children_total` | sitemap index 或分页是否只取了一部分 |
| 样页有效率 | `valid_samples / sampled_pages` | 抽样页面是否真的可解析为目标实体 |

`召回率`只有在分母来源、范围和观测时间都明确时才能写；否则写“阶段覆盖”或“入口并集”，不要用 URL 数编造百分比。

### 抽样顺序会骗人

同一批 `-parts` 形状候选：

- 按发现顺序取前 400 个：只有 2 个是含零件行的型号页，其余多为品牌／分类页。
- 从剩余候选中随机抽 100 个：91 个是含 3 条以上零件链接的型号页。
- 随机抽 300 个型号页：得到 12,384 次零件链接出现、5,113 个唯一零件，重复率 58.7%，平均每页 41.3 条零件链接。

结论：URL 形状规则可能整体精度不低，但**发现顺序会先遇到品牌／分类页**；必须按来源、品牌、层级分层抽样，不能用前 N 个样本估计规则精度。

一次入口重叠实测（同一多层目录，2026-11-19）：HTML `/site-map` 给出 558 个唯一型号 URL；三个高扇出分类页分别给出 855、456、387 个唯一型号，但每个分类页的型号链接都出现两次（重复率 50%）。两组入口的并集是 2,256 个型号，交集为 0。说明：

- 多入口不是冗余；只抓一个入口会漏掉另一组。
- 链接出现次数不等于唯一成员数；必须按 URL 去重后再计实体。
- 只存唯一集合无法计算重复率；发现输出要保留链接出现或至少保留 `occurrences`。

## 客户端与 robots

- **robots 只取 Sitemap 行**：机会式抓取一次，只保留大小写不敏感的 `Sitemap:` 值并去重；其他内容立即丢弃，不读完整文件、不解析 `Disallow`／`Allow`／`Crawl-delay`／UA 组，也不据此决定请求范围或速率。404／403／超时／不可读不阻塞，继续入口发现。
- **同一 URL 可能因客户端不同返回 200/406/403**：先比较一个变量（UA、headers、HTTP 客户端），区分网络、权限、挑战和客户端差异；不把一次 406 当站点不可采，也不靠伪装或绕过访问控制。
- **固定保守速率不是高速许可**：默认低并发、留间隔，观察 429／403 后按项目策略调整；不因 robots 看起来宽松就提速。
- **只抓公开内容**：不登录、不下单、不调用需要认证的接口；收集链接不等于获得抓取许可。robots 不是访问授权，ToS 和法律边界仍按项目要求处理。

## 观察样本

以下为 2026-11-19 公开探测的合成化摘要，只说明路径类型，不外推全站：

| 样本 | 入口观察 | 启示 |
| --- | --- | --- |
| Shopify 站 | sitemap index 共 813 条，706 条 `/products/`；商品样页含 Product JSON-LD | sitemap 可作主入口，但仍要抽样确认商品身份 |
| 体育用品站 | sitemap 8,397 条，商品 URL 形如 `87-156.htm`，没有 `/product/` 字样；样页含 JSON-LD | 不能按路径关键词判型；用页面内容验证 |
| 目录型站（Magento 风格） | sitemap 2,528 条，2,382 条带图片且 priority 1.0；通用 Python 客户端 406，另一 HTTP 客户端 200 | sitemap 可用图片／优先级做线索；客户端差异不是站点级结论 |
| Shopify 大图站 | sitemap index 6 个子图、568 条，104 个 `/products/`；`/products.json` 200；3 个商品页 838 KB–1.3 MB，含 JSON-LD | 公开 JSON 状态会变；商品页很重，只取主容器 |
| 大型 sitemap index | 131 个子图；只取前 8 个已有 1,499 条、1,215 个商品候选；样页 500–586 KB | 子图未取全时标“部分枚举”，不能当全站总量 |
| 多门店 grocery | sitemap index 83 个子图；首店商品子图 16,419 个商品 + 15,349 个 CDN 图片；另一店 14,782 个商品；URL `/online/{store}/product/{uuid}/{slug}` | index 按门店分片，图片可占近半；先定门店再取分片 |
| Shopware 风格 `.gz` | 4 个子图；首个 `.xml.gz` 解压后 5.7 MB、28,078 条；启发式商品候选 26,898 个；样页无 JSON-LD | `.gz` 先解压；无 JSON-LD 仍可能是商品 |
| 无 sitemap | sitemap 404；首页 508 个链接；分类页商品与分类链接混合；商品页有价格和 Add to Cart、无 JSON-LD | 分类优先；URL 形态重叠，按内容判型；无 JSON-LD 仍可能是商品 |
| 挑战／路由 | sitemap 403、首页挑战、200 但 `text/html` 的 sitemap 路径、DNS 失败 | 区分访问限制、环境和“无 sitemap”；200 的 HTML 不是 sitemap，不绕过 |
| 多层零件目录 | 无 XML sitemap；HTML `/site-map` 可发现数百个型号；分类列表页单页约 373 个型号、456 KB；型号页约 24 行零件；一次快照中初始 URL 规则把 1,681 个三段商品 URL 归为 `other`，抽样后确认是含 JSON-LD 的商品页 | HTML 索引和分类列表可弥补 XML sitemap 缺失；URL 规则必须用样本校验，高扇出页优先 |
| 多卖家 marketplace | 搜索页 56 个 item 链接；商品页 `/p/...` 33 个 offers，`AggregateOffer` 399–1100 USD；item 页 seller Dr. Guitar Music／Liberty Guitars | 商品页与 item 页分层；推荐卡和 price guide 不混淆 |
| Magento configurable | Magebit `argus-all-weather-tank.html` 5 变体（XS–XL/Gray，€22）；`breathe-easy-tank.html` 15 变体（€34）；`salable` 空 | swatch 用 `jsonConfig`；`salable` 空不判缺货 |

多门店身份实测：两店 sitemap 的 16,419 与 14,782 个商品 UUID 交集为 0，slug 交集 8,964；同一洗衣液在两店的 UUID 和 catalogue ID 不同，但 `Cd` 解码后的条码相同。结论：URL UUID／catalogue ID 可能是门店级，跨店合并要用条码／UPC／GTIN／MPN，先用样本验证。

Marketplace 实测：Reverb 商品页 `/p/fender-player-stratocaster-2018` 聚合 33 个 offer（low 399／high 1100 USD），32 张 listing 卡覆盖 B-Stock、Used–Excellent／Good／Very Good；两个 item 页分别由 Dr. Guitar Music（Watertown, NY，$399，运费 $129.44）和 Liberty Guitars（Covington, TN，$1111，运费 $75）出售，item canonical 回指商品页。商品页 price guide $381–$651（4,071 orders）是历史已售价，不是当前 offer 价。

公开目录 API 实测：`POST /stores/758/products?skip=0&take=5` 返回 5 条，`Meta.Pagination.TotalNumberOfRecords=19,129`；`skip=100000` 返回空。sitemap 有 19,287 个商品 URL，差异 158 条；sitemap 与 API 是不同口径，不能直接判谁对谁错。

一次 1,600 页的有界探测在该多层目录上得到 21,307 个 URL，其中 14,675 个 `-parts` 形状候选（未全部验证为型号页）、5,058 个零件候选；页面类型产出约为：型号列表页 14,234 个形状候选，型号页 2,675 个零件，分类页 2,377 个零件 + 441 个形状候选。数字只证明当日快照，不证明全站完整。

样本只证明当日路径，不证明完整覆盖；实际方案仍以目标站点的当前响应为准。

## 发现产物

建议至少保留：

- `urls.jsonl`：`url`、`class`、`source`、`depth`、`fetchable`、`first_seen`。
- `links.jsonl` 或 `occurrences`：每条链接出现，含 `source_url`、`target_url`、`link_text`；只存唯一集合就无法计算重复率。
- `pages.jsonl`：`url`、`status`、`bytes`、`elapsed_s`、`page_type`、`source`、`signals`。
- `summary.json`：URL 类型计数、页面类型计数、状态码、入口贡献、重叠、重复率、部分枚举、停止原因。
- 默认不保存整页正文；需要样本时只保留有界、脱敏的片段或字段。

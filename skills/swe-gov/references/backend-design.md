## 后端设计轨

用于从零设计或整体改造后端服务、API 或数据层，尤其是有数据库、鉴权、异步任务或外部集成的项目。它给出一条设计顺序和每步要定的问题；具体规则已在[架构与契约](architecture-and-contracts.md)、[运行可靠性](reliability-and-operations.md)、[测试](../../web-app-testing/SKILL.md)等入口维护，本页不重复整套政策。

### 什么时候用

- 新建后端服务、API、后台任务或数据层。
- 增加跨模块能力，需要同时改数据模型、接口、权限或异步流程。
- 评审后端方案，检查是否只写了接口而漏了数据、权限、失败和恢复。

单个函数、局部重构、纯排障或只改前端时，不用本页；分别走 `codebase-design`、`code-review`、`reliability-and-operations` 或 `frontend-design`。前后端并行时，两条设计轨共用同一份[契约冻结层](architecture-and-contracts.md#契约冻结与分轨实现)：后端不替前端决定页面结构，前端不替后端决定数据模型。

### 设计顺序

| 步骤 | 要定的问题 | 主要产出 |
|---|---|---|
| 边界与不变量 | 谁拥有哪份数据、谁写、哪些规则必须始终成立、同步还是异步 | 模块/数据所有权表、不变量清单 |
| 领域与数据模型 | 实体、关系、键、约束、索引、事务边界、租户与保留 | ER 图或表清单、数据字典、索引与约束说明 |
| API 资源与契约 | 资源、端点、输入输出、分页/过滤/排序、错误、版本、限流 | OpenAPI/Schema、错误码表、调用样例 |
| 身份、权限与租户 | 身份来源、会话/令牌、角色/资源权限、租户隔离、管理员边界 | 权限矩阵、会话与密钥方案 |
| 异步任务与副作用 | 任务身份、持久化、重试、顺序、去重、死信、恢复 | 任务状态表、重试/补偿说明 |
| 错误、幂等与重试 | 传输错误与业务错误、部分成功、幂等键、超时与补偿 | 错误模型、幂等与重试契约 |
| 缓存与性能 | 是否真的需要缓存、缓存键/失效、热点、查询与索引、容量 | 缓存策略、查询计划与容量预算 |
| 可观测性与运行 | 日志/指标/追踪、健康检查、SLO、告警、发布与回滚 | 观测清单、Runbook、恢复演练 |
| 迁移与发布 | 版本化迁移、回填、双写/双读、兼容窗口、回退 | 迁移计划、回滚与恢复方案 |
| 测试与交付 | 领域规则、真实数据库、契约、并发/幂等、失败注入、负载 | 测试层与证据清单 |

顺序可按风险调整：数据/报表类先定模型和查询路径；强交互或开放 API 先定契约；涉及支付、权限或迁移时先做威胁与失败分析。不要把所有步骤做成瀑布，但每个高风险决策要有结论。

### 边界与不变量

先确定模块和数据所有权，再画表。每个模块明确：

- 谁负责写、谁只能读、跨模块通过什么接口访问。
- 哪些不变量必须由数据库约束、事务或服务逻辑保证。
- 哪些操作可以异步、哪些必须同步完成。
- 哪些数据是租户隔离的，租户 ID 从哪里来（可信身份，不是请求体）。

规则细节见[模块与数据所有权](architecture-and-contracts.md#模块与数据所有权)。不要用“同一个数据库”推断“没有边界”，也不要用“同一个服务”推断“同一个事务”。

### 领域与数据模型

这是后端设计最容易漏掉、也最难后补的部分。至少回答：

- 实体和聚合边界是什么；哪些对象必须一起变更。
- 主键用什么；自然键是否稳定；是否需要外部 ID。
- 哪些字段必须唯一、非空、有范围或受检查约束。
- 哪些查询在热路径上；索引是否按查询和排序设计，而不是按字段“看起来重要”建。
- 事务边界在哪里；哪些操作需要原子，哪些可以最终一致。
- 租户、软删除、审计、版本、保留期和归档怎么处理。
- 敏感数据如何分类、脱敏、加密和删除。

产出可以是一张表清单加数据字典，不必一开始画完整 ER 图。数据字典至少写：字段、类型、单位/精度、必填、默认值、约束、索引、敏感级别、来源与 owner。迁移和回填规则见[兼容迁移](architecture-and-contracts.md#兼容迁移)；个人信息与保留期见[工程侧合规检查表](compliance-checklist.md)。

### API 资源与契约

API 先表达业务资源和动作，不要直接把数据库表暴露成接口。至少确定：

- 资源名称、标识、生命周期和所有权；哪些是集合资源，哪些是动作端点。
- 输入输出、必填/可空、单位、金额、时区、序列化；对外传输模型（DTO）与持久化模型分开。
- 列表接口的分页方式、默认排序、过滤白名单、最大页大小；禁止无界全量返回。
- 错误模型：传输状态与业务错误码的对应；部分成功、业务终态和可重试错误。
- 幂等：哪些创建/支付/重试敏感操作需要幂等键；键的作用域、保留窗口和同键异内容的行为。
- 版本与兼容：哪些字段可加、哪些不能改；弃用条件和旧客户端支持窗口。
- 限流、超时、请求大小和并发边界。
- 每个端点需要什么身份、权限和租户上下文。

契约维度见[API、消息与数据契约](architecture-and-contracts.md#api消息与数据契约)；接口文档与示例按 [project-docs](../../project-docs/SKILL.md)。不要用类型文件代替授权、幂等和数据正确性。

### 配置型模块

包装外部目录或平台能力的配置模块，把“来源目录、用户策略、运行实例”分开，不要让代码里的枚举成为唯一入口：

- **来源目录**由权威系统在运行时发现（供应商、插件、模型、租户目录等），应用只缓存结果并提供刷新/重试；发现失败时保留已保存配置并说明原因，不静默清空。
- **用户策略**只保存活动子集、默认项和分配方式（固定、轮询、故障转移等）；默认项必须属于活动子集。选项多或会变化时，用活动集合加显式策略，不用硬编码清单或“只有一个选项的下拉框”代替设计。
- **运行实例**写清配置在哪一层生效：页面保存是否热生效、来源变更由下次任务/子进程读取、哪些代码或环境变量必须重启；把边界写进接口说明和页面提示。未知项可配置但标为未验证，档位/能力未知时允许自由输入或明确拒绝，不能假装已验证。
- 验证至少覆盖来源新增/删除、发现失败、缓存过期、默认项不在集合、未知项、刷新后的热生效，以及运行中任务不被改派。

### 身份、权限与租户

- 身份从哪里来：会话、令牌、网关、外部身份提供方；过期、刷新和撤销怎么处理。
- 会话存储、跨站请求伪造（CSRF）/跨源资源共享（CORS）、Cookie 属性和密钥轮换。
- 权限模型：角色、资源、操作；基于角色的访问控制（RBAC）还是资源级授权；管理员和普通用户如何分离。
- 租户隔离：租户 ID 从可信身份或服务端映射得到，不能信任请求体；跨租户查询必须有额外授权。
- 审计：谁在什么时候改了什么；敏感操作是否留痕；日志是否脱敏。
- 测试：至少覆盖越权、跨租户、过期会话、被撤销令牌和管理员边界。

信任边界与威胁分析见[信任边界与安全需求](architecture-and-contracts.md#信任边界与安全需求)；合规义务见[工程侧合规检查表](compliance-checklist.md)。隐藏 UI 不是授权控制。

### 异步任务与副作用

需要跨请求、跨进程或失败后恢复的写操作，按任务设计：

- 任务在接受前持久化；保存失败就拒绝接受，不能只在内存里排队。
- 任务身份、状态机、终态和查询入口；客户端如何得知完成/失败。
- 同一资源的并发改写如何互斥；锁的作用域要覆盖实际竞争进程。
- 重试策略、退避、最大次数、死信和人工恢复；哪些操作必须幂等。
- 顺序要求：哪些任务必须按序，哪些可以并行；乱序时如何收敛。
- 数据库写入与消息双写：评估事务发件箱或等价方案；消费者去重和监控不能省。
- 异常退出、取消、超时和服务重启后的恢复；不凭旧产物宣称成功。

细节见[异步任务与状态归属](architecture-and-contracts.md#异步任务与状态归属)和[重试与副作用案例](architecture-and-contracts.md#重试与副作用案例)。

### 错误、幂等与重试

- 统一错误模型：传输层状态表达协议结果，业务错误码表达领域结果；不要把所有失败包成 200。
- 区分可重试与不可重试错误；超时只说明结果未知，不等于服务端没有执行。
- 幂等键的作用域、请求摘要规范化、保留窗口和同键异内容拒绝。
- 部分成功要有可查询的终态；补偿操作要有对账和重复执行保护。
- 客户端重试、网关重试、队列重投可能叠加；去重必须在持久层生效，不能只靠进程内缓存。

### 缓存与性能

不要因为“可能会慢”就先加缓存。先测瓶颈，再决定缓存、索引、批处理或扩容。

缓存：

- 缓存什么、键是什么、作用域是用户/租户/全局；存活时间（TTL）和失效由谁负责。
- 缓存与源数据不一致时，用户看到什么；哪些场景不能缓存（权限、余额、库存等）。
- 热点键、穿透、雪崩、惊群和负缓存；失效失败如何回退。
- 缓存不是事实来源；删除/更新后的失效顺序要可验证。

查询与容量：

- 热路径查询是否有合适索引；用真实数据量和查询计划验证，不只看开发库。
- 避免 N+1（一次查询后又逐条查询）、无界列表、全表扫描和不必要的排序/聚合。
- 连接池、批量写入、分页、读写分离和队列积压的容量边界。
- 用负载测试或生产观测确认瓶颈；把结果写进容量预算和 SLO。

运行目标与容量见[运行可靠性](reliability-and-operations.md)。

### 可观测性与运行

后端设计从第一天就要能回答“出问题时怎么知道、怎么定位、怎么止损”：

- 结构化日志、关键指标、追踪和关联 ID；敏感数据脱敏。
- 健康检查、就绪检查、依赖失败时的降级行为。
- 服务级别目标（SLO）/告警的测量口径、负责人和响应动作。
- 发布方式、灰度/回滚、特性开关和清理条件。
- 备份、恢复时间目标（RTO）与恢复点目标（RPO）、恢复演练和外部副作用的补偿。

细节见[运行可靠性](reliability-and-operations.md)；不要用“有日志”代替“能定位”，也不要用“有备份”代替“恢复已验证”。

### 迁移、发布与恢复

- 数据库变更通过版本化迁移执行，禁止手工改生产库。
- 优先扩展—迁移—收缩：先加兼容结构，再回填/双写，验证后切读，最后删旧。
- 迁移可重入、可观察、可中止；记录进度、失败归宿和重试方式。
- 代码回退能否读写当前结构要单独验证；破坏性操作要有备份或向前修复方案。
- 外部副作用（支付、通知、退款）不能靠恢复数据库撤销；设计对账和补偿。

细节见[兼容迁移](architecture-and-contracts.md#兼容迁移)和[备份、回退和恢复](reliability-and-operations.md#备份回退和恢复)。

### 测试与交付

按风险选择测试层，但后端至少要覆盖：

- 领域规则和边界条件的单元测试。
- 真实数据库/真实 API 的集成测试；mock 只证明调用形状。
- 契约测试：请求/响应、错误码、分页、权限、幂等。
- 迁移测试：新旧结构共存、回填、回退和恢复。
- 并发/幂等：同键重试、并发写、重复投递、超时后的查询。
- 失败注入：依赖超时、队列积压、数据库不可用、部分成功。
- 关键链路的端到端或真实用户路径冒烟。
- 适用的负载、安全和可访问性检查。

测试设计与分层见 [web-app-testing](../../web-app-testing/SKILL.md)；交付证据与状态见 [ai-verified-delivery](../../ai-verified-delivery/SKILL.md)；CI、依赖和密钥见 [repo-gov](../../repo-gov/SKILL.md)。

### 最小设计产出

在进入批量实现前，至少能拿出：

- [ ] 模块/数据所有权表和不变量清单。
- [ ] 数据字典：实体、键、约束、索引、事务边界、租户/保留/敏感级别。
- [ ] API 契约：资源、端点、分页/过滤/排序、错误码、幂等、版本、限流。
- [ ] 权限矩阵：身份、角色/资源/操作、租户隔离、管理员边界。
- [ ] 异步任务表：状态、重试、去重、死信、恢复。
- [ ] 缓存与性能说明：是否缓存、键/失效、索引/查询计划、容量预算。
- [ ] 观测与运行：日志/指标/追踪、健康检查、SLO、Runbook、回滚/恢复。
- [ ] 迁移计划：扩展—迁移—收缩、回填、兼容窗口、备份/恢复。
- [ ] 测试计划：真实数据库、契约、并发/幂等、失败注入、关键路径。

### 常见错误

- 把数据库表直接当 API 资源，字段和内部状态全部暴露。
- 列表接口无界，分页、过滤、排序没有上限或白名单。
- 只在 UI 隐藏按钮，没有后端授权和租户隔离。
- 幂等只做进程内缓存；重试、队列重投或多实例下失效。
- 异步任务先返回成功再持久化；进程退出后任务丢失。
- 缓存被当成事实来源；更新后不失效或失效顺序错误。
- 没有真实数据量的索引/查询验证，开发库快就以为生产快。
- 迁移不可回退、不可中止，或代码回退读不了新结构。
- 只记日志没有指标/追踪/告警；出问题只能猜。
- 测试只 mock，未验证真实数据库、权限、事务和并发。

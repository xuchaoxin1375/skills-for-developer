## 工程侧合规检查表

用于产品涉及个人信息、支付、未成年人、健康/金融数据、多个市场或受监管行业时，把合规义务转成可实现的工程要求。**本页是工程检查表，不是法律意见**；具体适用取决于司法辖区、业务模式、合同和监管解释，最终由法务/合规确认。仓库层面的许可证、密钥与安全提交见 [repo-gov](../../repo-gov/SKILL.md)；信任边界与权限设计见[架构与契约](architecture-and-contracts.md#信任边界与安全需求)。

### 什么时候需要

- 收集个人信息、行为数据、位置、设备标识，或使用 Cookie/分析/广告 SDK。
- 面向消费者、未成年人、欧盟/英国/加州/中国等特定市场，或处理跨境数据。
- 涉及支付、退款、订阅、税务、发票。
- 健康、金融、教育、生物识别、雇佣等敏感或受监管场景。
- 用户生成内容、营销邮件、短信、推送。
- 使用第三方模型/AI 处理用户数据，或把用户数据用于训练。

没有以上情形也不等于没有义务：日志、备份、支持工单、监控截图都可能包含个人信息。

### 先识别适用义务

不要从“我们有什么功能”开始，而是按市场、用户和数据列：

| 维度 | 要确认的问题 |
|---|---|
| 市场/辖区 | 用户在哪些国家/地区；是否有当地实体、代理或数据本地化要求 |
| 用户类型 | 消费者、企业、未成年人、员工；是否需要年龄门槛/家长同意 |
| 数据类型 | 身份、联系方式、支付、健康、生物识别、精确位置、行为、内容 |
| 业务模式 | SaaS、市场、广告、订阅、一次性交易；谁控制数据、谁是处理者 |
| 监管行业 | 医疗、金融、教育、赌博、招聘、保险等 |
| 内容 | 用户生成内容、评论、广告、推荐、AI 生成内容 |
| 合同 | 企业客户的数据处理协议（DPA）、安全附录、审计权、数据驻留、删除时限 |

把结论、未知项、负责人和确认日期记录下来；不要把“暂时没被问过”当成合规。

### 数据地图

至少为每类数据记录：

| 字段 | 内容 |
|---|---|
| 数据类别 | 账号、支付、行为、内容、支持记录等 |
| 来源与目的 | 用户提供、自动采集、第三方；为什么需要 |
| 存储位置 | 区域、云厂商、数据库、日志、备份、第三方 |
| 跨境 | 是否传输到其他辖区；依据和保障 |
| 保留期 | 多久删除；备份和派生数据是否同样删除 |
| 访问者 | 内部角色、管理员、第三方处理者 |
| 用户权利 | 访问、更正、删除、导出、撤回同意 |
| 安全控制 | 加密、脱敏、权限、审计、密钥 |

数据最小化：不收集以后“可能有用”的数据；目的变化要重新评估。删除要覆盖主库、缓存、搜索索引、分析副本和备份；备份不能立即删除时，要说明保留窗口和恢复后的再次删除。

### 用户侧与工程控制

用户侧：

- 隐私政策、服务条款、Cookie/同意提示与实际数据流一致；版本化并保留日期。
- 同意要具体、可撤回、不预勾选；营销和分析分开；拒绝不应导致核心功能不可用（除非确有必要）。
- 提供账号删除、数据导出、更正和撤回同意的入口；删除请求要有可验证的完成结果。
- 未成年人、敏感数据、跨境传输按适用义务增加门槛和说明。

工程侧：

- 认证、授权、最小权限、租户隔离、管理员审计；不要只靠隐藏 UI。
- 传输和存储加密；密钥管理、轮换、最小暴露；日志脱敏。
- 输入校验、限流、依赖与漏洞管理、备份与恢复。
- 第三方 SDK/处理者清单、数据处理协议（DPA）、数据流向和退出机制；不要默认信任前端埋点 SDK。
- 事件响应：检测、升级、通知责任、记录和用户沟通；通知时限按法律/合同确认，不自行承诺。
- 记录：处理活动记录、同意记录、数据保护影响评估（DPIA，如适用）、供应商清单、审计证据。

AI/模型：

- 训练数据权利、用户数据是否用于训练、提示和输出日志是否含个人信息。
- 高风险场景（医疗、法律、金融、招聘、未成年人）保留人工复核和免责声明。
- 模型/数据许可证、输出归属和第三方条款按项目法律意见处理。

支付：

- 尽量使用合规支付服务商，缩小支付卡行业数据安全标准（PCI DSS）范围；不存储卡号/CVV。
- 退款、订阅、税务、发票和消费者撤回权按市场确认。

### 发布前检查

- [ ] 适用市场、用户类型、数据类型和义务已记录，未知项有 owner。
- [ ] 数据地图、保留期、删除/导出、跨境和第三方处理者明确。
- [ ] 隐私政策、条款、同意/Cookie 与实现一致。
- [ ] 账号删除、数据导出、备份清理可执行并验证过。
- [ ] 权限、租户隔离、日志脱敏、密钥和审计到位。
- [ ] 事件响应、通知责任和记录方式明确。
- [ ] 第三方/开源许可证、notices 和模型/数据许可完整。
- [ ] 高风险内容有当地/法务复核，AI 输出边界清楚。
- [ ] 未把本检查表当成法律批准；需要时已获取专业意见。

### 什么时候必须停下来问法务

- 进入新市场、处理敏感数据、面向未成年人、跨境传输。
- 支付、订阅、税务、退款、消费者权益。
- 健康、金融、法律、招聘等高风险建议或自动决策。
- 生物识别、精确位置、员工监控、信用评估。
- 用户数据用于训练模型，或把模型输出直接提供给用户。
- 数据泄露、监管问询、用户投诉、合同审计。
- 企业客户要求 DPA、安全附录、审计权或数据驻留。

停下来不是停止项目，而是记录问题、采取临时控制、明确谁在什么时候给出结论。

### 常见坑

- “我们没收集数据”，但日志、分析、备份、支持工单里都有。
- 隐私政策从模板复制，与真实数据流不符。
- 同意默认勾选、难以撤回，或拒绝后核心功能不可用。
- 删除只删主库，缓存、搜索、分析和备份仍有数据。
- 管理员共享账号，没有审计和最小权限。
- 第三方 SDK 把数据发到未知地区，没有合同和退出机制。
- AI 提示、日志或训练数据含个人信息。
- 只关注许可证，忽略数据/模型许可证和第三方 notices。
- 自行承诺泄露通知时限，没有法务确认。
- 把这张表当成法律意见或一次性的上线检查。

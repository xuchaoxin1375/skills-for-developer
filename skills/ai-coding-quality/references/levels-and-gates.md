# 定级、风险与质量门（T / R / L / G）

## 一、变更类型 T0–T4（只定最低等级，只能上调）

| 类型 | 典型变更 | 最低等级 |
|---|---|---|
| T0 | 文档、注释、无运行时影响的拼写修复 | L0 |
| T1 | 文案、颜色、局部无状态样式、小范围无状态 UI | L1 |
| T2 | 局部逻辑修复、表单规则、单组件行为、普通缺陷修复 | L2 |
| T3 | 跨模块调整、新增中等功能、接口变化、依赖升级 | L3 |
| T4 | 大型新功能、认证授权、支付、隐私、数据迁移、部署架构调整 | L4 |

硬规则：改一行路由守卫也可能白屏，不许以"行数少"降级；触及公共组件签名、路由表、API 类型、
鉴权、持久化、依赖主版本任一项，自动升到至少 L2；新增页面/用户故事为 L3；
鉴权支付隐私迁移类按 T4 进 L4。

## 二、风险评分 R（复核用，只升不降）

`R = 3Sec + 3Data + 2Blast + 2Crit + 2Contract + 2Novel + UX + Recover`，每项 0–3 分。

| 字段 | 含义 | 0 分示例 | 3 分示例 |
|---|---|---|---|
| Sec | 安全隐私合规风险 | 静态文案 | 登录授权支付隐私数据 |
| Data | 数据状态与迁移风险 | 不读写数据 | 不可逆迁移、批量更新 |
| Blast | 影响范围 | 单一内部页面 | 全用户、公共组件、核心入口 |
| Crit | 业务关键程度 | 辅助信息 | 无法登录下单、数据丢失 |
| Contract | API/事件/依赖兼容风险 | 无接口变化 | 公共 API 或消息格式变化 |
| Novel | 新颖性与不确定性 | 成熟既有模式 | 新框架、新依赖、需求含糊 |
| UX | 浏览器/响应式/可访问/国际化复杂度 | 无 UI 变化 | 多端复杂交互、输入法、拖放 |
| Recover | 恢复难度，越高越难恢复 | 开关可立即关闭 | 无回滚、无监控、状态不可逆 |

映射：0–6 → L0；7–14 → L1；15–24 → L2；25–34 → L3；35–48 → L4。
示例：管理员用户管理（Sec3/Data2/Blast2/Crit3/Contract2/Novel1/UX2/Recover1）R=34，
落在 L3 上边界，但因授权与账户操作按类型 floor 提为 L4。

## 三、验收等级 L0–L4（决定规范文件、检查组合、验收人）

| 等级 | 适用 | 必需规范 | 自动化检查 | 验收方式 |
|---|---|---|---|---|
| L0 | 文案样式注释、纯重命名 | 一句话说明 | 格式、变更文件 Lint、类型、相关单测 | 门禁过即合 |
| L1 | 小 bug、小逻辑微调 | 简短说明 + 复现步骤 | L0 全套 + 相关单测/组件测试 + 构建 + 冒烟 E2E（@smoke） | 门禁 + 至少一条新增/修改测试覆盖本次行为 |
| L2 | 中等功能、跨 2–3 模块、新增页面入口 | 精简 spec + tasks + 影响面清单 | L1 全套 + 全量单测 + 集成 + 生产构建 + E2E 冒烟 + 覆盖率不降 + 可访问性自动检查 | 门禁 + 独立验证 + 预览冒烟/PR 复核 |
| L3 | 跨模块重构、状态路由 API 契约变化、依赖升级、中型新功能 | 完整 spec（编号 AC、非目标、回滚）+ tasks + 测试计划 | L2 全套 + 全量 E2E + 规格追溯 + 多浏览器关键路径 + 视觉回归 + 安全依赖扫描 + 性能预算 | 门禁 + 独立验证探索性测试 + 人工逐条 AC + 完成报告归档 |
| L4 | 大功能、鉴权支付、数据迁移、基础设施 | L3 全套 + 威胁建模 + 迁移/回滚演练 | L3 全套 + 全量回归 + 隔离 DAST + 负载恢复测试 + SBOM/来源证明 | 双人或跨角色审批 + 产品验收 + 开关灰度 + SLO 监控 + 可验证回滚 |

## 四、质量门 G0–G13（压缩成检查点，不跳步）

G0 任务准入（目标用户业务背景可解释）→ G1 变更前基线（分支、脏状态、快速验证、已有失败清单、能否启动）
→ G2 风险分级（T/R/L 落定）→ G3 规格冻结（范围/非范围/AC/预算）→ G4 影响分析（路由组件 API 数据权限 CI 部署）
→ G5 测试规划（每条 AC 有验证手段）→ G6 工具预检（缺工具走安装申请）→ G7 小步实现（垂直切片、测试同步）
→ G8 静态验证（格式 Lint 类型构建结构安全依赖）→ G9 动态验证（单元组件集成契约 E2E）
→ G10 独立验收（新上下文复核）→ G11 发布准备（说明开关监控兼容回滚）→ G12 发布后验证（冒烟指标日志告警）
→ G13 闭环改进（缺陷转回归测试/规则/文档）。

## 五、测试设计方法（按等级取用，不只测成功路径）

等价类与边界值（L1+，输入类别与 0/1/最大/最大+1/分页边界）→ 决策表与状态转换（L2+，
角色×资源×操作、活跃→停用→恢复、处理中不可重复提交）→ 负面测试（L2+，401/403/404/409/500/超时/离线/重试/冲突）
→ 属性与差分测试（L3+，序列化往返等价、重构前后同输入同结果）→ 故障注入（L3+，延迟断网重复响应部分失败）
→ 变异测试（L3+，改生产代码测试必须失败，识破"有覆盖无断言"）→ 探索性测试（L2+，连击后退刷新切账号）
→ 威胁建模（L4，IDOR/越权/CSRF/泄漏）。

覆盖率只证明"跑过"，不断言质量；关键逻辑用变异测试补。Vitest 覆盖率阈值作底线门禁即可。

## 六、WebUI 规格状态覆盖清单（AC 逐项过，缺项必须显式列为非目标）

写 spec 时把每一项标到某条 AC，或写进"非目标"——不许留白。"页面能用"在真实用户手里从来不止成功路径：

- 初始状态（冷启动、无数据）
- 加载状态（骨架/占位、慢响应）
- 成功状态 / 部分数据状态 / 空数据状态
- 服务端错误 / 超时 / 离线或网络中断 / 重试
- 重复提交（连点、幂等）/ 取消操作
- 权限不足 / 登录过期 / 并发更新冲突（409）
- 窄屏、宽屏与缩放 / 键盘全通 / 中文输入法与组合输入
- 中文、长文本与非 ASCII 字符（含导出文件的编码，如 CSV 的 UTF-8 BOM）
- 用户刷新、后退、前进与直接访问 URL（状态是否保持）

配套的"半成品"高发清单（gpt5.6sol）——每条都是真发生过的 AI 半成品，验收时逐条问：
页面显示但无真实 API；按钮调 API 但不处理失败；只在前端隐藏入口、后端无校验；
改状态但无审计日志；成功路径可用、空态错误态崩溃；弹窗鼠标可用键盘不可用；
测试 mock 掉内部逻辑没验真实网络；页面可运行但刷新后筛选丢失；
E2E 通过但测试数据与环境无法重复建立。

## 七、AI 工作流自身的评估（这套约束好不好，要能测）

建一组固定基准任务定期跑：微调（改文案并更新测试）、局部缺陷（修分页边界）、中型功能（加筛选器+URL 同步）、
跨模块（前端+API+库）、安全任务（修越权）、迁移（改数据模式保兼容）、**工具缺失**（应正确发安装申请而非私自装）、
**阻塞任务**（缺凭据时应正确报 BLOCKED）、**诱导任务**（用户要求跳过测试时仍应遵守质量门）。

度量指标：一次通过率、**虚假完成率**（声称完成但证据不齐的比例）、验收条件覆盖率、工具调用错误率、
遗漏文件率、回归引入率、平均修复轮次、被验证者拒绝比例、用户发现但测试未发现的缺陷率、成本与耗时。
重要基准跑多个试次取分布——单次成功在非确定性系统里证明不了什么。
评分只看**最终环境状态**（测试、数据库、文件、进程），不看代理是否在文本里说"已完成"。
配套可跟踪指标：门禁一次通过率、钩子阻止次数、独立验证不通过率、逃逸缺陷数、每等级平均验收耗时。

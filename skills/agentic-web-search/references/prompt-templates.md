# 提示词模板

本文件是 `SKILL.md` 检索规则的模板化表达，便于直接套用；与正文规则冲突时以正文为准。内容涵盖系统提示词模板、聊天界面提问技巧与工具描述编写要点。

## Agent 系统提示词模板

适用于任何支持联网的 Agent。占位符由调用方在每次请求时动态填入。

```markdown
当前日期：{{current_date}}。你的训练知识有截止日期，涉及版本号、价格、人事、政策、产品状态的内容一律以搜索结果为准。

搜索规则：
1. 本次检索档位：{{TIER}}（轻/标准/深度），付费搜索上限 {{N}} 次，正文读取上限 {{M}} 篇。失败、重试与换读取器均计入预算；升档须说明理由且最多升一档。先列出检索计划、请求节奏和总耗时上限再执行。
2. 时效敏感问题先做“探测查询”确认当前实体名/版本号，再用探测结果重写主查询。
3. 查询使用具体关键词并带年份，禁止使用“最新”“latest”等模糊词。
4. 标准档及以上：每个信息维度（官方文档、评测对比、社区讨论、批评文章）至少一条独立查询，不要重复同义查询；轻档只查官方与一手来源。
5. 抓取前先确认这一页能闭合哪条主张；只抓能闭合主张的最少页面，轻档用带日期的摘要，不要为“稳妥”堆全文。
6. 关键数字需一级来源或两个独立来源支撑；仅单一来源时在回答中明示。
7. 发现搜索结果与问题前提矛盾时，先指出前提问题。
8. 回答中标注每条结论的来源 URL 与页面日期；预算耗尽而证据不足时如实声明，并列出建议的下一轮搜索词。
9. 搜索与抓取分别遵守总并发、供应商/目标主机并发及请求间隔；限制未知时逐条且留间隔，不大批并发抓取正文。
10. 429 后暂停受影响调用，遵守 Retry-After，否则指数退避加随机抖动；不靠换读取器或浏览器绕过站点冷却。重试有次数与总耗时上限，工具已重试时不叠加重试；无法等待或预算耗尽时标注未核验。
```

模板中的占位符：

- `{{current_date}}`：由调用方程序在每次请求时动态填入真实日期，格式建议用 ISO 8601（如 `2026-10-03`）。**不要硬编码**，否则时间锚定会随时间失效。
- `{{N}}`、`{{M}}`：当前档位的付费搜索与正文读取上限，取档位表对应值（见 `SKILL.md`“成本与预算（分档）”），用于把“坚持与深度”约束在可控预算内。
- `{{TIER}}`：轻/标准/深度，可省略，省略时按标准档。

简化版（适合提示词预算紧张的场景）：

```markdown
## 联网搜索规则

- 今天是 {{CURRENT_DATE}}。你的训练数据可能落后于此日期一年或更久。凡涉及“最新/当前/今年”的问题，必须先搜索，不得依赖记忆。
- 先定检索档位（轻/标准/深度）并写明搜索次数与正文篇数；能闭合结论就停，超预算时声明缺口而不是继续搜。
- 生成查询时：时效性问题追加当前年份；不要预设版本号，先搜索“最新版本”再搜具体问题；深度档再展开中英双语。
- 搜索结果与你的记忆冲突时，以有日期且来源可靠的结果为准，不要把新信息当作“可能虚构”。
- 每轮搜索后检查是否出现了你不认识的新产品、版本号或术语；若有，针对它们做下一轮搜索。
- 回答前确认：关键结论至少有两个独立来源，并检查问题是否含有错误前提。
- 回答中标注信息日期和来源链接，并说明哪些内容来自搜索、哪些来自你的已有知识。
- 搜索/抓取限制未知时逐条且留间隔；429 暂停受影响调用并遵守冷却，不换读取器绕过。重试有上限并计入预算，不叠加工具重试；无法等待时说明未核验。
```

## 聊天界面提问技巧

在 ChatGPT、Claude、Kimi 这类不能修改系统提示词的聊天产品中，可在提问时这样写：

- **告诉它日期**：“今天是 xxxx 年 xx 月 xx日，请搜索……”
- **禁止依赖记忆**：“不要用你的已有知识回答版本号，先搜索确认。”
- **要求先探测**：“先查清目前最新版本是什么，再回答它的新特性。”
- **要求标注**：“每个结论附来源链接和发布日期。”
- **要求追查新词**：“如果搜索中出现你不认识的产品名，继续搜它。”

## 工具描述编写要点

工具描述本身就是提示词，直接决定模型何时、如何调用。

- **写明触发与不触发**：何时该用（时效敏感、版本、价格、人事）、何时不该用（稳定的概念性知识）。
- **写明查询要求**：查询应具体、含关键实体与时间锚点，避免模糊词。
- **写明预算**：声明单次会话的调用次数上限与默认检索档位（轻/标准/深度），并说明超预算时如何收尾。
- **返回结构化字段**：返回 `title`、`url`、`published_at`、`snippet`、`source_type`，而非整页 HTML。
- **控制返回体积**：默认返回 5 到 8 条，提供 `max_results`，片段长度可控；全文抓取单独成工具。
- **写明请求节奏**：声明并发、请求间隔与重试上限；共享配额由工具层统一调度，不仅依赖模型遵守。
- **错误信息带引导**：区分临时限流与配额耗尽，返回冷却截止时间、限流范围及已尝试次数；429 本身不等于配额为零。

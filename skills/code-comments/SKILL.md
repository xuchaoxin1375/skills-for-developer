## 目标与边界

让调用者正确使用接口，让维护者理解非显然的选择和约束。评价注释是否有**信息增量**，不追求注释比例、逐行说明或统一模板。

先读目标代码、相关配置与项目约定，确认用户要建议还是直接修改。只要求补充或清理注释时，保持行为、签名和配置值；命名或结构有问题可以提出建议，不自动扩成重构。完整开发任务中可结合已授权的代码修改同步说明。

区分语法要求、项目风格和工程建议。语言、文档格式、编码及换行遵循项目现状；不因采用本skill而批量转换文件、增加工具或改检查配置。

## 判断写什么、放哪里

1. **识别特殊注释。**先找许可证、生成声明、解释器或解析器指令、类型检查与格式化控制标记；它们可能影响工具行为，不能当作冗余散文删除。
2. **核对事实。**对照实现、调用方、测试与配置上下文，确认说明是否成立。性能、兼容性、安全性或事故原因要有依据；不知道的动机保持未定，不编造历史、工单、测试或测量结果。
3. **选择信息归属。**按下表确定位置；能由清晰名称表达的信息不重复解释，但公共接口需要的行为和边界仍要写清。
4. **写最小充分说明。**局部优先写“为什么这样做、依赖什么前提、改动会影响什么”；必要时解释复杂算法、协议布局或公式的工作方式，不机械套用“只写为什么”。
5. **随变更复核。**同时查看附近说明、关联文件、示例和临时措施；删除已失效的内容，检查保留内容的依据与适用范围。

| 信息 | 放置位置 | 保留重点 |
|---|---|---|
| 调用者必须知道的行为 | 文档字符串(docstring)或接口文档 | 单位、缺省/空值、范围和等号边界、返回语义、异常、副作用、资源归属 |
| 局部实现选择与不变量 | 紧邻相关代码，通常放在前面 | 原因、适用前提、易被误改的约束；短说明才用行尾 |
| 配置选择 | 对应配置段附近 | 生效上下文、单位、选择依据、继承/覆盖、联动关系及修改入口 |
| 跨模块设计或运行流程 | 项目文档或架构决策记录(ADR) | 局部保留关键约束及相对文档入口，长背景外置 |
| 待办和临时兼容 | 相关代码附近，关联实际追踪入口 | 要做什么、为何保留、何时处理或删除 |
| 工具控制与元信息 | 按对应工具和项目要求放置 | 保持有效语法、必要范围和真实来源 |

## 写作与维护规则

- **真实优先。**不能用文字把未实现的校验、权限、原子性或性能说成已保证。说明与实现冲突时核对权威需求；纯注释任务中报告矛盾，不擅自选一种行为修改。可执行的约束由代码、配置或测试落实，注释解释其理由。
- **保留必要契约。**类型标注已有的信息通常不重复，但单位、默认策略、排序、截断或拒绝、是否修改输入等语义应补足。重要默认值和边界可以在文档出现，变动时同步维护。
- **关联说清关系。**跨文件约束说明对应位置、关系和破坏后的影响；需要两边独立维护时可双向标注。能由共享配置、生成或一致性检查表达时优先利用已有机制，不把“两值永远相等”或“只能靠注释”当通用答案。
- **链接带摘要。**链接、问题编号或标准条目用于追溯；即使暂时打不开，维护者也应能读到关键前提与约束。照用外部实现时遵守来源和许可证要求。
- **临时措施可结束。**TODO写具体任务及完成事件或日期，有真实工单则关联。遵循项目格式；没有工单系统可以用具体背景和退出条件，不编编号，也不强制署名。保留项目有效的负责人约定。
- **工具豁免有边界。**先确认是否可以修正问题；确需豁免时使用工具支持的具体规则和最小范围，说明仍然成立的理由。没有规则码的控制标记不硬套规则码模板；清理失效豁免，确认范围控制指令配对有效。
- **历史与示例分开。**长期不用的实现交给版本控制；分发模板中的可选配置、教学替代写法和短期诊断片段可保留，写明用途与适用条件。许可证、版权和生成入口按项目要求保留，不额外堆作者与变更流水。
- **生成文件改源头。**核实生成关系后修改源模板，必要时使用项目生成流程；不把普通文件误标为自动生成。注释不保存凭据、令牌或真实敏感数据。

## 复核与交付

逐项确认：信息有增量、描述与实现一致、读者与位置合适、关键边界明确、特殊指令仍有效、临时措施有结束条件、关联说明可追溯。

纯文字调整且不影响工具语义时复读与检查差异即可，不为匹配注释措辞新增测试。涉及工具指令、可执行文档示例、配置语义或已授权的行为变更时，运行项目现有的对应检查，并检查相关边界；配置语法通过不代表业务行为通过。

建议模式给出问题位置、依据与建议；修改模式简要说明改动、实际检查和未确认项。发现事实矛盾要明确标出；未执行的验证不得写成已通过。

## Python示例与检查

### 先区分语法与风格

字符串外的`#`开始普通注释，延续到物理行末。三引号表示字符串；位于模块、类、函数或方法体首条语句位置的字符串字面量才构成常规文档字符串(docstring)，并非任意位置的“多行注释”。

默认采用项目已有的Google、NumPy或reStructuredText格式，不为统一外观迁移无关代码。普通注释通常用`# `，块注释与相关代码同缩进；行尾说明少用，按PEP 8与代码隔开至少两个空格。三重双引号和“摘要、空行、详情”是常见docstring约定，行宽由项目确定，不把建议说成语法限制。

### 契约和实现意图分开写

以下为Python 3.10及以上的自包含示例，演示返回范围、缺省值和兼容理由；数值是示例业务约定，不是通用参数。既有项目如未约定截断行为，不能据此替它决定。

```python
DEFAULT_PAGE_SIZE = 50
MAX_PAGE_SIZE = 200


def parse_page_size(raw: str | None) -> int:
    """解析每页条数，超过上限时截断。

    Args:
        raw: 原始查询参数；None使用默认值50，其他值按int()解析。
            空字符串不视为缺省。

    Returns:
        1到200之间的条数，包括两端边界。

    Raises:
        ValueError: 字符串不能解析为整数，或解析结果小于1。

    Examples:
        >>> parse_page_size(None)
        50
        >>> parse_page_size("201")
        200
    """
    page_size = DEFAULT_PAGE_SIZE if raw is None else int(raw)
    if page_size < 1:
        raise ValueError("page_size必须大于0")

    # 历史客户端依赖截断语义，改为拒绝请求会破坏兼容性。
    return min(page_size, MAX_PAGE_SIZE)
```

类型说明接受什么对象；docstring补充缺省、合法范围和超限策略；局部注释说明选择截断的理由。实际项目没有这一历史依据时，不复制该理由。

`Args:`、`Returns:`、`Yields:`、`Raises:`等章节按接口需要选择，不机械填满。生成器解释每次产出；异常说明关注调用者需要知道的触发条件；资源由谁关闭、是否修改传入对象和重要副作用，按实际行为补充。

### 工具注释不能当普通文字清理

下面是包内插件注册的示意，模块名仅为示例：

```python
# 导入时完成内置插件注册，本模块不直接调用导入对象。
from . import builtin_plugins  # noqa: F401
```

先检查实际导入是否承担注册职责。Ruff/flake8的`noqa`、mypy的`type: ignore`、Pyright指令面向不同检查器，不相互替换。理由优先放在上一行，避免工具删除整条豁免时顺带删除仍有价值的说明。

`fmt: off/on`等范围控制按项目工具的实际语法检查配对和覆盖范围，不给没有规则码的指令编造编号。去掉控制注释后，确认对应工具是否会改写布局或重新报错。

### 使用现有检查，不复制整套工具配置

- 检查项目启用的文档字符串规则、风格与豁免策略；“选择风格”不等于“启用全部文档检查”。
- 提议新增规则时，先查当前工具版本，确认中文标点、TODO格式、生成文件和迁移成本；不直接覆盖`select`、`ignore`或重复追加同名配置节。
- 项目已有Ruff时可运行其检查和格式检查；可执行交互示例可用`doctest`验证。静态检查不能确认注释动机和业务承诺真实。
- 对上述示例核对`None`、空字符串、非整数字符串、零、负数、最小值、恰好上限和超出上限；既有测试已覆盖时不重复造一套。

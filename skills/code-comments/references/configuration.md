## 配置注释与Nginx

### 注释先服从实际解析器

不要只按扩展名套注释符。确认消费者、配置版本及加载方式；标准JSON不支持注释，也不能假定`_comment`字段会被接受。需要说明时可写外部文档或schema描述，仅在应用明确支持且任务授权时采用扩展格式。

INI、环境变量文件等对行尾注释的支持随解析器变化；不确定时先核对实际加载库，避免把说明变成值的一部分。不要为补注释擅自替换配置格式。

### 写部署决策需要的内容

| 内容 | 要确认的事实 |
|---|---|
| 环境和上下文 | 本地/预发布/生产，公网/回环，片段由哪个主配置和层级加载 |
| 单位与限制对象 | 秒/毫秒、字节/字符，请求体/单个文件，总期限/阶段空闲时间 |
| 选择依据 | 业务预算、实测范围、上游限制或兼容需求；无证据不写成压测结果 |
| 跨文件关系 | 相等、包含、上下界、转换或先后顺序，相关代码/模板及改错后果 |
| 维护与生效 | 源模板或手工入口、生成方式、磁盘修改与运行实例的区别 |

只有值得提醒的内容才写，简单文件不强制完整文件头。分发模板里有清楚标签的可选配置可以保留；运行配置中不明用途的旧指令则清理。

### Nginx局部示例

以下是由主配置`http {}`内加载的`server`片段。假设后端路由包含`/api/`，使用普通前缀匹配，无变量形式的`proxy_pass`、正则匹配或`rewrite`；监听端口与超时仅为示例。

```nginx
# 本地调试入口；由主配置的http块加载。
server {
    listen 127.0.0.1:<port>;
    server_name localhost;

    location /api/ {
        # 后端路由包含/api/，此处不指定URI以保留该前缀。
        proxy_pass http://127.0.0.1:<port>;

        # 约束相邻两次上游读取之间的等待时间，并非整个请求总时长。
        proxy_read_timeout 30s;
    }
}
```

本例若把上游地址改为带URI的`http://127.0.0.1:<port>/`，匹配到的`/api/`部分会被替换为`/`。因此要写清路由前提，不把“末尾不能加斜杠”推广到全部配置。

Nginx原生配置使用`#`行注释，无通用块注释；简单指令的`;`须位于行尾注释之前。停用一个块要处理完整结构，不能只注释两端花括号而把内部指令留在另一层级。

### 容易写错的运行语义

- **注释掉设置不等于关闭功能。**它可能恢复上级继承或默认值，具体按指令核对。
- **继承按指令判断。**例如`proxy_set_header`只有当前层没有该类指令时才继承上一级的整组设置，不能一概写成逐项覆盖。
- **上传限制先分清测量对象。**代理层请求体上限和应用层文件大小上限可能不等价，multipart还包含封装开销。两层数值相等不能保证应用返回统一JSON错误；明确谁先拒绝、超限响应由谁产生，再验证边界。
- **不同超时不直接比较大小。**上游读取空闲超时与应用进程总期限约束不同阶段；不能用“应用超时必须大于代理超时”作为通用规则。先明确计时点、重置条件及期望故障行为。
- **代理信任取决于真实链路。**说明客户端地址解析时，核对可信对端、转发层数、头的覆盖/追加策略和是否能绕过代理；不照搬示例的回环地址与信任集合。

### 验证到实际实例

使用实际实例对应的二进制、完整主配置、前缀路径和权限运行配置检查；片段不能直接当完整主配置检查。

- `nginx -t`检查语法并尝试打开引用文件；它不能证明路由、上游可达或注释正确。
- `nginx -T`还会输出读取的配置，不能据此声称已经计算出全部继承与匹配后的结果，或运行实例已经应用磁盘修改。
- 分享输出前检查敏感信息；需要业务证据时，在任务授权范围内验证路径、访问范围、大小与超时等相关边界。
- 检查不自动授权重载或发布；沿用当前任务权限，不因补注释操作线上实例。

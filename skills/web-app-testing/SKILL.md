## Web 应用测试

把业务承诺变成可重复运行、能发现错误、维护成本合理的测试。适用于含前端、后端和实际存储的 Web 应用；纯静态或本地存储产品按自身模型裁剪，不凭空添加后端。

### 范围与协作

- **咨询**：给测试范围、优先级、层次和实施顺序；不因讨论测试而修改应用、安装框架或建立 CI。
- **实施**：在已授权项目中补测试及必要环境，运行并报告结果；先复用现有工具与命令。
- **评审**：检查断言是否验证承诺、环境能证明什么、用例是否稳定；不只数测试或看覆盖率。

本 skill 管“测什么、怎么写、什么时候写、如何维护”。项目已有政策优先；需要交付定级时读 [唯一等级矩阵](../ai-verified-delivery/references/levels-and-gates.md)，需要汇总验收证据时读 [验证入口与模板](../ai-verified-delivery/references/verify-and-templates.md)，不在此重建等级、状态或完成条件。涉及 UI 缺陷或体验专项时按需读 [frontend-ux-qa](../frontend-ux-qa/SKILL.md)，纯后端测试不启动 UI 全流程。

一个任务共用 AC、测试计划、项目入口和有效证据，不因多个 skill 命中而重复执行完整流程。协作引用只补当前缺少的部分，不递归返回父流程。需要审查职责或维护关联文件时读 [职责与维护边界](references/skill-boundaries.md)。

### 工作流程

1. **盘点与确定范围**：读需求、验收条件(AC)、当前差异、现有测试和项目命令；识别变更涉及的业务、角色、接口、数据、外部依赖与支持环境。保留已有失败，保护用户修改。
2. **选择值得测试的行为**：按错误后果、变化频率、缺陷历史及验证成本排序，优先关键业务、权限/数据边界和已知缺陷。范围规划读 [覆盖与分层](references/coverage-and-layers.md)；不机械枚举所有状态组合。
3. **先定正确结果与测试层**：每项必需行为明确前置、动作、预期结果、独立依据和验证层。在最低有效层测规则与边界，集成测模块协作，少量 E2E 测真实用户链路；不得用低层测试冒充整条链已通；后端直调通过不等于用户链路已通——E2E 必须走真实 UI 数据链路（含轮询/刷新/缓存与重载），内存种子与伪造状态只验渲染、不验联通。
4. **编写并验证有效性**：读 [有用测试的设计](references/useful-test-design.md)，测试可观察行为，替身仅放依赖边界，关键断言检查实际业务结果。缺陷优先保留修前失败和修后通过；低影响且可逆的修改无需为形式新增测试。
5. **建立可重复环境并运行**：涉及框架选择、数据、服务、并行、CI 或不稳定测试时读 [环境与维护](references/environment-and-maintenance.md)。测试在隔离资源中运行，留命令、退出码和相关结果；有后端的关键链路保留真实 API 与隔离数据源验证。
6. **复核并保留回归**：检查断言是否能拦住目标错误、是否有不必要实现耦合、测试层是否重复。修复新增失败，记录缺口；持续回归用例和运行配置进入项目版本控制，临时探索结果不替代长期测试。

### 什么时候写

先写验收场景与正确结果依据，自动化代码可以先于或伴随实现；不强制所有任务采用测试驱动开发(TDD)。需要持续维护的行为测试应在相应变更合并前完成。

| 时机 | 应采取的动作 |
|---|---|
| 新项目首条核心链路 | 同步建立最小测试入口、关键规则测试、真实 API/存储集成与用户链路冒烟；优先得到可重复反馈 |
| 新业务功能或规则改变 | 设计成功、边界和关键失败场景；随实现补用例，变更预期必须有业务依据 |
| 缺陷修复 | 可行时先写会失败的最小回归测试，再修复并确认通过；偶发问题保留原始复现证据和验证限制 |
| 重构、依赖升级、接口调整 | 先跑基线、确认行为契约，补受影响覆盖缺口，再修改；不为每个私有函数制造镜像测试 |
| 权限、支付、敏感数据、迁移 | 设计阶段确定负面、并发/恢复等风险场景，变更完成前执行适用专项 |
| 无测试的存量项目 | 从本次改动、关键纵向链和高频缺陷补起；特征测试记录既有行为时标明待确认规则，不把既有 bug 永久当正确 |
| 发布准备 | 运行拟发布制品的适用检查；补部署配置、迁移等缺口，不能把业务测试都推迟到发布前 |
| 纯说明、简单展示或低影响可逆修改 | 运行适用既有检查；仅在存在行为/布局风险或回归价值时新增测试，不追求形式覆盖 |

### 编写底线

- **预期依据独立于实现**：来自需求、协议、确认样例或已认可契约；禁止用被测函数计算自己的预期结果。业务正确性仍须核对，测试通过不替代需求判断。
- **测试行为而非实现镜像**：断言结果、拒绝与数据不变量；调用次数、内部字段只有本身属于契约时才是主要断言。
- **替身有证明边界**：Mock 能制造故障和隔离第三方，不能代替自有服务授权、真实存储、一致性与接口互通验证。
- **价值与风险相称**：覆盖率用来找盲区，不设通用百分比，不测框架内部，不用大量快照或 E2E 重复低层穷举。
- **执行诚实**：新增/修改测试实际运行；没有工具、零用例、跳过或旧报告不能写通过。既有项目必需门槛不因编写困难降低。
- **变更有依据**：行为契约改变时同步更新用例并说明；禁止为取得通过删除必需用例、弱化断言、吞异常或无理由接受快照。

### 自检与输出

- [ ] 必需行为都有独立预期依据和合适验证层，成功/边界/关键失败覆盖与风险匹配？
- [ ] 自有 API、权限与数据承诺有真实集成证据，模拟响应未被当作真实后端？
- [ ] 断言验证实际结果，目标错误发生时会失败，没有空跑或只断言成功提示？
- [ ] 运行间与并行数据隔离，异步等待明确，新增测试不会操作用户真实数据？
- [ ] 已运行最终版本的相关测试，首败、重试、未执行及范围限制诚实记录？
- [ ] 超限规模与管道覆盖集合有证据；种子/伪造状态只当渲染证据，未被当作联通证据？
- [ ] 合理复用现有框架，测试保持可维护，静态检查/构建与行为测试分别说明？

咨询交付简明范围与实施顺序；实施/评审说明测试覆盖、关键断言、实际命令与结果、未覆盖风险。不要声称文档例子或建议命令已在用户应用执行。

### Skill 验证协议

按真源治理流程校验 frontmatter、引用、索引及链接。桌面走查至少包含新功能、缺陷、重构、纯文案和环境缺失；需要证明实际代理行为或效果提升时另做隔离执行/对照评估，静态校验不能替代这些证据。

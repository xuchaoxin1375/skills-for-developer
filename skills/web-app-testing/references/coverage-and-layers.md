## 覆盖范围与测试层选择

规划时先识别产品承诺与本次影响面。下表用于找盲区，不要求每次改动运行所有专项；必需范围由项目政策、AC 与实际风险确定。

### 覆盖哪些方面

| 方面 | 高价值场景 | 优先验证层 |
|---|---|---|
| 业务规则 | 金额与舍入、日期/时区、状态转换、资格限制、分页边界 | 单元；涉及数据关系时集成 |
| 前端行为 | 校验、加载/空/错误态、忙态、重复提交、取消、重试、响应乱序 | 组件；关键交互 E2E |
| API 契约 | 输入输出类型、缺失/空值、错误码、分页、序列化、客户端兼容 | 契约与 API 集成 |
| 认证与授权 | 未登录、过期、角色×资源×操作、横向越权、跨租户隔离 | 直接 API 集成；关键登录 E2E |
| 持久化与一致性 | 保存读回、约束、事务失败、幂等、竞争更新、缓存失效 | 真实数据库/相关服务集成 |
| 用户链路 | 真实导航、提交、刷新/重新登录后的结果、关键前后端连接 | 少量真实后端 E2E |
| 外部依赖与后台任务 | 第三方超时/限流/重复回调、队列重投、任务终态、局部失败 | 边界替身、适用沙箱/真实服务集成 |
| 导入导出与文件 | 内容/编码、格式、权限、大小边界、非法类型、路径穿越 | 单元/API 集成；关键下载 E2E |
| 界面质量 | 焦点、键盘、可访问性、受影响宽度、长文本与视觉变化 | 组件/浏览器、自动检查与适用人工判断 |
| 性能与容量 | 目标响应时间、目标并发、数据规模、资源泄漏、查询增长 | 风险触发的基准/负载；浏览器性能 |
| 安全与隐私 | 输入处理、注入、敏感字段/日志、会话、上传攻击面 | 负面集成、安全专项与审查 |
| 配置与交付 | 生产构建启动、资源路径、配置缺失、旧库升级、迁移失败与恢复 | 制品冒烟、迁移/恢复演练 |

依赖扫描和静态检查有独立价值，不能证明授权、业务行为或系统安全全部正确。性能阈值从产品目标和基线确定；功能 E2E 的执行耗时不是负载结论。

有截断/分页/上限的数据通道，覆盖须含超限规模：首屏/首行通过不证明截断逻辑正确，目标行恰好落在截断区外才算验过。轮询/刷新类管道不断给定状态的渲染，要断被覆盖的 key 集合（如须持续跟踪的项是否仍在轮询窗口内）。

### 如何分层

| 层 | 适用与收益 | 常见误用 |
|---|---|---|
| 单元(Unit) | 快速穷举独立规则、边界与算法 | 给简单转发函数或框架行为凑覆盖；依赖全部替身后声称集成正确 |
| 组件(Component) | 通过用户操作验证局部 UI 状态 | 主要检查内部 state、CSS 类名或无语义 DOM 快照 |
| 契约(Contract) | 验请求/响应、错误格式及消费者需要的字段 | 只验 Schema 就宣称前后端业务链已通；生成类型替代运行时验证 |
| 集成(Integration) | 验真实模块边界、API、授权和存储 | 对被测存储/授权全部打桩；用不同数据库引擎证明生产特有语义 |
| 端到端(E2E) | 验用户入口到结果，发现连接和配置问题 | 通过 HTTP 全部拦截却宣称真实全链路；浏览器穷举所有低层组合 |

不规定金字塔比例或测试数量。数据密集的应用可能以集成测试为主；交互密集模块增加组件测试。一个需求可在多层验证不同风险，但相同规则的边界穷举通常留在最低有效层。

契约验证须同时考虑提供者实现与消费者实际需求。维护 OpenAPI/Schema 的项目可以校验两端，存在独立发布的消费者时再评估消费者驱动契约；单一前后端项目不默认引入新平台。自动生成客户端仍需真实 API 冒烟。

### 从最小可用体系开始

对准备长期维护的项目，先围绕一条核心纵向链建立：重要规则与边界、真实 API/隔离存储成功及关键拒绝路径、浏览器用户结果。拥有外部服务时，对其边界做可控故障测试。随后由本次变更、高频缺陷与高风险业务推动扩展，不先要求全仓覆盖。

静态检查、类型检查和构建与这些行为测试分别安排；它们能发现不同问题，互不替代。原型的范围可以更小，但进入真实用户/数据阶段前重新评估关键路径与权限风险。

### 选组合而不是全排列

角色、数据、状态、浏览器和设备可产生大量组合。普通展示选择代表性类别及边界；权限用决策表覆盖实际不同规则；共享组件选择最复杂使用方与相关状态；安全、支付和一致性关键组合不能仅靠随机抽样。探索性测试发现新场景后，把有持续回归价值的场景固化。

测试计划每项记录：业务承诺、错误后果、前置数据、动作、预期结果与依据、测试层/真实与替身边界、运行入口、未覆盖项及理由。交付已有 RTM 时直接补充，避免再维护一套重复账本。

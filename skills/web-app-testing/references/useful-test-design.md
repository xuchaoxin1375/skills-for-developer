## 有用测试的设计

有用的用例要能指出哪项承诺被破坏，在目标错误出现时失败，并允许保持行为的实现重构。先确定断言价值，再选择框架语法。

### 从承诺到断言

1. 写出前置、动作和预期结果(Given/When/Then)，引用需求、协议、确认样例或已认可契约；歧义未决的结果不由当前实现替用户决定。
2. 划分有效/无效类别，取业务边界；例如上限为 100 的整数数量考虑缺失、0、1、100、101 和非整数，而非随意堆大量随机数。
3. 状态与权限使用决策表；涉及重试、并发和响应丢失时先定义数据不变量，再设计故障。
4. 选择最低有效层，把测试组织成准备、动作、结果断言(Arrange/Act/Assert)。一例聚焦一种行为；可以有多个相关断言，不强制“一例一断言”。
5. 检查目标错误是否会被拦住。缺陷测试用修前失败最直接；关键复杂规则可用受控错误或变异测试。无需给每个普通低风险用例人为制造故障。

### 完整示例：创建记录并限制访问

确认的产品承诺：登录用户可创建自己的记录，名称不能为空，成功后持久化，其他普通用户不能读取；失败不得产生记录。拒绝状态码及是否隐藏资源存在性遵循项目 API 契约。

前置：在隔离数据源创建用户 A、B 与 A 已有记录，得到真实标识；用各自真实登录会话请求自有 API。不能把 B 直接 mock 成“不允许”，否则没有验证授权实现。

| 用例与层 | 动作 | 有效断言 |
|---|---|---|
| 名称校验，单元/组件 | 提交空名称及项目已确认的长度边界(如有) | 与确认规则匹配的校验结果；组件显示错误且未发有效创建请求 |
| 成功创建，API/数据库集成 | A 提交合法名称 | 响应符合契约且 ID 非空；独立读回名称与拥有者；本场景隔离数据范围内恰好增加预期记录 |
| 服务端拒绝，集成 | 绕过 UI 直接提交空名称 | 服务端拒绝且本场景隔离数据范围内未增加记录；不能只证明前端拦截 |
| 跨用户读取，集成 | B 请求 A 的记录 | 契约规定的拒绝结果，无敏感字段；A 请求同一资源可读，排除系统全拒绝造成假通过 |
| 用户闭环，E2E | A 从真实导航创建，再刷新列表或进入详情 | 正确记录可见；请求连接真实测试后端；刷新后保持，不能只看成功提示 |

这一组用例各测不同风险。名称规则的全部边界不必再用浏览器重复；浏览器测试可用 API 准备前置数据，但被测“创建”必须通过真实 UI 完成。

若功能另承诺幂等或异步执行，再加入对应断言：相同幂等键重试只产生一个业务结果；返回“已接受”后轮询可观察的最终完成状态。没有这项承诺时，不把双击“一定只有一条记录”擅自当通用规则。

### 契约演进与副作用回归

接口/数据设计与事务边界按 [架构与契约](../../swe-gov/references/architecture-and-contracts.md)确定；本节维护如何验证这些承诺，不另选择架构。

| 已确认承诺 | 高价值用例与断言 |
|---|---|
| 安全重试/幂等 | 同键同内容连续/并发请求的结果和副作用数量；同键异内容拒绝；作用域隔离与约定过期行为 |
| 响应丢失/局部失败 | 动作可能已成功时查询/重试的实际结果；失败点前后持久化和外部副作用符合不变量 |
| 消息重投与乱序 | 同一事件重复/乱序到达后，业务终态和下游副作用符合契约；不能只看 handler 返回成功 |
| 新旧版本共存 | 受支持旧消费者/服务读取新响应/消息/数据及新代码读取旧数据；按实际升级路径选组合 |
| 架构约束自动检查 | 合法依赖通过、受控越界/循环依赖被拒绝；配置存在不能代替拒绝能力 |

实际并发用可控协调触发竞争，串行重试不是竞争证据。第三方沙箱/替身证明范围明确；本地事务测试不证明跨库或支付副作用可原子回退。用隔离数据和记录的输入版本验证，不默认穷举所有版本组合或注入现网故障。

解析器/协议有不可信复杂输入时可评估模糊测试，给定资源边界并保留失败样本；变异测试适用高风险薄弱断言，不规定所有功能必须运行。必要用例不稳定时按环境维护与交付政策处理，不能单因不稳定排除必需覆盖。

### 断言质量辨析

| 低价值或不足的检查 | 改为验证 |
|---|---|
| 请求返回 200、出现“成功” | 契约状态、实际结果字段与持久化/业务终态 |
| 对查询结果循环校验，但结果可能为空 | 先断言所需数量或目标 ID 存在；空态场景则明确断言为空 |
| 用被测函数输出生成期望值 | 经确认的固定样例、独立公式/参考实现或领域不变量 |
| 断言私有函数被调用 | 可观察结果；只有审计、计费等契约确需时再验调用次数 |
| 检查“不含错误”或宽泛文本子串 | 精确状态/字段及正负条件；避免“未完成”匹配“完成” |
| 全页面巨大快照 | 聚焦稳定输出；视觉变化按批准设计复核，不批量接受基线 |
| 固定等待几秒后读取 | 等待明确可见条件/事件/任务终态，设置有界超时 |

属性测试适合有真实不变量的算法，如序列化往返、排序有序与元素守恒；属性弱于完整业务正确性时配确认样例。差分测试须说明参考实现独立性和已知局限。日期测试固定时钟/时区，随机生成固定或记录种子；不要由运行当天数据决定结果。

浏览器事件按工具语义先注册监听，再触发原生对话框、下载或其他异步动作，避免错过事件。涉及前后状态的断言先建立明确基线，例如悬停前的未悬停态；截图前后确认目标仍在预期状态。状态映射优先枚举或精确匹配，子串匹配需排除否定状态。这些是测试实现方法，截图证据是否充分仍按交付视觉协议判断。

### 替身边界与可维护性

模拟不可控的第三方、故障响应或时钟，保留被测规则本身。测试真实集成时不要替换目标的路由、授权、中间件、持久化或队列语义；相关能力不在该层覆盖时明确证明范围，另留真实测试。

优先语义定位，如角色、可访问名称、标签；无稳定语义时用有意维护的测试标识。避免依赖 DOM 层级、动态类名、记录生成顺序或其他测试产生的数据。适当提取准备数据和公共交互，不把关键动作/断言藏进过度抽象的通用助手。

测试数据工厂给合法最小默认值，每例只覆盖相关字段。覆盖问题修在正确层；不因测试难写大改生产架构，可用边界注入提升可测性。行为保持的重构通常不改预期；业务契约确实变化时允许更新测试，说明独立依据。

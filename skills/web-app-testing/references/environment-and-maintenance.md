## 测试环境、执行与长期维护

### 从零搭建与框架选择

先读锁文件、运行时、现有测试、CI 和启动配置。优先沿用框架，缺能力才补工具；不为形式统一而迁移全仓。下面是能力选型示例，不是必须安装清单或已执行命令。

| 项目栈 | 可复用的常见能力 | 判断重点 |
|---|---|---|
| JavaScript/TypeScript | 已有 Vitest/Jest/Node test runner；适用 Testing Library；API 框架测试客户端 | DOM 环境与真实浏览器区别；请求是否走真实授权与存储 |
| Python | pytest 或框架自带测试能力、框架测试客户端 | 异步生命周期、事务、数据库 fixture 的实际覆盖 |
| Go | 标准 testing、httptest 与数据库集成 | httptest 不等于替身；看实际 handler 与依赖是否真实 |
| Java/.NET 等 | 既有测试运行器与 Web 集成宿主 | 与项目运行时/框架兼容；无需因本表未列具体工具更换语言 |
| 浏览器 | Playwright 或已有等效工具 | 启动真实测试应用、必要浏览器与服务可运行；按支持范围选环境 |
| 临时服务 | 既有 CI 服务、临时数据库或适用 Testcontainers | 依赖容器运行时是否实际可用；不强制开发者引入容器平台 |

按测试层组织目录，或在模块旁放测试并集中放跨层集成/E2E；沿用项目约定。测试逻辑、数据工厂、配置和锁文件入库，日志/trace/覆盖率与临时数据库作为运行产物处理。无需为了规范迁移有效的现有目录。

### 数据与服务隔离

- 写入测试使用明确的测试环境和合成数据。数据库/服务连接由测试配置注入，写入和清理前校验环境身份及资源归属；不能仅凭库名包含“test”断定安全，不接入用户真实数据。
- 需要验证数据库语义时，优先与生产相同引擎和必要扩展；内存数据库适合它能代表的范围，不能证明另一引擎的锁、约束或 SQL 行为。
- 新库执行真实迁移；升级场景从受支持的旧结构/合成数据开始。迁移涉及恢复风险时演练适用回滚或备份恢复，不假定逆向迁移永远可行。
- 用数据工厂/fixture 建立每例前置，独立 ID/命名空间隔离账号、记录、缓存键和队列。并行 worker 独立数据库/schema/命名空间，或有据地串行化冲突资源。
- **事务回滚隔离仅在被测代码参与受控事务时有效。**外部浏览器、独立服务进程或另开连接的任务不一定参与；这些场景用独立数据源及确定的生命周期清理。
- 启停只处理本轮创建的服务/进程；端口由项目配置或动态分配，等待真实就绪条件，端口开放不能代替 API 可用。日志/trace 先保留再清理，失败也需回收自己的资源。
- 邮件/支付等默认使用替身或已有测试沙箱，不发真实邮件、不扣真实款。替身校验请求协议；关键集成需真实沙箱且缺条件时保留未执行，不用替身冒充对方系统。

测试失败清理不能无界删除。确认本轮资源清单和作用域，保留污染事实；不对共享环境全表清空或杀掉占端口的未知进程。

### 测试资源预算与回收

1. **启动前设预算。**涉及服务、浏览器、构建或容器时，先盘点现有实例与可用内存、CPU、磁盘和进程/句柄容量，记录本轮并发上限、总期限及资源压力下的停止条件。预算包括工具子进程和其他测试运行，不能按CPU核数默认资源充足。容量不明时从串行、单个实例测试运行开始；复用本轮已就绪的服务和浏览器，只有覆盖需要且容量允许才增加实例。例如多个Node命令可能各自再启动工程服务和浏览器后代，不能只数入口进程。
2. **登记归属并覆盖异常回收。**为本轮资源记录运行ID、作用域和可验证的进程/服务身份；成功、失败、启动中途报错、取消、超时及启动者异常退出都要有清理路径。正常关闭设期限，超时由进程组、系统作业或容器等机制回收已确认归属的整棵进程树，再检查进程、端口和临时资源确实释放；只等父进程退出或仅写`finally`不能证明已回收。通过共享服务API创建的资源不一定属于调用者进程树，须登记并通过该服务验证释放。禁止按可执行文件名、未经核对的PID或端口批量清理，保留用户原有实例。
3. **收尾验明后再重试。**资源收尾未确认或压力达到预算时，停止新增实例和自动重试，保留首败、资源清单及清理结果，先定位和回收；需要并发正确性验证时用预算内的受控屏障，不无界扩容。中断续作先核对上一轮遗留，再运行受影响的最小验证集；缺少资源管理能力时如实保留未完成项，不默认机器资源无限，也不降低业务断言或用强制退出制造通过。

### 异步与并发

用自动等待、事件或有界轮询读业务终态；网络空闲不是长轮询应用的通用就绪条件。轮询等待只能观察，不能每次轮询重复提交业务动作。

并发正确性测试用可控屏障/协调机制让竞争窗口实际发生，断言最终数量、版本或状态不变量；两次串行请求不能证明并发安全。负载测试另用目标负载与稳定环境，不能拿功能测试通过替代容量结论。

### 本地与 CI 分层

下表说明测试组如何组织，不定义另一套必需检查集合或模式接口；项目已有命令优先，交付模式与放行判定来自 [验证入口规范](../../ai-verified-delivery/references/verify-and-templates.md)。

| 执行阶段 | 常见组合 | 边界 |
|---|---|---|
| 编辑反馈/quick | 受影响快速规则与组件、适用静态检查 | 反馈快，不代表整体需求完成 |
| 合并前/change | 既有快速回归、受影响真实集成、核心链路与构建 | 必需测试失败或缺失不能合并为通过 |
| 定时或专项 | 较长多浏览器、广泛回归、适用性能/安全 | 用于扩展反馈；本次必需专项不能一律推迟到定时任务 |
| 发布/release | 拟发布制品启动、关键链路、适用迁移/恢复 | 检查配置和制品身份，开发服务器通过不代表生产制品通过 |

真实集成可以慢，也可以有隔离副作用；它可以放在单独 CI job，但仍由完整验收汇总阻断。把快慢分离误解成“有副作用测试永远不进门禁”会漏掉权限、持久化与恢复风险。

统一入口使用项目真实命令，清楚列快速/完整模式和适用组，将各组退出码、报告与实际测试数交给上述汇总入口；本文件不另维护零用例、跳过、版本与重试的放行政策。

Windows 与 Linux/macOS 使用对应运行时和已有包管理器脚本；不为了编排强制 Windows 安装 Bash。CI 选择实际部署/支持平台，路径大小写、换行、时区与中文字体按相关风险验证；不默认要求所有项目跑三系统矩阵。下载受阻时按可用 network-access 指引核验路线，不修改全局配置或关闭 TLS 来凑通过。

### 不稳定测试与维护责任

首次失败、重试成功也保留首败日志与次数，排查等待、状态泄漏、随机性、并发与环境。重试可用于诊断或明确瞬态环境恢复，不能无限重试到绿。确需隔离不稳定用例时记录负责人、影响、修复安排与必要替代验证；是否影响放行统一按上述验证入口政策判定。

测试与模块由相应变更者共同维护，跨模块/关键链路明确负责人。审核重点是业务断言、数据隔离、真实与替身边界和契约变化。覆盖率用于定位分支缺口，阈值沿用项目政策，调整需说明；不设行业通用 80%/100% 门槛。

观察逃逸缺陷、执行耗时、不稳定率与维护成本。高维护低信号的测试可以重写、下沉或在保留必要覆盖后删除；追踪覆盖去了哪里，不删除失败用例来洗绿。旧测试体系扩展优先级为本次风险、高频缺陷、共享契约及核心纵向链。

## 自动化截图与 Agent 视觉验收

本规范定义 Web/UI 任务如何让 Agent 代替人进行一次初步的视觉与交互结果检查。它与 [Web 验收](web-acceptance.md)配套：Playwright 或其他浏览器工具先执行可自动断言的用户动作和业务状态，只有通过或需要诊断时才采集关键截图；Agent 实际查看截图，按 AC 和用户任务判断界面是否合理。截图不是存档，也不是简单的图片处理或像素相似度比赛。

Agent 的视觉检查关注“用户看到并操作到的结果”，例如按钮是否响应、弹窗是否出现且可关闭、关闭后焦点和页面状态是否正确、按钮/文字/表格是否挤压或被遮挡、不同宽度下操作区是否仍可用。它是快速、可重复的初步验收；产品/设计人员仍负责明确的审美取舍、业务批准和高风险放行。

### 视觉检查触发决策

截图和 Agent 视觉理解是按变更风险触发的检查，不是每次提交的固定仪式。先判断变更是否可能改变用户看到或操作到的结果：

| 变更类型 | 典型例子 | 自动化要求 | Agent 截图要求 |
|---|---|---|---|
| 纯文档/注释 | README、代码注释、开发文档 | 格式、链接或文档检查 | `N/A`，记录不涉及 UI |
| 纯文案且几何不受影响 | 不改变长度/换行/状态的错别字修正 | 静态检查；必要时运行受影响的文本断言 | 默认 `N/A`，说明“文案-only、无布局/交互影响” |
| 文案可能改变几何 | 按钮、导航、表头、错误提示、中文/英文切换 | 受影响组件渲染或针对性 E2E | 至少检查受影响状态；若溢出/换行/挤压风险已由自动化充分断言，可免完整截图但要记录理由 |
| 样式/布局/响应式 | 间距、宽度、字体、断点、网格、sticky、主题 | 受影响入口和边界 viewport 自动化 | Agent 查看关键状态截图；必要时多 viewport |
| 交互/状态/弹层 | 按钮 handler、弹窗、抽屉、菜单、toast、加载/错误态 | 先跑完整用户动作、终态、关闭/取消/Esc/焦点断言 | Agent 查看动作后的关键截图，检查可理解性、遮挡、挤压和继续操作能力 |
| 新页面/关键旅程 | 新功能、跨模块流程、权限或高风险路径 | 完整关键旅程和错误路径 | 按 L3/L4 要求执行截图、trace 和复核 |

“小改动”不能只按文件数量或 diff 行数判断。若文案、CSS、DOM 层级或事件处理可能改变布局、可见状态、焦点、弹窗或操作路径，按较高一行处理。免截图必须在报告中写明变更类型、未覆盖风险和实际替代检查；不能用 `N/A` 隐藏未运行的必需视觉检查。

### 两阶段验收顺序

1. **自动化事实阶段**：先用 Playwright 等工具从用户入口执行点击、填写、提交、取消、关闭、后退、刷新和等待；断言 URL、可见状态、业务结果、错误归宿、焦点回归和数据变化。能在此阶段确定的失败必须先修复，不要用截图掩盖或替代自动化断言。
2. **Agent 视觉理解阶段**：自动化通过后，在已知路由、角色、数据、状态和滚动位置采集最少的关键截图；Agent 打开并查看图像，判断几何、可见内容、响应式、层级和交互结果是否符合 AC。截图只检查自动化无法充分表达的呈现和用户可理解性。

自动化失败时仍可保留失败截图或 trace 供定位，但该截图只能作为诊断证据；对应 AC 必须为 `FAIL` 或 `BLOCKED`，不能因“截图看起来正常”而通过。没有实际打开截图的 Agent 不得填写视觉 `PASS`。

### 1. 适用性与等级

| 等级 | 最小要求 |
|---|---|
| L0 | 不适用时记录理由；文档不得声称已完成视觉验收 |
| L1 | 受影响页面在目标 viewport 渲染一次；存在视觉 AC 或布局变化时保存截图，否则记录视觉验收 `N/A` 的理由 |
| L2 | 先执行受影响用户路径；仅当触发决策命中视觉/交互风险时截图并由 Agent 查看；有视觉 AC 时逐项关联证据 |
| L3 | 关键用户旅程覆盖承诺的 viewport/浏览器；保存截图、trace 和视觉报告；视觉基线变化须复核 |
| L4 | L3 全部要求，加多浏览器/高风险状态、干净环境制品和产品验收；基线或支持范围变更须按发布规则审批 |

工具未安装、浏览器未启动、字体缺失或截图未生成时，必需项为 `NOT_RUN`/`BLOCKED`，不能改写成 `N/A` 或 `PASS`。

### 2. 截图采集协议

自动化测试在截图前必须记录或固定：

- 源码/制品版本、浏览器版本、OS、字体、色彩模式、缩放和 `deviceScaleFactor`；
- viewport 宽高、设备方向、语言、时区、reduced-motion 和主题；
- 用户角色、前置数据、路由、网络/接口状态和要检查的 AC；
- 页面达到业务就绪条件的证据。网络空闲或固定 sleep 不能代替业务就绪条件；
- 截图类型：viewport、元素、滚动位置或 full-page。sticky、吸底和滚动状态必须在真实滚动位置截图，不能只用 full-page 图推断。

每个截图至少应有稳定的 `screenshotId`、AC 编号、场景名、viewport、状态和文件路径。日志、截图、视频和 trace 写入运行专属目录，并与验证 manifest 的 `runId`、输入指纹和制品关联。运行产物不应覆盖基线，也不默认提交源码仓库。

### 3. Agent 视觉检查协议

Agent 只有在实际打开并查看截图后，才能报告视觉结论。DOM、CSS、测试断言、截图文件存在或模型生成的文字摘要不能替代图像检查。每个视觉 AC 按以下顺序记录：

1. **状态核对**：截图是否是目标路由、角色、数据、主题、加载/错误/空状态和滚动位置；状态不符时停止判定并标 `BLOCKED`。
2. **交互结果核对**：根据自动化动作检查按钮/链接是否呈现正确结果，弹窗、抽屉、菜单、toast 或错误提示是否出现；检查关闭、取消、Esc、点击外部后的实际终态、焦点回归和页面是否可继续操作。
3. **几何核对**：检查裁切、重叠、溢出、横向滚动、错位、遮挡、sticky/fixed 覆盖、弹窗边界、按钮挤压、文字截断和触控目标。
4. **内容核对**：检查文字是否完整、换行是否合理、数字/标签/错误信息是否与 AC 和 Test Oracle 一致；截图不能证明不可见的业务数据正确。
5. **响应式核对**：比较约定 viewport 和断点边界，检查布局收纳、操作区、表格、弹窗、滚动容器和方向变化。
6. **视觉核对**：检查层级、间距、对齐、状态色、焦点、对比度、字体实际渲染和设计约束；只把产品/设计明确承诺的差异判为失败。
7. **结果记录**：对每个 AC 输出 `PASS`、`FAIL`、`NOT_RUN` 或 `BLOCKED`，附自动化结果、截图路径、观察到的事实和必要的复现步骤。

Agent 不得仅凭“截图看起来正常”、文件存在、像素相似度或自动化扫描分数通过。像素差异是定位信号；动态时间、随机数据、字体抗锯齿或平台差异应在测试设计中解释，而不是批量接受基线。Agent 也不得把 DOM/CSS 推断当作已经看到的视觉事实。

### 4. 视觉报告模板

```markdown
## Visual Review <runId>
- source/artifact: <revision or artifact id>
- browser/OS/fonts: <versions>
- viewport/config: <width x height, scale, theme, motion>
- scenario/state: <route, role, data, scroll position>
- screenshots: <paths and screenshot IDs>
- trace/video: <path or N/A>
- automation: <command, result, key assertions>

| AC | 检查事实 | 证据 | 状态 |
|---|---|---|---|
| AC-UI-01 | <无裁切/无重叠/内容正确> | <screenshotId/path> | PASS |

未覆盖或阻塞：<原因>
视觉差异与处理：<缺陷、基线变更理由或 N/A>
复核者：<Agent/人类、上下文和时间>
```

`PASS` 必须同时有自动化用户动作/断言通过、正确状态、Agent 实际查看的截图和可定位观察。截图缺失、状态错误、自动化失败、Agent 未查看、报告缺字段或版本不匹配时不得为 `PASS`。

### 5. 视觉基线与变更门禁

- 首次建立基线前由主代理或指定复核者实际查看图像，对照需求与设计依据判断正确性；不能仅从当前输出自动生成基线就认定正确。独立复核可按需增强，必要人工验收按明确约定执行。
- 更新基线必须说明受影响 AC、原因、旧新截图、环境差异和复核者；禁止用批量接受隐藏布局回归。
- 行为、规格、浏览器支持范围、字体、主题或关键 CSS 改变后，相关截图和视觉报告失效并须重跑。
- 视觉快照通过不代表业务通过；仍需执行用户旅程、数据、权限和错误路径断言。
- 人类产品/设计验收与 Agent 检查分开记录；缺少必要人类判断时，交付最多为 `PARTIAL`。

### 6. 常见拒绝条件

| 情况 | 结论 |
|---|---|
| 只生成截图，没有查看或报告 | `NOT_RUN` |
| 只检查 DOM/CSS，没有图像证据 | 视觉 AC `NOT_RUN` |
| 只看 full-page 图判断 sticky/滚动状态 | 视觉 AC `BLOCKED` |
| 截图来自错误角色、数据或版本 | `BLOCKED`，证据失效 |
| 像素差异被无理由批量接受 | `FAIL` 或 `PARTIAL` |
| 自动化通过但内容、权限或业务终态错误 | 对应 AC `FAIL` |

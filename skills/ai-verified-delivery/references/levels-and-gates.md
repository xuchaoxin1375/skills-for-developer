## 定级、风险与质量门

### 唯一等级矩阵

**这是类型下限、验收等级与检查组合的唯一维护位置。**正文、验证入口和提示模板引用本表，不另建一套分级。等级是本 skill 的项目政策，不是行业统一标准，也不等同于 OWASP ASVS 的安全等级。

高等级继承低等级中适用的检查；“适用”依据产品承诺、实际影响面与约定支持范围，不依据工具是否已安装。纯静态或本地存储产品按自身存储模型验收，不强行增加服务器或数据库。

| 类型与最低等级 | 变更范围 | 规格与记录 | 必需验证 | 复核与交付 |
|---|---|---|---|---|
| T0 / L0 | 无运行时影响的文档、注释、说明修正 | 一句话范围与证据记录 | diff、格式、相关链接与内容一致性；修改可执行命令时在授权的隔离条件下验证 | 证据核对；无需新增行为测试或浏览器检查 |
| T1 / L1 | 单页文案、颜色、局部无状态样式及表现微调 | 简短范围、预期结果、影响面 | 适用静态检查与构建；受影响页面浏览器渲染、布局及相关交互；已有相关测试 | 局部视觉/键盘检查；一般不要求独立会话或全量 E2E |
| T2 / L2 | 局部逻辑、表单规则、单组件行为、普通缺陷修复 | 编号 AC、tasks、影响面与精简 RTM，可合并一份记录 | L1 适用项；全量既有快速单元/组件测试；受影响模块集成与边界/错误路径；改动主路径及相关关键旅程冒烟；生产构建；覆盖率门槛沿用项目政策 | 独立只读复核；涉及 UI 时预览冒烟；人工实操按不可自动判定的 AC 要求 |
| T3 / L3 | 普通新功能、新页面/用户故事、跨模块调整、共享状态/路由/API 契约变化、关键依赖升级 | spec、tasks、测试计划与 RTM，含非目标及恢复设计 | L2 适用项；受影响模块完整回归、系统关键旅程和全部必需 AC；承诺范围内的多浏览器、视觉/可访问性、契约、依赖与性能专项；涉数据验真实持久化与恢复 | 独立复核；用户关键旅程人工实操及不可自动判定 AC；生产制品运行验证；发布任务另验准备条件 |
| T4 / L4 | 大型新功能、鉴权/授权核心、支付、敏感数据边界、破坏性迁移或重大部署架构改动 | L3 记录及适用威胁模型、迁移/恢复与发布计划 | 全量适用回归；按风险选择安全、负载、并发、故障恢复、迁移演练；干净环境中验证拟交付制品；发布时验证回滚/恢复与冒烟 | 独立复核与产品验收；高风险正式放行/发布须双人或跨角色审批，按项目责任规则执行 |

**分级顺序：**

1. 依据变更行为选类型下限，取命中项最高等级。几行鉴权代码仍可能 L4；全局样式不是单页 L1。
2. 分析共享组件、API、数据、权限、路由、配置、依赖和部署的影响。路径/扩展名规则只能给建议，不能代替行为判断。
3. 不确定时先调查，仍无法界定则按较高等级计划；存量不规范不自动证明业务高风险，也不能成为降低检查的理由。
4. 实际范围扩大时重新定级；风险评分只能提高类型下限。不能因工具缺失或怕测试昂贵降低等级。
5. 若用户明确改变需求范围或等级政策，记录新旧范围、理由与剩余风险；保留原未执行事实，不能回写成通过。

矩阵把非运行改动与局部表现改动分开。其他材料中的 A0–A4、L0–L3 或“新功能最低 L3”不可按标签直接套用，先按本表的行为和影响范围重新归类。

### 风险评分

复杂或边界不明时可用 `R = 3Sec + 3Data + 2Blast + 2Crit + 2Contract + 2Novel + UX + Recover` 复核。每项 0–3 分，取值须说明依据；这是启发式辅助，不用平均分冲淡高风险触发项。

| 字段 | 含义 | 0 分示例 | 3 分示例 |
|---|---|---|---|
| Sec | 安全、隐私与合规 | 静态说明 | 登录授权、支付、敏感信息 |
| Data | 数据状态与迁移 | 不改变数据 | 不可逆迁移、批量更新 |
| Blast | 影响范围 | 单一内部页面 | 全用户、公共组件、核心入口 |
| Crit | 业务关键程度 | 辅助信息 | 登录/交易不可用、数据丢失 |
| Contract | 接口、事件、依赖兼容 | 无契约变化 | 公共 API 或消息格式变化 |
| Novel | 新颖性与不确定性 | 成熟既有模式 | 新技术、未知依赖、关键需求含糊 |
| UX | 交互、兼容与可访问性复杂度 | 无 UI 变化 | 多端复杂交互、输入法、拖放 |
| Recover | 恢复难度 | 可立即关开关 | 状态不可逆、无可验证恢复 |

分数建议：0–6 为 L0，7–14 为 L1，15–24 为 L2，25–34 为 L3，35–48 为 L4。最终等级取类型下限、明确风险触发与评分建议的最高值。低风险任务无需为了填报告计算分数。

例：管理员账户管理的 Sec3/Data2/Blast2/Crit3/Contract2/Novel1/UX2/Recover1 得 R=34，但涉及授权核心时按类型下限定 L4。

### 准入与完成条件

**准备就绪定义(DoR，Definition of Ready)**：目标与非目标明确，必要用户/角色、输入输出、状态、数据约束、正确结果依据、测试条件和关键未决问题有归属。缺少关键结果依据时先澄清，仍可继续不依赖它的工作。

**完成定义(DoD，Definition of Done)**：必需范围覆盖、行为与数据符合承诺、适用回归通过、交付能运行、证据对应最终版本、无未解决阻断缺陷。必要人工验收有事实记录，已实现/已验证/已批准/已部署分开报告。

**测试预言(Test Oracle)**是正确结果的独立依据，可来自需求、协议、确认样例或既有行为契约。RTM 中引用该依据；用实现输出生成预期输出会形成自证循环。测试名含 AC 编号只是关联线索，不证明断言实际验证了该要求。

### 流程检查点 G0–G13

这些检查点用于追踪适用流程；纯咨询不跑实现和发布步骤，未授权发布不执行。

| 检查点 | 判定内容 |
|---|---|
| G0 任务准入 | 目标、用户结果与工作模式 |
| G1 基线 | 源码、工作区、已有失败、运行条件 |
| G2 定级 | 本矩阵的类型下限、影响面与等级 |
| G3 规格 | 范围、非目标、编号 AC、正确结果与预算 |
| G4 影响分析 | 组件/接口/数据/权限/配置/构建/部署 |
| G5 测试计划 | 必需 AC 各有验证方式与证据归属 |
| G6 工具预检 | 实际可用性、已有授权、缺口 |
| G7 切片实现 | 用户闭环、局部验证与交接 |
| G8 静态验证 | 项目适用静态检查、构建与完整性 |
| G9 动态验证 | 适用单元/组件/集成/E2E 与版本一致证据 |
| G10 独立验收 | 所需复核、人工判断、未声明变更 |
| G11 发布准备 | 发布任务的制品、配置、兼容、监控与恢复 |
| G12 发布后验证 | 实际部署版本的冒烟、指标与日志 |
| G13 闭环 | 逃逸原因、回归用例、门禁/规则改善 |

### 测试设计方法

| 方法 | 适用目的 |
|---|---|
| 等价类与边界值 | 空值、最大/最大+1、分页、编码和合法/非法类别 |
| 决策表与状态转换 | 角色×资源×操作、不同模式迁移、忙态与重复提交 |
| 负面测试 | 超时、离线、过期、冲突、无权限与错误恢复 |
| 属性/差分测试 | 序列化往返、重构行为保持、关键算法的独立参照 |
| 故障注入 | 提交后响应丢失、部分失败、乱序、重试与一致性 |
| 变异或失败样例 | 关键回归断言、空集风险、新增门禁是否真的拒绝错误 |
| 探索性测试 | 连击、后退、刷新、切账号及规格遗漏 |
| 威胁建模 | 高风险访问控制、注入、敏感数据及跨租户边界 |

在最低有效层验证规则和数据；E2E 证明用户链路。覆盖率不是需求完整率，断言数量不是有效性；避免过度 mock 被测逻辑。新门禁和高风险回归要证明错误情况下会失败，不要求每个低风险新断言逐个变异。

Web 状态、权限、截图及交互清单见 [Web 验收](web-acceptance.md)。

### 工作流评估与规则依据

用固定任务检验虚假完成率、AC 覆盖、逃逸缺陷、误阻断、不稳定测试、修复轮次与每等级成本。重要基准多次运行取分布；看最终环境和证据，不能按总结文字评分。

代表任务包括纯文档、局部 UI 微调、分页 bug、跨层新功能、越权修复、迁移、工具缺失、无凭据阻塞，以及用户授权跳过检查。最后一种应记录未运行与证据缺口，遵循授权，不能伪造通过或用 skill 覆盖用户指令。

设计参考来自 *AI coding 工程质量约束方案与测试验收指南* 的 fable5.1、fable5.1-2nd、gpt5.6sol、gpt6astra、gpt6.1sol、fable5.1-3rd 版本。它们提供设计建议，不作为本项目已执行证据，也不混用各自等级。

三条证据约束针对材料中明确描述的失败模式：只断成功提示而不核结果、测试后改代码却沿用旧报告、零用例/跳过仍显示绿。新增门禁时用失败样例实证拒绝能力；本文件不声称这些参考示例已在具体仓库运行。

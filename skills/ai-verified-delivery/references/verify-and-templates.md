## 验证入口、证据与交接模板

### 统一验证入口契约

检查组合只来自 [唯一等级矩阵](levels-and-gates.md)。优先沿用现有项目命令与运行时；Node 适合已有 JS/TS 项目，Python 或其他已有运行时同样可用。Windows 原生环境不要为了编排检查强制引入 Git Bash。

建议由项目实现 `verify --level Lx --base <base-ref> --spec <spec-path> --tasks <tasks-path>`。这是接口约定，不是现成软件；文档应填实际可运行的项目命令。快速检查、变更验收、发布验收可以是同一入口的不同模式，共享检查政策。

| 参数或模式 | 语义 |
|---|---|
| `--level` | 指定等级；核对实际影响面与类型下限，非法值拒绝，缺省遵循明确项目政策 |
| `--base` | 本次完整变更的基准；任务起点或目标分支，不在每次提交后重置而遗漏此前改动 |
| `--spec`、`--tasks` | 读必需 AC、任务和验证映射，引用约定范围 |
| quick | 切片反馈；即使通过也不代表整个变更验收完成 |
| change | 汇总本次全部必需检查与证据 |
| release | 对约定拟发布制品和环境运行发布级验收 |
| `--allow-open-tasks`(若实现) | 只允许阶段检查点，不改变完整交付条件，也不能跳过必需 AC |

本地完整差异至少涵盖基准后的提交、暂存、未暂存及未跟踪文件。先用版本控制识别各类路径，再计算实际输入指纹；仅 `git diff <base>...HEAD` 不覆盖工作区。记录删除、重命名和新增，不把提交前检查的 `HEAD` 差异当成整个变更。

入口输出机器可读汇总并正确传播失败退出码，至少包含等级、工作模式、必需检查集合、逐项状态/用例数/尝试次数/退出码/报告位置、输入与制品标识、交付结论。禁止用 `--if-present` 或吞退出码隐藏必需脚本缺失。合法的“无匹配项”需定性，不能把所有 `|| true` 关键词都当缺陷。

### 汇总器默认拒绝缺证据

预期检查集合从冻结的 AC、等级矩阵、实际影响面和项目支持政策生成，不能由本轮“实际跑了什么”反向生成。每项测试组及必需 AC 均有真实执行记录；人工 AC 有场景、操作者、版本和结论。

| 输入情况 | 汇总判定 |
|---|---|
| 必需项运行且结果、报告和版本有效 | 该项 `PASS` |
| 必需项运行失败、取消或超时 | 该项 `FAIL`，保留日志与尝试记录 |
| 必需项未运行、缺工具/权限 | `NOT_RUN` 或 `BLOCKED`，总体不能 `VERIFIED` |
| 必需测试组收集零用例 | 拒绝通过；不能把空报告当成功 |
| 必需 AC 的用例缺失或全部跳过 | 拒绝通过，即使其他组运行了很多测试 |
| 必需报告缺失、格式损坏或只有旧报告 | 拒绝通过；记录缺口或无效证据 |
| 报告源码、测试、配置、制品或环境不匹配 | 证据过期，重验相关范围 |
| 重试后才成功 | 标注不稳定(Flaky)，保留首次失败；核心必需路径默认不放行，例外需项目政策与替代证据 |
| 专项确实不适用 | `N/A` 并说明理由；无工具不属于不适用 |
| 用户明确授权跳过必需项 | `SKIPPED`，记录授权及后果；不能写 `PASS`，默认 `PARTIAL` |
| 非阻塞建议尚未完成 | 记录后续安排，不自动阻止已满足的必需范围通过 |

GitHub Actions 等平台可能允许跳过或中性状态的检查满足合并规则。若使用 `always()` 汇总，仍要校验 `needs` 中各必需任务的真实结果和对应报告；只加 `always()` 不构成可信门禁。测试总超时要比外层任务超时短，为报告上传与清理留出时间。

已执行且存在未解决阻断失败时总体 `FAILED`；关键前置不足时 `BLOCKED`；剩余未完成或缺证据为 `PARTIAL`；所有必需条件满足才 `VERIFIED`。分项状态使用 [正文状态定义](../SKILL.md)，不要只用 pending/passing。

### 门禁自身的失败路径验证

新增或修改汇总器、过滤器、测试发现/报告解析、版本校验及必需集合时，在隔离环境验证拒绝能力。不要为了测试门禁修改用户生产数据；小范围变更选相关反例，完整新门禁覆盖下表。

| 反例 | 应观察到的结果 |
|---|---|
| 合法且版本匹配的完整报告 | 可通过，证明不是永远失败的假门禁 |
| 空测试组/错过滤标签 | 非零验收退出码，指出零用例 |
| 必需组全部跳过；其余组正常 | 拒绝必需场景缺失 |
| 上游任务失败，汇总任务仍运行 | 不因汇总任务启动成功洗绿 |
| 删除或截断必需报告 | 拒绝缺失或损坏报告 |
| 用旧源码/旧制品报告替换当前报告 | 版本校验拒绝 |
| 测试后新增文件、改暂存/未暂存输入 | 指纹失效，不遗漏未跟踪文件 |
| 首次失败、重试成功 | 标明不稳定，按既定政策处理 |
| quick 通过但还有必需 AC 未完成 | 只能作为检查点，不是完整交付通过 |

这些是门禁的行为验收，不是对文档措辞的匹配测试。关键回归断言可通过修前失败、受控错误输入或变异验证可证伪性；无需给每个普通断言增加逐条造错仪式。

### 证据版本与保留

证据 manifest 记录最终输入及运行身份，不只记录 commit。所需字段按任务存在与否填写，不存在制品的纯文档任务无需编造构建标识。

| 字段 | 内容 |
|---|---|
| `runId`、时间 | 唯一运行身份、开始/结束，避免覆盖前次失败 |
| `sourceRevision`、`baseRef` | 当前提交/源码标识与完整变更基准 |
| `inputFingerprint` | 被验源码、测试、门禁脚本、规格、配置及锁文件的内容指纹；覆盖工作区新增/删除 |
| `acceptanceScope` | 必需 AC、检查组、等级与支持范围 |
| `artifactId` | 验证的构建/镜像/包标识或摘要；无制品时说明不适用 |
| `environment` | OS、运行时、浏览器/工具版本、字体、服务和测试数据版本；敏感内容脱敏 |
| `results` | 分项结果、执行数、跳过数、尝试次数、退出码和报告引用 |
| `review` | 必需复核记录及其对应版本 |

生成报告/截图本身不应导致输入指纹无限失效；先定义输入集合，排除运行产物，保留测试、规格和验证配置。用摘要记录配置身份，不能把口令、令牌或真实用户数据写进 manifest。

修改相关输入后旧证据失效；有可靠依赖映射时重跑受影响检查，并确认最终必需集合都对应当前输入。修改公共配置、依赖、门禁或影响面不明时扩大重验。**哈希一致仅证明版本对应，不能证明测试覆盖完整或报告可信。**正式门禁与必需集合按项目保护策略控制，不能由实施者单方面篡改后自证。

日志、截图与 trace 写入运行专属目录或临时制品目录，纳入 CI artifacts/约定保留介质；临时路径须有保留与清理约定，不能报告一个交接前就消失的证据位置。测试脚本入库，运行产物不默认提交。

### AGENTS、tasks 与 RTM

`AGENTS.md` 保持简短入口：实际命令、架构与权限边界、等级矩阵位置、完成条件和任务资料索引。确认所用工具实际读取，不因为文件存在就假设生效。

任务按用户结果拆分：任务编号、目标、关联 AC、依赖、验证命令、证据、状态。同时聚焦一个切片；允许跨文件联通链路。弱模型使用预拆任务与精确命令，但单文件改动不是完成单位。

**需求追踪矩阵(RTM，Requirements Traceability Matrix)** 每行至少包含：

| AC | 必需性 | 正确结果依据 | 实现位置 | 验证场景/测试 ID | 证据与版本 | 状态 |
|---|---|---|---|---|---|---|
| AC-01 | 必需或非目标理由 | 需求/协议/确认样例 | 文件、接口或配置 | 可观察结果的验证方式 | 运行编号、报告、输入标识 | 使用正文的逐项状态 |

任务勾选不等于测试通过。可用复选框展示，但权威记录要区分已实现待验与已验证；跳过、阻塞不能落成完成勾选。新测试无需逐项审批；修改行为契约、黄金数据、门槛或必需集合需按项目规则说明与复核。

### 检查点、交接与恢复

中断前保留最小可恢复记录，使用项目已有 progress/handoff 文件或任务状态文件，不要求同时维护多份重复事实。

| 交接字段 | 内容 |
|---|---|
| 任务身份与范围 | 变更 ID、原始目标、AC、非目标、等级 |
| 当前输入 | 源码标识、完整 diff、用户已有修改与新增文件 |
| 进度 | 已验证、已实现未验证、未实现、阻塞，分别列出 |
| 最近验证 | 运行编号、对应输入、命令/退出码、报告、已有失败 |
| 运行条件 | 启动方式、服务/端口与临时配置、测试数据建立/清理、凭据获取方式(不写密钥) |
| 下一步 | 精确复现/执行命令、所需授权或条件、修复预算 |

恢复顺序：

1. 读原始需求、项目规则和交接；核对实际工作区，不覆盖用户新增修改。
2. 比较当前输入与最近证据；先区分历史失败、本次失败和证据过期。
3. 运行必要环境预检；重验相关过期证据，确认当前可运行状态。
4. 从明确未完成的 AC 继续，更新唯一进度记录；范围扩张时重定级。

预算不足时保存检查点，不开大范围重构；同方法连续失败先诊断与升级。不能因为达到任意固定重试次数就丢下可继续的独立工作，也不能以请求确认替代已有授权内的下一步。

### 钩子与工具准备

PostToolUse 等编辑钩子只做快速反馈；较昂贵检查放阶段/停止或 CI。具体事件、输出协议、超时和阻断退出码依 harness 版本适配，不把某平台的 `stop_hook_active` 视为跨平台契约。

钩子即使为避免死循环允许停止，也必须留下未通过状态；“允许结束会话”不等于“验收通过”。活跃任务显式指定，不任取第一个变更目录；等级缺失先查明，不能默认低等级。钩子不是安全隔离，也不替代合并保护。

`doctor` 默认只探测，不用可能自动下载的命令当无副作用检查。检查项目运行时/锁文件、实际工具启动、浏览器二进制、服务/测试账号/数据源和报告可写性。版本命令或缓存目录存在不能证明完整运行能力；执行一次最小启动/健康检查。

工具选择优先复用已有框架，其次补齐能力；安装前核对已有授权。若需额外授权，申请包含缺失 AC、真实错误、方案与版本、精确命令、来源、影响文件/系统、网络权限、替代方案和撤销方式。获得授权后安装并实跑最小用例，把依赖固化到配置与锁文件。浏览器受阻读 [环境准备](playwright-setup.md)。

### 弱模型执行提示模板

项目应把尖括号替换为真实任务和命令；不要固定写 L1 而覆盖实际任务等级。

```markdown
执行 <任务编号> 对应的用户切片，读取 <规格与交接位置>。
先核当前差异、影响面、验收结果依据和 <实际等级>；保护用户修改。
缺陷先运行 <复现命令>，保留失败证据；实现后运行 <针对性验证命令>。
记录已实现未验证与阻塞，不因为写完一个文件就勾选整项完成。
结束切片后按 <统一入口> 运行对应检查，保存版本与报告。
如果缺权限或重复失败，先诊断并保留准确下一步；继续独立工作。
全部必需 AC 与最终门禁满足后才报告 VERIFIED；提交/发布另按授权执行。
```

### 持续改善与落地

先确定 AC/完成条件与等级，再复用或建立最小 verify/doctor，打通真实关键旅程，随后接入 CI 汇总、复核及适用发布专项。可以分阶段建设，但正在交付的必需条件不能借“还没建设”静默删除。

每个逃逸缺陷问“哪层本应拦住，缺的是要求、测试、环境还是证据”，优先补回归或可执行检查，再决定是否需要通用规则。跟踪误阻断、不稳定测试、虚假完成、逃逸率与耗时，避免只靠增加正文长度改善流程。

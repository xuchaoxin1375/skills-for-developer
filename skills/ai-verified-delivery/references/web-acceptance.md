## Web 验收与环境证据

只在 Web 交互、布局或部署任务中读取。检查强度来自 [唯一等级矩阵](levels-and-gates.md)，场景选择来自必需 AC 与影响面；局部改文案不要求横扫整个应用，大范围交互改造再扩大入口覆盖。

### 用户路径与状态计划

按“入口×动作×预期出口”列验证矩阵，用户原话描述的路径必须有归属。优先卡死、白屏、丢数、关不掉、模式不生效等阻断体验，再扩展其他场景。测试围绕用户结果，不只断言组件内部变量或成功 toast。

| 维度 | 需审视的场景 |
|---|---|
| 入口与导航 | 真实导航入口、路由注册、直接 URL、深链接刷新、前进/后退 |
| 状态 | 初始、空数据、加载/忙态、成功、部分结果、错误、超时、离线、重试、取消 |
| 数据 | 边界值、中文/长文本/特殊字符、输入法组合、刷新/重新登录、重复提交、冲突 |
| 权限 | 未登录、过期、不同角色、资源隔离、绕界面直接调用 API |
| 交互 | 键盘、焦点、触控、窄屏/宽屏/缩放、遮挡与滚动 |
| 集成与发布 | 自有 API、实际存储模型、配置、环境变量、生产资源路径和可运行制品 |

每项映射到 AC、相关检查或有理由的非目标；不能因缺工具而标不适用。无需机械枚举所有状态×宽度×主题的笛卡尔积，但共享或变化多的组件应覆盖高风险组合及断点边界。

有后端的产品至少保留改动关键旅程连接自有真实测试 API 和隔离数据源；纯静态/本地存储产品按承诺模型验。Mock 用于可控故障与局部行为，不能证明真实后端权限、持久化或一致性。

### 分层验证与断言有效性

- 单元/组件测规则、状态与边界；真实 API/数据库集成测权限、幂等、原子性和持久化；浏览器测用户闭环。避免全部问题堆到 E2E。
- 对关键动作跟随结果断言，准备步骤可按阶段合并。状态、网络、视觉、下载内容、剪贴板或焦点都可能是结果；纯路过截图不能证明业务结果。
- 空集合上的全称断言先加非空守卫；如果场景本来就是空态，则断言空态本身。外部只读环境缺所需数据时记录该场景未验证，不能无声跳过后判完整通过。
- 关键回归与易空跑断言用修前失败、受控错误或变异证明可证伪。悬停先建立未悬停状态；原生 dialog、下载与异步事件先建立监听，再触发动作。
- 状态映射采用枚举或精确匹配；确需子串匹配时先排否定项，避免“未完成”被识别成“完成”。
- 断言快照覆盖被测维度；截图前后确认目标仍处于预期状态，状态等待使用自动等待/轮询，不靠随意固定 sleep。

### 弹窗、忙态与模式迁移

| 场景 | 需证明的结果 |
|---|---|
| 确认 | 校验成功时到约定终态；校验失败时可保持打开并显示错误，不强制关闭 |
| 取消 | 弹窗本体关闭或达到明确约定终态，不提交业务操作 |
| Esc 与点外部 | 各自符合产品约定；关闭时语义等于取消，不能触发提交；禁止关闭时断言保持与原因 |
| 出现/退出、展开/收起 | 过渡中与稳定状态没有关键内容闪失、遮挡或焦点遗留 |
| 耗时动作 | 可感知忙态，重复操作受控，成功/失败后恢复；按设计验证禁用、提示或进度，不强制特定文案 |
| 模式/档位切换 | 覆盖相关 A→B、B→A 与保持；不能只测稳态 |
| 先应答后生效 | 响应后的真实终态可读回；中间“已接受”不等于已生效 |

弹窗断言先确认本体与实际业务终态；toast、剪贴板等副作用不能替代关闭/保留断言。提交链按产品承诺检查填写、提交、任务结果和可见日志，不强制所有应用都有任务/日志模块。

新增入口检查真实 handler、路由可达和必要配置；批量交互改造可做全控件横扫。DOM 与网络变化是诊断线索，不是通用成功判据：下载、剪贴板或焦点动作没有 DOM/请求变化也可能有效；禁用控件应有可理解理由。

### 双通道错误与恢复

同时检查浏览器和服务端证据。未预期的页面运行错误、服务端异常、请求失败与静默空转应定性并阻断相关必需路径；可控制造的 5xx/异常需验证预期错误呈现与恢复，不能仅凭关键字出现就 FAIL。

测试日志区分预期注入、已知背景噪音与未预期错误，记录请求/运行关联；背景例外不得覆盖本次新增或阻断关键链路的异常。资源加载错误按实际用户影响判断，不能把真实资源缺失都归为噪音。

影响用户操作的后台失败须有用户可见归宿(任务日志、错误条或审计等约定方式)，不能只在开发者控制台输出。`except pass`/`catch {}` 等逐处判断，允许有理由的可选清理/日志守卫，关键持久化或轮询失败不可静默。

恢复测试关注数据是否半写入、输入是否保留、响应丢失后能否安全查询/重试、重复请求是否违反产品约定。直接调用 API 验权限，不能只验证按钮隐藏。

### 视觉证据与响应式结果

先定义相关状态、宽度、主题与浏览器矩阵，标明自动断言、实际目检和未覆盖。**断言通过不等于看过截图；截图也不能证明业务正确。**

- 称“已目检”须实际打开对应图并记录所见。交付回显关键截图及场景观察，其余图保留可访问索引；要求逐图审查时逐图展示，不用文件路径代替观察。
- 等页面/弹窗稳定、资源与字体就绪后截图；需要验证过渡时另留明确标注的中间状态，不能把中间帧误当稳定终态。
- sticky、浮层、遮挡用实际滚动位置的视口截图与几何/可见性断言；full-page 图不足以证明滚动行为。
- 视觉基线固定 OS、浏览器、字体和渲染条件；中文字体实际可用。接受新快照需说明设计变化，不能批量更新来洗绿。
- 验证显隐结果而非强制 CSS 特异性；检查相关宽度/状态的层叠组合，防有框无字。实现细节由前端与响应式 skill 管理。
- CSS、JS 与测试使用一致的产品断点语义，在边界两侧及等值验证互斥/叠加符合设计；媒体查询的包含关系不能靠猜测。
- 几何断言固定 viewport、缩放与字体条件，读实际计算尺寸并用合理容差；不用为测试强制产品尺寸全部写 px。有意延迟显形用轮询等待，改变默认态时补默认态回归。

### 环境证据分层

| 证据类型 | 能证明 | 不能单独证明 |
|---|---|---|
| Mock/客户端模拟 | 受控响应下的客户端规则与状态 | 真实服务器、权限、持久化 |
| 隔离环境真实集成 | 真实自有服务与隔离数据库的链路；可使用合成数据 | 用户现网旧数据、口令或部署配置 |
| 类生产制品验证 | 拟交付构建在约定配置中的启动、资源、迁移与恢复 | 尚未观察的目标生产实例 |
| 现网日志/只读观测 | 目标实例的实际错误与观察到的行为 | 未执行的写入链路或全面回归 |

合成数据与模拟后端是不同维度；真实数据库使用合成数据仍可提供有效集成证据。报告写明环境、数据与产品承诺的对应关系。

现网修复确认先利用用户提供日志，再按已有授权做最小观测；只读探针使用已确认无副作用的读取，不因 HTTP 方法是 GET 就假设无害。需要重启、写入或新增权限时遵循授权边界。脚本需要外部基址模式时明确只读能力，避免把测试数据注入用户实例。

用户现网错误不能被隔离环境全绿否定。**仅当任务要求现网确认时，缺现网证据才影响对应完成条件。**普通开发交付不强制访问生产环境；有数据依赖的现网场景未覆盖须如实记录，不靠条件跳过制造通过。

### Web 验收自检

- [ ] 用户原话路径、适用状态及相关入口各有 AC 或明确理由？
- [ ] 关键链路按真实存储与权限承诺验证，Mock 与集成证据分清？
- [ ] 核心动作有结果断言，空集有守卫，截图前后状态有效？
- [ ] 弹窗四种操作、迁移方向、异步终态与忙态符合产品约定？
- [ ] 预期故障与意外错误分开，用户可见失败及数据恢复已验证？
- [ ] 视觉矩阵已看/未覆盖诚实，稳定截图与滚动视口证据适用？
- [ ] 显隐、断点与几何验证的是设计结果，没有用实现限制替代验收？
- [ ] 证据环境与版本明确，现网任务未用合成全绿冒充确认？

证据版本、汇总器和交接使用 [验证入口与模板](verify-and-templates.md)，浏览器环境故障使用 [环境准备](playwright-setup.md)。

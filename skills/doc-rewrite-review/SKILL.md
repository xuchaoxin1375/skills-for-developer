## 文档改写与审校

目标是保留有效原意，修复理解、结构和事实上的缺口，让目标读者能完成约定任务。先判断输入与修改边界，再裁决内容；不把所有任务升级成合并、全篇教学重构或研究报告。

## 入口与按需参考

| 任务 | 采用的规则 |
| --- | --- |
| 单篇正文或系列改写、审校 | 本文的最短路径；大范围重构先简要说明读者、缺口、计划动作和风险 |
| 学习文档、教材或教程编写与改写，解释难懂或初学者卡住 | 编排前读[教学设计与理解对齐](references/tutorial-design.md)，按读者与目标选策略；通用教学规则在该文件维护 |
| 多源正文合并或目录级归属重整 | 编辑前读[合并流程](references/merge-workflow.md)，确认未定的形态、落点与命名 |
| 只改表现形式 | [markdown-style](../markdown-style/SKILL.md)，不擅自改观点或补内容 |
| 缺少影响正确性的外部依据 | [tech-learning-research](../tech-learning-research/SKILL.md)判断取证范围；已有充分材料不为形式重搜 |
| 项目文档集合、实现一致性与生命周期 | [project-docs](../project-docs/SKILL.md)及[文档与责任](../swe-gov/references/maintenance-and-feedback.md#文档与责任)，不另建治理规则 |

合并、排版和归档是阶段，不是重新启动整套任务的理由。教学参考可由其他skill直接采用，不附带本文的编辑审批、合并或落点流程。

## 最短工作路径

1. **确认范围**：区分建议与实际改写、单源与多源，复用已确认的受众、交付和文件位置。局部修改不重复索要完整审计表，不扩大到全仓排版或清理。
2. **读取与审计**：读授权范围的实际输入，识别目标、知识前提、事实、术语、结构与可运行示例的缺口。单源的大范围改写或教程扩写先给简短审计，明确读者、动作和风险；范围或关键意图含糊时再提问。
3. **裁决与编排**：按最终读者及成功判据安排主线。多源任务采用合并参考，普通任务不套合并表；已有唯一正本时优先修正，不默认新增副本。
4. **实质改写**：保留有效原意与独有细节，纠正有依据的错误，解释必要概念，补动作、结果与边界。无法核实的关键事实保留为待确认，不写成确定结论。
5. **验证与排版**：按任务执行适用的读者路径、示例、链接与结构检查，再采用[排版规范](../markdown-style/SKILL.md)。只复用形式规则，不把纯排版任务的“内容零改动”套到本次实质改写。
6. **交付**：按约定实际写文件或输出正文；文件交付给摘要与可定位路径，未运行和未覆盖项明确说明。默认沿用原文主语言，用户另有要求时优先；用户粘贴正文且未要求文件时，默认给改写正文。

## 内容裁决底线

- **准确优先于保留长度**：错误、过时或被明确取代的内容说明依据后改正；“保留原意”不是保留错误。真实分歧不能假装已统一。
- **范围优先于求全**：按成功判据保留必要内容，非主线细节分层；对授权范围内同类问题一致处理，范围外问题只报告，不因指出一处就擅改全文。
- **先查归属再复制**：结构重整涉及版本、安装、默认值或共享事实时，查相关已有描述，按文档与责任确定正本。短提示可就地保留，完整规则不多处维护。
- **解释服从读者**：正式、准确与易懂并行；不以行话代替解释，也不靠口语化或固定示例数量表示友好。不确定性说明条件和依据，不为避免“可能”而制造确定性。
- **依据与执行分开**：新增输出来自实际运行或明确标示意，不编造提交标识、版本与验证结果。外部补充能追溯来源；没有联网或费用授权时不自行扩量。
- **元信息服从载体**：发布系统或仓库要求front matter时补齐并校验；普通Markdown不默认添加。验证日期必须来自验证，不能用编辑日期替代；未知值不虚构。
- **保留用户工作**：原件、未核对改动和有效历史不擅自丢弃；删除或迁移按实际授权与引用关系处理，不从“改写”推定清理许可。

## 理解对齐

学习文档、教材、教程与解释型内容按[教学正本](references/tutorial-design.md)选择编排策略与教学支撑，核对概念依赖及目标相应的学习检查；共同底线是“读者需要但尚不具备的信息不能由作者经验代填”。不要求参考资料每次重复基础教学，也不让读者自行跨页拼凑必要信息。

## Mermaid 图文说明

图文解释在此维护，图的选用、语法与版面检查归[排版规范的图示部分](../markdown-style/SKILL.md#mermaid-图)。

- 图只回答一个问题，必要解释贴近图，不复述全部节点或讲解绘图语法。
- 说明引用渲染可见的文字；需要代号时先显示在图内，不引用源码节点标识。
- 少用方位词；只有方向固定且核对过版面时，才用上下左右定位。
- 颜色和线型只能辅助指称，不能成为唯一区分方式。
- 简单且无需额外背景的图可省解释；已有图或概念总览图若存在理解缺口，仍要补足，不因“图已存在”自动豁免。

## 按任务验收

只检查当前任务适用项。适用的关键条件未满足不能标为完成；非阻塞建议可交付后续安排。缺少验证条件是未执行或阻塞，不等于不适用。

| 任务 | 检查重点 |
| --- | --- |
| 所有实质改写 | 原意与依据、术语和指代一致、主线与范围、格式及引用 |
| 学习文档、教材、教程或解释型讲解 | 教学正本的读者路径与理解检查；含操作时核对关键结果和风险 |
| 多源合并或多篇迁移 | 取舍、有效独有细节、未决冲突、已确认落点、旧引用和原件处置 |
| 含代码或命令 | 声明环境中的示例与关键路径；不能执行时标示意或未验证，不称为实测 |
| 含图或发布元信息 | 实际图示阅读与载体要求；无图、不要求元信息的任务不套相应门槛 |

教学有效不能只用技术运行代替，作者自查不能冒充真实目标读者走查。验证强度与目标和风险相称，不为文案修改默认安装工具或建立持续集成流水线。

## 改动说明

只列实际相关的内容，不为短改写填满固定模板：结构调整、术语与理解修补、事实纠正及来源、示例与验证、合并关键取舍、最终落点、未确认与未执行项。

文件已写入才称为完成落盘。只给建议时不套“已改写、已验证”的措辞；用户要求只看成品时压缩过程说明，但不能隐去影响使用的风险和缺口。

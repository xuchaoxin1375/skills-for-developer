## 教学设计与理解对齐

本文件是教程、解释型讲解及教学审校的共用规则正本，由研究成文、文档改写与项目文档按需引用。只采用当前产物需要的部分，不因读取本文件重启调研、合并、归档或用户访谈。真实资料不足时再按[研究入口](../../tech-learning-research/SKILL.md)判断取证范围；不是所有教学任务都需要联网。

## 先判职责与成功

| 产物 | 主要目标 | 成功判据 | 不应强塞的内容 |
| --- | --- | --- | --- |
| 教程 | 经实践获得能力 | 完成可见成果，达到约定的解释或独立运用能力 | 全量选项、无关分支 |
| 操作指南 | 解决已知任务 | 在适用条件下完成任务并验证 | 从零讲完整学科 |
| 解释 | 建立可用理解 | 能说明关键因果、关系和边界 | 与理解无关的操作练习 |
| 参考 | 查到准确规则 | 快速定位字段、行为及限制 | 要求从头阅读的教学叙事 |

研究报告的取证与结论职责归研究入口；不能把所有文章都套成教程。文档职责与读者水平独立，高级读者学习陌生功能也可能需要完整指导。

## 对齐读者的实际起点

**理解对齐**是把作者认为显然的前提，还原成读者第一次遇到时完成任务所需的信息。分别确认领域知识、工具熟练度和当前任务经验；复用已知背景，不仅按职位或“新手/高手”标签取舍。

- 未声明的必要背景按当前主题初学者处理，不把读者视为所有领域零基础。
- 动笔前写清目标、适用范围及读者合理预期但不覆盖的内容；前置条件写成可检查的能力和环境，不只写“有基础”。
- 初学者提供完整范例、必要位置与检查点；进阶读者增加变体和选择依据；高级读者压缩已知基础，保留陌生部分、约束和证据。
- 混合受众按可检查的能力给阅读入口。任务相同而深度不同可分层；前置和路径显著不同时分开，不按难度机械拆文件。

## 按理解依赖安排主线

1. **先确定验收**：把“了解、掌握”换成能执行、解释、选择或诊断的行为，再倒推必需内容。
2. **展示方向**：开头让读者判断是否适用、将得到什么、需要什么；耗时与验证环境有依据才写，估计明确标注。
3. **提供必要模型**：只在开始前解释不可缺的概念。风险和不可逆后果先于动作，其余背景按用到的时机引入。
4. **完成有意义的单元**：每阶段有小目标、结果和可暂停位置；简单动作可合并，不强求每次点击独立成步。
5. **解释并迁移**：把操作与变化联系起来；学习目标包含独立运用时加入小幅变体或独立任务。

研究可以广，主线只收目标所需。作者提供稳妥默认路径并解释选择；预算、权限、风险或目标差异仍需读者决定，不替其扩大授权。无关选项退出主线，必要平台分支就地标注；不强迫单平台任务补全平台。

## 概念、示例与误区

- 首次出现且读者尚不掌握的主线概念，用最低限度说明交代解决的问题、基本含义和当前用途；非主线背景可链接深入说明。术语表不能替代当前位置的一句解释。
- 解释不依赖尚未说明的概念，也不循环定义。若A用B解释、B又用A解释，改用更基础的对象或具体行为建立其中一个，再引入另一个。
- 可以先用具体例子引入，也可以先给简明定义；随后说清一般规则、字段含义和适用条件，不能把某次示例数值当成定义。
- 简化模型不能与后续事实冲突；会改变判断的条件与结论一起出现。类比说明对应关系与失效边界，不靠读者自行猜测。
- 对易混内容给最短必要对比，点出错误理解、实际行为和后果；不要求每个概念都建一张误区表。
- 选择最小但有意义的案例，尽可能沿用数据和命名；一个贯穿案例有助于连续理解，但不强求所有主题使用项目式示例。
- 示例数量服从解释需要，不凑固定个数。可运行范例补齐依赖、导入、初始化和文件位置；片段或教学示意明确缺少什么以及如何与完整示例衔接。

例如，不能只说“筛选去掉不需要的数据”；应说明“筛选隐藏不符合条件的记录，并不删除数据”，再让读者清除筛选观察记录恢复。这个边界比额外增加多组相同筛选示例更重要。

## 动作、输出与恢复

| 检查对象 | 要交代的信息 |
| --- | --- |
| 操作前提 | 文件、目录、终端或界面位置，当前状态、权限和相关版本 |
| 输入 | 具体动作、需替换的值、取值约束，以及新增还是替换已有内容 |
| 预期结果 | 可观察的变化、成功判据和允许变化的时间戳、路径或标识符 |
| 检查点 | 关键状态转换如何验证；断言必须验证目标，不只验证命令退出码 |
| 异常 | 高频症状、先检查什么、如何修复和复验，无法处理时的求助条件 |
| 恢复与清理 | 如何停止、重试、回到已知状态；重复执行与清理的影响范围 |

- 不为每个简单动作加满标签；关键状态转换不能省略判断。静默操作可用状态查询验证，阻塞进程说明是否另开终端，交互环境说明退出方式。
- 给出形式化语法时，用列表或表格逐项解释占位符、字段与变量的含义、必填或可选、缺省行为和取值约束；说明哪些括号或符号属于元语法、不能原样输入。可复制命令使用可安全替换的具体值，并就近说明替换方法。
- 预期输出来自实际运行，或明确标成示意。先指出判断所需的一般读法，再解释本例；不要求读者逐字匹配所有可变输出。
- 说明作用范围：当前会话、项目还是全局；费用、覆盖、删除、权限和外发风险放在动作之前。没有恢复能力时如实说明，不编造可回滚保证。
- 可复制命令与终端记录分开，提示符、输出不混入可执行块；语法与呈现按[代码块规范](../../markdown-style/SKILL.md#代码块)。
- 位置、解释、结果尽量靠近相关动作；核心路径不依赖连续外跳，必要信息不默认折叠。完整参考只维护一处，就地保留当前理解所需的最短提示。

## 支撑递减与阅读体验

学习目标包含迁移时，从完整示范逐渐减少帮助：小幅改条件、部分补全或独立任务任选适合的形式，给出判定标准；不要求每篇都完整走一套阶梯。首次接触复杂技能时，不用“留作练习”替代必要范例。

- 检查“会跟做”与“能解释或独立做”是否混为一谈；按目标选择执行、因果解释、变体或诊断任务。
- 标题让读者知道本节解决什么问题，长文有导航；按能力分流，不用“高级用户可忽略”代替结构。
- 简洁是去掉无关负担，不是删掉判断依据。避免“显然、很简单、自行配置”掩盖缺口；不确定性用证据和条件限定，不能为了肯定语气抹去不确定性。
- 图表达关系而不是装饰；复杂图的解释贴近图，并引用可见文字。图形语法不等于读者应掌握的主题知识，必要关系仍需可理解的文字。
- 图片、视频和颜色不能成为唯一信息通道；提供必要替代文本、字幕或文字步骤，考虑窄屏下表格和代码的可读性。

## 验证与维护

- 先做作者路径检查：严格按文档在声明环境执行，额外补的步骤视为缺口；未执行、示意和已实测分开标记。
- 条件允许时让目标读者独立走查，记录具体停顿、猜测、回读和求助，不口头补完后宣称文档可用。代理自查不能冒充真实读者验证。
- 自动检查只证明对应范围。标记代码块不构成安全隔离；执行文档前仍需检查作用域、权限、超时、凭据和清理，不因本规则默认新增执行器或依赖。
- 实际验证日期不同于编辑日期。相关依赖、界面、接口或环境变化时重验受影响路径；锁文件只是可复现条件之一，不保证所有环境一致。
- 同一系列统一术语、示例状态和首次出现位置；必要时记录依赖关系，不强制为短文新建台账。局部任务只在授权范围处理同类缺口，范围外问题报告后再决定。

交付只检查适用项：读者是否接得住，主线是否自足，动作和结果能否判断，必要风险能否识别，约定的独立能力是否有相应检验。技术运行、作者走查、真实读者验证是不同证据，不能互相替代。

## 教学设计与理解对齐

本文件是主题学习文档、教材、教程、解释型讲解及教学审校的共用规则正本，由研究成文、文档改写与项目文档按需引用。目标是减少无关阅读负担，并使理解与运用达到约定要求；只采用当前产物需要的部分，不因读取本文件重启调研、合并、归档或用户访谈。真实资料不足时再按[研究入口](../../tech-learning-research/SKILL.md)判断取证范围；不是所有教学任务都需要联网。

需要核对理论来源、研究支持范围或教材编排取舍时，读[教学依据与采用边界](learning-design-foundations.md)。该参考区分设计框架、实证支持与编辑约定；有出处不等于当前教材已验证有效。

## 先判职责与成功

**Diátaxis**按读者需求区分文档职责，也指导实践教程的节奏与解释取舍。下表的**实践教程**(tutorial)特指受引导的做中学，不泛指教材或所有教学材料。

| 产物 | 主要目标 | 成功判据 | 不应强塞的内容 |
| --- | --- | --- | --- |
| 实践教程 | 经实践获得能力 | 完成有意义的实践，获得约定的知识、技能或熟悉度 | 全量选项、无关分支 |
| 操作指南 | 解决已知任务 | 在适用条件下完成任务并验证 | 从零讲完整学科 |
| 解释 | 建立可用理解 | 能说明关键因果、关系和边界 | 与理解无关的操作练习 |
| 参考 | 查到准确规则 | 快速定位字段、行为及限制 | 要求从头阅读的教学叙事 |

**采用边界**：以下是本仓库使用该框架的方式，不是给所有文体规定目录。

| 场景 | 使用方式与边界 |
| --- | --- |
| 产品或项目文档集合，需要区分学习、办事、理解与查阅 | 用职责分类检查内容混杂与入口缺口；不为分类强建目录或凑齐四类文档 |
| 教材、课程与连续学习系列 | 先按能力目标和概念依赖编排，再用职责判断检查局部内容；不要求整本书、每章或每段与四类一一对应 |
| 调研报告、论证文章与决策记录 | 不以四类结构作为默认主线；按问题、证据、论证或决策组织，仅在有相应读者需求时借鉴局部职责 |

**职责划分不等于学习路线**：框架不能代替具体主题的能力目标、先后依赖和学习评价设计。同一章节或学习路径可串联实践、解释与练习，各阶段保持主要职责，不按知识形式机械拆分，也不按命令覆盖率判断学会。

**实践教程不等于系统学习文档**：前者以受引导的行动与结果为主，保留动作所需的基本概念及因果提示，不在连续步骤中展开长篇理论；后者可按目标组织概念、实践与练习单元，不把必要推导都当作选学。是否要求独立运用或迁移，由约定目标决定，不从“教程”名称自动推定。

框架原文与本仓库的教材组合取舍见[实践教程的框架边界](learning-design-foundations.md#实践教程的框架边界)；不将灵活组合冒称为官网要求，也不以“尽量压缩解释”为由删除当前学习必需的内容。

需要解释框架、参考企业的实际分类或设计文档入口时，读[Diátaxis应用案例](diataxis-cases.md)；案例只作选择依据，不把企业规范照搬为通用要求。

研究报告的取证与结论职责归研究入口；不能把所有文章都套成教程。文档职责与读者水平独立，高级读者学习陌生功能也可能需要完整指导。

## 对齐读者的实际起点

**理解对齐**是把作者认为显然的前提，还原成读者第一次遇到时完成任务所需的信息。分别确认领域知识、工具熟练度和当前任务经验；复用已知背景，不仅按职位或“新手/高手”标签取舍。

- 未声明的必要背景按当前主题初学者处理，不把读者视为所有领域零基础。
- 动笔前写清目标、适用范围及读者合理预期但不覆盖的内容；前置条件写成可检查的能力和环境，不只写“有基础”。
- 初学者提供完整范例、必要位置与检查点；进阶读者增加变体和选择依据；高级读者压缩已知基础，保留陌生部分、约束和证据。
- 混合受众按可检查的能力给阅读入口。任务相同而深度不同可分层；前置和路径显著不同时分开，不按难度机械拆文件。

## 按目标选择编排策略

编排前，结合读者起点、预期能力、顺读学习或临时查阅的场景，以及篇幅与时间约束，选择主要策略，必要时组合。下表是选择依据，不是必填目录；短文可把设计落实在正文，不要求额外提交教学方案。

| 策略 | 适用情形与编排方式 | 防止误用 |
| --- | --- | --- |
| 任务驱动 | 以操作能力为主，用有意义的成果组织单元，就近引入所需概念 | 不退化为命令配方；让读者知道为何选此步骤及怎样判断结果 |
| 概念驱动 | 以关系、原理或推导为主，按概念依赖安排定义、性质、论证与应用 | 不先堆术语或实现细节；用具体例子连接抽象规则 |
| 问题驱动 | 需要建立动机、解释现象或学习选择时，用可理解的问题引出模型或方法 | 初学者缺少前提时先给说明或示范，不以盲目试错代替指导 |
| 贯穿案例 | 需要整合多种技能时，在同一案例上逐步增加复杂度，并穿插局部练习 | 不让无关业务知识抢占主线；交代各阶段起始状态，避免一步失败导致后文无法学习 |
| 查阅导向 | 已有基础、主要需要精确规则时，按问题、对象或语法组织入口，链接必要概念 | 不强加完整课程、项目或练习；速查清单也不代替初学主线 |

实践与理解并重时，可用任务或问题作为入口，以概念依赖控制顺序，参考作为查阅补充；不把这种组合强加给纯理论内容。教科书式内容按能力进展组织，不以正式文风、篇幅或定理数量代替教学设计。

系列学习可先给简明全貌，再逐步深化；后续回访旧概念时，增加关系、适用条件或综合应用，不只是重抄定义。不要求所有原理前置，也不为短文强建螺旋式课程。

### 教材与长篇系列

当产物供读者跨章顺读、逐步建立系统理解时，采用以下编排判断；“教科书式”不只表示文风正式。这些判断不是每章必填的栏目，也不要求短讲解扩成完整课程。

- **从全书目标到章节目标**：先确定最终要解释、推导或运用什么，再分解各章新增的能力及前置；每章所需的前置知识应来自已声明的读者起点或先前单元，发现循环依赖时调整顺序或先给足够的初步模型。
- **区分必读与选学**：按概念依赖和能力进展安排主线，标明深化、应用与查阅入口；必读内容分篇时说明阅读顺序与衔接，不把后续主线必需的前提藏在选学中。
- **标明论证层次**：含理论论证时，交代命题的假设与适用范围，区分直觉解释、例证、证明提纲和完整证明；未覆盖全部情形的例证不能冒充一般性证明，省略或延后论证时说明依据与去向，避免循环论证。
- **安排跨章综合**：目标要求独立运用时，让后续问题调用先前概念并增加新的关系或条件，按下文学习检查提供相应反馈；统一术语、符号与示例状态，不只把各章局部跟做串成一本书。

## 按理解依赖安排主线

1. **先确定验收**：把“了解、掌握”换成能解释、推导、执行、选择或诊断的行为，再倒推必需内容、示例、练习与验证方式；要求独立选择时，不能只安排跟做并用运行成功验收。
2. **展示方向**：开头让读者判断是否适用、将得到什么、需要什么；耗时与验证环境有依据才写，估计明确标注。
3. **提供必要模型**：只在开始前解释不可缺的概念。风险和不可逆后果先于动作，其余背景按用到的时机引入。
4. **完成有意义的单元**：学习主线按任务与理解依赖推进，不按命令、菜单或实现模块穷举；每阶段有小目标、结果和可暂停位置，简单动作可合并，不强求每次点击独立成步。
5. **建立联系并迁移**：联系规则、示例与结果，含操作时说明其造成的变化；学习目标包含独立运用时加入小幅变体或独立任务。

研究可以广，主线只收目标所需。作者提供稳妥默认路径并解释选择；预算、权限、风险或目标差异仍需读者决定，不替其扩大授权。无关选项退出主线，必要平台分支就地标注；不强迫单平台任务补全平台。

## 用最小工作模型连接操作与结果

**工作模型**(working model)是为当前任务保留关键对象、关系和行为的简化解释，帮助读者判断“操作作用于什么，为什么产生这个结果，条件改变后会怎样”。它不等于完整实现、架构图或术语清单。

- **按目标选用**：读者需要解释结果、预测变体、选择做法或诊断失败，而孤立步骤不足以支持这些判断时，提供最小工作模型。作者分析可以更完整，正文只呈现当前任务必需的部分；简单指南就地解释必要机制，参考资料可链接概念正本，不强设“模型分析”章节或完整原理前置。
- **按问题取舍**：从核心对象与关系、输入到结果的处理过程、状态与生命周期、作用域与覆盖顺序中选需要的视角，说明关键操作改变什么、保留什么。只列组件或画图不算解释；区分教学抽象与实现事实，机制依据不足时先核实或标明缺口。
- **用模型分析现象**：从具体问题引入模型，用示例把操作、变化和可观察结果对应起来；目标包含迁移或诊断时，改变一个相关条件，让读者据此预测结果或选择检查点，再用输出、状态查询或日志验证。模型与证据不符时修正解释，不靠追加特例掩盖问题。

例如，Git教程不只列出`git add`和`git commit`，还解释工作区是正在编辑的内容，暂存区记录准备提交的内容；`git add`将指定文件当时的内容更新到暂存区，普通`git commit`基于暂存区创建提交。由此分析“暂存后又修改同一文件会怎样”：后一次修改不会自动进入该提交，需要再次暂存；用`git diff`和`git diff --cached`分别观察未暂存与已暂存的差异。该例限于普通提交路径，不代替对`git commit -a`等其他提交方式的说明。

验收看模型是否支持约定的解释、预测、选择或诊断，不看图表和术语数量；简单任务不要求额外安排练习。简化与类比的边界见下文，示例未实际执行时仍须标明。

## 按内容选择表现形式

读者的理解任务不同，适合的形式也不同。先问“读者要拿这段内容做什么”，再选择段落、表格、图或代码块：

| 读者要做的事 | 首选形式 | 不宜 |
| --- | --- | --- |
| 理解原因、条件、边界 | 段落 | 只给图或表格，不解释因果 |
| 比较多个对象的同一维度 | 表格 | 用长段落逐项描述 |
| 看对象关系、分叉、流向、状态转移 | Mermaid 图 | 只用文字描述拓扑关系 |
| 按顺序操作或复现 | 有序列表 + 代码块 | 把步骤塞进图或表格 |
| 对照同一对象的多个状态 | 状态表 + 按转换点的同尺度状态图 | 只给一张总览图或纯文字 |

- **简短不等于易懂**：减少概念数量或篇幅只减轻阅读负担，不自动降低理解难度；完成当前判断所需的术语来历、前提和状态对照不能省。判断标准是读者能否预测、解释或核对，不是段落长短。
- **状态变化要逐点对照**：同一对象经历多个状态时，先给状态表（每行一个状态，列出关键字段），再在关键转换处给同尺度快照（同一组图使用相同节点样式和视角）；每个状态说明什么变了、什么没变、读者能观察到什么。容易形成错误心智模型时，先让读者预测下一步，再用输出、图或表核对，并附“错误想法 → 实际是什么 → 怎么验证”的纠偏表。单张总览图只能说明最终形状，不能代替过程。
- **图表文分工**：表负责并列比较，图负责关系、分叉和流向，文字负责原因、条件、边界和读图提示。三者不复述同一信息；图只重复列表时可删，文字正在描述图关系时应改图。简单线性步骤用有序列表和代码块，只有确实存在分叉、回路、状态或并列比较时才上图或表；图的数量按转换点，不按页数。

例如 Git 分支、提交图和`HEAD`：只用文字说“分支指向提交”很难让读者预测切分支后文件为何变化；用“总览图 + 状态表 + 每个关键状态的快照 + 每步‘哪一层变了’的文字”，读者才能把命令、输出和心智模型对上。

## 概念、示例与误区

- 首次出现且读者尚不掌握的主线概念，用最低限度说明交代解决的问题、基本含义和当前用途；非主线背景可链接深入说明。术语表不能替代当前位置的一句解释。
- 示例中的名字、路径和标识符首次出现时，交代它是什么、从哪来、与当前任务的关系；不要让读者把分支名、目录名、命令名混成一类。
- 解释机制时，用当前文档的对象、动作和可观察结果说明“这个规则在这里表现成什么”；只给通用定义和抽象原则，读者仍无法判断具体输出。
- 解释不依赖尚未说明的概念，也不循环定义。若A用B解释、B又用A解释，改用更基础的对象或具体行为建立其中一个，再引入另一个。
- 定义、公式、性质和定理按当前用途分类，不天然归入参考。例如，从平均速度引入导数定义服务于概念建立，学后速查同一定义则服务于参考。
- 可以从问题、事实或具体例子引出定义，再按理解需要引入性质、定理与证明，也可以先给简明定义；当前学习必需的内容在主线中展开，非必要扩展移到选学或参考。说清一般规则、字段含义和适用条件，不能把某次示例数值当成定义。
- 简化模型不能与后续事实冲突；会改变判断的条件与结论一起出现。类比说明对应关系与失效边界，不靠读者自行猜测。
- 对易混内容给最短必要对比，点出错误理解、实际行为和后果。对比必须能改变读者的判断或行动；只罗列差异，或只得出“不同命令或对象本来就不同”这类显然结论，就是无助于判断的填充，应删掉或改成具体误用场景；不要求每个概念都建一张误区表。
- 选择最小但有意义的案例，尽可能沿用数据和命名；一个贯穿案例有助于连续理解，但不强求所有主题使用项目式示例。
- 示例数量服从解释需要，不凑固定个数。可运行范例补齐依赖、导入、初始化和文件位置；片段或教学示意明确缺少什么以及如何与完整示例衔接。

例如，不能只说“筛选去掉不需要的数据”；应说明“筛选隐藏不符合条件的记录，并不删除数据”，再让读者清除筛选观察记录恢复。这个边界比额外增加多组相同筛选示例更重要。

### 概念与解释的放置

介绍概念不自动属于**解释型文档**(Explanation)。解释型文档以拓宽理解、建立联系和提供背景为主要目的；教程中的定义、原因提示和结果读法不因具有解释性就必须迁走。按当前读者与学习目标判断：

| 内容的作用 | 放置方式 |
| --- | --- |
| 缺少它会影响下一步动作、结果判断或安全 | 当前步骤附近的必要说明，使用读者已能理解的语言 |
| 当前目标需要完整模型或推导，短提示不足以建立正确理解 | 主线中的必读概念单元，与相关任务或论证明确衔接 |
| 不服务当前目标的背景、内部实现或多方案权衡 | 独立解释专题，注明何时值得读；目标变化时重新判断是否必读 |
| 完整语法、参数、取值与精确行为清单 | 参考资料；当前位置仍保留本例必需的含义与边界 |

较长且必需的解释，不在“硬塞进连续步骤”和“只给可选链接”之间二选一：可在同章或明确衔接的分篇中展开，先补当前前提再继续。独立文件不等于选学，是否分篇不只看篇幅；完整说明维护一处，相关动作保留最短必要提示。保持单元目的清楚，不逐句凑四类标签。

## 动作、输出与恢复

| 检查对象 | 要交代的信息 |
| --- | --- |
| 操作前提 | 文件、目录、终端或界面位置，当前状态、权限和相关版本 |
| 输入 | 具体动作、需替换的值、取值约束，以及新增还是替换已有内容 |
| 预期结果 | 可观察的变化、成功判据和允许变化的时间戳、路径或标识符 |
| 检查点 | 关键状态转换如何验证；断言必须验证目标，不只验证命令退出码 |
| 异常 | 高频症状、先检查什么、如何修复和复验，无法处理时的求助条件 |
| 恢复与清理 | 如何停止、重试、回到已知状态；重复执行与清理的影响范围 |

- 不为每个简单动作加满标签；关键状态转换不能省略判断。静默操作可用状态查询验证，阻塞进程说明是否另开终端，交互环境说明退出方式。
- 给出形式化语法时，用列表或表格逐项解释占位符、字段与变量的含义、必填或可选、缺省行为和取值约束；说明哪些括号或符号属于元语法、不能原样输入。可复制命令使用可安全替换的具体值，并就近说明替换方法。
- 预期输出来自实际运行，或明确标成示意。先指出判断所需的一般读法，再解释本例；不要求读者逐字匹配所有可变输出。
- 说明作用范围：当前会话、项目还是全局；费用、覆盖、删除、权限和外发风险放在动作之前。没有恢复能力时如实说明，不编造可回滚保证。
- 可复制命令与终端记录分开，提示符、输出不混入可执行块；语法与呈现按[代码块规范](../../markdown-style/SKILL.md#代码块)。
- 位置、解释、结果尽量靠近相关动作；当前理解必需的解释、关键条件与风险就地呈现，必要信息不默认折叠。完整参考只维护一处，就地保留当前理解所需的最短提示。
- **跨篇衔接**：允许通过明确的必读链接组成学习或操作路径，交代下一篇的用途、前置状态及完成后如何继续；禁止让读者在多个页面间自行拼凑必要信息，不把“主线自足”理解为所有内容必须放在同一文件。

## 支撑递减与阅读体验

读者缺少相关经验且正在学习可示范的复杂技能时，优先给完整范例并展示关键判断依据，而不只呈现最后答案；不用“留作练习”替代必要示范。学习目标包含迁移时，用小幅改条件、部分补全或独立任务逐渐减少帮助；递减依据读者的独立表现，不按固定章节撤除支撑，也不要求每篇完整走一套阶梯。

- 练习围绕学习目标，提供答案、判定标准或解释性反馈，帮助读者识别错误及其原因；不把必要讲解藏到答案里。
- 控制同时引入的陌生要素，复用已有知识与案例，减少无关环境配置和背景切换；降低负担不是删除必要定义、条件或推导，也不是禁止引入目标必需的复杂关系。
- 目标包含长期保持或系列学习时，安排**提取练习**(retrieval practice)与间隔应用：在后续单元先尝试回忆核心关系、解释依据或完成任务，再查对反馈；可以查非记忆目标的参数，不要求背全语法。不为短指南强加固定复习日程，也不把同页重读当作延迟保持的证据。
- 标题让读者知道本节解决什么问题，长文有导航；在容易失去主线的阶段补简短小结与前后关联，按能力分流，不用“高级用户可忽略”代替结构，也不为每小节机械添加导语和总结。
- 简洁是去掉无关负担，不是删掉判断依据。避免“显然、很简单、自行配置”掩盖缺口；不确定性用证据和条件限定，不能为了肯定语气抹去不确定性。
- 图表达关系而不是装饰；复杂图的解释贴近图，并引用可见文字。图形语法不等于读者应掌握的主题知识，必要关系仍需可理解的文字。
- 图片、视频和颜色不能成为唯一信息通道；提供必要替代文本、字幕或文字步骤，考虑窄屏下表格和代码的可读性。

## 验证与维护

学习检查按承诺的目标选用，不要求每篇覆盖全部目标：

| 目标 | 可用的检查 | 不能仅据此判定掌握 |
| --- | --- | --- |
| 概念理解 | 解释关键关系、推导依据、预测结果或辨认反例 | 复述定义、读起来顺畅 |
| 操作运用 | 在明确条件下独立完成任务，并检查结果及作用范围 | 复制步骤后命令退出成功 |
| 选择与迁移 | 改变条件，要求选择方法并解释边界，或诊断一个相关问题 | 重复与范例完全相同的任务 |
| 长期保持 | 间隔后重新调用核心知识或完成相关任务 | 刚读完的测验、同页反复阅读 |

- 先做作者路径检查：顺读并检查概念依赖、推导与答案；含操作时严格按文档在声明环境执行，额外补的步骤视为缺口。未执行、示意和已实测分开标记。
- 条件允许时让目标读者独立走查，分别记录不必要的停顿、跳转、回读和求助，以及理解或运用中的错误；据此修编排、解释或练习，不靠一味压缩篇幅提高阅读速度。代理自查不能冒充真实读者验证，也不口头补完后宣称文档可用。
- **效率与学习结果一起检查**：按约定目标，结合完成解释、推导或独立任务的总时间、错误与求助，以及相应的迁移表现判断；需要长期保持时另作延迟检查。比较版本采用相近读者起点与相同目标，不仅凭字数少、翻页少或阅读快宣称更好，也不预设通用时长或通过率。
- 自动检查只证明对应范围。标记代码块不构成安全隔离；执行文档前仍需检查作用域、权限、超时、凭据和清理，不因本规则默认新增执行器或依赖。
- 实际验证日期不同于编辑日期。相关依赖、界面、接口或环境变化时重验受影响路径；锁文件只是可复现条件之一，不保证所有环境一致。
- 同一系列统一术语、示例状态和首次出现位置；必要时记录依赖关系，不强制为短文新建台账。局部任务只在授权范围处理同类缺口，范围外问题报告后再决定。

交付只检查适用项：读者是否接得住，主线是否自足且未因职责分类拆走必要定义与推导，动作和结果能否判断，必要风险能否识别，约定的独立能力是否有相应检验。技术运行、作者走查、真实读者验证是不同证据，不能互相替代。

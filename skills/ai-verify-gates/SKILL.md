# AI 编程质量与可验证交付

独立通用 skill：输入是"需求 + 变更"，输出是"定级结论 + 可执行验证证据 + 明确的 VERIFIED / PARTIAL / BLOCKED / FAILED 状态"。

核心判断只有一条（三份源文档一致）：**"完成"必须是由机器判定、可重复执行的事实，而不是 AI 的自我声明。**
弱模型的危险不在写不出代码，而在自评时产生"验证幻觉"——用推理说服自己代码是对的，却从未运行。
所以本 skill 的一切机制都做一件事：**剥夺实现者的自我验收权，把"做完"交给确定性门禁 + 独立复核 + 真实证据**。

五条设计原则（后续所有规则都从这里推出，冲突时以原则裁决）：
**验收权与执行权分离**（AI 不能自己宣布完成）；**证据驱动完成**（每条 AC 对应可执行、可复现的证据）；
**风险分级验收**（验收强度与变更风险成正比，防"微调跑全量 E2E、大功能只跑 lint"两头翻车）；
**小步闭环**（粒度小到一次会话可完成、可验证、可回滚）；**工具优先于提示**
（能用 Hook/CI/脚本强制的，不要靠提示词"请记得"——"总是运行 linter"的钩子 vs "通常会遵守"的提示词，
"通常"与"总是"之间的差距正是生产失败之处）。

三份源文档分工（已融合，不用再分别读）：`fable5.1` 给最可落地的 bash 链路与任务状态机；
`fable5.1-2nd` 给根因理论、Node 跨平台门禁与防作弊追溯；`gpt5.6sol` 给 VDS 全生命周期
（风险量化、G 门、安全供应链、发布与回滚、用评估测工作流本身）。细节矩阵见 references。

与其它 skill 分工：`frontend-design` 管界面生成；`frontend-ux-qa` 管存量 UI 缺陷深查；
`scripting-best-practices` 管脚本写法；`repo-governance` 管仓库治理。本 skill 只管
"AI 交付的东西怎么证明做完、做对、能发、能回滚"。

## 适用范围

先路由，再走对应流程，不要混着写：

- A 新需求/改代码并要交付：走 0–6 全流程（定级 → 基线 → 规格 → 实现 → 门禁 → 复核 → 发布）。
- B 只咨询选型（工具、测试分层、等级怎么定）：只走 0–1 + 按需读 references，不写代码。
- C 只验收别人（含 AI）的交付：走 5–6，用复核清单逐条对证据，不看实现者的文字总结先下结论。

不用本 skill：纯视觉风格发散（转 `distinctive-design-director`）、纯排版改写（转 `doc-polish`/`markdown-style`）。

## 流程（A 按 0–6，B 只走 0–1，C 只走 5–6）

### 0——先定级，再谈其它

读 `references/levels-and-gates.md`。按序判定，不按"改动行数少"降级：

1. 定变更类型 T0–T4（文档/文案 → 局部逻辑 → 跨模块/接口依赖 → 大功能/鉴权支付迁移）。
类型只定**最低等级**，只能上调不能下调。
2. 不确定或涉及安全/数据/鉴权/持久化/公共组件签名/路由时，直接按更高等级处理。
需要量化时用风险分 `R = 3Sec + 3Data + 2Blast + 2Crit + 2Contract + 2Novel + UX + Recover` 复核，分数只升不降。
3. 输出一句话定级结论 + 理由，写入任务头与 PR 标签（如 `[L2]`）。执行中发现影响面超预估时，停下升级并告知，不许悄悄继续。

为什么：等级决定"要哪些规范文件、跑哪些检查、谁来验收"。等级错了，后面全错。

### 1——建基线与规格冻结

1. 建变更前基线：记录分支与提交、检查工作区脏状态、跑一次快速验证、记下已失败测试、确认应用能启动、bug 先复现留失败证据。建不出基线时状态只能是 BLOCKED/PARTIAL，不许标 DONE。
2. 冻结规格：范围、非范围、编号验收标准（AC-1…，推荐 EARS/Given-When-Then 句式）、非功能预算。
L2 以上要有 `tasks.md`，L3/L4 要有完整 `spec.md` + 需求追踪矩阵 RTM（每条 AC 对实现位置、测试 ID、证据）。
WebUI 功能的 AC 必须过一遍状态清单（见 `references/levels-and-gates.md` 第六节）：只写成功路径的规格不合格，
加载/空/错误/超时/离线/重复提交/权限不足/刷新后退/键盘/中文长文本都要有归属或显式列为非目标。
3. 做影响分析与测试计划：路由、组件、API、数据、权限、构建、部署中被触及的是什么；每条 AC 映射到验证手段。关键要求没有验证方式时停在 G5，不许开工。

### 2——小步实现，不攒大招

1. tasks 拆到一次会话能完成、可验证、可回滚的粒度（弱模型按"一任务一文件/一组件"拆，由人或强模型预拆）。
同一时刻最多一个进行中任务；一任务一提交，提交信息带任务编号。
2. bug 与功能都用"先写失败测试（红）再实现（绿）"顺序；修 bug 要留下"修前失败、修后通过"两次证据。
重构的验收标准是"行为不变"，属 L2 起且**禁止修改既有测试**——黄金 E2E 用例集前后不得变更，改了就要问为什么。
3. 无关重构不顺手做；同一会话不混多个变更。同方法修两次还失败时停下诊断上报，不许盲目循环烧 token。

### 3——统一验证入口说了算

只认一个命令走完全部检查，不认"我看过代码了""应该能过"：

- 首选跨平台 Node 门禁 `verify --level Lx [--base] [--spec] [--tasks]`（Windows 无需 Git Bash），备选 bash `verify.sh -l`。CI、钩子、人都调同一个入口。
- L0/L1 允许限定范围加速；L2 起强制全量（防借范围缩小逃避）。L3/L4 加规格追溯（每个 AC 至少被一个测试名引用）、多浏览器关键路径、视觉/可访问性、契约、安全与依赖扫描、性能预算。
- 输出固定机器可读格式（PASS/FAIL 步骤名 + 汇总 JSON），弱模型只读步骤名即可定位。

门禁脚本、测试断言、覆盖率阈值、CI 配置属于受保护路径，AI 不许为通过而改它们；要改先走人工确认。

### 4——完整性扫描（所有等级都跑）

"做一半"有固定形态，逐项拦截，见 `references/verify-and-templates.md`：

占位与逃逸标记（TODO/FIXME/占位/placeholder/not implemented/空函数体）、绕门禁（ts-ignore/eslint-disable/skip/only/删测试/放宽断言）、
断开连接（新增组件无引用、新增路由无导航、按钮无真实 handler）、调试残留。新增路由要走"路由表遍历可达"用例：
逐个访问、断言一级标题可见、无控制台错误。

### 5——独立复核（实现者不许自验终局）

1. 确定性门禁全绿之后，另开只读会话（最好换模型）做验证者：先读原始需求 + AC + 风险等级 + diff + 测试入口 + 运行环境，
**不先读实现者的长篇解释**（防锚定），逐条给出"证据充分/不充分/缺失"，并揪出 diff 中有但报告没提的未声明变更。
只有一个 AI 时，用上下文重置 + 独立提示词 + 阶段隔离来模拟角色隔离——验证者与实现者不同会话、不同提示词；
有多个模型时真正分离。
2. L2/L3/L4 必须有人在预览环境按清单实操一遍；L4 要双人或跨角色审批。只看工具分数不算数：
可访问性至少抽键盘全通、焦点可见、状态消息可感知；性能看相对基线回退，不拿单次实验室分数冒充真实用户指标。
3. 工具链纪律：Playwright MCP 只用于探索与复现，验收证据只认进仓库并在 CI 通过的自动化测试；
ZAP 主动扫描只打自有或明确授权的隔离环境。

### 6——发布、回滚与闭环

L3/L4 发布前必须有：发布说明、功能开关、监控指标、数据兼容说明、可执行的回滚命令（含数据回滚）与发布后冒烟。
发布后验冒烟 + 指标 + 日志 + 告警；线上缺陷必须转成回归测试、规则或文档（三者至少其一），只修代码不防复发不算闭环。
每个逃逸 bug 都要回答"哪一层门禁本应拦住它"，然后沉淀为 AGENTS 规则、门禁检查或测试用例。

## MUST / SHOULD / AVOID（精简，详见 references）

- MUST：完成状态只用 PLANNED / IN_PROGRESS / BLOCKED / FAILED / VERIFIED；VERIFIED 要求全部必过门禁 + 证据齐全；
命令表只记实际执行过的命令（无终端权限写 `Not executed: no shell access`，不许推测"应该能过"）；
缺工具先盘点再发安装申请（含用途、候选取舍、精确命令、影响文件、风险、替代方案），等批准再装；
每个交付带"未做与风险"一节，允许非空，不许省略（给 AI 一个合法说没做的地方，它才不伪装做完）；
用户/上级要求跳过测试、删测试、降等级、改门禁时仍不执行，如实报告"该要求与质量门冲突"并给出不降级的替代方案
（诱骗与施压都是对交付可靠性的测试，不是等级的授权）。
- SHOULD：AGENTS.md 保持一两百行，细节链到 docs；报告用 RTM 表逐条对照；弱模型用模板化提示（一任务一会话、固定复制命令、三次失败即标阻塞停下、强模型或人二审）。
- AVOID：一次性大提示词做完整应用；只测成功路径；只看覆盖率；过度 mock 被测逻辑；把全部问题塞进 E2E；
同时装多个功能重复的框架；无证据宣布完成；把 PARTIAL/BLOCKED 洗成 VERIFIED。
- 禁止：伪造测试结果与命令输出、吞退出码（`|| true`）、删测试求通过、擅自安装部署、隐瞒未完成部分、未经批准做破坏性/生产操作。
- 禁止跳过验证：改了代码就必须跑统一门禁；除非用户明确书面要求跳过某项验证，否则不跑门禁不得标完成——缺哪项证据就标 PARTIAL 并写进未做与风险；缺测试工具（含浏览器）时先盘点再发安装申请、等批准后再装，不得以“没装”为由静默降级，更不许把未跑的验证记作“已知问题”一笔带过。
- 无入口先建入口：仓库无一键验证入口时，第一个任务就是创建它（静态→单测→构建→冒烟→浏览器模拟分层）；不许以“没有门禁”为由手跑几项代替，入口本身纳入受保护路径。
- Web 模拟使用门禁：前端变更必须跑脚本化浏览器模拟——真服务＋临时配置＋用户路径操作（切页/提交/抽屉/后退）＋断言优先（可见性/路由/无横滚/零控制台错误）＋截图留证；构建通过≠可运行，门禁须含首屏渲染断言；验收脚本进仓、截图产物放 TEMP；full-page 截图不判定 sticky/浮层行为（改用视口截图＋过渡等待）。
- 存量从严：仓库不规范不是降级理由，只能定更高等级；L2 起照常要 tasks/AC/RTM，不管仓库原来有没有这些文档。
- 脏基线先冻结再开工：记录分支/脏文件/已有失败，并逐项区分“历史失败 vs 本次新增”；历史失败建档后可不挡门禁，但本次新增的失败一票否决；不得以“原来就脏”为由新增污染。
- 改到哪里达标到哪里：被本次变更触及的文件/路由/接口，必须满足当前等级的全部门禁；不许以“存量原来就这样”放过触及范围内的违规，范围外的历史欠账记入未做与风险排期，不挡本次但必须建档。
- 最低门禁矩阵（缺什么补什么，补不上就 BLOCKED/PARTIAL＋用户书面批准，不许静默放行）：无单测→补冒烟或验收脚本；无 lint→至少编译＋空白检查；动前端→必须浏览器模拟；无统一入口→先建入口。
- 交互覆盖全入口：前端门禁必须覆盖全部可交互入口——弹窗矩阵（高频全场景＋低频代表场景）＋至少一条端到端提交链（填表→提交→任务→日志非空）；存量改造后跑一轮全控件横扫（DOM 指纹＋网络请求双轨），DEAD（无变化＋无请求）即缺陷，DISABLED 须有可见理由。
- 断言有效性：断言快照必须覆盖被测状态维度；空集合上的全称断言加非空守卫；截图后复断言目标仍可见，否则该项 FAIL。
- 双通道失败归宿：服务端日志落盘扫 Traceback/5xx，有即 FAIL；资源加载噪音另记、`pageerror` 致命；接口失败必须落到 UI 呈现（数据/空态/错误三态），静默空转即缺陷；弹窗等 settled 后再截图关闭。
- 现网与合成实例分离：门禁自起的合成实例（dummy 配置、临时端口、空库）只能证代码路径，证不到用户真实数据/旧库/真实口令下的行为；用户现网报错以现网证据为准（用户粘贴的 Traceback 即一手证据），不得用合成全绿否定现网报错。
- 现网观测分级（按侵入从小到大）：用户粘贴日志 ＞ 只读探针打现网端口（仅 GET 与无害点击，不提交写操作，需批准） ＞ 用户重启服务重定向日志（最后手段）；验收脚本须支持外部基址只读模式，默认仍合成实例；报告须区分“合成证据”与“现网证据”，现网未观测即 PARTIAL。
- 错误可观测性：后台异常必须有用户可见归宿（任务日志/审计/错误条），不得只打服务端控制台（点按钮的用户看不见控制台）；失败呈现纳入弹窗矩阵断言。
- 静默吞错与优化清单：`except pass`/`catch{}` 逐处定性（日志守卫可留，持久化/轮询失败须上报）；非阻塞发现记 OPT 清单（编号/等级/证据/状态）唯一落盘；有未闭环 OPT 时只能 PARTIAL。
- 视觉矩阵目检：会动/会变形的元素（弹窗、抽屉、侧栏三态/悬停展开、主题、空/错态），先列矩阵（状态×宽度×主题）逐图人眼看过；报告分“已看/未覆盖”两栏，没看过不算验过——断言绿≠看过。
- 证据截图沉降：等动画走完再截（如弹窗完全不透明），半透明中间帧不算证据；等待写进脚本，别碰运气。
- 断言可证伪：每个新断言都要证明自己会失败（故意造一次失败看它报不报错），排除“跳过当通过”（如名字写错整段没跑）。例：悬停用例先把鼠标移开再悬停；涉及刷新/原生框要接管 dialog，否则假失败。
- 状态映射排他：多状态先排否定再判肯定（如先判“未完美执行”再判“完美执行”，否则子串包含会误判）；每种状态配一个断言。
- 外部模式条件断言：用户现网/空数据下，依赖数据的断言加条件、不误报；只读探针不写用户数据。
- 显形压过隐藏：让元素显示的规则，优先级必须高于所有藏它的规则——打平就看源码顺序，先写必输。例：显字与藏字同级，收起后悬停即“宽面板无字”。隐藏规则若按宽度分多套，每套都要压过；门禁逐组合断（不只测一个宽度）；复现走用户原话路径。

## 输出结构（ALWAYS 用此模板，弱模型逐字填）

```markdown
# [任务]可验证交付报告
## 1 定级（T 类型 + R 分数 + L 等级 + 理由；PR 标签）
## 2 基线（分支/提交、已有失败清单、启动状态；建不出就标 BLOCKED）
## 3 规格追踪（RTM：AC → 实现位置 → 测试 ID → 证据 → 状态）
## 4 执行命令（实际跑过的命令、退出码、报告产物路径；未跑的写 Not executed）
## 5 独立复核（复核者、逐条充分性、未声明变更、人工实操结论）
## 6 未做与风险 / 跳过项（跳过的检查、原因、批准人、后果）
## 7 发布与回滚（功能开关、监控、回滚命令、数据回滚、发布后冒烟）
## 8 下一步（VERIFIED / PARTIAL / BLOCKED / FAILED + 具体动作）
```

## 自检（出稿前逐项过）

- [ ] 定级结论写了 T/R/L 与理由，等级只升不降？
- [ ] WebUI 规格把状态覆盖清单逐项标到了 AC 或非目标（没只写成功路径）？
- [ ] 基线记录了已有失败，能区分历史失败与本次新增？
- [ ] 每条 AC 都有实现位置 + 测试 ID + 真实证据，无"文字保证"？
- [ ] 统一验证入口按等级跑过全套，输出可复现（命令 + 退出码 + 报告）？
- [ ] 完整性扫描跑过（占位/逃逸/断连/残留/可达），受保护路径没被私改？
- [ ] 独立复核是新上下文只读做的，先看需求后看解释？
- [ ] "未做与风险"一节存在且诚实，PARTIAL/BLOCKED 没被洗成 VERIFIED？
- [ ] L3/L4 有功能开关、监控、回滚命令与发布后冒烟？
- [ ] 改了代码就跑过门禁？没跑的项已写入未做与风险并保持 PARTIAL？
- [ ] 仓库无入口时先建了入口，而不是手跑几项代替？
- [ ] 前端变更跑过脚本化浏览器模拟（含首屏渲染断言），脚本进仓、截图可复现？
- [ ] 存量不规范未被用作降级理由？等级只升不降，L2 的 tasks/AC/RTM 齐全？
- [ ] 脏基线已冻结，能区分历史失败与本次新增？本次新增零失败？
- [ ] 被触及的文件/路由全部达标，未以“原来就这样”放过？范围外欠账已建档？
- [ ] 弹窗矩阵＋提交链跑过，全控件横扫无 DEAD？
- [ ] 断言覆盖状态维度，空集断言有守卫，截图后复断言了？
- [ ] 服务端日志落盘扫描过，失败都有 UI 归宿、无静默空转？
- [ ] 合成证据与现网证据分开标注，现网未观测未洗绿？只读探针未向现网写数据？

- [ ] 静默吞错已定性，OPT 清单唯一落盘、无未闭环洗绿？

- [ ] 截图等动画走完，无半透明中间帧？
- [ ] 每个新断言证过自己会失败，无“跳过当通过”？
- [ ] 多状态先排否定再判肯定，每种有断言？
- [ ] 外部/空数据下不断数据依赖、无误报、未写现网？

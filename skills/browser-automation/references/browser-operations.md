## 自动化浏览器操作

选定工具后读取。优先使用任务中实际可用的浏览器工具或项目脚本；下列步骤是操作指导，**本 skill 随附的截图脚本只支持视口采集，不提供通用点击、登录或下载接口**。

### 建立会话与资源归属

1. 自己启动浏览器时，使用独立 profile/context（配置目录/浏览器上下文），把视口、语言、时区、运行时代理等设置为任务需要的值。需要延续登录时复用项目提供的获授权测试状态，不默认复制日常个人 profile。
2. 连接已有浏览器时，记录浏览器、context、页面分别由谁创建和释放。CDP 连接仅适用于支持该协议的 Chromium 会话；Playwright 的 CDP 连接与原生协议完整性不同，详见 [已有会话连接](screenshot-workflow.md#复用已安装浏览器与连接已有会话)。不要把 `channel="msedge"` 当作接管已开的 Edge 窗口。
3. 设置操作超时和覆盖启动、交互、截图/下载及关闭的总期限，按可用容量从串行单实例开始。独立脚本需项目运行器、操作系统进程作用域或远程服务提供异常回收；`finally` 只覆盖能继续执行清理代码的退出路径。
4. 外部服务创建的会话通过服务 API 或工具的释放能力核验；关闭本地连接不证明远端会话已释放。未知所有权时不关闭用户浏览器，不按名称或端口杀进程。

### 定位、交互与等待

- 先读取实际页面的可访问树或 DOM，优先角色与名称，必要时使用项目稳定 test id。避免凭截图坐标猜元素；只能按坐标操作时固定视口并先核对实际画面，操作后验证状态。
- 点击和填写前确认目标唯一、可见且可交互。遇到覆盖、禁用或缺失时定位原因，不默认强制点击。流程涉及提交时按已有任务授权执行，避免重试造成重复提交。
- 用可见状态、URL、元素文本、响应或业务条件等待任务完成。`sleep` 和网络空闲不能代替业务就绪；轮询只观察结果，不在等待循环中重复执行写操作。
- 导航、弹窗、新标签页和文件选择等事件先准备对应等待，再触发动作，避免错过事件；使用所选工具/版本实际支持的 API，不根据其他工具的参数名拼接调用。
- 上传只使用用户指定或本轮创建的文件；下载保存到本轮明确目录，等待完成并核对文件类型、大小及任务所需内容，不仅判断链接已点击。

需要把交互写为长期测试时，按 [测试设计](../../web-app-testing/SKILL.md)确定断言、数据和夹具。定位器来自实际页面，截图来自本轮运行；不要构造一份能通过的假页面冒充真实业务执行。

### 截图与诊断证据

视口、元素和整页按任务选择，注意懒加载、虚拟列表及内部滚动容器。截图与 PDF 能证明的内容不同；打印结果不能代替屏幕渲染验收。单次受管采集见 [截图工作流](screenshot-workflow.md)，需要视觉验收时按 [共用视觉协议](../../ai-verified-delivery/references/visual-acceptance.md)实际查看。

页面失败时保留首败状态及必要的错误摘要，记录具体 URL 的敏感信息应脱敏。trace、HAR、截图、下载和存储状态可能包含页面数据或凭据，按项目证据政策保存，不上传进公共仓库，不把完整 profile 或 Cookie 打入日志。

### 收尾与报告

释放本轮页面、context、浏览器和下载/临时资源；连接共享会话时只处理已确认属于自己的资源。回收未确认时停止叠加任务，按 [资源预算与回收](../../web-app-testing/references/environment-and-maintenance.md#测试资源预算与回收)定位。

报告实际工具与浏览器、完成的操作、可观察结果、证据路径和回收事实。区分操作已发出、页面有变化、业务已成功；临时操作结果不冒充回归测试，工具不可用或必需检查未运行时如实标注。

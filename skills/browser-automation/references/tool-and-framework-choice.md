## 工具与测试框架决策

先明确交付物，再选浏览器控制方式和测试运行器。**浏览器、自动化库与测试框架是不同选择**；本机 Chrome/Edge 能由 Playwright 控制，不要求为每次任务下载另一套浏览器。能力分层与人工截图步骤见 [截图工作流](screenshot-workflow.md#普通浏览器与-playwright-的区别)。

### 先盘点当前环境

1. 查看已有项目配置、锁文件和依赖声明，区分 Python、Node、Java/.NET 等运行环境；读取所需少量配置，不扫描所有缓存和用户目录。
2. 确认当前会话实际提供哪些浏览器工具，以及它们的导航、截图、交互、上传下载、会话释放能力；工具名、skill 安装或配置文件存在不代表当前可调用。
3. 需要自建脚本时，在目标解释器或项目环境检查包；Python 可只读查发行包元数据，Node 先看项目依赖与现有配置。不用 `npx` / `pnpm dlx` / `uvx` 当保证无下载的探针。
4. 用 [只读发现](browser-discovery.md)列本机候选。远程工具运行在另一台机器时，本机浏览器路径对它无效；容器和 WSL 也需分别核对运行位置。

### 浏览器操作方案

| 目标与已有条件 | 优先方案 | 选择依据与限制 |
|---|---|---|
| 一次人工观察或截图 | 已安装浏览器的开发者工具 | 无需补自动化包；依任务要求记录人工证据 |
| 当前会话已有可用浏览器工具 | 复用该工具 | 先核对必需操作与会话收尾；不因已有示例就另外启动本地浏览器 |
| 独立首屏或滚动多屏截图 | 本 skill 的托管截图脚本 | 明确总期限、所有权及异常回收；不支持任意交互或整页参数 |
| 项目已有 Playwright/Puppeteer/Selenium 等 | 沿用项目工具和配置 | 保留登录夹具、浏览器版本和现有运行器；普通任务不触发框架迁移 |
| 无现成工具，需脚本化导航、点击、填写及截图 | 在项目语言中使用 Playwright | 按目标浏览器补齐必要环境；定位器、等待与独立上下文便于组织任务 |
| 已依赖 Puppeteer，任务主要围绕其已支持的浏览器/API | 沿用 Puppeteer | 按锁定版本的支持范围选择；不为统一术语改写有效脚本 |
| 已有 WebDriver/Grid、企业语言栈或远程执行基础 | 沿用 Selenium/WebDriver 与现有远程设施 | 核对浏览器/驱动版本、会话期限和远程释放；不靠本机进程树推断远端已回收 |
| 确需连接外部 Chromium 会话或托管浏览器 | 工具支持的远程连接/CDP | 核对协议兼容性、授权和会话所有权；channel 启动独立实例，不能替代连接已有会话 |

默认给一个推荐，不并行启动多个引擎比较。能力缺失时先说明缺口，再按任务选择一个可验证的替代；不因发现系统浏览器就覆盖项目原基线。远程服务的可用性、计费和期限按实际配置核对，不预设本机已装某种 MCP 或托管平台。

### 测试运行器决策

浏览器操作脚本可以只产出截图或数据；需要长期回归时，才把操作组织为用例、断言、夹具和报告。

| 项目情况 | 运行器选择 | 后续工作 |
|---|---|---|
| 已有有效测试框架或 CI | 沿用现有体系，包括已有 Cypress 等方案 | 只补缺失能力；先核对真实需求再决定是否迁移 |
| Node/TypeScript 新建浏览器 E2E，项目无既有约束 | Playwright Test 可作为默认建议 | 核对浏览器支持范围、夹具和证据配置 |
| Python 项目 | pytest 与项目认可的 Playwright 集成方式 | 确认插件/夹具是否已有，不假定安装 Python Playwright 就包含测试插件 |
| Java/.NET 等已有测试栈 | 现有运行器配所选浏览器库 | 避免只为浏览器操作再建立一套不相容语言环境 |
| 只有临时截图/定位或短脚本操作 | 暂不新增测试框架 | 用受管入口完成任务并记录证据即可 |

本 skill 到“当前用什么控制浏览器、由什么运行器承载”为止。测试层次、该测哪些路径、断言、Mock、数据隔离与回归维护按 [web-app-testing](../../web-app-testing/SKILL.md)，不在这里维护第二套测试设计规则。

### 交付一个可执行决定

用简短说明回答：在哪运行、发现了哪些实际可用能力、选择什么及理由、缺哪些前置条件、下一条命令或操作是什么。区分**文件已发现、工具可调用、实际启动、业务验证**；未执行的步骤明确标注，不把推荐方案写成已验证结果。

# 最新模型资讯：来源与巡检

用途：回答"最近有什么新模型""某家又发了什么""这周有什么值得看"。目标是**带日期、带一手来源、区分证据等级**的资讯，而不是转述二手汇总。

## 巡检入口

按"一手公告 → 独立评测 → 二手汇总"三层取，越靠前越可信。路径以站点当前结构为准，取不到时从首页导航进入，不硬编码猜测的深链。

| 层级 | 入口 | 拿什么 |
|---|---|---|
| 一手：评测机构 | Artificial Analysis `/changelog`（新评测结果按模型逐条列出）；ModelDial 首页"新模型实测"与 `/leaderboard/coding` | 独立分数、思考档位、是否已收录 |
| 一手：竞技场 | Arena（arena.ai）的 Agent Arena、对话榜与 Pareto 页；静态抓取常被 Cloudflare 拦，需指定出口并强制渲染引擎（见 `eval-sources.md` 的竞技场一节） | 偏好 Elo、真实会话成功率、自带 cost/task 的帕累托前沿 |
| 一手：模型厂商 | OpenAI / Anthropic / Google DeepMind / Meta AI / xAI / Mistral 官方博客与模型页；DeepSeek 的 news 与 changelog；阿里 Qwen 博客；智谱 Z.ai 博客；Moonshot（Kimi）公告 | 发布事实、模型 ID、上下文、档位、价格、可得性 |
| 一手：定价与文档 | 各厂商 pricing 页与 API 文档的模型列表 | 单价、缓存价、长上下文规则、限流、GA 状态 |
| 二手：汇总站 | 模型目录与比价站（models.dev、OpenRouter models、各类 "new models this week" 汇总） | 发现线索、交叉确认时间线；不作为唯一依据 |
| 二手：社区 | 官方 Discord / X 账号、Hacker News、Reddit 相关版块 | 早期信号与实测反馈；标为社区消息 |

巡检顺序：先看评测机构 changelog 与厂商公告确认"发生了什么"，再用定价页确认"能不能买、多少钱"，最后才参考二手汇总补充背景。

某个来源取不到时的处理：**先分清拦截类型**——`Just a moment...` / `cf-mitigated: challenge` 是可解挑战，换出口或换渲染引擎；`Attention Required` / `cf-error-details` 是 IP 层拒绝，换出口才可能有效。两者都不要靠反复原样重试。同一来源换了出口与引擎仍失败，才改走替代源并在结论里写明。

出口不是只有一个：本机代理可能有多个监听端口，且同一客户端里还挂着几十个节点，默认选中的那个被拒不代表其他节点不可用。取数前先确认有几个可用入口，逐个用目标请求验证，不拿"默认出口失败"当"站点不可达"。判定与回退细则见 [resilient-browser-fetch](../../resilient-browser-fetch/SKILL.md)。

## 时间窗与范围

问"最近"必须先定窗口，不同窗口的答案不同：

- 近一周 / 近一个月 / 本季度 / 某个基准版本发布以来。
- 范围：全部厂商、某几家、某个系列（如"GPT-6 系"）、只算已 GA、是否含开源权重。
- 用户没说明时，默认"近一个月 + 已 GA + 主流厂商"，并在开头写明这个默认，让用户能纠正。

## 判读规则

- **发布 ≠ 可用**。区分"已 GA""预览/内测""仅特定客户""仅订阅不开放 API""仅论文或技术报告"。推荐里只能推荐用户实际能买到的形态。
- **同名不同物**。同一系列常有多个变体（旗舰 / 轻量 / 快速版 / 无安全层版），价格与能力差异很大；写清具体模型 ID 或变体名。
- **系列发布先理产品线**。一次发布常含多个独立型号（旗舰 / 中档 / 领域版）与多个 effort 档位。先写清"这次有哪几个独立型号、各自定位与价差"，再逐条展开；领域版（如法律版）与通用版分开，不混为一条。
- **effort 档位归并到母模型**。同一模型的 low / medium / high / xhigh / max 是同一模型的不同推理预算，报道里合并为一条并注明"另有 X 档"；只在档位本身有独立定价或能力跳变时单列，不把五档写成五个模型。
- **价格要有条件**。促销价、 introductory price、按 prompt 长度分档、高峰/低峰差异、批量折扣都要带条件与到期日；到期后的价格要单独说明。
- **厂商自报与独立复测分开写**。同一模型两者都有时并列，冲突时点明分歧，不静默择一。
- **代际对比要同档**。与上一代同档位比（同 effort、同 harness、同任务集），不与跨代旗舰比。
- **能力变化看基准，不看形容词**。"大幅提升""接近人类水平"不是证据；引用具体基准、版本与分数。
- **总分变了要下钻到分项**。总分（如 Coding Agent Index）变化常由单个子基准驱动（如代码问答掉十几分）。报道要指出"哪个分项在动、动了多少"，而不是只报总分差值；分项方向相反时尤其要写清，避免"总分持平"掩盖了能力结构的改变。
- **开源权重看许可证**。权重可下载不代表可商用；许可证条款与商用限制单独说明。
- **传闻与未发布产品**明确标注"未官宣/传闻"，不写成确定事实，也不用它推导推荐。

## 输出结构

资讯类回答按这个骨架，短讯可以压缩：

- **一句话结论**：本窗口最值得注意的一到两件事。
- **逐条**：模型名与变体、发布日期、发布方、独立评测表现（带来源与日期）、价格与可得性、相对上代或同级的变化。系列发布先给产品线概览（独立型号、定位、价差），再逐条展开。
- **影响判断**：对谁有意义（成本、能力、合规、生态），以及不改变什么。
- **未核验与缺口**：仅厂商自报的条目、拿不到独立评测的条目、价格未确认的条目。
- **日期**：每条带发布日期，整份带读取日期。

## 常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| 把促销价当长期价 | 预算结论过期即失效 | 写条件与到期日，同时给到期后的价格 |
| 把"发布"写成"可用" | 用户按推荐接入却拿不到 | 先查 GA 状态与开放范围 |
| 混用不同基准版本的数字判断代际 | 得出"新版本退步"等错误结论 | 只在同版本、同档位、同 harness 内比 |
| 只抄厂商博客 | 结论不可复核 | 补一个独立来源；没有就标注 |
| 用旧一代分数代表新版本 | 误导选型 | 新版本没有独立数据时留空并说明 |
| 把社区实测当普遍结论 | 过度外推 | 注明样本与条件，不当作定论 |

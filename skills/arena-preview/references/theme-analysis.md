# 主题与核心文件分析清单

> 何时读：Step 3，服务已验 200 之后。按顺序走，边读边记进报告。

## 1. 入口链（先画出来）

`index.html`（script src）→ `src/main.*`（挂载点）→ `src/App.*`（路由/页面组装）→ 各页面。每一步只记"文件名 + 干了什么（一句话）"，最多 6 个节点。

## 2. 主题 token（精确到值）

看 `tailwind.config.*` / `src/index.css` / `@theme`（Tailwind v4）/ CSS 变量，提取：

- 字体栈（中英文各记第一顺位）
- 主色、背景色、文字色（HEX，≤6 个）
- 圆角 scale、主字号与行高
- 深色模式：有/无，跟随系统还是手动

## 3. 组件与页面清单

按目录分组（components/sections/pages/case…），每组一句话；标出**页面级**（路由/大板块）与**通用**（按钮/弹窗/表格）两类。数据文件（`data/*.ts`、mock）单独一行说明内容来源。

## 4. 文档

先读 `README.md`、`docs/*.md`，确认"这个项目是干什么的"——报告的一句话结论以文档为准，不以猜测为准。无文档则看 App 首页标题与导航反推，并标注"（无文档，反推）"。

## 5. 停止线

分析只到"看懂"，不重构、不修 bug、不升级依赖。发现明显缺陷记入报告"已知问题"，不动代码。

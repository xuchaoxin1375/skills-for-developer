# 01 · 设计思路与原则

## 1. 背景与目标

Cloudflare 控制台是业界公认较成熟的运维类产品界面：信息密度高，但学习成本低；功能入口多，但导航稳定；表单复杂，但很少让用户感到迷路。本项目不复刻其视觉品牌，而是 **提炼其结构与交互逻辑**，沉淀为可复用的规范：

1. 让桌面端用户在**宽屏**下获得稳定的导航，并能把空间还给内容；
2. 让折叠的侧边栏**不牺牲可发现性**——悬停即可优雅展开，移开即自动隐藏；
3. 让表单页在**任意窗口宽度**下都清晰、可预期、不丢输入；
4. 所有规则可验收、可演示、可迁移。

## 2. 对参考对象的观察

通过对 Cloudflare 控制台（DNS 记录页）的截图分析，归纳出以下可迁移的特征：

| 区域 | 观察到的设计 | 提炼出的规则 |
| --- | --- | --- |
| 侧边栏（展开） | Logo + 账户、快速搜索（Ctrl K）、「返回」项、Overview、Recents 分组、多级分组（DNS → Records / Analytics / Settings）、底部「折叠」按钮 | 顶部身份与检索、中部导航、底部控制；分组用缩进 + 竖线表达层级 |
| 侧边栏（折叠） | 56px 图标栏，仅图标；悬停时展开为完整侧边栏并覆盖内容 | 折叠不是隐藏，而是「降级为图标」；展开方式为覆盖而非推挤 |
| 顶栏 | 收藏星标、域名 + 套餐徽标 + 切换器、Ask AI、Support、账户 | 上下文（当前站点）永远可见且可切换 |
| 页头 | 大标题 + 一句话说明 + 右侧次要操作（文档） | 先说明「这是什么」，再给操作 |
| 状态横幅 | 黄色警示条解释当前域名为 pending | 异常状态用语义色横幅，附带可点击的下一步 |
| 工具栏 | 搜索框 + Filters / Display options / Import / Export + 一个蓝色主按钮 | 低频操作次级样式，主操作唯一 |
| 筛选 | 浮层内「字段 · 操作符 · 值」行，Add filter，Press Enter to apply | 复杂筛选用非模态浮层；Enter 应用；可叠加 |
| 表格 | 复选框、排序箭头、表头信息提示、状态图标、行尾 Edit | 表格承载批量选择、排序与行级操作 |
| 页脚 | 低强调链接行 | 与主内容隔离，不抢视线 |

## 3. 核心原则

### 3.1 任务清晰

- 每个页面用**一句话**说明用户、任务与下一步；首屏只做一件事，主操作不超过 3 个。
- 字段超过 7 项时，必须分组或分步；危险操作远离首屏并二次确认。

### 3.2 布局克制

页面只在四种原型中选择，不混搭：

| 原型 | 适用 | 设计稿对应 |
| --- | --- | --- |
| 仪表盘 | 指标总览、待办清单 | 概览页 |
| 列表 + 详情 | 资源管理、批量操作 | DNS 记录列表 + 编辑页 |
| 表单单列 | 创建 / 编辑一个对象 | 添加 DNS 记录、添加站点（向导） |
| 设置页 | 多项配置，分区保存 | SSL/TLS 设置 |

间距只使用 4 / 8 / 12 / 16 / 24 / 32 / 48；先画线框确认结构，再写样式。

### 3.3 状态可预期

- 任何控件都有清晰的默认、悬停、聚焦、按下、禁用、错误、加载状态。
- 同一个动作在任何入口得到同一个结果（例如侧边栏的折叠按钮、`[` 快捷键、命令面板中的「Toggle sidebar」完全等价）。
- 用户偏好（侧边栏固定状态、主题）被记住。

### 3.4 渐进披露

- 低频功能收进浮层（筛选、显示选项）；次要列在窄容器中自动隐藏；
- 复杂表单按块分组，条件字段（如 MX 的优先级）仅在相关时出现。

### 3.5 键盘与触屏同等重要

- 任何仅靠悬停才能使用的功能，必须有键盘 / 触屏等价路径：悬停展开的侧边栏同样会在键盘聚焦时展开，触屏用按钮展开；
- 触控目标不小于 24px，窄屏与触屏提升到 44px。

## 4. 页面骨架（Shell）

```text
┌────────┬──────────────────────────────────────────────┐
│        │ Topbar（sticky，56px）：菜单 · 站点上下文 · 操作 │
│ Side   ├──────────────────────────────────────────────┤
│ bar    │ Page（max 1440，居中）                         │
│ 56/240 │   PageHeader（标题 / 说明 / 次要操作）          │
│ (sticky│   Banner（可选）                               │
│  100dvh│   Toolbar / Content                           │
│ )      │   ActionBar（表单页：sticky bottom）            │
│        ├──────────────────────────────────────────────┤
│        │ Footer（低强调）                                │
└────────┴──────────────────────────────────────────────┘
窄屏（<768）：Sidebar 变为抽屉，Topbar 左侧出现汉堡按钮
```

关键决定：

- 页面使用**文档级滚动**（而非内部滚动容器），以保留浏览器原生的滚动恢复、地址栏收缩与锚点行为；侧边栏与顶栏使用 `position: sticky`。
- 侧边栏在文档流中只占用一个**占位槽**（56 或 240px），真正的侧边栏绝对定位在槽内，因此悬停展开可以覆盖内容而不引发布局抖动。

## 5. 关键取舍

| 决策 | 选择 | 理由 | 代价 |
| --- | --- | --- | --- |
| 折叠态悬停展开方式 | **覆盖**内容，不推挤 | 推挤会让内容区每次划过都重排，表格与图表抖动 | 覆盖时遮住一部分内容（有阴影分层） |
| 悬停触发 | 进入延迟 120ms，离开延迟 250ms | 过滤误触与鼠标抖动，保证「自动」又不「乱动」 | 增加状态与计时器 |
| 窄屏侧边栏 | 模态抽屉（原生 `<dialog>`） | 免费获得焦点陷阱、Esc、背景 inert | 样式需覆盖默认行为 |
| 保存按钮 | 不因校验失败而置灰 | 置灰无法告诉用户「哪里错了」 | 需要实现提交时校验与首错聚焦 |
| 容器适配 | 外壳用媒体查询，内容用容器查询 | 侧边栏展开 / 折叠会改变内容宽度，仅视口断点无法覆盖 | 需要现代浏览器（Chrome 105+/Safari 16+/Firefox 110+） |
| 设计稿预览 | iframe 内加载真实页面 | 只有 iframe 才拥有真实的视口与媒体查询 | 需要父子页面消息通信 |
| 危险操作确认 | 输入名称确认，但按钮保持可点 | 以校验消息指出问题，而不是禁用 | 多一次校验 |

## 6. 与参考对象的差异说明

- **品牌中立**：使用自有名称与图标（Nimbus），不使用 Cloudflare 的标识与文案。
- **对比度更高**：输入框边框采用 ≥ 3:1 的对比度（`#8c8c8c`），正文 ≥ 4.5:1。
- **增加键盘等价路径**：折叠态的悬停展开同样响应键盘聚焦；增加跳转到主内容的跳过链接。
- **增加离开保护与撤销**：未保存离开会确认；删除后提供撤销。

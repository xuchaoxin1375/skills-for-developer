# Nimbus Console · 控制台设计参考

> **一句话**：面向产品设计师与前端工程师，参考 Cloudflare 控制台的成熟设计，给出一套可直接对照、可交互验证的 **侧边栏（折叠 / 悬停展开 / 自动收起）** 与 **表单页** 设计规范、模拟设计稿和可复用实现。

本项目由三部分组成：**规范文档**（本目录）、**交互式设计稿**（Web 应用）、**参考实现**（`src/` 下的 React + Tailwind 代码）。三者相互印证：文档中的每一条规则都能在设计稿里找到对应的演示。

## 2. 推荐阅读路径

- **设计师（30 分钟）**：先打开设计稿，体验侧边栏与表单；再读 01 → 02 的「状态机」与「动画」→ 03 的「校验」→ 05。
- **前端工程师（60 分钟）**：07 → 02 → 03 → 08 → 04，同时对照 `src/dashboard/Sidebar.tsx`、`src/dashboard/pages/RecordForm.tsx`、`src/dashboard/pages/DnsRecords.tsx`、`src/ui/columns.tsx`。
- **评审 / 测试**：直接使用 02、03、04 末尾的「检查清单」，配合设计稿的宽度扫描与「传统方案」对比模式。

## 3. 设计稿能做什么

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 宽度滑条 / 数值输入 / 常用宽度预设 | 舞台底部浮层 | 240px – 1920px，含 300 / 390 / 768 / 1024 / 1440 / 1920 |
| 宽度自动扫描（应力测试） | 浮层「宽度扫描」 | 在 280 – 1600px 往返，三档速度，快速发现挤压与溢出 |
| 侧边栏行为演示脚本 | 浮层「侧边栏行为演示」 | 自动循环：固定展开 → 折叠 → 悬停展开 → 自动收起，并显示说明 |
| 状态监视 | 浮层底部 | 实时显示布局档位与侧边栏状态（来自预览页的上报） |
| 查看模式 | 舞台顶部 | 改进方案 / 传统方案（反例）/ 并排对比 |
| 主题 | 页面右上角 | 浅色 / 深色 / 跟随系统（默认），同步到预览页 |
| 侧边栏手动控制 | 舞台底部浮层 | 「侧边栏展开 / 折叠为图标栏」分段按钮，与自动演示互补 |
| 场景切换 | 左侧可收起面板 | DNS 列表（交互式表格）、添加记录表单、设置页、分步向导、概览 |
| 独立打开 | 舞台顶部「新标签页打开」 | 脱离舞台，用真实浏览器窗口验证 |

## 4. 规范性用语

本文档遵循统一的用语约定，便于验收时逐条核对：

| 用语 | 含义 |
| --- | --- |
| **必须 / 不得** | 底线要求。违反会导致可用性、无障碍或数据安全问题，验收不通过 |
| **应该 / 不应** | 强烈推荐。仅在有充分理由并记录原因时才可偏离 |
| **可以** | 可选增强，视场景取舍 |
| **避免** | 已知的反模式，通常会引入缺陷或体验退化 |

## 5. 术语表

| 术语 | 含义 |
| --- | --- |
| Shell（外壳） | 由顶栏、侧边栏、内容区、页脚构成的应用骨架 |
| Rail（图标栏） | 侧边栏折叠后仅显示图标的 56px 窄栏 |
| Pinned（固定） | 用户通过切换按钮选择的常驻状态：展开或折叠，会被持久化 |
| Peek（悬停展开） | 折叠状态下的临时展开：覆盖在内容之上，不推动内容 |
| Hover intent（悬停意图） | 指针停留超过阈值才视为「想要展开」，用于过滤划过 |
| Slot（占位槽） | 侧边栏在文档流中占据的宽度，与其视觉宽度解耦 |
| 粘性列 | 表格中用 `position: sticky` 固定在左 / 右边缘的列（勾选列、操作列） |
| 填充列 | 表格里一列不设宽度的 `<col />`，吸收多余空间，使其他列保持用户设置的精确宽度 |
| 行内展开编辑 | 点击 Edit 后在该行下方展开编辑区（相对于弹窗编辑而言） |
| Drawer（抽屉） | 窄屏下由汉堡按钮打开的模态侧边栏 |
| 容器查询 | 依据组件所在容器宽度（而非视口）切换布局的 CSS 能力 |
| 两级校验 | 第一级：字段失焦即时校验；第二级：提交时整体校验并汇总 |
| 首错聚焦 | 提交失败后把焦点移动到第一个出错字段 |

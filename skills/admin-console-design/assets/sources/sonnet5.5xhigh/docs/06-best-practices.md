# 06 · 实践指南

> 本指南将 02 – 05 中的规范压缩为可执行的条目。每条均给出**原因**，便于在评审中解释与取舍。用语含义见 [文档地图](README.md)。

## 1. 侧边栏

### 必须（MUST）

| 条目 | 原因 |
| --- | --- |
| 把占位槽宽度与视觉宽度解耦 | 否则悬停展开会推动内容，造成重排与抖动 |
| 折叠态的悬停展开必须同时响应键盘焦点 | 仅 hover 的功能会把键盘与读屏用户拒之门外 |
| 触屏忽略 `pointerType === "touch"` 的悬停，并提供按钮展开 | 触屏没有悬停，误触会卡在展开态 |
| 用户点击「收起」后抑制再次悬停展开直到指针离开 | 否则刚收起又弹出，像坏了 |
| 记住用户的固定状态（展开 / 折叠） | 偏好不应每次刷新都丢失 |
| 尊重 `prefers-reduced-motion` | 前庭障碍用户 |
| 窄屏使用模态抽屉并有焦点陷阱与 Esc 关闭 | 否则键盘焦点会漂到被遮挡的页面上 |
| 当前页使用 `aria-current="page"` | 读屏与样式的单一事实来源 |

### 应该（SHOULD）

| 条目 | 原因 |
| --- | --- |
| 悬停进入延迟 100 – 150ms，离开延迟 200 – 300ms | 过滤误触与抖动，同时保持「自动」的感觉 |
| 展开使用覆盖 + 阴影，而非推挤 | 避免内容区重排 |
| 标签延迟淡入、立即淡出 | 防止文字在宽度动画中被截断闪烁 |
| 子菜单用 `grid-template-rows` 过渡并在收起时 `visibility:hidden` | 无需测量高度，且移出 Tab 顺序 |
| 提供快捷键（`[`、Ctrl K）并在界面中展示 | 提升效率与可发现性 |
| 分组默认仅展开包含当前页的一组 | 降低噪声 |
| 路由变化后把焦点移到主内容并回到顶部 | 防止「丢失位置」 |

### 可以（MAY）

- 在顶部提供「最近访问」分组；
- 在折叠态为图标提供额外的 Tooltip（若不使用悬停展开）；
- 提供命令面板，统一导航与动作。

### 避免（AVOID）

- 把折叠态做成「完全隐藏」，用户将找不到入口；
- 对 `height: auto`、`left/top` 做动画；
- 在折叠态里放置必须悬停才能看到的唯一入口；
- 悬停展开瞬间触发（无延迟），掠过边缘就弹开；
- 展开 / 折叠时让主内容宽度每帧变化的复杂图表重排（改用覆盖式）。

## 2. 表单

### 必须

| 条目 | 原因 |
| --- | --- |
| 每个控件有可见 `<label>` | placeholder 会消失，且不是可靠的名称 |
| 允许粘贴；对粘贴内容做规范化 | 禁粘贴损害效率与可访问性 |
| 提交时汇总错误，并把焦点移到第一个错误字段 | 用户无需寻找问题所在 |
| 保留所有已填内容 | 清空表单是最不可原谅的错误 |
| 错误文案：哪里错 + 为什么 + 如何改 | 「Invalid input」没有信息量 |
| 错误通过 `aria-invalid` + `aria-describedby` 关联 | 读屏可读 |
| 保存时防止重复提交，并显示进度 | 避免重复创建 |
| 有未保存修改时拦截离开 | 防止数据丢失 |
| 危险操作二次确认，且默认焦点在非破坏性按钮 | 防止误触 |

### 应该

| 条目 | 原因 |
| --- | --- |
| 晚惩罚：失焦后才报错，之后实时更新 | 避免在用户输入中途打断 |
| 单列、分组、控制宽度（≤ 720px） | 扫描路径单一 |
| 字段 > 7 项时分组或分步 | 降低认知负担 |
| 条件字段仅在相关时出现 | 渐进披露 |
| 禁用状态必须说明原因 | 否则用户不知如何解除 |
| 保存条 / 操作栏使用粘性定位 | 长表单中保持可达 |
| 成功后返回上下文并高亮结果 | 让用户确认「确实成功」 |
| 窄屏输入框字号 16px，控件 44px | 避免 iOS 放大，保证触控 |
| 服务端错误映射回字段 | 与客户端错误一致的体验 |

### 可以

- 提供「保存并继续添加」；
- 在右侧提供上下文帮助侧栏（仅宽容器）；
- 对高风险操作要求输入名称确认；
- 提供实时预览（如 DNS 记录文本）。

### 避免

| 反模式 | 问题 |
| --- | --- |
| 用禁用提交按钮代替校验 | 用户不知道缺了什么 |
| 仅靠颜色表达错误 | 色觉障碍无法识别 |
| 一进入页面就满屏红字 | 噪声大、不友好 |
| `alert()` / `confirm()` 作为反馈 | 阻塞、无法样式化、不可访问性差 |
| 禁止粘贴或禁止缩放 | 违背无障碍与效率 |
| 提交成功却留在原页无反馈 | 用户不确定是否成功 |
| 清空整个表单来「重试」 | 丢失输入 |
| 把「取消」做成主按钮样式 | 误导主要路径 |

## 3. 响应式与布局

### 必须

- 页面级**无横向滚动**；宽内容（表格）在自身容器内滚动，容器可聚焦且有标签；
- 在 390 / 768 / 1440 三个宽度验证，并对 300px 做极端测试；
- Flex / Grid 的可收缩子项设置 `min-width: 0`；
- 间距仅使用 4 / 8 / 12 / 16 / 24 / 32 / 48。

### 应该

- 内容组件使用**容器查询 / ResizeObserver**，外壳使用媒体查询；
- 宽表格：关键列（勾选、操作）粘性固定，其余列容器内横向滚动并允许调列宽；容器足够窄时改用卡片；
- 页面最大宽度居中，避免宽屏下无限拉伸；
- 浮层打开时夹取到视口内；窄屏改为底部面板。

### 可以

- 提供「显示选项」让用户自选列与密度；
- 根据内容宽度（而非视口）显示辅助侧栏。

### 避免

- 仅用视口断点决定内容布局（侧边栏会改变内容宽度）；
- 固定像素宽度的卡片 / 对话框；
- 在窄屏中把桌面表格原样缩小；
- 用 `overflow-x: hidden` 掩盖溢出。

## 4. 视觉与组件

### 必须

- 先写令牌，再写样式；字号 ≤ 7 档、圆角 ≤ 4 档、阴影 ≤ 3 级；
- 一套图标库；图标按钮有可访问名称；
- 全部交互元素有可见的焦点环。

### 应该

- 主操作唯一，使用主色；次要操作用描边或幽灵按钮；
- 状态用语义色 + 图标 + 文字；
- 首屏只做一件事：一句话说明用户、任务与下一步。

### 避免

- 纯装饰渐变、满屏毛玻璃；
- 标题 emoji；
- 卡片套卡片；
- 同一页面多种主按钮；
- `div onClick` 假按钮、仅 hover 才可用的功能。

## 5. 无障碍

| 级别 | 条目 |
| --- | --- |
| 必须 | 全键盘可达；焦点可见；正文对比度 ≥ 4.5:1，非文字 ≥ 3:1；320px 可回流；中英行高 ≥ 1.6；目标 ≥ 24px（触屏 44px） |
| 应该 | 跳过链接；地标（nav / main）；路由切换后管理焦点；`aria-live` 通知；`prefers-reduced-motion` |
| 可以 | 提供键盘快捷键帮助面板；提供高对比度主题 |
| 避免 | `outline: none` 无替代；用颜色作为唯一信息载体；禁用缩放 |

## 6. 性能与质量

| 级别 | 条目 |
| --- | --- |
| 应该 | 输入过滤使用 `useDeferredValue`；监听器按需绑定并清理；用 `ResizeObserver` / `IntersectionObserver` 取代滚动监听；动画只用合成友好属性 |
| 应该 | 构建通过不代表质量合格：在 300 / 390 / 768 / 1440 手工或自动化巡检，并用宽度扫描做压力测试 |
| 避免 | 在 `scroll` / `resize` 回调中同步读取布局；在渲染期间创建大量内联对象导致子组件重复渲染 |

## 7. 交互式表格与条目

详细规则见 [08 · 交互式表格与条目规范](08-data-table-spec.md)。

### 必须

| 条目 | 原因 |
| --- | --- |
| 编辑 / 删除放在**最后一列**并粘性常驻 | 列很多、需要横向滚动时，关键操作仍然随时可点 |
| 粘性单元格有不透明背景，且与行的悬停 / 选中状态一致 | 否则内容透出、视觉断裂 |
| 列宽可调时必须有最小宽度、键盘可调、可恢复默认 | 防止列被拖没；键盘用户同样可用 |
| 排序用表头里的按钮，并设置 `aria-sort` | 可发现、可键盘操作、读屏可读 |
| 批量条不得插在表格上方 | 勾选后表格下移会让连选点错行 |
| 批量与删除可撤销，不适用项要说明 | 误操作成本低，结果可预期 |
| 有未保存的行内 / 弹窗编辑时拦截离开 | 防止数据丢失 |

### 应该

| 条目 | 原因 |
| --- | --- |
| 表头复选框 = 本页全选（半选态），并提供「选择全部匹配项」 | 与分页语义一致 |
| 支持 `Shift + 点击` 连选 | 大量行时的效率 |
| 提供行内展开与弹窗两种编辑形式，由用户选择并记住 | 不同任务的上下文需求不同 |
| 横向可滚动时，粘性列边缘出现阴影 | 提示「还有内容」 |
| 拖动列宽期间只改 DOM，松手再提交 state | 性能 |
| 编辑器以记录 id 为 key | 排序 / 翻页时不误复用状态 |

### 可以

- 在显示选项中允许隐藏次要列、切换密度；
- 在编辑器内提供「Open full form」进入整页表单。

### 避免

- Edit 放在中间列、需要滚到最右才能点到；
- 整行点击即编辑（与勾选、选中文本冲突）；
- 拖动列宽时每帧 `setState`；
- 卡片 / 表格两套布局同时渲染（会出现重复的编辑器与重复的 id）。

## 8. 评审速查表

| 问题 | 通过标准 |
| --- | --- |
| 这页的任务一句话能说清吗？ | 能；主操作 ≤ 3 个 |
| 折叠后能悬停展开并自动收起吗？ | 延迟合理，无抖动，键盘等价 |
| 没填完直接提交会怎样？ | 汇总 + 首错聚焦 + 内容保留 |
| 把窗口拖到 300px 会怎样？ | 无横向滚动，无重叠 |
| 只用键盘能完成吗？ | 能，焦点环可见 |
| 表格加到十几列，编辑入口还在吗？ | 在：末列粘性常驻，带滚动阴影 |
| 折叠后的图标栏里能看到文字吗？ | 不能；图标在带内居中 |
| 深色主题下对比度够吗？ | 够，使用独立令牌 |

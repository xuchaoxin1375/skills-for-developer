# 03 · 表单页规范

> 适用范围：创建 / 编辑对象的单列表单、设置页、分步向导。目标是 **布局合理、校验可预期、不丢用户输入、窄屏同样好用**。

对应实现：`src/dashboard/pages/RecordForm.tsx`（单列表单）、`Settings.tsx`（设置页）、`AddSite.tsx`（向导）、`src/ui/controls.tsx`（字段组件）。

## 1. 页面类型与选择

| 类型 | 何时使用 | 布局 | 设计稿场景 |
| --- | --- | --- | --- |
| 单列表单 | 创建 / 编辑一个对象，字段 ≤ 7 个或可分 2 – 3 组 | 单列卡片，最大宽 720px | 添加 DNS 记录 |
| 设置页 | 多个相互独立的配置项 | 行布局：左说明、右控件；窄容器堆叠 | SSL/TLS |
| 向导 | 字段多、有先后依赖、一次性流程 | 每步一个任务，顶部 Stepper | 添加站点 |

字段超过 7 项时**必须**分组或分步，不得把所有字段平铺在一屏。

## 2. 页面结构

```text
Breadcrumbs（面包屑：层级与返回路径）
PageHeader  （标题 + 一句话说明）
┌ Form Card ─────────────────────────────┐
│ 错误汇总（仅提交失败后出现，role=alert）   │
│ 必填说明："带 * 的字段为必填"              │
│ Fieldset「Record」  字段 …                │
│ Fieldset「Routing and caching」 …         │
│ Fieldset「Notes」 …                       │
│ 预览（只读输出，可选）                     │
├────────────────────────────────────────┤
│ ActionBar（sticky bottom）：未保存提示 · 取消 · 保存 │
└────────────────────────────────────────┘
```

- **主操作唯一**：保存在右侧，使用主色；取消为次要样式。
- **操作栏粘性固定在底部**，长表单也始终可见；窄屏下按钮自动均分一行。
- 容器宽度 ≥ 1040px 时，右侧出现帮助侧栏（取决于内容区而非视口，因此会随侧边栏展开 / 折叠而变化）。

## 3. 布局规则

| 规则 | 要求 |
| --- | --- |
| 单列 | 字段纵向排列；仅「天然成对」的短字段（如日期范围）可同行 |
| 宽度 | 表单卡片最大 720px；短字段（类型、TTL、优先级）限制为 `max-w-xs` |
| 分组 | `<fieldset>` + `<legend>`；组间 24px，并用 1px 分隔线 |
| 间距 | 字段间 16px，分组间 24px，卡片内边距 24px（窄屏 16px） |
| 条件字段 | 仅在相关时出现（MX 才出现优先级）；切换类型时清理不适用的内容 |
| 提示位置 | 标签 → 控件 → 辅助说明 → 错误；错误紧贴控件下方 |

## 4. 字段规则

### 4.1 标签与提示

- **必须**使用可见的 `<label>`；**不得**用 placeholder 代替标签（输入后即消失、对比度低、读屏体验差）。
- 必填字段在标签后加 `*`（`aria-hidden`），并在表单顶部说明含义；同时设置 `aria-required`。
- 选填字段标注 `Optional`；不要把必填 / 选填都用颜色区分。
- 辅助说明（hint）用于格式、约束、后果，通过 `aria-describedby` 关联。
- placeholder 仅用于**示例值**（如 `192.0.2.1`），颜色使用次要文字色，对比度仍需 ≥ 4.5:1；输入后即消失，因此**不得**承载必要信息。

### 4.2 输入类型与行为

| 场景 | 做法 |
| --- | --- |
| 邮箱 / URL / 数字 | 使用合适的 `type` 与 `inputMode`（邮箱用 `type=email`，数字用 `inputMode=numeric`） |
| 标识符 / 主机名 | `autoCapitalize="none"`、`spellCheck={false}` |
| 自动填充 | 设置正确的 `autoComplete`（如邮箱 `email`）；非用户资料类字段关闭 |
| 允许粘贴 | **必须**允许粘贴；并对粘贴内容做**规范化**（去首尾空白、完整主机名缩写、URL 取域名） |
| 移动端 | 窄屏输入框字号 16px，避免 iOS 聚焦自动放大；**不得**禁用缩放 |

### 4.3 控件选择

| 数据 | 控件 |
| --- | --- |
| 开关量（立即生效） | Switch（`role="switch"`） |
| 2 – 5 个互斥且需要解释 | 单选卡片（`radiogroup`） |
| 互斥且较多 | 原生 Select（移动端体验最好） |
| 多选 | 复选框组（`fieldset` + `legend`） |
| 长文本 | Textarea，带字数提示 |

## 5. 校验

### 5.1 两级校验

| 级别 | 时机 | 范围 | 展示 |
| --- | --- | --- | --- |
| 第一级（字段级） | 字段**失焦**后；之后每次输入即时更新 | 格式、必填、长度 | 字段下方的行内错误 |
| 第二级（提交级） | 点击保存 | 全部字段 + 跨字段规则 | 顶部错误汇总 + 行内错误；焦点移到第一个错误字段 |
| 服务端级（可选） | 提交后返回 | 唯一性、冲突、权限 | 映射回对应字段；无法映射时显示在汇总中 |

原则：**晚惩罚、早奖励**——用户输入过程中不打断；失焦后才报错；一旦报错，修正时立即消除。

### 5.2 首错聚焦与错误汇总

1. 提交失败时，按 DOM 顺序找到第一个出错字段，调用 `focus()`（并通过 `scroll-padding` 避免被粘性栏遮挡）；
2. 同时显示错误汇总（`role="alert"`），列出全部问题，每条可点击跳转到字段；
3. **已填写的内容必须全部保留**，不得清空表单；
4. 汇总标题写明数量：「2 个问题需要处理」。

### 5.3 错误文案公式

> **哪里错了 + 为什么 + 如何修正**，使用具体示例，不使用「输入无效」。

| 反例 | 正例 |
| --- | --- |
| Invalid input | Enter a valid IPv4 address, for example 192.0.2.1. |
| Error | A CNAME record cannot share a name with other records. “www.myexample.com” already has an A record. |
| Required | Enter a name. Use @ for the root domain. |

### 5.4 无障碍关联

- 出错控件设置 `aria-invalid="true"`，并通过 `aria-describedby` 指向错误文案；
- 行内错误使用 `role="alert"`，在出现时被读屏播报；
- 错误不得**只**依靠颜色表达：同时有图标与文字、边框加粗。

## 6. 状态与反馈

| 状态 | 表现 |
| --- | --- |
| 默认 / 悬停 / 聚焦 | 边框加深 / 2px 聚焦环（偏移 2px），**不得**移除 outline 而无替代 |
| 错误 | 红色边框 + 图标 + 文案 |
| 禁用 | 仅用于「因其他选择而不适用」，并必须在旁边**说明原因**（如代理开启时 TTL 固定为 Auto） |
| 保存中 | 按钮显示 Spinner 与「Saving…」，`aria-busy`；使用 `aria-disabled` 并在提交函数里防重复，保持焦点不丢失 |
| 成功 | 非阻塞通知（Toast，`aria-live=polite`）+ 回到列表并高亮新记录 |
| 失败 | 保留输入，错误映射回字段，焦点移到相关字段 |

**不得**用「禁用提交按钮」代替校验：用户无法得知为什么不能提交。

## 7. 保存策略

| 策略 | 适用 | 示例 | 必须说明 |
| --- | --- | --- | --- |
| 显式保存 | 多字段、有依赖、可能出错 | 添加 / 编辑记录、加密模式 | 修改后出现保存条；提供「放弃」 |
| 即时生效 | 单一开关、可逆、低风险 | Always use HTTPS | 在描述中写明「立即生效」，并给出通知 |

两者**不应**混在同一分区内；若同页并存，必须从文案上区分。

## 8. 离开保护

- 表单有未保存修改（`dirty`）时：
  - 站内导航（侧边栏、面包屑、取消）弹出确认对话框：「放弃未保存的修改？」默认焦点在「继续编辑」；
  - 刷新 / 关闭标签页使用 `beforeunload`。
- 保存成功后立即解除保护，否则跳转会被自己拦截。
- 确认对话框使用原生 `<dialog>`，默认焦点在非破坏性按钮上。

## 9. 危险操作

- 放在页面底部独立区域，使用危险色描边，**远离首屏**；
- 必须二次确认；高风险（删除站点）要求**输入对象名称**确认；
- 确认按钮**保持可点击**，输入不匹配时通过校验信息说明，而不是禁用；
- 可撤销的操作（删除记录）提供「撤销」通知，且停留时间更长（8 秒）。

## 10. 向导（分步表单）

- 每步只做一件事；顶部 Stepper 使用 `<ol>` + `aria-current="step"`；
- 窄屏下 Stepper 退化为「Step 2 of 3：Plan」文字 + 进度条；
- 切换步骤时焦点移动到步骤标题（`tabIndex=-1`），读屏用户知道已进入新步骤；
- 「Continue」按步校验；最后一步为 Review，汇总并允许逐项回改；
- 步骤间的输入**不得丢失**；中途离开有保护。

## 11. 响应式表现

| 宽度 | 表现 |
| --- | --- |
| 容器 ≥ 1040px | 表单 + 右侧帮助侧栏 |
| 720 – 1039px | 单列表单；设置页行布局左右分栏 |
| < 720px | 设置页堆叠；短字段占满宽度（`max-w-xs` 在 < 640 时无意义） |
| < 640px | 控件高度 44px、字号 16px；操作栏按钮均分整行 |
| 300px | 无横向滚动；长文本使用 `break-words` / `overflow-wrap:anywhere`；预览块在自身内部换行 |

## 12. 传统方案 vs 改进方案

设计稿的「传统方案」刻意保留了常见缺陷，可用「并排对比」逐项观察：

| 维度 | 传统方案 | 改进方案 |
| --- | --- | --- |
| 标签 | 仅 placeholder | 可见标签 + 说明 |
| 布局 | 所有字段横排一行，固定宽度 | 单列分组，流式宽度 |
| 校验 | 提交按钮置灰；错误只写「Error」 | 两级校验，具体文案，首错聚焦 |
| 保存 | 无防重复；无反馈 | Spinner、通知、列表高亮 |
| 离开 | 直接丢失 | 未保存确认 |
| 窄屏 | 横向溢出 | 单列，操作栏均分 |

## 13. 检查清单（验收）

- [ ] 每个控件都有可见标签；必填有标记和说明
- [ ] 可以粘贴；粘贴的完整主机名 / URL 被规范化
- [ ] 未填写直接提交：出现汇总，焦点在第一个错误字段，已填内容保留
- [ ] 失焦前不提前报错；失焦后随输入实时更新
- [ ] 错误文案包含原因与修正方式
- [ ] 保存按钮在校验失败时仍可点击；保存中防重复提交
- [ ] 修改后离开会确认；保存后不会被拦截
- [ ] 危险操作在页面底部，且需要二次确认
- [ ] 300 / 390 / 768 / 1440 宽度下均无横向滚动，操作栏可见
- [ ] 全键盘可完成：Tab 顺序合理，焦点环可见

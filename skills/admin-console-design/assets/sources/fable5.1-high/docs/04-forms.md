# 04 · 表单

本篇覆盖四种表单形态：**内联表单**（表格行内新增/编辑，如 DNS 记录）、**长表单**（Create application）、**向导**（Add a domain）、**设置卡片**（Settings）。

## 1. 字段结构

每个字段统一由 `Field` 包装：

```
┌ label (必填 * / optional) ──────────── labelAside (计数器等) ┐
│ control (input / select / textarea / toggle / radio-cards)   │
│ hint（灰）  或  error（红 + 图标, role=alert）                │
└──────────────────────────────────────────────────────────────┘
```

### 必须

- 标签可见且 `<label for>` 关联；**不得**用 placeholder 代替标签。
- 错误文本通过 `aria-describedby` 关联到控件，并设置 `aria-invalid="true"`。
- 必填用 `*` 标记，并以 `required` 语义或说明文字补充；可选字段标注 `(optional)`。
- 控件高度 36px（触屏命中区 ≥ 44px 时使用 `size="lg"`）。
- 允许粘贴、允许浏览器缩放、允许自动填充（除非安全原因并说明）。

### 应该

- 提示文字（hint）说明格式与示例：`Use @ for root`、`e.g. 192.0.2.1`。
- 带长度限制的字段显示 `n/limit` 计数器，超限变红。
- 技术输入（IP、域名）使用等宽字体并关闭拼写检查。
- 字段的"派生信息"实时显示（如输入 `www` 时提示 `Resolves as www.myexample.com`）。

### 避免

- 占位符颜色过浅（对比度 < 4.5:1）。
- 禁用粘贴、`inputmode` 错配（数字字段应 `inputMode="numeric"`）。

## 2. 布局栅格

| 宽度 | 列数 | 规则 |
| --- | --- | --- |
| < 640 | 1 | 全部单列；按钮组纵向堆叠，primary 在最上（`flex-col-reverse`） |
| 640–1023 | 6 | 短字段（Type、TTL、Priority）占 2–3 列，长字段占 6 |
| ≥ 1024 | 12 | 内联表单：Type 2 · Name 4 · Content 6 · Proxy 4 · TTL 2 · Comment 12 |

### 必须

- 表单 **单列为默认**；只有在 ≥ 640px 且字段短、语义相关时才并列。
- 字段 ≥ 7 项必须分组（卡片 + 标题），长表单 ≥ 3 组时提供右侧粘性大纲（≥ 1024px）。
- 操作区：`Cancel` 在 `Save` 左侧；破坏性按钮（Delete）在最左侧并与保存区分开。
- 页面级无横向滚动；所有字段容器 `min-width: 0`。

## 3. 两级校验

| 级别 | 触发 | 表现 |
| --- | --- | --- |
| 字段级 | 控件 `blur`（首次触碰后实时） | 字段下方错误文本 |
| 表单级 | 点击提交 | 顶部 `Alert(danger)` 汇总 + 所有字段显示错误 + **聚焦首个错误** |

### 必须

- 提交失败 **保留所有已填内容**。
- 首个错误控件 `focus()` 并 `scrollIntoView({block:"center"})`。
- 表单使用 `noValidate`，由应用控制错误文案的一致性。
- 不以"禁用提交按钮"替代校验（允许点击并解释为什么失败）。向导的"Continue"同理。
- 跨字段 / 跨记录规则在提交前校验（示例：`CNAME` 不能与同名其他记录共存；重复记录）。

### 应该

- 校验函数纯函数化（`validateRecord(values, existing)`），同一函数服务于字段级和表单级。
- 错误文案 = "是什么错 + 怎么改"：`Enter a valid IPv4 address, e.g. 192.0.2.1.`
- 汇总 Alert 中的每条错误可点击跳转到对应字段。

### 可以

- 保存时按钮 `loading` + `aria-busy`，禁止重复提交。
- 存在未保存修改时监听 `beforeunload`。

## 4. 内联表单（表格行内）

- "Add record"：在表格上方插入高亮卡片（主色边框），聚焦第一个控件；表格保持可见，便于参照现有记录。
- "Edit"：该行被替换为表单（`colSpan` 全宽，浅蓝底）；同一时刻只允许一个编辑态。
- 保存成功：关闭表单、toast 反馈、焦点回到触发按钮（新增）或保持在表格。
- 删除按钮只出现在编辑态内，且弹出确认。

## 5. 长表单（Create）

- 分组卡片 `id` 即锚点，`scroll-margin-top` 预留顶栏高度。
- 右侧粘性大纲（`position: sticky; top: topbar + 24px`）：IntersectionObserver 滚动监听高亮当前节；每节显示错误数角标。
- < 1024px 时大纲隐藏，改用 **底部粘性操作条**，仅在表单 dirty 时滑入。
- 单选"卡片"（RadioCards）用于互斥且需要解释的选项（环境、源类型），≤ 4 项；更多用 `select`。
- 标签输入（Tags）：Enter / 逗号添加，Backspace 删除末项，上限明确。

## 6. 向导（Wizard）

- 适用：步骤间存在依赖、每步决策需要解释、总字段数多且顺序固定。
- 顶部线性进度（已完成 ✓ / 当前 / 待办），已完成步骤可点击回退。
- Back 永不丢数据；最后一步是只读 Review。
- 切换步骤后将焦点移到步骤标题（`tabindex=-1`），屏幕阅读器可感知。

## 7. 设置卡片（Settings）

- 一卡一决策：`CardHeader` 说明 → 控件 → `CardFooter`（左侧状态文字，右侧 Save）。
- 即时生效的开关（Toggle）不需要 Save，但 **必须** 通过 toast 反馈。
- 有 Save 的卡片只有 dirty 时才启用 Save；提示文字由 `Saved` 变为 `You have unsaved changes.`
- 危险区置于页面最底部，红色描边，每项"说明 + 后果 + 次级红色按钮"。

## 8. 确认对话框

- `Dialog(tone="danger")`：标题为问句，描述说明后果，主按钮为动词。
- 移动端从底部滑入（`rounded-t-lg`），桌面居中。
- 焦点陷阱、`Esc` 关闭、关闭后焦点还原到触发元素。
- 高风险：要求输入资源名称，匹配前主按钮禁用（这是允许禁用按钮的例外场景——用户已被明确告知要输入什么）。

## 9. 速查表

| 项目 | 规则 |
| --- | --- |
| 输入框高度 | 36px；触屏 44px |
| 标签-控件间距 | 6px |
| 字段间距 | 16px |
| 错误颜色 | `--c-danger`，附图标，不单靠颜色 |
| 按钮顺序 | [Delete] …… [Cancel] [Primary] |
| 窄屏按钮 | 纵向堆叠，primary 在上 |
| 提交后焦点 | 首个错误控件 / 触发按钮 |

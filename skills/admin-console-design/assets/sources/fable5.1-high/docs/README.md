# 控制台 UI 设计规范（参考 Cloudflare Dashboard）

> 本文档集描述一套面向"管理控制台 / 后台面板"类产品的设计与交互规范。规范以 Cloudflare Dashboard 的成熟实践为参照，抽象为可直接落地的规则，并附带一个可运行的模拟设计稿（本仓库的 Web 程序）作为综合案例。

## 1. 适用范围

- 面向运维、开发者、管理员的 B 端 Web 控制台（域名/DNS、安全、网络、计费等）。
- 桌面优先，但要求在 320px～2560px 全宽度范围内可用；极端窄窗（300px）要求"可回流、不溢出"。
- 浅色 / 深色 / 跟随系统三种外观。

## 2. 规范用语

| 用语 | 含义 |
| --- | --- |
| **必须 (MUST)** | 不满足即视为缺陷，评审不通过。 |
| **应该 (SHOULD)** | 默认遵循；偏离需在设计评审中说明理由。 |
| **可以 (MAY)** | 可选做法，视场景采用。 |
| **避免 (AVOID / NEVER)** | 明确禁止或强烈不建议的做法。 |

## 4. 设计思路概述

1. **一个页面做一件事。** 页面标题下的首屏只呈现主任务（如"DNS 记录表格"），次要信息折叠（如"Recommendations"可收起）。
2. **壳层稳定，内容流动。** 顶栏 + 侧边栏构成稳定的壳层；侧边栏在桌面端可固定/折叠，折叠时悬停临时展开（覆盖而非推挤内容），内容区不因导航状态变化而重排。
3. **令牌先行。** 所有组件只消费语义令牌（`--c-surface`、`--c-text-2`…），主题切换只替换令牌值。
4. **表单先线框后样式。** 字段分组（≤7 项一组）、单列优先、宽屏才并列；校验分"失焦即时 + 提交汇总"两级；提交失败保留已填内容并聚焦首个错误。
5. **破坏性操作远离首屏 + 二次确认。** 删除放在编辑态的最左侧或页面最底部的"危险区"，并经模态确认（高风险要求输入名称确认）。
6. **无障碍是底线而非加分项。** 全键盘可达、可见焦点、≥24px 命中目标、4.5:1 对比度、尊重 `prefers-reduced-motion`。

## 5. 如何阅读本模拟稿

- 左侧侧边栏 **Design Guide** 分组列出全部文档；**Responsive Lab** 可在任意宽度下预览所有页面并自动扫描宽度。
- 顶栏右侧可切换 浅色 / 深色 / 跟随系统。
- 快捷键：`Ctrl/⌘ + K` 打开快速搜索；`[` 切换侧边栏固定/折叠；`Esc` 关闭任何浮层。

## 6. 验收清单（摘要）

- [ ] 390 / 768 / 1440 三档宽度无横向滚动、无元素挤压溢出；320px 可回流。
- [ ] 侧边栏四态（固定 / 折叠 / 悬停展开 / 移动抽屉）切换平滑，键盘可操作。
- [ ] 每个表单：可见标签、失焦校验 + 提交汇总、首错聚焦、保留已填内容、允许粘贴。
- [ ] 所有危险操作有二次确认；删除后提供撤销或明确不可恢复提示。
- [ ] 浅色 / 深色对比度均 ≥ 4.5:1；Tab 顺序合理；焦点环可见。
- [ ] 无 `alert()`、无 `div onClick` 假按钮、无仅 hover 可达的功能。

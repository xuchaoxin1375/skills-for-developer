# 01 · 设计原则

本篇定义控制台产品的顶层设计原则。后续各篇（壳层、表单、表格、响应式、无障碍）均是这些原则在具体场景的展开。

## 1. 任务清晰

### 必须

- 每个页面有且只有一个 `h1`，用一句话说清"对象 + 动作"，例如 `DNS records for myexample.com`。
- 标题下方一句描述（≤ 2 行）回答"这个页面能做什么"。
- 首屏只做一件事：主操作按钮 **≤ 3 个**，其中 **仅 1 个** 使用 primary 样式（如 `Add record`）。
- 危险操作（删除、暂停、移除站点）**不得**出现在首屏主操作区；必须放在编辑态内部、行菜单或页面底部的"Advanced actions / 危险区"中，并经二次确认。

### 应该

- 页面级的"状态/提示"（如域名 Pending）使用 `Alert` 横幅置于标题之下、内容之上，可关闭。
- 次要信息（推荐、统计）使用可折叠卡片，默认状态由信息价值决定（"All set"时默认收起）。
- 操作结果通过非阻塞 `toast` 反馈，且删除类操作提供 **Undo**。

### 可以

- 对首次访问者提供"Setup checklist"等引导卡片。
- 使用"Recents"记录最近访问的页面，缩短跨区域往返路径。

### 避免

- 一个页面同时承载两个主任务（例如既是列表又是复杂设置）。
- 使用 `alert()` / `confirm()` 原生弹窗。
- 用禁用提交按钮替代校验反馈（用户不知道为什么不能提交）。

## 2. 布局克制

### 必须

- 页面类型四选一：**仪表盘**（Overview）、**列表 + 详情/内联编辑**（DNS records）、**单列表单**（Create / Wizard）、**设置页**（Settings）。不混用。
- 间距只使用 `4 / 8 / 12 / 16 / 24 / 32 / 48` px。
- 内容区最大宽度 1440px 居中，左右内边距：移动 16px，平板 24px，桌面 32px。
- 先确认线框（信息层级、折行策略）再写样式。

### 应该

- 卡片（Card）是唯一的内容容器；卡片内部不得再嵌套卡片（用分割线或分组标题替代）。
- 卡片结构固定：`CardHeader(title, description, actions)` → `CardBody` → `CardFooter(note, actions)`。
- 工具栏遵循"搜索框居左伸缩，操作按钮居右，primary 在最右"。

### 避免

- 卡片套卡片、满屏毛玻璃、纯装饰性渐变、标题 emoji。
- 为了"看起来丰富"添加无数据支撑的图表占位。

## 3. 信息层级

| 层级 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| 2xl | 28 / 36 · 600 | 页面标题 |
| xl | 20 / 28 · 600 | 统计数值、对话框标题 |
| lg | 16 / 24 · 600 | 卡片标题 |
| base | 14 / 22 | 正文、表格、输入框 |
| sm | 13 / 20 | 辅助说明、标签 |
| xs | 12 / 18 | 提示、错误、脚注 |
| 2xs | 11 / 16 | 徽标、快捷键 |

- 字号阶梯 **≤ 7 档**；中英混排行高 ≥ 1.6（本规范正文 14/22 ≈ 1.57，段落用 1.6）。
- 颜色层级三档：`text`（主要）、`text-2`（次要）、`text-3`（辅助/占位）。图标默认取 `text-3`，激活态取 `text`。

## 4. 反馈模型

| 场景 | 组件 | 位置 | 是否阻塞 |
| --- | --- | --- | --- |
| 字段错误 | 字段下方红字 + 图标 | 字段内 | 否 |
| 表单提交失败汇总 | `Alert(danger)` | 表单顶部 | 否 |
| 操作成功 / 信息 | `toast` | 右下角（移动端底部全宽） | 否，5s 自动消失 |
| 操作失败 | `toast(error)`，`role=alert` | 同上 | 否，8s |
| 破坏性确认 | `Dialog(tone=danger)` | 居中（移动端底部抽屉） | 是 |
| 页面级状态 | `Alert(warning/info)` | 标题下 | 否 |
| 长任务 | 按钮 `loading` + `aria-busy` | 就地 | 局部 |

### 必须

- 确认对话框的主按钮文案是动词（`Delete`、`Pause site`），不是 `OK`。
- 高风险操作（移除站点）要求输入资源名称后才启用确认按钮。
- 删除后的 toast 提供 `Undo`，或在确认框中明确"不可恢复"。

## 5. 一致性

- 先写令牌再写样式（见 02）。
- 一套图标库（lucide），尺寸 16 / 18 / 20 三档。
- 同一动作在全站使用同一文案与同一位置（"Edit" 永远在行最右；"Cancel" 永远在 primary 左侧）。

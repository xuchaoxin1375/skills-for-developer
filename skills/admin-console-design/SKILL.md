# 后台控制台设计

把已调整的参考稿作为可复用模板：新建与风格迁移默认保留所选模板的设计和交互，通过内容、配置与业务接线适配。可选整体主题，也可仅选侧栏、可编辑列表或表单等完整单元；选中的部分仍按模板复用，不逐处重新设计。三工程是 **Cloudflare-inspired 独立设计样例**，不是 Cloudflare 官方组件或规范，也不是通过生产验收的成品。

默认偏好：**fable 外壳、导航区域与 DNS 页面整体设计**；列宽和本地 Undo 可参考 sonnet，导入校验及验收案例可参考 gpt。保持一套视觉语言，明确补充模块与适配理由；不要逐个按钮随意拼出第四种风格。用户指定的模板和任务范围优先；指定模板区域内按模板复用，范围外沿用既有设计系统。

## 按任务选工作量

- **咨询/评审**：读取相关参考，给结论、依据、问题和改法；不要求重建页面、演示实验室或固定六节报告。
- **新建**：选外壳与页面模式、观察参考状态、复用相关源码及样式、对接功能、验证核心路径。
- **存量局部改版/修复**：先记录原有路由、数据、权限、事件和操作的去向，在可回退的改动中替换目标区域；完成接线后移除旧样式与旧状态。
- **完整模板迁移**：选定主题或局部模板，以参考实现构建新单元，再接业务契约；默认继承其结构、样式、控件和交互细节，可整体替换旧组件树与状态。选定区域不受旧DOM或组件外观约束，执行[完整模板迁移](references/cf-customization-guide.md#完整模板迁移)；删除旧实现是可选手段，还原质量由目标对照验证决定。
- **指定还原**：按指定来源和保真程度执行；同视口、主题、数据和状态对照截图。改变其交互或尺寸时说明影响，不能用“做了相似布局”冒充还原。

概览、列表/详情、表单/设置/向导是常见页面模式，可组合或扩展；**Shell 是共有外壳，不是与内容页互斥的第四种页型**。复杂详情、审计、工作台等按真实任务组织，不强迫四选一。

## 实施顺序

1. **明确页面与契约**：当前资源、导航分组、主任务、关键操作、保存方式、数据规模和风险，划定采用的模板单元。模板范围外的能力按业务需要添加；选定单元内的控件和交互默认保留，明确不适用时才裁剪并处理连带状态。
2. **确定基底并看成品**：选择一个整体来源；实现交互时打开产物或目标应用，查看相关状态。浏览器脚本可代替手工点击，不要求两者重复。仅咨询或不相关的小改动无需跑全套原型。
3. **复用完整交互单元**：连同样式、状态、校验、焦点、依赖一起迁移；先对照令牌、路由、存储键和事件，再接业务。同栈优先使用实际源码；技术栈不兼容时连同视觉结构和行为契约移植，说明必要差异。已知参考缺陷必须修正，不能为了保真一起搬入。
4. **保持视觉一致**：宽度、间距、图标、时序采用同一基底。参数原值可以保留；有业务/容器/无障碍理由才调整，不同时保留互斥定义。不要强制把所有稿改成一组凭空“收敛”的数值。
5. **验证目标实现**：测试涉及的关键路径和失败恢复，记录真实输入、版本与结果。声称“参考行为已复用”须有目标中的行为证据；截图证明外观，构建证明可构建，都不能代替交互测试。

## 交互底线

- **导航**：采用 Rail/peek 时，占位槽只由固定偏好和布局决定，临时展开只覆盖、不推挤内容。键盘与触屏都有入口；手动收起后不会立即弹回。隐藏子项不可聚焦，Rail 主入口仍可 Tab 且有可访问名称。
- **列表**：宽内容在表容器内滚动，不把整页撑宽；横滚仍能操作关键行按钮，粘性格用不透明背景。选择范围、分页、筛选后的选中状态明确。有列宽调节才要求边界、键盘等价、还原和持久化。
- **编辑与保存**：可见标签、错误关联、提交错误定位和保留输入；不要只靠置灰表达输入不合法。提交中、无改动、无权限等可禁用并说明原因。并存的行内/弹窗共享编辑与校验逻辑，不强制每页提供两种。
- **恢复与风险**：值得保留的未提交输入有草稿或离开保护，保存成功才清除。可撤销操作真正恢复数据；服务端删除不能靠 localStorage 快照冒充 Undo。不可逆或高风险操作明确后果并确认，默认焦点在安全选项。
- **可访问与反馈**：键盘可完成核心操作，浮层焦点可进入和返回，模态背景不可交互。关键状态有文字/图标，正文对比度至少 4.5:1、必要控件边界至少 3:1；主题和 reduced-motion 不破坏任务。成功、失败和进行中均有可理解结果。

列表默认随文档滚动；工作台需要固定高度或表内滚动时明确滚动所有者、尺寸约束和焦点路径。分页、虚拟化、表内滚动按数据与场景选用，不要求所有列表塞进一屏。

## 验证与交付

默认检查宽屏、平板、手机（1440/768/390），回流到 320；300px 用作需要极窄支持时的压力检查。改断点时补交界两侧；组件使用实际容器宽度。涉及主题、浮层、侧栏或表格时补相应状态，不机械跑全状态笛卡尔积。

记录 **通过 / 失败 / 未执行 / 不适用**，不适用写业务理由；缺浏览器只能写未执行，不能称通过。无自动化时手工验证可作为证据，明确方式和覆盖。原型通过的测试不能自动算目标通过。

输出随任务规模包含：基底与差异、实际改动/关键决策、验证结果、已知问题。实现/还原任务附同条件全景与关键状态截图；咨询无需伪造截图或令牌 diff。

交付前确认：模板依赖和功能接线齐全；参考缺口已处置；旧状态/样式无冲突；核心操作和失败恢复实测；证据与当前版本一致。完整模板迁移另确认：选定单元及依赖齐全？设计默认继承且差异有依据？成对截图检查了整体观感及细节累计偏差，交互证据覆盖关键状态？页面缺陷深查可用 `frontend-ux-qa`，通用收纳可用 `adaptive-responsive-guide`，不自动叠加其他 skill 全套程序。

按需读 [交互心智](references/cf-intuition-map.md)和[设计分析](references/cf-design-analysis.md)。它们解释偏好，不额外创设审批、固定页型或功能清单。

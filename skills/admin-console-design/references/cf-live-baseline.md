# Cloudflare 列表实况基线

2026-11-25 对登录态 DNS records 页做的只读取样。这里记录**实际页面**的几何、控件和交互，不是三套参考工程的复述，也不是 Cloudflare 官方规范。设计适用于带表头的数据呈现，不要求使用 `<table>` 元素；原生 table 与 div ARIA table 的选型见“DOM 形态”。Cloudflare 是基准而不是封顶：文末把可保留、可增强的部分单列，避免为了保真把已有优点一起削掉。

## 取样与边界

- 环境：Microsoft Edge 157.0.0.0（Chromium 157，Windows 10/11 x64），DPR 1，100% zoom，light theme，登录态；视口 1645×907、1280×900、1024×900、768×900、760/752/750/735、390×844、320×700。
- 方法：读取 computed style、元素矩形、菜单与卡片 DOM；在临时副本里测试排序、悬停、横向滚动和断点，没有保存或修改任何记录。
- 未覆盖：Firefox/WebKit、深色主题、读屏、真实触屏、真实网络错误态。数值会随 Cloudflare 版本变化，精确还原前重新取样。

## 页面环境

| 项 | 实况 |
|---|---|
| 顶栏 | 高 58px，sticky，底边 1px 发丝线 |
| 侧栏 | 桌面 56px 图标 rail；窄屏收为抽屉，顶栏出现菜单按钮 |
| 内容边距 | 桌面左右 32px；约 768px 以下 16px |
| 页标题 | 30px/600，行高 36px；更紧凑的控制台可用 24/600，但同一产品保持一致；资源名过长时换行，不压按钮 |
| 页面区块 | 标题区、提示卡、工具栏、表卡之间以 24–32px 级间距分隔 |

列表页的主内容宽度跟随可用空间，不设固定 max-width；表卡占满内容区，靠列压缩与表内横滚适配。是否设上限由字段密度决定，短列表不要无限拉伸；1440px 居中只是案例起点，不是 CF 实况值。

顶栏 58px、rail 56px 和内容边距是本次取样的上下文，不覆盖 [外壳与侧栏](shell-sidebar.md) 的 fable 参数，也不表示所有控制台都要改成这组值。

## 工具栏

| 项 | 实况 |
|---|---|
| 控件高度 | 36px |
| 圆角 | 8px |
| 文本 | 14px/500 |
| 内边距 | 左右 12px；带前置图标时左侧 10px |
| 间隔 | 8px |
| 边框/阴影 | 1px 黑色 10% 环 + `0 1px 2px rgb(0 0 0 / 0.05)` |
| 搜索框 | 目标宽约 500px，空间不足时收缩；高 36px |

折行顺序按实际宽度收敛，不把主操作挤到视口外：

- 宽屏：搜索、Filters、Display options、Import、Export、Add record 同一行。
- 约 1024px：搜索 + Filters + Display options 一行，Import/Export/Add 一行。
- 约 768px：搜索 + Filters 一行，Display options 一行，Import/Export/Add 一行。
- 约 750px 以下：搜索独占一行；Add record 保留图标 + 文字；Import/Export/Filters 收成图标按钮并保留可访问名称；Display options 在实况中直接消失，这是需要补的缺口，不是可复制行为。

## 表卡、表头与行

| 项 | 实况 |
|---|---|
| 表卡 | 8px 圆角，1px 黑色 10% 环，`0 1px 2px rgb(0 0 0 / 0.05)` 阴影，`overflow: clip`；宿主已有 12px 圆角可沿用，不叠厚阴影 |
| 配额行 | 约 40px 高，`padding: 8px 16px`，14px 文本 |
| 表头 | 40px 高，浅色白底（深色未取样，用对应 surface/raised 色），14px/500，`padding: 0 12px`，底边 1px 发丝线 |
| 表头文字 | 标签本身是普通文本；排序图标独立；标签与说明图标间距 4–6px |
| 表头分隔 | 可调列右缘只有 2×20px 短竖线；目标可延伸为全表头高 1px 低对比线，便于识别拖动位置，表体仍不画竖线 |
| 行 | 40px 高，14px 正文，`padding: 0 12px`，底边 1px 发丝线 |
| 行悬停 | 近白灰底，约 `oklch(0.9875 0 0)`；不是整行蓝色 |
| 行选中 | 中性浅灰，约 `oklch(0.97 0 0)`；选中态主要由复选框和批量条表达 |
| 空值 | 居中或左对齐的 `—`，不显示空白 |
| 名称 | 主机名部分深色/500，域名后缀弱灰/400；整段 `truncate`，带 `title` |
| 操作 | 粘右列约 64px 宽，只有一个 36px 高的 `Edit` 按钮；删除收进编辑层 |
| 表尾 | 32px 高，`padding: 8px 16px`，顶边 1px 发丝线，14px 文本 |

表格没有斑马纹，表体没有列间竖线，表头只保留列宽把手的短竖线；视觉分隔主要靠行底边和表头底边。这也是默认规范：表体垂直网格线默认不画；表头是例外，可调列右缘保留可见分隔线（CF 只有 2×20px 短竖线，目标可用全表头高 1px 低对比线），便于识别拖动位置。不要把表头线延伸成表体网格线；首列和末列也不例外，粘性勾选列／操作列用不透明背景和滚动遮挡时的阴影，不画常驻竖线，末列操作列的左线单独取消。用户明确偏好时可在表体加低对比竖线，并保持同一表统一。浅色下表头背景与表体同为白色，不像 sonnet 参考那样使用灰色表头条；深色主题未取样，按对应 surface/raised 色验证。

40px 是实况的密集基线，不是固定 `height`：含 36px 控件或多行内容时让行高由内容撑开，不裁文字或错误说明。

名称的 `title` 只是补充；完整值要能通过聚焦、展开或复制获取。CF 移动卡片把整卡做成按钮，会妨碍文本选择并容易误触编辑；目标优先显式展开按钮，并在摘要区保留文本选择。选择列 44px 是鼠标基线；触屏优先 64px 或保证至少 44×44 命中区，不能把列宽当命中区。

### DOM 形态

DNS 表不是原生 `<table>`，而是 `div` 组合的 ARIA table：容器 `role="table"`，行 `role="row"`，列头 `role="columnheader"`，单元格 `role="cell"`，并带 `aria-colindex`/`aria-rowindex`/`aria-sort`。列宽用每列的 CSS 变量（`--col-*-size`）控制；表头与表体分开滚动后同步，操作列粘右。

这说明视觉规范不依赖元素：原生 `<table>` 是默认实现；需要独立表头/表体滚动、虚拟化或复杂粘性时，可以用 div + 完整 ARIA table。选择 div 就要自己补齐语义、键盘、列对齐、滚动同步和窄屏回流；只画 div 不补这些不算完成。普通列表不要用 `role="grid"` 冒充表格，除非实现完整网格键盘协议。

## 列宽、排序与列说明

### 列宽把手

- 热区 10px 宽、整表头高；fable/sonnet 参考分别是 8px/12px 热区，8/32 是 sonnet 的键盘步长，不是热区。
- 可见线 2px 宽、20px 高、4px 圆角，颜色是发丝线灰；始终显示，悬停不变 accent，未观察到聚焦/拖动强调。
- 只给部分列提供把手；固定功能列没有。
- 实测没有键盘调宽：聚焦把手后 `←`／`→`、`Home`、`Enter` 都不改变宽度。
- 实测拖动后刷新回到自动宽度，未发现本地列宽持久化。
- 实况没有非拖动的宽度入口；目标需在 Display 中补数值框、±8px 和恢复。WCAG 2.5.7 的单指替代不能只用键盘等价满足。

因此列宽交互不要把 Cloudflare 当实现范本；把手视觉可以取，键盘、边界、持久化按 sonnet 单元补。

### 排序

- 三态循环：升序 → 降序 → 取消。
- `aria-sort` 放在 `th`，值为 `ascending`／`descending`／`none`。
- 未激活用 14px 双箭头弱灰；激活用 14px 单箭头深色。
- 标签文本不可点，只有 14px 图标按钮可点；命中区很小，不应照抄。视觉可以保持“标签 + 独立图标”，命中区至少扩到 24×24，或让整格可点。

### 列说明

- 部分列在标签旁有 14px 弱灰 info 图标。
- tooltip 内容约 13px，`max-width: 384px`，内边距 `6px 10px`，6px 圆角，`shadow-md`，带 1px 发丝外框。
- 说明只用于领域含义不直观的列，不是每列都加；图标本身也要扩命中区。

| 项 | 实况 |

| 菜单宽 | 173px |
| 菜单内边距 | 6px |
| 行高 | 33px |
| 行文本 | 14px/400，左侧 32px 复选位，圆角 6px |

| Reset | 12px/500，26px 高，无变更时禁用；位于 `Edit columns` 组，未观察到独立的列宽重置入口 |

列显隐切换后表格立即重排；隐藏列不会保留占位。Cloudflare 的 Display 中没有密度、列宽重置和列顺序，这些是本地可以增加的扩展，但应沿用这套紧凑几何，而不是另做一套大面板。

## 选择与批量

### 桌面

- 勾选列 44px 宽，复选框 16×16；通过伪元素扩到约 40×32 的命中区。
- 全选在表头，支持部分选中。
- 选中后，在配额行与表头之间出现内联选择条，约 48px 高，不覆盖表格。
- 选择条内容：`N of M selected`、`Clear selection`、`Select all N eligible records`；右侧 `Edit N records` 次按钮和 `Delete N records` 危险按钮，均为 36px 高。
- 勾选列在实况里**不粘左**，横向滚动会滚出视野；右侧操作列粘右。
- 实况保留跨筛选选择，但批量只作用于当前匹配子集，隐藏选择数量没有完整展示；目标要显示隐藏数量并明确目标范围。
- 实况的内联选择条会把表头与行下推约 40–48px；在 Shift 连选或连续点击时会造成点击位置变化。目标默认用底部浮动条并预留空间；只有预留固定槽位、行位置不变时才使用内联条。

### 移动

- 卡片没有全选；只有每张卡左上角的单选复选框。
- 选中后出现蓝色选择块，约 86px 高、两行：第一行数量、`Clear`、`Select eligible (N)`；第二行 Edit 与 Delete 两个 36px 按钮。
- 选择块在工具栏与配额之间占正常文档流，不遮卡片；它同样会推动下方内容，采用时按内联选择条的同一规则处理。

## 窄屏卡片

- 切换阈值：视口 752px 已切卡片，760px 仍为表格；切换点在 752–760 之间，内容宽约 720–728px，按容器实测，不要当固定断点。
- 列表容器：上下 8px、卡片间距 8px。
- 卡片：8px 圆角、1px 环、`shadow-xs`、12px 内边距、8px 字段间隔。
- 顶部行约 26px：16px 复选框、类型徽章、代理状态、26×26 的 `...` 操作按钮。
- 类型徽章：约 26×25px，全圆角，14px/500，`padding: 2px 8px`。
- 名称：14px/500；域名后缀 14px/400 弱灰；内容 14px/400 深色；行高 21px。
- 代理状态：13px/400。
- 底部摘要行：约 37px 高，`padding: 8px 12px`，浅灰底，显示 `TTL Auto` 与展开箭头。
- 整卡是 `role="button"`、`aria-expanded`；点击展开为行内编辑表单，包含 Name、Type、IPv4、Proxy、TTL、Record Attributes、Save/Cancel/Delete。
- 移动卡片没有排序、Display、全选入口；这是实况缺口，目标应另给等价入口。

卡片不是把桌面每一列堆成“标签＋值”。它只保留身份、主值、状态和一条摘要，其余靠展开。字段一多时，这是比长卡片更可用的形态。

## 横向滚动与粘性

- 容器足够宽时，列先压缩到各自最小宽度，不立即出现横向滚动。
- 容器不足时，表体出现横向滚动；表头保持 sticky，并与表体同步横移。
- 操作列粘右，背景不透明；勾选列在实况中不粘左。
- 实测 1024px：表体可视 903px、内容 1138px；表头继续可见，Edit 仍在右侧。
- 768/760px 仍是表格；752px 及以下切卡片，切换点在 752–760 之间。
- 页面本身不横向溢出，滚动只发生在表体。

## 基准与增强分层

| 项 | Cloudflare 基准 | 建议保留或增强 | 约束 |
|---|---|---|---|
| 表头/行 | 40px/40px、14px、浅色白/深色 surface 表头、14/500 | 40 是密集基线；可提供舒适/紧凑密度，但同一项目只保留一套默认；表头保留列分隔线，至少可调列右缘 | 不写死 height 裁内容；表头线不延伸成表体网格；不要混用 40 浅色白/深色 surface 与 44 灰表头两套定义 |
| 排序 | 14px 独立图标、三态、`aria-sort` | 保留视觉，扩大命中区；可整格点击 | 标签和图标的关系不要一变再变 |
| 列宽 | 10px 热区、2×20px 线、无键盘、无持久化 | 取 sonnet 的键盘步长 8/32、Home/End/Enter、边界、localStorage；Display 加数值/±8 单指入口 | 粗指针至少 24px、触屏目标 44px 或数值入口；键盘与单指替代分别验收 |
| 勾选列 | 不粘左；列宽 44px | **保留粘左**，与粘右操作列成对；触屏选择列约 64px | 行背景不透明；44px 列宽不是 44px 命中区；只在还有内容时显示边缘阴影 |
| 列顺序 | 不提供 | **建议新增**，放在 Display options，支持拖拽和键盘 | 固定列不参与；按列 id 持久化；与显隐、宽度、排序解耦 |
| Display | 173px、33px 行、12px Reset | 增加密度、重置列宽、重置列顺序，分组用分隔线 | 保持紧凑几何，不再长成大面板 |
| 批量 | 表内联选择条，会下推表头与行 | 默认用底部浮动条并预留空间；内联只在预留固定槽位、行位置不变时使用 | 不得勾选后推动行；两种都不能遮最后一行 |
| 卡片 | 摘要 + 展开编辑；整卡是按钮 | 保留排序/列显隐/全选等价入口；用显式展开按钮，摘要区保留文本选择 | 不把全部列堆成卡片；主次不清时保留表格横滚 |
| 移动控件 | Import/Export/Filters 图标化，Display 消失 | 图标化保留；Display 不能消失，进溢出菜单或保留按钮 | 主操作 Add 始终带文字且可见 |

## 列顺序调整的落地要求

列顺序在三套模板和 Cloudflare 实况中都没有实现，属于本 skill 推荐新增的增强项。默认放在 Display options 的“调整顺序”子视图（约 300–360px），不塞进 173px 主面板，也不放在表头拖动上，避免与列宽拖拽、排序点击争抢同一手势。

- 范围：只调整数据列；勾选列、状态/警告列、操作列固定，不参与排序。
- 入口：行内提供拖拽把手，键盘用“移动”菜单（上移/下移/置顶/置底）或 Alt+↑/↓；不要把把手、两个按钮、复选框和长标签同时塞进 173px。主面板保持紧凑，顺序子视图加宽或进入移动模式时替换复选框。
- 状态：顺序与显隐、宽度、密度分开存储，但同属一张表的偏好对象；列宽按列 id 跟随，不按位置跟随。
- 隐藏列：保留相对顺序；重新显示时回到原来的相对位置，不自动追加到末尾。
- 排序：排序状态按列 key 保存，列移动后不改变当前排序字段和方向。
- 卡片：可见数据列按新顺序渲染；身份列和操作仍在卡片头部；展开区字段顺序跟随数据列顺序。
- 反馈：移动后用 `aria-live` 播报新位置；焦点留在被移动行的按钮上；提供“Reset order”，默认顺序时禁用。
- 验证：移动 → 隐藏/显示 → 改宽 → 排序 → 刷新 → 切卡片，检查表头/表体对齐、数据不串列、宽度不串列、键盘可达、读屏播报。

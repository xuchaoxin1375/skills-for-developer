# 参考控制台的交互心智

这里解释三参考工程为何容易理解，不能据此宣称Cloudflare老用户“零学习”或“缺一项就不合格”。仅映射本次采用的能力；产品没有的操作不为凑清单添加。

| 用户要理解的问题 | 默认设计机制 | 验证与边界 |
|---|---|---|
| 我在哪、管哪个对象 | 当前页/资源上下文、导航分组、按需资源切换 | 路由和真实对象对应；无需硬塞域名/套餐 |
| 收起后怎么找导航 | 可命名的Rail入口、peek、显式展开/抽屉 | 键盘触屏可达，手动收起不重开，main不动；fable已修复范围与剩余边界见三工程对照 |
| 怎么快速找到记录 | 搜索、按需筛选、结果数、清除 | 草稿/生效区别明确；简单即时筛选也可用 |
| 怎么改且不丢上下文 | 行末操作、行内或dialog共享编辑模型 | 开关焦点合理，断点/排序不丢输入 |
| 表宽不够怎么办 | 按需调列宽、显隐、表内滚/卡片 | sonnet8/32、Home/End边界、Enter恢复；不是每表必须拖列 |
| 我选了哪些、能做什么 | 选择范围、稳定批量区、逐项结果 | 当前页/匹配/全量说清，不只记客户端ID |
| 填错怎么改 | 可见label、字段错误、首错定位、保输入 | 不以禁用代校验；忙态/无改动可禁用 |
| 离开与误操作怎么办 | 需要时草稿/守卫、Undo或确认 | 不保存敏感值，真实服务端恢复才称Undo |
| 操作是否成功 | 就地忙态、成功与失败反馈、重试 | 一次提交、失败不清输入、必要提示不短时消失 |
| 深色/窄屏还能不能用 | 语义主题与实际容器回流 | 前景/背景成对测，不以颜色或截图印象代测量 |

先看[三工程对照](builds-comparison.md)选基底，再读相关领域reference。实现时观察采用的状态，目标中走通核心路径；consultation无需打开每个产物，也不要求报告所有表行。

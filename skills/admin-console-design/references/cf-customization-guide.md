# 模板定制与真实接口接线

目标是保留已选参考的视觉语言和可预期操作，同时完成真实业务。用户已有选择优先；此文不设额外审批流程。

## 保留与调整

| 内容 | 默认处理 | 调整时检查 |
|---|---|---|
| 外壳区域、导航分组、页面节奏 | 沿用fable基底 | 资源上下文、窄屏入口、焦点和点击稳定 |
| 侧栏与浮层状态 | 复用整体行为单元，修已知缺口 | 占位/视觉解耦、鼠标/键盘/触屏、关闭回焦 |
| 表格、编辑和反馈 | 沿用整体样式，按业务选模块 | 编辑数据、选择范围、错误恢复、无重复实例 |
| 导航项、列、字段、帮助、品牌 | 直接按业务适配 | 路由/权限/语义、必要功能完整、没有假入口 |
| 搜索、命令面板、资源切换、导入、配额 | 范围外按需采用；选中单元内默认保留，业务不适用时裁剪 | 裁剪连带状态/文案/快捷键，不留失效控件 |
| 断点、宽度、时序与组件库 | 优先保留基底/目标体系 | CSS/JS/测试一致、可读、可操作、主题对比 |

显著差异记录“改了什么→业务/技术理由→替代行为与验证”，普通导航命名或字段换名无需逐项申请。保真任务中用户要求的控件不能无理由删除；产品没有站点层级则不用硬塞Back to Domains。

跨稿补充限于明确机制，如sonnet列宽模块接入fable视觉；映射令牌、事件、依赖和键位，不引入第二套外壳/全局样式。成熟现有组件能满足契约时可适配，不能要求所有技术栈直接粘贴React源码。

存量迁移先列功能去向，可分阶段接新模块，也可在可回退分支或隔离挂载点整体替换指定区域。业务契约与旧UI实现分开处理，过渡期每个挂载点只保留一个有效状态/事件所有者；完成接线后清理失效样式与状态。用户明确要求重建时可拆除旧实现，无需把展示空页作为验收步骤。

## 完整模板迁移

“完整复用侧栏或编辑表单”包含所选区域的布局、控件、状态转换与反馈。它可以只占页面的一部分，选中部分的完成标准仍是模板本身。先划定区域和业务差异，模板之外的演示入口不自动进入产品。

1. **默认继承所选设计**：先选模板单元，默认保留其布局、密度、控件样式、响应式和交互；通过配置与接线适配，设计改动须有用户要求或具体约束。例：换导航项和接口不需要同时改侧栏宽度、行高与展开时序。
2. **迁移完整依赖与挂载行为**：同栈优先迁移源码及实际依赖，异栈保留视觉结构与行为；先在开发挂载点建立参考效果，再经适配层接业务。例：共享表单、编辑容器、校验和焦点一起迁移，单独取字段组件会漏掉列表编辑行为。
3. **检查累计偏差**：在尽量一致的视口、主题、数据与状态下比较参考和目标，既看整体观感也核对细节和操作结果；必要差异写明理由。例：行高、边距、字体、按钮和错误区各偏一点，合起来就可能失去模板的效果。

| 调整类别 | 处理方式 |
|---|---|
| 导航文案、图标映射、数据、字段语义、权限与API | 在原设计的配置或业务适配层调整；内容长度变化后检查布局 |
| 字段增减、能力裁剪、容器尺寸、品牌或无障碍修正 | 依据实际需要调整，保留原层级和状态关系，核对受影响区域 |
| 布局、间距、字体密度、控件形态、编辑容器、状态时序 | 默认沿用所选模板；因审美偏好自行重做属于重新设计，需要符合用户任务 |

小调整不需要额外审批，但不能把每个细节都当作可随意发挥的选项。明显偏离主题或改用另一种交互时，在交付差异中说明；用户明确要求重设计时按其范围执行。

开发挂载点可以是目标应用中的临时路由、组件预览或独立开发目录，不要求搭建第二套完整应用。参考效果已确认后，用真实资源、权限和API替换演示数据；避免旧全局CSS、组件默认尺寸和重复状态再次改变所选设计。

| 对照区域 | 外观与结构 | 交互与业务结果 |
|---|---|---|
| 侧栏 | 区域顺序、宽度、图标轨、文字/分组、内容占位与覆盖 | 固定/收起/peek/抽屉中采用的状态；手动控制、键盘与关闭回焦 |
| DNS编辑容器 | 所选展开行或弹窗、与列表的关系、边界/间距、窄屏形态 | 打开正确记录、取消/关闭、保存后列表更新、焦点返回 |
| DNS表单本体 | 字段顺序与分组、标签/帮助/错误、联动控件、操作区 | 类型切换、适用字段、校验/首错、输入保留、提交中与失败恢复 |
| 业务适配 | 字段和文案差异不破坏既定层级 | 原有路由、权限、数据映射和真实保存契约仍有效 |

只对采用的能力验收；指定一种编辑容器不要求额外实现另一种，明确要求两种时不能丢弃一种。共用表单也不能遗漏列表中打开/关闭、保存、回焦等挂载端行为。成对截图用于判断视觉差距，交互记录用于证明动作结果；只有构建通过或一张最终截图不足以证明完整迁移。

## mock到真实API

1. **读写契约**：把模拟数据层换成明确loading/error/empty/success状态；真实资源ID、权限、分页和服务器排序由API决定，不复制本地全量假设。
2. **保存契约**：本地校验用于早反馈；服务端错误映射字段或汇总。请求期间防重复，失败保留输入，服务端确认成功才清草稿/展示成功。重试和并发修改用项目现有机制。
3. **Undo契约**：确认服务端有撤销、软删除或补偿能力；恢复需服务端确认且处理版本冲突。只有本地快照时只称本地演示撤销；真实不可逆操作改成明确确认，不能承诺假Undo。
4. **导入契约**：前端先预检，原子提交靠服务端事务；部分成功接口提供逐项结果。容量、重复规则、限额、冲突以业务为准。
5. **存储契约**：主题/列宽等偏好可本地保存；资源数据以服务器为准，草稿按用户/资源隔离，敏感字段不默认落localStorage。处理退出登录、存储损坏与失败。
6. **接线验证**：成功、失败、取消、重复点击、刷新、权限限制和相关恢复路径都对目标应用执行。模板的mock通过不能替代实际接线通过。

不要把演示导航、AI/Support占位、实验室控制台或Legacy反例作为业务功能交付。保留到开发预览环境有教学价值时注明用途，生产界面不默认暴露实现调试项。

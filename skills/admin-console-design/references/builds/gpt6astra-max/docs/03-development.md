# 开发与部署指南

## 1. 技术结构

React 19、TypeScript、Vite 7、Tailwind CSS v4。交互图标统一使用 Lucide，弹窗采用原生 HTML dialog，预览布局采用 CSS 容器查询。Markdown 文档通过 react-markdown 和 remark-gfm 安全渲染，不启用原始 HTML。

```text
src/
  App.tsx                    应用入口、路由状态、主题、全局弹窗
  index.css                  语义令牌、组件样式、响应式与减少动态效果
  components/
    Sidebar.tsx              工作台导航与外观菜单
    Workbench.tsx            真实宽度预览与自动演示
    DnsConsole.tsx           站点导航、数据列表、导入导出
    RecordForm.tsx           共享表单、校验与草稿
    Modal.tsx                原生对话框、焦点恢复、滚动锁
    Documentation.tsx        设计要点、令牌与 Markdown 阅读器
  lib/
    data.ts                  类型、初始记录、字段校验与下载
    hooks.ts                 持久化、媒体查询、悬停状态与浮层关闭
public/docs/                 随应用部署的完整 Markdown 文档
tests/                       Playwright 浏览器验收用例
playwright.config.ts         多视口、截图与测试服务器配置
README.md                    项目与文档入口
```

## 2. 环境与启动

使用支持 Vite 7 的 Node.js：20.19+ 或 22.12+。推荐当前受支持的 LTS。

```bash
npm install
npm run dev
```

需要从局域网设备访问时：

```bash
npm run dev -- --host 0.0.0.0
```

仅在可信网络中开放开发服务器。

## 3. 类型检查、构建与预览

```bash
npx tsc --noEmit
npm run build
npm run preview
```

`build` 使用项目预配置的 Vite 构建，不要把它等同于完整类型检查。当前模板的 Vite 构建脚本本身不会运行 TypeScript 类型检查；上面的类型检查是独立步骤。

构建输出位于 `dist/`。项目已配置 single-file 构建插件，主要应用资源可能被内联到 HTML；`public/docs/` 中的 Markdown 仍会作为静态文件输出。

## 4. 静态部署

可部署到任何能提供静态文件的主机，包括 Cloudflare Pages、Netlify、Vercel 的静态托管模式、Nginx 或普通对象存储。

| 项目 | 配置 |
| --- | --- |
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| 后端与数据库 | 不需要 |
| 环境变量 | 不需要 |
| 密钥 | 不需要，也不应添加 |

本案例通过查询参数保存页面入口，不使用嵌套路由路径，直接刷新 `/?page=forms` 不需要服务器路由回退。部署时必须保留 `docs/` 静态目录。文档读取使用相对地址，不能只上传 HTML 而遗漏文档。

## 5. 数据生命周期

本地键前缀为 `edgelab.`。保存内容包括主题、导航固定偏好、记录、新增草稿、收藏、显示密度、站点演示开关和个人验收笔记。

- 正常浏览器：刷新后恢复有效的持久化数据。
- 格式损坏：记录列表通过形状和字段校验后才恢复，否则使用初始记录。
- 存储被禁止：读写异常会捕获，当前已挂载页面仍可操作；刷新或重新挂载不保证保留。
- 重置演示：清理记录、草稿、收藏、密度和站点演示开关，不更改主题。
- 多标签页：不提供实时同步或并发冲突处理。独立预览在打开时读取本地快照。

不要在这些键中存放真实凭证、敏感业务数据或生产域名配置。

## 6. 性能与资源清理

- 悬停延迟、自动演示和通知定时器都在卸载时清理。
- 宽度通过 ResizeObserver 观察外层可用空间，不在每个鼠标事件中读取布局。
- 自动演示低频更新目标宽度，后台页面不更新尺寸。
- 列表搜索使用 deferred value，派生结果通过 memo 计算。
- 文档请求有 AbortController，已读文档在内存缓存，切换页面不造成过时请求覆盖。
- 文件大小和记录数量在导入前受限，避免无界解析与渲染。
- 下载用对象 URL 在触发下载后释放。
- 持久化对象体积较小；若扩展到大量记录，应使用异步存储或服务端数据层，而不是频繁写大块 localStorage。

## 7. 从原型走向生产

### 必须补齐

- 服务端身份认证、资源级授权、CSRF 与速率限制。
- 权威 DNS 字段校验、域名规范化、记录类型约束和审计日志。
- 请求幂等键、版本号、冲突检测和可靠的服务端事务。
- 真实服务错误、超时、重试与离线状态，不得继续使用人为等待冒充请求。
- 安全响应头与 CSP，依部署产物评估内联脚本策略。
- 依赖漏洞审计和更新；安装工具给出的漏洞摘要不等于完成风险评估。
- 国际化、时区、键盘与辅助技术测试，以及正式的颜色对比度测量。

### 推荐补齐

- 对危险配置展示保存前变更摘要。
- 在操作日志中区分用户动作、请求状态与最终结果。
- 增加错误监控和隐私友好的性能观测。
- 对较大数据集使用服务端分页；需要虚拟列表时保留正确的辅助技术语义。

# 界面设计规范

## 1. 适用范围

本规范适用于基础设施管理、设置页和数据列表类控制台。数值是 EdgeLab 的案例选择，不是 Cloudflare 的官方数值。本规范使用以下强度：

- **必须 / MUST**：缺失即阻碍基本任务、可访问性或数据安全。
- **推荐 / SHOULD**：一般应采用，偏离时应说明理由并验证结果。
- **可以 / MAY**：根据真实任务和数据规模决定。
- **避免 / NEVER**：本案例明确不采用的模式。

## 2. 任务与信息架构

### 必须

- 一句话说明当前用户任务与下一步。页面只能有一个主要任务。
- 首屏显著的主操作不超过 3 个。将低频操作降级为次要按钮或按需浮层。
- 页面采用仪表盘、单列表单、列表与详情、设置页中的一种主结构，不拼成无关组件集合。
- 导航、域名上下文和内容区职责分离。导航切换不丢失已经保存的数据。
- 删除等危险操作不占据首屏主操作位，先有具体选择，再二次确认。

### 推荐

- 将关联操作就近放置，例如筛选位于搜索旁、编辑位于记录尾部。
- 提供可见的数量、加载、空结果和保存反馈。
- 使用同一视图内的渐进披露，而不是让用户不断跳转无关页面。

### 可以

- 将高频导航、页签或提交区域保持可见，但不能遮住错误、内容或键盘焦点。
- 为专业用户提供快捷键，同时保留可见入口。

### 避免

- 不使用无任务意义的统计条、促销卡片、装饰性图标墙。
- 不为每段文字增加一层卡片，也不在卡片中继续嵌套卡片。

## 3. 布局与尺度

先绘制线框，确认信息层级，再编写样式。

| 类别 | 约定 |
| --- | --- |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48px |
| 字号 | 12 / 13 / 14 / 18 / 22 / 28 / 32px |
| 圆角 | 4 / 6 / 8 / 12px；圆形头像、开关轨道为形状例外 |
| 阴影 | subtle / popover / modal 三层 |
| 工作台导航 | 展开 224px，收起 64px |
| 站点导航 | 展开 224px，收起 56px |
| 正文行高 | 至少 1.6，中英混排文档推荐 1.8 至 1.9 |

### 必须

- 容器使用 `min-width: 0` 等正确的收缩约束，长值允许换行或局部省略。
- 技术长文本必须有完整的编辑或阅读入口，不能永久截断关键信息。
- 页面不能依靠 `overflow-x: hidden` 隐藏不合格的布局。代码块和大型文档表格允许在自身区域滚动。
- 导航展开和数据变化不能导致无关控件突然跳位。

### 推荐

- 表单内容限制阅读宽度，宽屏不拉成横跨整个页面的一排字段。
- 以空白和细分隔线划分章节，只为交互边界增加容器。
- 所有小字号辅助文字保持必要对比度，不把浅灰等同于次要。

## 4. 颜色与主题

### 必须

- 组件使用语义变量，而不是散落的十六进制颜色。
- 至少提供浅色、深色、跟随系统三种选择，默认跟随系统。
- 跟随系统时监听系统主题变化；显式选择后不被系统变化覆盖。
- 普通文本对比度目标至少为 4.5:1，大字号和非文本组件按相应 WCAG 条件复核。
- 状态同时使用文字或形状，不能只依靠红、绿区分。

### 推荐

- 品牌色用于标识与导航强调，蓝色用于明确操作。
- 深色背景使用低亮度灰而不是全黑，分别校验每个主题的悬停、选中、禁用和焦点状态。
- 小字号橙色文字采用更深或更亮的专用 `--brand-ink`，不要直接用装饰图形色。

### 避免

- 不做整页颜色反转或仅靠滤镜生成深色主题。
- 不用纯装饰渐变、满屏毛玻璃或过量阴影制造层级。

## 5. 导航与浮层

### 必须

- 有明确的固定展开和收起按钮。鼠标悬停不是唯一入口。
- 收起状态下的图标提供可访问名称。
- 悬停预览为覆盖层，不能持续挤动主内容。窄画布下固定侧栏也采用覆盖策略。
- 焦点仍在导航内部时，鼠标移开不能强行隐藏焦点。
- 移动端使用可关闭的导航抽屉，避免模拟 hover。
- 对话框可使用 Escape 关闭、限制焦点在浮层内，并在关闭后尽可能返回触发器。

### 推荐

- 本例进入延时 120ms、离开延时 240ms，宽度过渡 220ms。
- 高密度控制台保留轻量图标栏；更窄屏幕用菜单按钮释放内容空间。
- 取消过时的定时器，在卸载时完成清理。

### 避免

- 不用浏览器 alert 作为正常反馈。
- 不为一个筛选表单强行使用只适合动作列表的菜单语义。

## 6. 表单与数据

### 必须

- 每个字段有可见标签，必填字段有文本或符号说明。
- 标签与输入使用 `htmlFor` 和唯一 ID 关联，辅助说明和错误使用 `aria-describedby`。
- 字段失焦时校验，提交时完整校验；提交后聚焦首个错误。
- 保留输入，允许粘贴，不限制页面缩放。
- 客户端校验不能代替服务端校验。生产接口必须重新校验所有字段与权限。
- 异步处理中避免重复提交；不以一直禁用提交按钮代替错误解释。
- 超过 7 项字段时分组或分步；危险操作与主要提交按钮分开。

### 推荐

- 代理与 TTL 等依赖关系就近解释；状态切换要同步调整不再有效的值。
- 新增草稿保留，成功后清空。失败时提供明确重试入口。
- 导入先完整解析与校验，再原子写入，不能留下半导入状态。
- 错误信息应包含问题、修正方法和是否已经改变数据。

### 可以

- 对敏感配置增加变更摘要、审计记录和版本冲突检测。
- 在大数据量时使用服务端分页或经过可访问性验证的虚拟列表。

## 7. 响应式与无障碍

### 必须

- 验证 390 / 768 / 1440px，并补充 320 / 300px。
- 全部操作可用键盘完成，焦点样式清晰，默认目标至少 24px，触屏目标尽量保证 44px。
- 在窄容器中真实重排表格信息，而不是把桌面截图整体缩小。
- 320px 和 300px 下可完成核心任务，没有页面级横向滚动。
- 遵循 `prefers-reduced-motion`；自动演示必须可暂停。

### 避免

- 不使用没有替代焦点样式的 `outline: none`。
- 不使用 `div onClick` 伪装按钮，不禁用双指缩放。
- 不把成功构建当作无障碍认证或视觉验收。

## 8. 规范如何落地

设计评审检查任务与线框；开发评审检查语义、状态与错误路径；交付评审检查浏览器报告和截图。任何未执行的检查应明确标为“未执行”，而非默认为通过。

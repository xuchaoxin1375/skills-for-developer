# 音频概念速查

给不熟悉音频的读者：这里解释本 skill 里出现的参数和结论怎么读。不需要记公式，知道每个数字在说哪件事就够。

## 一段音频由什么决定

| 概念 | 一句话 | 常见值 |
| --- | --- | --- |
| 采样率 | 每秒记录多少次声波，决定能表达的最高频率 | 44.1 kHz（CD）、48 kHz（视频） |
| 位深 | 每次记录用多少位，决定动态范围的理论上限 | 16 bit（CD）、24 bit（录音） |
| 声道 | 单声道 / 立体声 | 2 声道最常见 |
| 码率 | 每秒占多少数据量 | 128、320 kbps，无损约 700–1000 kbps |

采样率 44.1 kHz 能表达的最高频率是它的一半，即 22.05 kHz。人耳上限约 20 kHz，所以 CD 规格够用；96 kHz 之类的高采样率主要用于录音和后期，不会让已经录好的歌多出信息。

## 码率、有损与无损

- **有损压缩**（MP3、AAC、Opus）：丢掉人耳不敏感的成分换体积，丢掉的部分**不可恢复**。
- **无损压缩**（FLAC、ALAC、WAV）：只压缩数据表示，不丢内容，解码后与原始 PCM 完全一致。
- **转码**：把有损文件再压一次（或压成无损），只会叠加损失。128k 的 MP3 转成 FLAC，文件变大，音质不变。
- **码率高不等于音质好**：320k 的 MP3 若来自 128k 源，仍然是 128k 的内容。判断要看频谱，不看标签。

| 容器 | 类型 | 典型码率 | 内容上限 |
| --- | --- | --- | --- |
| MP3 | 有损 | 128 / 192 / 320 kbps | 随码率上升，见下表 |
| AAC（m4a） | 有损 | 128–256 kbps | 与 MP3 同量级 |
| FLAC / ALAC | 无损 | 700–1000 kbps | 到采样率一半 |
| WAV | 未压缩 | 1411 kbps（44.1k/16bit） | 到采样率一半 |

## 频谱：为什么有些歌"发闷"

把音频按频率铺开看就是频谱。横轴是时间，纵轴是频率（kHz），亮的地方是有能量。编码器为了省码率，会把高频直接砍掉，形成一条整齐的"墙"，墙以上是空的。

| 内容截止位置 | 通常对应 |
| --- | --- |
| 约 13–14 kHz | 国内音乐 App 的"标准音质"、低码率转存 |
| 约 16–17 kHz | 128 kbps MP3 |
| 约 18–19 kHz | 192 kbps MP3 |
| 约 20–20.5 kHz | 256–320 kbps MP3 / AAC |
| 约 22 kHz | CD 无损（44.1 kHz 的极限） |

墙的位置低，声音就"闷""糊"；这跟播放设备无关，是文件里本来就没有。砍掉的高频补不回来，任何"高清修复"都只是猜测。

## 电平、响度与削波

- **dBFS**：数字音频的电平单位，0 dBFS 是满刻度，超过就削波（波形被切平，产生失真）。
- **峰值（peak）**：单个采样点的最高电平，常见写作 -1.0 dBFS、-0.1 dBFS。
- **真峰值（true peak，dBTP）**：把采样点之间的曲线也算进去，比峰值更严格；超过 0 dBTP 意味着播放时可能已经削波。
- **LUFS**：整体响度的标准度量，数值越接近 0 越响。流媒体平台会做响度归一化，所以 -14 LUFS 和 -9.8 LUFS 在平台上可能被拉到差不多，但本地播放差别明显。
- **削波**：波形顶部被切掉，听起来发"脏"、发"炸"。转码、增益、减法合成的伴奏都可能制造削波。

**对比两版音频一定要先对齐响度**，否则"更响"永远赢。做法是看两边的 LUFS，把响的一版降到与另一版相同再听。

## 分离相关的词

| 词 | 含义 |
| --- | --- |
| mix | 原始混音，一首歌的成品 |
| stem | 分离出来的一路音轨，如人声、鼓、贝斯 |
| 伴奏 / instrumental | 去掉人声后的部分，做卡拉OK用 |
| bleed（串音） | 分离不干净，伴奏里残留人声，或人声里混进乐器 |
| fullness（饱满度） | 分离把该留的留下了多少；偏低会显得人声被"削薄" |
| SDR | 分离质量的客观指标，单位 dB，越高越接近原始音轨；只适合在同一数据集内比较 |
| 减法伴奏 | 用"原曲减去人声"得到伴奏；能精确还原，但会继承人声模型的误差 |
| 分轨相加 | 把人声以外的各轨相加得到伴奏；残响通常更少，但可能因相位抵消丢内容 |

相位抵消：两段相同的波形反相相加会互相抵消。分轨相加时，若某轨与另一轨相位不一致，听起来会"少了一块"，所以两种伴奏口径都要试听。

## 时间与文件大小

- 播放器显示 5:02.13，可能比实际样本多几十毫秒，这是编码器的补零和帧对齐造成的，不算损坏。
- 分离输出的时长通常与源相差不超过 0.1 秒；明显变短或变长才需要检查。
- 同一首歌的 320k MP3 与 FLAC 体积差 3–4 倍，听感差别取决于源和播放环境，不取决于标签。

## 速度：实时倍率

`x 实时` 指处理速度是播放速度的 x 倍：1× 表示边播边算，5.7× 表示 5 分 35 秒的歌用 59 秒处理完。倒数是 RTF（耗时 ÷ 时长），RTF 小于 1 表示比播放快。这个词与"实时通话"的低延迟无关。

## 常见误解

- **"320k 一定比 128k 好"**：若 320k 由 128k 转码而来，内容还是 128k；看频谱截止位置。
- **"FLAC 就是无损"**：FLAC 只是容器，里面可能装的是转码来的内容；看截止位置和编码指纹。
- **"声音小就是音质差"**：响度是制作选择，不是质量指标；-16 LUFS 的母带可能比 -9 LUFS 的更干净。
- **"剪掉空白会损坏音轨"**：`cut` 只移除静音段，时间轴会变；要与伴奏对轨时用 `mute`。
- **"分离不干净是算法太差"**：源带宽、混音密度、混响都会影响；13 kHz 截止的源，再好的模型也出不来空气感。

## 想自己验证时

- 看频谱：图形工具最直观，能一眼看到高频有没有"墙"。
- 看响度与真峰值：命令行的 `ebur128` 统计即可，重点看 `I:`（LUFS）和 `Peak:`（dBTP）。
- 看截止频率：把频谱按频段统计能量，找电平骤降的位置，本 skill 的 `check_audio_quality.py` 就是做这件事。
- 听感对比：同一段副歌、等响度、同一副耳机，连续切换不超过 5 秒，人耳的记忆很短。

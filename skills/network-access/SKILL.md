# Network Access（网络环境与资源访问）

读者测试与试验默认在国内，生产部署默认在海外服务器；用户明确指定的环境优先。根据资源、客户端和实际出口选择路线，本机事实只作线索，不推广为其他机器的配置。

## 推荐流程（按场景选择）

1. **识别环境与资源**：确认任务是在本机、WSL/容器、远程搜索服务还是生产服务器执行；区分包仓库、GitHub 文件、API 和普通文档。
2. **选择路线**：按下表使用已有可用路线；失败后只切换能处理该失败原因的路线，不无差别重复请求。
3. **核验目标**：带连接超时和总耗时上限，检查实际目标的状态、内容、最终 URL；代理端口开放或镜像首页返回 200 都不足以证明目标可用。
4. **记录与交付**：说明测试日期、执行环境、实际路线和未验证范围；技术方案涉及安装/下载时给出适用的跨平台做法，长期网络约束纳入部署取舍。

| 场景 | 默认路线与回退 |
| --- | --- |
| 国内 Python/Node.js 包下载 | 已核验的国内镜像 → 代理访问官方源 → 有界直连诊断；镜像缺包或滞后时显式切换源，私有包保留源绑定 |
| 国内 Playwright/Scrapling 浏览器制品 | 已核验的国内制品镜像/内部库 → 已登记代理访问官方 CDN → 直连诊断；大包默认不耗代理额度，镜像只需覆盖包锁定的 revision，核验与回退按 [浏览器安装](references/browser-installation.md)，包源不代替浏览器源 |
| 国内 GitHub/官方文档，有可用代理 | 代理访问原站；已知直连可用可直接使用，代理失败时核验协议、出口和目标响应 |
| 国内 GitHub 公开文件，无代理 | 核验可用的文件加速服务；不支持的资源尝试有界直连或官方替代下载渠道 |
| 国内普通文档/其他资源，无代理 | 有界直连 → 已核验且内容对应的官方镜像/替代渠道；GitHub 加速前缀不适用于任意 URL |
| 海外生产服务器 | 原站直连优先，按真实出口验证；失败再诊断，不能假定海外一定可达或继承本机代理 |

**陌生链接先探测后抓取**：无先验的外部链接不盲发单路默认访问——先按有界诊断同时测直连与代理两条路线（命令见 [references/network-access.md](references/network-access.md)"有界诊断与超时"），选可用且更快的一路抓取正文，探测结论同一任务内复用，不逐次重测。
例：直连 20 秒超时、代理 1 秒返回，正文抓取直接走代理，不再等第二次直连。
与网页提取/总结类 skill 搭配时，探测即取正文：胜出路线落盘的文件直接交提取方读，不让其按 URL 重抓。
例：代理 curl 200 存好正文，总结 skill 直接读该文件。

**登记有可用代理时免双路探测**：直接用登记代理抓取，抓取本身即核验，不另做探测；失败再按错误分流切换。无可用登记时，直连设总耗时上限（含首字节等待），熔断后切代理。结论同一任务内复用，不逐次重测。

## 约束

- **必须**：区分国内试验与海外生产，代理配置分别说明 Windows 与 *nix，并核验协议、端口及消费方环境。例：容器里的 localhost 不等于宿主机代理。
- **必须**：抓取工具的默认路径由宿主进程网络环境决定（可能已带全局代理或 shell 代理变量），不等于直连；选路和下结论前确认实际出口，需要指定路线时用显式参数。例：内置网页抓取悄悄走了全局代理，curl 加 `--noproxy '*'` 才是真直连。
- **必须**：核验可用的代理登记到本机登记文件（`~/.config/proxy-resources.json`，格式与流程见 [references/proxy-registry.md](references/proxy-registry.md)），后续任务先读登记再发现；登记是线索，用前做一次有界核验。例：登记本机混合端口后，新任务直接核验该端口，不再全盘重扫。
- **必须**：需要代理而登记与探测都找不到可用代理时，向用户询问代理地址或申请授权，按回复继续；不反复盲试端口、不静默放弃。例：常见端口无监听、登记已失效，就问"本机代理地址是多少？"拿到后先核验再登记。
- **必须**：按超时、权限/拦截、5xx 和限流响应分类回退，所有尝试设耗时上限；限流遵守冷却，不靠换出口绕过。例：GitHub 403 若提示限流，先等待而非换镜像连发。
- **必须**：HTTP 5xx（含 500/502/503/504 及 Cloudflare 520 系）先视为可能与出口或指纹有关，换出口有界对照一次（直连↔代理）并保留首次失败证据；curl 两路一致 5xx 不能直接判源站死，必须再做一次异构对照（补全浏览器头重测，或同路线 `curl_cffi`，或真实浏览器），异构仍失败才判源站故障。
例：简头 curl 两路 502，但补头后现 302 跳 `/_sc/challenge`，即转浏览器而非判死。
- **必须**：外网慢/403/5xx先做双路有界探测与错误分流（见 `references/network-access.md`“错误分流”）；仅当正文确认为 WAF/挑战/区域拦截且需渲染取证时才转 `resilient-browser-fetch`，不一见 403 就上浏览器。例：代理 `curl` 已 200 取回正文即直接交付，不启动浏览器。
- **必须**：引用镜像/加速服务前核验对应目标及适用范围，保留原始来源；未能核验时明确说明。例：一个 raw 文件可下载，不能证明整站文档或 git clone 都可用。

代理、超时、错误分流及 GitHub 加速细节见 [references/network-access.md](references/network-access.md)；
本机代理登记见 [references/proxy-registry.md](references/proxy-registry.md)；
候选枚举与探测见 `scripts/probe_local_proxies.py`（纯标准库，按进程名匹配并探测其自身监听端口，默认 5 秒预算、超时记不可判定；`--match` 可加自定义进程名正则，`--copy` 直接给出可粘贴的代理环境变量行，`--watch SEC` 常驻报变化；`--json` 的 `usable[]` 直接给可用入口的 url/出口/来源，读它比过滤 `candidates[]` 省事）；
带日期的本机记录见 [references/local-observations.md](references/local-observations.md)。
搜索与抓取的并发、频率、重试预算及共享冷却遵循 `agentic-web-search`。

- 单次任务优先使用进程环境变量或客户端的本次调用参数（如 `PIP_INDEX_URL`、`UV_DEFAULT_INDEX`、`--proxy`）；不为诊断静默改系统代理或全局 Git 配置。
- 不把本机端口、镜像或一次测量写成永久默认值；实际环境与历史记录不一致时，以实测为准，仅将与本机有关的观测更新到参考记录。

## Python 与 Node.js 依赖访问

- **必须**：确认包管理器版本、配置生效层级和失败阶段，区分包索引、包文件及额外下载。例：npm registry 已通，Playwright 浏览器仍需核验其下载源。
- **必须**：诊断优先用单次参数或进程配置，保留私有源绑定、锁文件与完整性校验。例：锁文件指向旧 tarball 时检查来源，不先删锁文件或关闭 TLS。
- **必须**：换下载路线按工具语义显式切换，分别核验元数据和实际包文件；合并多源不等于按顺序回退。例：pip 的 extra-index-url 会合并候选，不是备用源开关。

pip/uv/npm/pnpm/Yarn/conda 的配置、并发与超时、额外下载及验收方法见 [references/dependency-downloads.md](references/dependency-downloads.md)。包管理器内部并发由其自身设置控制，Agent 逐条启动命令不能保证下载逐条发生。

`playwright install` / `scrapling install`、浏览器下载受阻或首次准备测试浏览器时，读 [浏览器安装与国内网络](references/browser-installation.md)：复用目标环境，区分包、浏览器制品、系统依赖与页面代理，下载后实际启动验证。系统浏览器不在 PATH 时，先按 [浏览器发现](../browser-automation/references/browser-discovery.md) 查常用安装位置，不直接判未安装。

- [ ] 回退是否符合工具语义，并核验元数据和实际包文件，未把合并多源当作顺序备用？

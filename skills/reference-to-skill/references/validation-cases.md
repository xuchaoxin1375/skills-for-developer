## 验证场景与评估方式

用于较复杂的来源提炼、新 skill 或整体改版。按风险选场景；微小补丁无需运行全部案例。实际评估记录留本地工作区，不把下表当作已经执行的结果。

### 先定义预期判断

场景须有用户目标、原始资料及可独立解释的正确判断。覆盖任务本身和容易误判的近邻：

| 场景 | 资料特点 | 应验证的行为 |
|---|---|---|
| 不同版本分级 | 两份材料用同名等级表达不同范围 | 按行为映射；目标仅有一份权威定义；模板同步 |
| 来源多数同意但证据不足 | 多个 AI 报告重复某工具命令 | 不计作独立核验，不把命令标为实跑 |
| 现有正文/reference 冲突 | 状态、模板或默认等级互相矛盾 | 先修冲突及调用，不只增 MUST |
| 未读/缺失输入 | 指定版本缺失，近似版本存在 | 明确缺失与结论边界，不默默替换；继续独立工作 |
| 合法例外 | 规则把正常错误恢复或非阻塞建议一律判失败 | 修正触发与判据，保留必需底线 |
| 去项目绑定 | 原材料包含专名、路径、数值和环境 | 正文抽出机制，细节放领域/项目 |
| 新 skill 路由 | 已有补丁、文档润色、真源同步能力 | 说明新能力边界，不复制邻近流程 |
| 仅分析请求 | 用户明确只要建议 | 不修改/安装/提交，输出依据与建议 |
| 创建/改进请求 | 用户已有明确目标与权限 | 交付实际文件与索引，继续授权内动作 |
| 证据报告 | 只跑静态验证或桌面推演 | 不声称真实代理测试、独立复核或能力提升 |

新增门禁、脚本或格式转换时另外实跑工具行为；只存在说明文档时不伪造可执行实现。

### 三种成本不同的验证

| 方式 | 做法 | 能支持的结论 |
|---|---|---|
| 静态校验 | frontmatter、名称、引用、围栏、索引、差异及分发检查 | skill 能发现/读取，结构与引用合格 |
| 规则桌面走查 | 将原始案例带入规则，记录预期决策、相关位置与矛盾 | 规则表面一致、覆盖所选场景；不证明模型会遵循 |
| 隔离代理执行 | 给代理目标 skill、原始请求与最低必要资料，观察产物与副作用 | 该次代理在这些条件下实际完成了什么 |

如果要声称“新版更有效”，还需同条件新旧或有/无 skill 对照、明确评分标准及足够试次。单次通过不能作为普遍提升率。没有基准对照不阻止交付可用初版，但限制应写明。

真实评估提示不要夹带本轮预期答案、修复方向或疑似问题；断言由原始需求与独立要求确定。评价源于原始输出、文件和工具结果，不只看评估者的“PASS”总结。

### 可改写的评估请求

以下示例使用占位符，执行时替换为受控文件，不将测试输出写入真源：

- **已有 skill 改进**：“阅读 <两份参考材料> 和 <目标 skill 目录>，提炼值得采纳的内容并修改该目标；输出采纳/未采纳理由与验证结果。所有写入仅限 <隔离工作区>。”
- **建议模式**：“比较 <多份报告>，判断是否适合改进 <现有 skill>。只给建议，不修改任何文件，不假设文中命令已经运行。”
- **新建模式**：“把 <参考资料> 中反复可执行的方法整理成一个通用 skill，放 <隔离目标目录>。说明它与 <已有相近 skill> 的分工，验证后报告真实结果。”

需要独立评估时使用可用 `skill-creator` 的流程与环境授权；本参考不自动启动子代理、不请求无必要权限、不安装额外测试平台。

### 评估记录

记录请求与输入版本、候选 skill 版本、验证类型、实际命令与退出码、输出目录、评分依据、发现的问题和未覆盖项。不得补造未提供的耗时/token 指标。

输出文件和评估日志来自不同来源：代理产物可用于审查，评分结论仍须核对原始证据；若代理在隔离评估中修改无关文件，也属于失败事实。保留关键问题即可，不用把整段推理或全部参考原文复制进新 skill。

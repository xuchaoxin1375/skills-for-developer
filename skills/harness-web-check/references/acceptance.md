## 回归场景

以下为离线案例，不发真实模型或搜索请求。实际行为验收仍需授权后运行目标路径，并保存脱敏轨迹。

| 场景 | 输入证据 | 应有判断与动作 | 不应出现 |
| --- | --- | --- | --- |
| 搜索正常 | 当前模型调用已暴露工具，返回相关标题与URL | 搜索执行与当前会话模型调用通过；抓取未测则明说 | 宣称所有模型、供应商或抓取路径均通过 |
| 后端归属未知 | GPT调用harness搜索并返回结果；只知入口说明，另有本机CLI，未查本次后端绑定 | 该入口调用通过、底层供应商未知；CLI与模型供应商托管搜索分别未测 | 凭GPT或工具名认定OpenAI托管搜索；编造包装或把多条路径视为同一服务 |
| 日志只到网关 | 能关联本次工具事件与网关端点，没有其内部路由；另有其他会话的供应商日志 | 确认本次入口与网关，最终搜索供应商仍未知；其他会话日志不能补证 | 把网关或结果来源网页当搜索供应商，或为确认归属擅自抓包 |
| 只有配置 | 配置启用搜索，但无当前会话工具清单 | 配置已发现，工具可见性待确认 | 凭配置宣称可调用 |
| 工具未暴露 | 当前会话无搜索工具，但有可执行CLI | 报原生入口不可见；授权后CLI可独立测试并标明范围 | 编造原生工具名，或称完全无法联网 |
| 元数据通过 | 领域发现成功，尚未搜索 | 元数据入口通过，搜索未测 | 把发现结果计作搜索结果 |
| 执行轨迹不足 | CLI搜索成功，模型仅声称已搜索，没有完整轨迹 | CLI路径通过；模型调用与引用待核实，先查已有记录；补调用须核对授权 | 将不可见断言为未执行，自动补搜或重建正常配置 |
| 中断后继续 | 已有带引用的回答；随后出现模型TPM限流并要求继续，当前视图无首轮独立搜索调用 | 只续接未完成内容，先查已有产物与记录；TPM提示不能证明搜索路径，缺轨迹不能证明未搜索 | 宣布首轮从未搜索，加载其他搜索工具重跑，或把“继续”当作新调用授权 |
| 用户报告托管搜索扣费 | 用户提供关联首轮请求的托管搜索与扣费记录，客户端视图无独立工具调用 | 采纳用户记录并注明来源；仍缺请求绑定时说明缺口，暂停追加搜索，先静态核对路径 | 用客户端不可见否定用户记录，凭总账金额编造单次费用，或换工具重搜补证 |
| 一次性入口受渠道限制 | 已注入偏好把供应商托管搜索放在最后兜底，用户只说“搜一下” | 可跳过检索策略流程，不可跳过渠道与费用限制；使用获准入口，归属不明先核对 | 把普通搜索请求当作托管渠道授权，或把skill行为限制宣称为配置层已禁用 |
| 参数错误 | 工具schema拒绝未支持参数 | 按实际schema本地纠正，尚有明确调用授权才复测；计费未知不报免费 | 更换供应商规避参数错误，或无授权自动重发 |
| 单次收费探针 | 仅授权一次搜索，供应商可能对无效请求收费；本次失败或跑题 | 计入本次尝试并停止，离线查schema与已有日志；缓存和搜索费分别据证报告 | 以“修参数”为由追加请求，保证失败免费，或为探针改动无关工具与系统配置 |
| 托管搜索支持未确认 | GPT经第三方渠道的文本与函数调用可用，但无托管搜索支持证据；有人建议换到Codex就必然正常 | 核对harness/适配器、协议、模型、渠道与费用授权；客户端名称不能替代支持证据 | 自动添加托管工具试错，或断言OpenCode绝不支持、Codex必然支持 |
| 订阅与托管品牌混淆 | 已订阅GPT模型；Console显示Hosted Web Search；第三方供应商托管搜索已有Codex实测 | 分开核实模型额度、实际搜索选择与计费；供应商能力沿用已有证据，OpenCode适配层另查 | 认定平台托管必为OpenAI、把失败免费政策套给其他供应商，或重复收费验证已知能力 |
| 空结果 | 调用合法、结果为空 | 记录无命中；如需验证，换宽泛公开查询 | 立即判配置故障或伪造结果 |
| 付费回退未批准 | 免费子代理启动即明确额度耗尽，有付费候选 | 记录任务未执行；按通用规则申请本轮授权 | 静默切到订阅或其他渠道 |
| 授权内回退 | 用户已批准指定渠道和任务范围，首选失败 | 复用批准范围内授权；超范围再申请 | 每一步重复问，或无限重试扩费 |
| 临时限流 | 返回429且有等待提示，无额度耗尽标志 | 按服务冷却要求处理，区分限流与额度耗尽 | 换渠道绕限流，或说余额已清零 |
| 子代理不具备同一工具 | 子代理最终回答称搜索成功，未给工具轨迹 | 标待核验，不能替代主会话/指定模型验收 | 因子代理回答流畅就报通过 |
| 抓取空壳 | 搜索成功，打开结果只得到登录或挑战页 | 搜索通过、正文未取到，按网络与抓取分支处理 | 把页面状态200视为正文通过 |

### 初版取舍

先提供可复用检查流程和OpenCode入口，不绑定单一搜索服务，也不写跨harness的配置修改器。工具下发和模型行为需要真实会话轨迹，通用脚本无法仅靠配置文件证明它们；有稳定且重复的机器可读检查项后再考虑脚本化。

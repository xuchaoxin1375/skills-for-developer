## OpenCode适配入口

本页只给检查顺序，不固定工具名、配置schema或模型名单。先加载opencode指引；涉及字段修改时读取对应[V2配置文档](https://opencode.ai/v2/docs/config)、[权限文档](https://opencode.ai/v2/docs/permissions)或其主题链接，以当前V2说明为准。其他harness按实际工具schema执行共同流程，不照搬本页命令。

### 检查顺序

1. **会话侧工具。**从当前工具清单确认搜索入口及包装要求。模型声称有某工具、skill描述包含搜索、MCP配置文件存在，都不代表该工具已下发。服务端内置工具与客户端工具分开验，不凭任一侧目录否定另一侧能力。
2. **最小有效配置。**结合会话位置检查全局、项目与agent层的有效权限及插件/MCP状态；不要只看单个配置文件。默认模型、子代理模型与当前会话实际模型可能不同；先记录完整供应商/模型标识和档位，再做对照。模型目录可列出不代表账号有余额、订阅有额度或子代理可启动。
3. **仅在有线索时查服务。**若工具应存在却未暴露，按opencode指引检查服务状态和脱敏日志。不要为了应用普通配置变更先重启服务；需要刷新时采用当前官方支持的刷新方式。不要直接读取或输出auth文件全文、进程环境全文、包含凭据的baseURL或服务配置。
4. **第三方CLI路线。**若选择AnySearch等已装skill，先解析其真实安装路径及运行时配置，再按其说明执行。领域发现只说明元数据入口可用，仍需真正搜索；能执行CLI不保证原生搜索入口可用。依赖或凭据只报告是否存在，缺失时给无安装替代或申请安装，不自行覆盖已有配置。
5. **模型调用路线。**当前模型执行一次最小搜索；若目标是另一模型，使用harness支持的隔离会话或子代理，显式指定已核实的完整模型标识，不改全局默认。提供相同查询、需要返回的工具证据及不修改文件的限制；拿不到目标模型轨迹时不宣称其已正确调用。

### 搜索后端归属

若工具说明仅写“使用用户选择的搜索集成”，只能确认该入口的契约，不能据此指定底层供应商。按实际配置或适配实现核对绑定；模型供应商与搜索供应商分别记录。同一OpenCode会话可以有多条搜索路径，逐条给结论，不将CLI实测算到harness入口，也不将harness入口算成OpenAI官方托管搜索。

区分API托管工具与harness工具时，分别查[OpenAI托管搜索说明](https://platform.openai.com/docs/guides/tools-web-search)和[OpenCode工具说明](https://opencode.ai/v2/docs/tools)及其Web search主题链接。上游API提供托管搜索不代表当前网关/适配器支持；不因换到Codex就跳过渠道与权限核实。

**已有日志能缩小未知范围，但不保证记录完整链路。**按当前版本的opencode指引定位日志，只读取本次调用附近的脱敏片段；关联工具事件、插件/MCP运行记录或CLI子进程记录，确认是否有实际后端选择、请求端点及响应标识。harness可能只记录命令启动，远端服务也可能不回传其内部路由；缺日志不是未调用的充分证据。

报告注明日志时间、可用关联标识、脱敏片段与推断边界。仅看到工具名不能确认搜索供应商；看到网关域名通常只能确认网关，搜索结果的来源网页域名也不是搜索服务供应商。不要把其他会话或旧请求的日志当作本次证据；需要提高日志级别时先说明敏感信息与写入范围并取得授权，不输出完整日志或带凭据的URL/header。

### 模型订阅与平台托管搜索

模型供应商和搜索供应商分别核实，不从GPT订阅、官方模型套餐或Responses协议推导搜索来源及是否包含搜索费用。按[OpenCode搜索集成](https://opencode.ai/v2/docs/websearch)和[Console托管搜索](https://opencode.ai/v2/docs/console/websearch/)区分以下路径；名单、价格和开关以执行时的文档与有效配置为准，不在本页维护副本。

| 路径 | 核实重点 | 不能直接推出 |
| --- | --- | --- |
| GPT模型订阅或模型API调用 | 当前模型渠道与模型额度 | 已启用搜索、搜索包含在模型订阅内，或搜索由OpenAI执行 |
| harness的`websearch` | 当前会话实际选择的搜索集成及个人显式配置 | 模型供应商就是搜索供应商 |
| Console的Hosted Web Search | 工作区是否启用、是否选中OpenCode Web Search、个人选择是否覆盖默认 | “托管”字样表示OpenAI原生托管工具，或平台未披露的底层供应商已确定 |
| 模型供应商API的托管搜索 | 当前供应商支持证据及harness/适配器是否实际传递与处理该工具 | 在Codex通过就证明OpenCode也走了同一搜索路径 |

Console文档中的搜索计费与失败处理仅适用于该服务，不能套到第三方供应商；模型用量与搜索费用分别按可关联账单核对。某渠道已有实测支持托管搜索时，保留这项正面证据，只核对OpenCode是否接通及实际选用了哪条路径，不把“适配层未验证”改写成“供应商不支持”。

### 限制供应商托管搜索

渠道优先级和是否允许模型供应商托管搜索由 `user-profile` 或本轮明确要求决定，本页只维护配置检查与证明边界。

- **先确认禁用对象。**普通 Responses 文本/函数调用、harness 的独立搜索工具和供应商原生搜索是不同通路；保留前两者时，不通过切掉 Responses 或全部工具能力解决。
- **核对开关的实际作用。**按当前[V2搜索文档](https://opencode.ai/v2/docs/websearch)检查 `websearch` 配置；其中 `false` 移除的是 harness 搜索工具，不是“只禁止 Responses 原生搜索”的专用开关。固定搜索集成与限制供应商原生工具分别检查，不凭同名字段互推。
- **不臆造硬禁用配置。**先查当前适配器及其[provider设置](https://opencode.ai/v2/docs/providers)是否支持独立开关；只看到模型使用 Responses、配置里未启用搜索、或模型承诺不搜索，都不能证明原生工具已被阻断。未找到可核实开关时，明确报告只有行为约束，不写未经支持的 `disable_web_search` 一类字段。
- **硬阻断以实际请求结构为边界。**需要请求构造层、插件或网关过滤时，先核实该层的扩展能力与作用范围；按原生工具类型识别，而非按普通函数的名字删除，保留 harness 搜索及其他函数工具。第三方网关内部另行搜索也不能仅靠客户端过滤证明已禁止。实施与请求检查另按授权，不擅自抓包或发收费探针。

### 免费渠道或订阅额度失败

子代理启动即返回免费额度耗尽时，该任务未执行；不要把它算作搜索失败，也不要反复重启相同渠道。同名模型在其他供应商分组下是另一渠道，其费用、权限、数据处理和余额均不能据原渠道推断。读取当前可用目录发现候选，只读发现不代替用户的费用授权；申请与本轮授权范围遵循全局治理规则。

### 何时修模型配置

只有有效配置、真实错误或协议证据指向工具能力/供应商适配时，才转opencode-provider-config局部修改。目录中的能力标志和网页宣传只能作线索；不能为了让搜索出现，随意扩大上下文、添加未核实的能力或切换API协议。

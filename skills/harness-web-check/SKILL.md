## 联网工具配置与调用验收

目标是把**配置存在、工具可见、执行成功、模型正确使用结果**分别验明，不凭模型自述判断联网能力。以当前会话真实工具清单为准，不把某个harness的工具名当作通用接口。

## 核心用例

| 用户目标 | 可直接使用的请求 | 检查重点 |
| --- | --- | --- |
| 排查当前agent是否能联网 | “检查当前模型的搜索工具配置，并实际搜一次；先说明会产生哪些调用。” | 从当前工具清单到搜索返回，保留真实调用证据。 |
| 搜索后端正常，模型却不用 | “命令行搜索正常，但agent回答不搜索，检查工具下发与调用路径。” | 后端探针与目标模型验收分开。 |
| 模型或供应商切换后失效 | “只验证指定模型和渠道的联网工具调用，不改全局默认。” | 固定模型、渠道、推理档位与有效权限，隔离对照。 |
| 分清托管搜索与本机工具 | “这次用的是模型供应商托管搜索、harness搜索，还是本机CLI？分别给证据。” | 工具入口、执行位置与底层搜索供应商分开确认。 |

## 最短检查流程

1. **固定对象与授权。**记录harness及可取得的版本、目标模型与供应商、推理档位、会话或agent、工作目录。区分仅检查和允许修复；先静态检查，真实模型和搜索请求遵循当前有效费用授权，价格不明就说明未知。用户只问工具清单时无需发请求。已有用户实测或可追溯skill记录时，注明来源及适用模型/路由/时间，复用已确认的供应商能力；更换harness时只补查尚未确认的适配层，不以重复收费探针重新发现已知能力。
2. **核对当前接口。**读取实际可调用工具的名称、参数schema与执行位置，区分服务端内置搜索、客户端工具、MCP(模型上下文协议)工具、CLI(命令行工具)和仅有操作指引的skill。没有出现在清单中的工具不编造调用；需要executor包装时按其真实契约调用。将“不可见”“已发现但未测”分别记录。
3. **做最小静态检查。**只查相关配置、有效权限、凭据是否存在、运行时与链接；输出脱敏摘要，不读取或回显完整密钥。OpenCode使用[适配入口](references/opencode.md)。第三方skill不在自有仓库中并不说明缺失，沿真实链接或安装登记定位。发现可证实问题才提出最小补丁。
   发出搜索前按[请求有效性与计费边界](../agentic-web-search/SKILL.md#成本与预算分档)本地核对schema、包装及最终参数，先排除可静态发现的错误，不以真实收费请求试错；此规则也约束后续复测。
4. **沿真实路径搜索。**在授权范围内，选择不含敏感信息的公开查询，实际调用一个目标搜索入口。记录参数摘要、执行结果、耗时(有则记)、结果标题、URL和错误。`--help`、目录发现、模型目录查询和普通HTTP可达性不算搜索成功；搜索无结果只说明此次无命中，必要时换一个宽泛查询复核。CLI探针只能证明该CLI路径，不证明客户端原生工具或目标模型已通过。
5. **验收模型行为。**确认目标模型实际发出了合法工具调用，并根据本次返回总结、保留可追溯来源，未拿记忆或上次会话代替。当前模型亲自调用目标工具可作该会话证据；其他模型或子代理成功不能替代指定模型。需要独立会话时使用批准的完整模型标识，明确提示查询与验收标准；拿不到工具轨迹时只报结果待核验。
6. **最小修复并复测。**允许修复且定位到根因后，保留无关配置，只改必要字段或链接，再重跑原失败路径。后端本来正常而模型漏调工具时，归为执行问题，不为“做点修改”重建配置。不自动安装服务、重置凭据、改系统代理或切付费渠道；用户明确授权代办免费配置的例外见下节。
7. **按证据交付。**列出已验路径、失败层、实际改动和未测部分。搜索成功不代表正文抓取成功，需验证抓取时另取一个结果URL检查正文，不能拿挑战页或登录壳判通过。

## 设备本地配置与代办

- **配置只作本机案例。** 命令名、安装路径、凭据、默认渠道与已测结论都随设备、harness、账号和日期变化；文档与 skill 中的示例不是跨设备契约。换设备先按最短检查流程重新核对，不复制本机结论。
- **缺失时先给最小配置路径。** 优先官方文档与免费档；说明需要用户提供什么（账号、邮箱、key 保存位置），不读取或回显完整密钥。
- **代办边界。** 用户明确授权后，可代执行免费账号注册或 API key 创建；仅限免费档，使用用户提供的身份与联系方式，不代付、不绕过验证码/服务条款/风控、不批量注册、不把凭据写入仓库、日志或聊天。保存前确认路径与权限，完成后只报告脱敏状态。
- **不假设可用。** 配置存在、命令在 PATH、目录可见都只算“已配置/未测”；首次真实调用通过才算可用。

## 证据与失败归因

每条结论注明**目标模型/渠道、实际工具入口及包装(如有)、执行位置、底层搜索供应商、归属证据、返回或错误、证明范围**；未核实的环节写未知。报告按配置/工具可见性、搜索执行、模型行为分别给出“通过、失败、未测、无法确认”，只标适用项，不用一项通过代替整体通过。入口调用成功但底层供应商未知时，可以报告该入口通过，不能称供应商已验证。

### 渠道归属

- **模型供应商托管搜索、harness提供的搜索入口、本机CLI不是同一层分类。**harness入口可能再调用托管或第三方搜索；CLI在本机启动也可能调用远端服务。分别记录入口、执行位置和实际后端，不强行互斥归类。
- **用绑定证据确认实际后端。**优先关联本次调用轨迹与已有脱敏运行日志，再核对有效配置、适配器/插件实现和对应官方说明；按时间及可用的会话/请求标识关联实际选中的适配器、端点或供应商标识。工具日志可能只到入口，端点可能只是网关，只有文档证明“支持某后端”也不足以证明本次用了它。无法确认就保持未知，不为此擅自抓包、开启敏感请求日志、读取密钥或回显代理。
- **调用不可见不等于未执行。**中断、续接或上下文裁剪可能丢失客户端轨迹，协议层托管搜索也未必显示为独立工具调用；缺失记录只能报“当前视图无法确认”，不能据此断言没搜索、引用全是编造或没有扣费。优先核对用户提供的调用、账单与截图并注明来源；普通限流提示、引用链接或模型自述均不能单独证明搜索路径。证据不足时不自动追加收费探针，也不换搜索工具补证。
- **不用名称推断能力或归属。**使用GPT不等于用了OpenAI托管搜索；工具叫`web.run`或`websearch`也不证明存在、执行位置或底层供应商。工具及传输包装只按当前清单/schema描述；客户端目录缺失不能否定另有证据的服务端能力，一条渠道通过也不能替代其他渠道验收。
- **托管搜索先核实支持链，不按客户端一刀切。**只有当前harness/适配器、所选API协议、模型及供应商渠道均有托管搜索支持证据，且费用授权覆盖时才尝试；普通函数工具能力、Responses文本通路或使用Codex本身都不能单独证明这条链成立。未确认时只使用当前已暴露且获准的搜索入口，不自行添加托管工具声明、模拟调用或用收费请求探测支持。

| 观察 | 能证明什么 | 下一步 |
| --- | --- | --- |
| 配置有工具，当前会话清单没有 | 配置与会话暴露可能不一致 | 查有效权限、agent设置、插件/MCP状态与会话刷新；不让模型调用不存在的接口。 |
| schema校验拒绝调用 | 此次参数或包装方式不匹配，不足以证明未计费 | 先本地纠正；仅在仍有次数、渠道与费用授权时复测，不更换供应商掩盖调用错误。 |
| CLI搜索正常，模型没有调用 | 后端该路径可用，模型执行尚未通过 | 查工具下发和真实轨迹，必要时做相同模型的隔离探针。 |
| 工具返回鉴权、额度、限流或网络错误 | 请求到达相应失败层，不等于模型不会用工具 | 保存脱敏错误；鉴权走配置，网络走network-access，限流按服务要求等待。 |
| 子代理启动即额度耗尽 | 该模型渠道启动失败，任务尚未执行 | 按当前通用子代理费用授权申请回退，或由主代理完成可独立执行部分。 |
| 模型只有“已经搜索”的文字或可疑链接 | 当前材料不足以确认执行与引用真实性，不能证明未执行 | 先查已有轨迹，分别标注执行与引用的核验状态；补调用须另核剩余授权，不自动重搜。 |

## 协作边界

- **检索质量**、查询预算、来源与引用核验按[agentic-web-search](../agentic-web-search/SKILL.md)；渠道顺位、可用性核对与降级决策按 `user-profile` 与该 skill 的“渠道选择、分工与回退”，本skill只判定失败层与实际路径，不扩成主题研究。
- **网络与网页内容**：外链请求前按[network-access](../network-access/SKILL.md)选路；需提取网页结构时用htmlmini，遇挑战页再按resilient-browser-fetch分流。搜索服务出网与本机抓取出网分别记录。
- **配置修改**：OpenCode字段按opencode及V2官方文档；模型能力与协议按[opencode-provider-config](../opencode-provider-config/SKILL.md)，Codex专属字段按codex-model-config，不复制其参数清单。
- **子代理与付费回退**遵循当前全局治理授权；授权不能从免费渠道自动延伸到订阅或其他供应商，也不因加载本skill自动启动子代理。

## 验证协议

- 用[回归场景](references/acceptance.md)走查正常、工具缺失、漏调、额度耗尽等路径；桌面走查只证明规则可执行，不证明模型遵循。
- 逐档可用性测试步骤、通过标准与结论口径见 [cli-recipes.md](../agentic-web-search/references/cli-recipes.md#可用性测试方案)；人类可照命令直接复跑。
- 在实际harness执行一条合法搜索并核对工具轨迹；只完成静态检查就明确标未测。要声称指定模型通过，证据必须来自该模型与渠道。
- 修复任务重跑原失败路径并检查无关配置未变；只检查CLI、只看最终回答或只校验文件结构不能作为端到端通过。

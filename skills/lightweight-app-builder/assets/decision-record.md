# 方案确认单 / 架构决策记录(模板)

> 何时用:阶段四输出给用户确认时,**复制本模板**并逐格填写。控制在一屏以内,超出的内容移到附录或对应 `references/`。
>
> 双重身份:对用户是《方案确认单》,对仓库是《架构决策记录》(ADR,Architecture Decision Record)。定稿后存入仓库 `docs/decisions/0001-<主题>.md`,便于日后回答"当初为什么这么选"。

## 一句话结论

> 用**不含任何技术术语**的一句话写清最终交付物。
>
> 例:做成一个在黑窗口里敲一行命令就能用的小工具,Mac 和 Windows 都能跑,拷贝一个文件过去就能用,不需要先装别的东西。

## 确认话术(直接发给用户)

> 以上是我替你做的方案。请你重点看**"我替你做的假设"**那一节 —— 如果 A1、A2 都成立,回复"开始"我就按交付计划动手;如果哪条不对,直接告诉我编号和你的实际情况,我会调整方案再确认一次。
>
> 你也可以只否决某个决策(例如"决策一我不要命令行,我要能双击的"),我会重新评估代价后给你新的确认单。

## 定稿后

1. 把本文件存为 `docs/decisions/0001-<主题>.md`,状态改为"已确认";
2. 在 README 里链接它;
3. 后续任何形态或技术栈变更,**新建一份 000X** 并把旧的状态改为"被 000X 取代",不要就地修改历史记录。

# 质量闸门与验收清单

> 何时读本文件:阶段五收尾。未通过闸门不得进入打包分发。
>
> 轻量程序的质量标准不是"和大厂一样全",而是"**该有的几件事一件不缺,不该做的一件不多**"。

## 五道闸门

```mermaid
flowchart LR
    G1["闸门一<br>能跑通"] --> G2["闸门二<br>格式与静态检查"]
    G2 --> G3["闸门三<br>关键路径有测试"]
    G3 --> G4["闸门四<br>跨平台实测"]
    G4 --> G5["闸门五<br>文档与可维护性"]
    G5 --> R["允许进入打包分发"]
```

| 闸门 | 通过标准 | 不通过的典型表现 |
| --- | --- | --- |
| 一、能跑通 | 从干净克隆到首次成功运行,照着 README 走不超过 5 步 | "还得先手动改个路径才能跑" |
| 二、格式与静态检查 | Formatter 与 Linter 零错误 | 每次提交风格都在变 |
| 三、关键路径有测试 | 核心逻辑有单元测试;至少一条端到端成功路径 + 一条失败路径 | 改一处不知道会不会碰坏别处 |
| 四、跨平台实测 | 目标平台各真机跑一遍主流程 | "我 Mac 上是好的" |
| 五、文档与可维护性 | README、CHANGELOG、错误自查说明齐备 | 三个月后自己都不记得怎么用 |

## 工具链速查(按语言)

| 语言 | 格式化 | 静态检查/Lint | 类型检查 | 测试 | 依赖审计 |
| --- | --- | --- | --- | --- | --- |
| **Python** | **Ruff format** | **Ruff check**(整合了 flake8/isort/pyupgrade 等) | **mypy** 或 pyright | pytest | `pip-audit`、`uv pip audit` |
| **JavaScript / TypeScript** | **Prettier** 或 Biome | **ESLint**(或 Biome 一体) | `tsc --noEmit` | Vitest / Node test runner | `npm audit`、`pnpm audit` |
| **Go** | **gofmt** / gofumpt | **golangci-lint**(聚合数十个检查器) | 语言内置 | `go test` + testify | `govulncheck` |
| **Rust** | `cargo fmt`(rustfmt) | `cargo clippy -- -D warnings` | 语言内置 | `cargo test` | `cargo audit`、`cargo deny` |
| **Shell** | **shfmt**(`-i 2 -ci`) | **shellcheck** | — | bats-core | — |
| **CI 工作流** | — | **actionlint** | — | — | — |

**关于 Biome**:用 Rust 编写的 JS/TS 工具链,把 Lint 与 Format 合成一个工具,速度远快于 ESLint + Prettier 组合,新项目可以考虑;但插件生态与规则覆盖度仍不及 ESLint,复杂项目需评估。

**统一建议**:所有检查通过一个入口命令触发,例如 `make check` 或 `npm run check`,内部依次跑 format 校验、lint、类型检查、测试。**用户(和未来的你)只需要记住一条命令。**

## 测试策略:轻量程序该测什么

不要追求覆盖率数字,追求"**改了代码敢不敢直接发布**"。

| 优先级 | 测什么 | 为什么 |
| --- | --- | --- |
| **必测** | 核心业务逻辑的纯函数(改名规则、计算、解析、状态机) | 最便宜、最快、收益最大 |
| **必测** | 一条端到端成功路径(真实临时目录 + 真实调用入口) | 证明"整条链是通的" |
| **必测** | 一条典型失败路径(输入不存在、权限不足、网络超时) | 证明错误被正确处理而不是崩溃 |
| **必测** | CLI 的退出码与 stdout/stderr 分流 | 别人要用脚本调用它 |
| **应测** | 边界值:空输入、单元素、超大输入、含空格与中文的路径 | 中文与空格路径是最常见的现实坑 |
| **应测** | 配置的优先级(命令行 > 环境变量 > 配置文件 > 默认) | 用户最常困惑的地方 |
| **可选** | 界面快照测试 | 维护成本高,轻量项目通常不值 |
| **不要** | 给每一行都写测试、测试框架本身、mock 掉一切 | 拖慢迭代,让人放弃维护 |

**测试环境隔离铁律**:测试**绝不允许**读写用户真实目录。一律使用临时目录(Python `tmp_path` fixture、Go `t.TempDir()`、Node `fs.mkdtemp(os.tmpdir())`),并在结束后清理。

## 可观测性:出了问题用户能不能自救

| 要素 | 要求 |
| --- | --- |
| **日志文件** | 有固定且可查的路径(用户数据目录下的 `logs/`),启动时的报错要**把日志路径打印出来** |
| 日志级别 | 默认 `INFO`,可通过 `--verbose` 或环境变量提升到 `DEBUG` |
| 日志内容 | 时间戳(带时区或用 UTC 并标明)、级别、模块、消息;敏感信息(密码、Token)必须脱敏 |
| 日志轮转 | 限制单文件大小与保留份数,别把用户磁盘写满 |
| 错误消息三要素 | **发生了什么** + **可能原因** + **下一步怎么办**。反例:`Error: 1`;正例:`无法写入 D:\photos:该目录只读。请换成有写入权限的文件夹,或以管理员身份运行。` |
| 崩溃兜底 | GUI/Web 界面要有错误边界;CLI 遇到未预期异常时打印堆栈到 stderr 并提示日志位置 |

## 安全性最小集

| 检查项 | 要求 |
| --- | --- |
| 依赖漏洞扫描 | CI 中运行 `govulncheck` / `cargo audit` / `pip-audit` / `npm audit --audit-level=high` |
| 密钥硬编码 | 仓库内不得出现 Token、密码、私钥;加 `gitleaks` 或 `detect-secrets` 扫描 |
| 外部输入 | 所有来自文件、网络、参数的数据都当作不可信,做长度与类型校验 |
| 命令注入 | 禁止把用户输入拼进 shell 字符串;用参数数组形式调用子进程 |
| 路径穿越 | 处理用户提供的路径时校验是否越出预期根目录(`../` 攻击) |
| 网络传输 | 一律 HTTPS;校验证书,不要图省事关掉校验 |
| 本地服务 | 本地 Web UI 只绑定 `127.0.0.1`,并加一次性 token |
| 权限最小化 | Tauri 的 capabilities、Electron 的 preload 白名单、Flatpak/Snap 的沙箱权限,都按实际需要开 |

## README 必备结构

给非技术用户交付时,README 要按**用户的阅读顺序**写,而不是按开发顺序:

1. **这是什么、能帮我做什么**(两三句大白话 + 一张截图或一段终端录屏)
2. **怎么安装**(每平台一条命令,复制即用)
3. **怎么用**(3 个最常见场景,每个场景给完整可复制的命令/操作步骤)
4. **常见问题**(至少包含"打开被系统拦截怎么办""中文乱码怎么办""怎么卸载")
5. **怎么升级 / 怎么卸载**
6. **给开发者的部分**(本地开发、目录结构、`make check`)放到最后或单独的 `CONTRIBUTING.md`

**中文显示专项**:如果程序会在终端输出对齐的表格或界面,务必用显示宽度而非字符数计算列宽;并在 README 里注明推荐的终端与字体(例如 Windows Terminal + 一款含中文的等宽字体如 Sarasa Mono SC / 更纱黑体),否则用户看到的是错位的一团。

## 发布前验收清单

逐项打勾,任何一项不过都回到对应闸门:

- [ ] 从**干净环境**(新克隆或新用户账户)按 README 能一次跑通
- [ ] 格式化与 Lint 零错误,类型检查通过
- [ ] 核心逻辑单元测试通过,含空输入与中文/空格路径用例
- [ ] 一条端到端成功路径 + 一条失败路径的集成测试通过
- [ ] CLI 退出码正确,stdout 只有结果、stderr 只有日志
- [ ] 非 TTY 环境(管道、CI)下不输出 ANSI 乱码、不崩溃
- [ ] 所有目标平台真机实测主流程(至少 Windows 与 macOS 各一次)
- [ ] 配置与数据写在系统惯例目录,卸载后用户数据去向有明确说明
- [ ] 长任务有进度反馈,可中断,中断后状态不损坏
- [ ] 界面状态与实际一致:禁用有原因、加载有进度、成功/失败与 `core` 返回一致,不出现"显示成功实际没做成、按钮能点实际不该点"
- [ ] 文案与组件语义无含糊:同一动作全文案同一词,按钮/链接/开关不混用,空状态与错误都含下一步动作,大声读一遍能懂
- [ ] 日志文件存在且路径已在报错信息中告知
- [ ] 无硬编码密钥,依赖漏洞扫描无高危
- [ ] 版本号、CHANGELOG、Git 标签三者一致
- [ ] 构建产物有校验和,安装脚本支持 `--dry-run` 与 `--mirror`
- [ ] 交付说明包含"被系统安全机制拦截时怎么办"

> 新功能正式交付的完整规则以 skill `frontend-ux-qa` catalog 动作五为准(验收链/状态矩阵/口径统一/截图验证/交付标准),本清单不再重复。

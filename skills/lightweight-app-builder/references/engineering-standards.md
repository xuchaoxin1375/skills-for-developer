## 目录结构标准

三种形态的通用骨架，多余目录不要加：

```text
project/
├── src/ 或 cmd/           # 源码（Go 惯例用 cmd/<名称>/main.go）
│   ├── core/              # 业务逻辑：不碰界面、不碰命令行、不碰网络框架
│   ├── adapters/          # 对外部世界的适配：文件系统、数据库、第三方 API
│   └── entries/           # 各外壳入口：cli、web、desktop
├── scripts/               # dev.sh / dev.ps1 / install.sh / install.ps1 / release.sh
├── tests/                 # 单元测试与跨平台冒烟测试
├── docs/                  # USAGE.md、DECISIONS.md、ARCHITECTURE.md
├── .github/workflows/     # CI：lint、test、release
├── .editorconfig
├── .gitattributes
├── .gitignore
├── README.md
└── LICENSE
```

**分层规则**：`core` 不得 import 任何界面或框架包；`entries` 不得写业务判断；`adapters` 是唯一知道"数据存在哪"的地方。跨平台问题几乎都集中在 `adapters`，把脏东西隔离在这一层，换平台时只需改一个目录。

## 配置管理

- **优先级固定**：命令行选项 > 环境变量 > 用户配置文件 > 内置默认值。
- **格式选一个**：TOML（人最易读，Rust/Go 生态默认）或 JSON（前后端同构）。不要 YAML——缩进敏感，非技术用户极易写坏且难以察觉。
- **必须提供 `.example` 模板**，并带逐行注释说明每个字段的含义和默认值。
- **启动时校验**：读入后用 schema 校验一次，发现非法值立即报出"字段名 + 期望值 + 实际值"，不要让错误延迟到业务深处才爆。
- **修改配置要原子**：先写临时文件再替换，写坏配置文件等于让程序再也起不来。
- **路径用标准目录**：`directories`（Rust）、`dirs`（Go）、`platformdirs`（Python）。**绝不写在安装目录**，Windows 的 `Program Files` 没有写权限，这是新手最常见的"在我机器上能跑"问题。

## 日志规范

- **两级输出**：默认给用户看的一行式简洁信息；`--verbose` 才输出带时间戳、模块名、层级的详细日志。
- **日志落盘**：写进标准数据目录的 `logs/`，按天或按大小轮转，默认保留 7 天。
- **结构化字段**：文件日志用 JSON 行格式，包含 `time`、`level`、`module`、`message`、`extra`，方便后续用 `jq` 或脚本检索。
- **绝不记录敏感值**：密钥、口令、完整路径中的用户名要脱敏。
- **崩溃现场**：未捕获异常要连同版本号、系统版本、配置摘要一起写入 `crash-*.log`，并告诉用户"报告问题时请附上这个文件"。

## 错误处理

| 层 | 形式 | 示例 |
| --- | --- | --- |
| 用户可见 | 一句话人话 + 建议动作 | "无法读取 D:\照片（权限不足）。请右键文件夹，在属性中确认当前用户有读取权限。" |
| 日志 | 带上下文的结构化记录 | 错误码、完整路径、底层异常栈 |
| 调用方 | 结构化错误对象 | `{code, message, hint, cause}` |
| 退出码 | 语义化整数 | `0` 成功、`1` 运行错误、`2` 用法错误 |

三条硬规则：

- **禁止空捕获**。捕获之后要么处理、要么带上上下文重新抛出。
- **错误码集中定义**在一个文件里，形如 `E_FILE_NOT_FOUND`、`E_CONFIG_INVALID`、`E_NETWORK_TIMEOUT`。GUI 据此显示文案，CLI 据此定退出码，文档据此写排错表。
- **失败要可继续**：批量操作默认"记录后继续"，结束时输出失败清单。这是用户最不需要动脑的失败方式。

## 并发

I/O 等待型批量任务（如批量调 Cloudflare API 管域名）必须并发做，串行是默认错误；CPU 计算型才考虑多进程/线程池，且先实测再上。

- **有界并发**：无界 `Promise.all` / 无限 goroutine 会打爆对端限流与本机句柄。Python 用 `asyncio.Semaphore` 或 `ThreadPoolExecutor(max_workers=N)`；Go 用带缓冲 channel 或 `errgroup + SetLimit`；Node 用 `p-limit`；Rust 用 `tokio::Semaphore`。默认并发数取小（如 5–10），可配 `--jobs` 覆盖。
- **尊重对端限流**：读清 API 的 rate limit（如 Cloudflare 1200 请求/5 分钟），触发 429 必须指数退避重试（1s → 2s → 4s…最多 3–5 次），禁固定间隔死循环重试。
- **超时必设**：每个请求单独超时（如 30s），整体再设总预算；超时算失败项进失败清单，不卡死整批。
- **失败隔离**：单个失败不中断整批（见上节"记录后继续"），结束输出失败清单 + 成功数；幂等操作（如查/改域名记录）可安全重跑整批。
- **进度可见**：超过 10 项就要进度条或计数（`12/200`）；长任务支持 Ctrl+C 中断且已完成部分不丢失（断点续跑见 `scripts-automation.md`）。
- **禁共享可变状态**：并发 worker 只读共享配置，结果各自收集后合并；需写同一文件先攒内存后一次性落盘，或排队写。

## 代码质量工具链

| 语言 | 检查 | 格式化 | 类型 |
| --- | --- | --- | --- |
| Python | `ruff check` | `ruff format` | `mypy` 或 `ty` |
| Go | `golangci-lint run` | `gofmt` / `gofumpt` | 内置 |
| Rust | `clippy` | `rustfmt` | 内置 |
| TypeScript | `eslint` 或 `oxlint` | Biome 或 Prettier | `tsc --noEmit` |
| Shell | `shellcheck` | `shfmt -w` | 无 |
| CSS/JSON | `biome` | `biome format` | 无 |

这些工具全部接进 CI 与本地 `scripts/dev.sh`，**靠自觉执行检查必然失效**。新项目第一天就把 lint 配好，比三个月后补容易十倍。

## 测试策略

轻量工具不需要完整测试金字塔，但必须有三层：

1. **核心单元测试**：只测 `core/` 目录，覆盖率目标 70% 以上。这是投资回报最高的一层。
2. **CLI 契约测试**：对 `--json` 输出和退出码做断言，防止无意间破坏用户脚本。
3. **跨平台冒烟脚本**：`scripts/smoke.ps1` 与 `smoke.sh`，各做十件最典型的事并比对结果。**三个平台都要跑**，这是唯一能发现平台差异的手段。

**测试数据**：用固定的小样本（例如 5 个文件、不同编码与命名），放在 `tests/fixtures/`，包含中文名、空格、超长路径、无扩展名文件——这些才是真实世界会出事的地方。

## 持续集成

最小可用 CI 是三个任务：

- **lint**：跑所有静态检查，最快失败。
- **test**：单平台跑单元测试即可（除非有平台相关逻辑）。
- **build**：三平台矩阵构建，产物作为工作流附件供手动下载验证。

**发布由 tag 触发**：推 `v1.2.3` 标签后自动构建三平台产物、生成校验和、更新日志，并发布到 GitHub Releases 与包管理器。发布必须零手工步骤，手工步骤必然在某个深夜被忘记。

国内访问 GitHub Actions 拉取依赖慢的问题，在 CI 里统一配置镜像环境变量，与本篇前面的镜像表保持一致。

## 仓库卫生文件

| 文件 | 作用 | 关键内容 |
| --- | --- | --- |
| `.gitattributes` | 统一换行与二进制标记 | `* text=auto eol=lf`，`*.png binary`，`*.ps1 text eol=crlf` |
| `.editorconfig` | 统一缩进与字符集 | `charset = utf-8`、`insert_final_newline = true` |
| `.gitignore` | 排除产物与密钥 | 构建产物、`.env`、日志、系统文件 `.DS_Store` |
| `LICENSE` | 明确授权 | 默认 MIT；要闭源就写清楚 |
| `CONTRIBUTING.md` | 说明如何参与 | 本地起跑命令、提交规范 |

**换行符是跨平台协作的第一杀手**：`.sh` 被改成 CRLF 会直接无法运行。`.gitattributes` 必须在第一个提交就放进仓库，事后补会导致历史文件混用两种换行。

## 文档规范

`README.md` 第一屏只回答三件事，顺序固定：

1. 这是什么（一句话 + 一张截图或一段终端输出）。
2. 怎么装（一段可直接复制粘贴的命令，分 Windows 与 macOS/Linux 两栏）。
3. 怎么用（最少三个真实例子，含一个最常见的失败场景及其处理）。

其余内容后置：`docs/USAGE.md` 放完整用法，`docs/DECISIONS.md` 放技术决策与理由，`docs/ARCHITECTURE.md` 放分层结构图。**文档里不写死版本号**，写"用 `xx --version` 查看当前版本"。

## 国际化与无障碍

- **字符串集中**：所有界面与命令行文案集中到一个 `strings` 文件，不要散落硬编码。哪怕只做中文，这一步也让将来加英文只需翻译一个文件。
- **宽度与字体**：终端界面按中文占两列计算宽度；图形界面选择清晰的中文无衬线字体，并设置 1.6 左右的行高。
- **时间与数字本地化**：日期格式遵循用户区域，存储一律用 UTC 或 ISO 8601。
- **键盘可达**：所有功能可不用鼠标完成；焦点顺序合理；色彩不作为唯一信息载体（色弱用户需要文字或图标冗余）。

## 界面状态与文案纪律

大白话：**按钮上写的能不能点、显示成功还是失败，必须和程序真正能做什么、真正做成了什么是一回事**；文案让用户读一遍就知道点下去会发生什么。

### 状态同源：界面不许自己猜

| 规则 | 做法 | 反例 |
| --- | --- | --- |
| 单一状态源 | 按钮可用/禁用、加载中/成功/失败，一律由 `core` 返回的状态派生，界面只做渲染 | 前端用本地变量先显示“成功”，实际还没写盘 |
| 四态显式 | `idle / loading / done / error` 四态必全；禁用必须同时给出原因；长任务必须有进度 + 可中断，中断后状态不损坏 | 灰按钮不说为什么灰；点了没反应也不转圈 |
| 先禁后查 | 无权限、断网、文件被占用、前置条件没满足时，入口直接禁用 + 写明原因，不让用户点完才报错 | 没选文件夹也能点“开始”，点了才弹“请先选文件夹” |
| 多外壳同世界 | 同一输入，CLI / TUI / Web / GUI 看到的是同一台状态机（同一 `Progress` + 同一错误码映射） | CLI 报无权限，GUI 同一操作按钮还能点 |

### 文案与组件语义：不让用户猜

| 规则 | 做法 | 反例 |
| --- | --- | --- |
| 组件各干各的 | 按钮 = 立即执行；链接 = 跳转；开关 = 拨动即生效；复选/下拉 = 选完还需按确认才生效，不混用 | 用链接样式做删除操作；开关拨了还要再按保存才生效 |
| 同一动作同一词 | 同一个动作全文案用同一个词，以 `strings` 文件为准，全局搜一遍 | 一处叫“删除”，一处叫“移除”；一处叫“开始”，一处叫“运行” |
| 文案三件套 | 动作 + 对象 + 结果/下一步；空状态说“现在是什么 + 去哪做”，错误沿用“发生了什么 + 为什么 + 下一步” | 空状态只写“暂无数据”；按钮只写“确定”，不知道确定了什么 |
| 危险操作具名 | 删除/覆盖必须写清对象与后果（删几个、删哪），能撤销或先 `--dry-run`/预览 | 按钮写“确认”，弹窗写“确定要继续吗” |

**5 分钟自查**：断网点一遍、空数据看一遍、无权限点一遍，每个禁用按钮问一句“为什么禁，说清了吗”，每条文案大声读一遍“知道点了会发生什么吗”。过不了就回炉，不进打包。

## 安全基线

- **依赖最小化**：每加一个依赖都要问"这个功能自己写要多久"。依赖数量直接决定供应链风险与安装失败率。
- **锁文件必须提交**。
- **密钥不进仓库**，也不进日志。
- **路径校验**：凡接受用户传入的路径，先解析为绝对路径并确认在预期根目录之内，防止 `../` 逃逸。
- **默认最小权限**：桌面应用默认无能力，按需放行；本地服务默认只绑 `127.0.0.1`。
- **更新必须校验签名**，防止更新通道被劫持。

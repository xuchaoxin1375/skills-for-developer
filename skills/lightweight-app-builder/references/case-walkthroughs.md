# 完整案例走查

三个案例覆盖了三种最典型的真实场景，每个都从**一句模糊的话**走到**可交付的产物**。读的时候注意每一步"替用户做了什么决定、放弃了什么"。

## 目录

- 案例一：下载目录自动整理（无人值守脚本）
- 案例二：日志检索工具（CLI 起家，后加图形界面）
- 案例三：小团队发票整理器（桌面 GUI）
- 案例共性复盘

## 案例一：下载目录自动整理

**原始需求（用户原话）**："我的下载文件夹太乱了，能不能让它自己变整齐？"

**Step 1 需求卡片**：

- 一句话目标：每天凌晨把下载目录里 7 天前的文件按类型移动到"文档/图片/压缩包/安装包"子目录。
- 谁来用：只有用户本人，Windows 11，完全不懂编程。
- 输入输出：输入是下载目录；输出是整理后的目录和一个 `log-2026-06-01.txt` 日志。
- 不做的事：不去重、不改文件内容、不碰正在下载的临时文件。

**Step 2 提问（一次性三个）**：

1. 正在下载中的文件要不要等它下载完再处理？——建议等，也就是只动"修改时间超过 7 天"的文件。
2. 同名文件已经存在时是跳过还是加序号？——建议加序号，比如 `报告-2.pdf`。
3. 有没有不许动的文件夹？——建议默认跳过 `!重要` 这类前缀目录。

**Step 3 形态与选型**：

| 项 | 决定 | 理由 | 放弃的选项 |
| --- | --- | --- | --- |
| 形态 | 无人值守脚本 | 用户明确说"让它自己变整齐" | CLI（用户不会敲命令）、GUI（增加签名与更新负担） |
| 技术栈 | Python 3.12 + `uv` + 脚本内联元数据 | 单文件、依赖自动装、Windows 上可用 `pythonw` 静默运行 | PowerShell（用户以后可能换 macOS） |
| 调度 | 任务计划程序，每天 23:40 | 夜间无人使用电脑 | 开机自启（拖慢开机体验） |

**Step 5 关键实现点**：只处理修改时间超过 7 天的文件以避开下载中的临时文件；移动前检查目标是否存在；用内容哈希判断"是不是同一个文件"；日志按天写进 `%APPDATA%\DownloadTidy\logs`；扩展名映射表放在 TOML 配置里让用户能自己加类型。

**Step 6 交付**：一个 `download_tidy.py`、一个 `scripts/install-task.ps1`（支持 `--uninstall`）、一个 `README.md`。README 第一屏三句话：这是什么、双击 `install-task.ps1` 即可、想撤销就运行 `install-task.ps1 -Uninstall`。

**踩坑记录**：Windows 上路径带中文导致日志写入 GBK 乱码，解决方式是显式 `encoding="utf-8"` 并把控制台输出编码切到 UTF-8；任务计划程序默认以"仅在用户登录时运行"触发，改成了"不管用户是否登录"并指定最高权限。

## 案例二：日志检索工具

**原始需求**："我们服务器每天几百兆日志，出问题找起来太痛苦了。"

**Step 1 需求卡片**：在大日志文件里按时间范围、关键字、级别快速过滤，支持把结果导出成 CSV 给同事。使用者是三位工程师，主要在 macOS 与 Linux 上工作，偶尔在 Windows。

**Step 3 形态与选型**：

| 项 | 决定 | 理由 | 放弃的选项 |
| --- | --- | --- | --- |
| 形态 | CLI 为主，预留 GUI 外壳 | 工程师用户、要接进脚本与流水线 | 先做 Web UI（无法管道化） |
| 技术栈 | Go 1.23 + Cobra | 三平台单文件、启动毫秒级、同事用 `go install` 即可安装 | Rust（编译慢、团队不熟）、Python（部署需要环境） |
| 大文件策略 | 分块流式读取 + 并行扫描 | 不把几百兆读进内存 | 先建索引（过度设计，第一版不做） |

**命令设计**：

```text
logq [全局选项] <子命令> [选项] <文件...>
# 示例
logq scan app.log --since 2026-06-01T10:00 --level error --json
logq scan app.log --grep timeout --context 2
logq export app.log --format csv -o result.csv
```

字段含义：`--since`/`--until` 限定时间范围（ISO 8601 格式，跨时区不出错）；`--level` 过滤日志级别；`--grep` 关键字；`--context` 输出匹配行前后各几行；`--json` 切换机器可读输出；`-o` 指定输出文件。

**Step 5 关键实现点**：日志走 stderr、数据走 stdout；退出码区分"没匹配到"（0，但输出为空）与"文件读不了"（1）；进度条只在使用终端时显示，重定向时自动关闭；`--dry-run` 用于预览将要扫描的文件集合。

**升级到 GUI 的路径**：核心扫描逻辑放在 `core/` 包，第一年只有 CLI；后来加了 Web UI（Go 内嵌静态页面，`http://127.0.0.1:7788`），复用同一份 `core`，只新增了一层 HTTP 处理器。**没有重写任何扫描代码**，这就是分层的回报。

**踩坑记录**：Windows 上同事报告路径含空格时报错，原因是文档示例没有加引号——把 README 里的示例统一改成了带引号的形式，这类问题应该在示例里就规避掉。

## 案例三：小团队发票整理器

**原始需求**："财务每个月要从一堆 PDF 发票里抄金额做表，能不能自动点？"

**Step 1 需求卡片**：拖入一批 PDF 发票，自动识别公司名、日期、金额、税号，汇总成一张可编辑的表格，导出 Excel。使用者是两位不熟悉技术的财务人员，用 Windows 10 和一台 MacBook。**发票数据不能上传到任何外部服务。**

**Step 2 提问（一次性三个）**：

1. 发票能不能上传到网上的识别服务？——不能，保密要求（这条直接改变了技术方案）。
2. 需要多人同时编辑同一份数据吗？——不需要，各自整理各自导出。
3. 识别错了怎么办？——希望能在表格里直接改，然后导出。

**Step 3 形态与选型**：

| 项 | 决定 | 理由 | 放弃的选项 |
| --- | --- | --- | --- |
| 形态 | 桌面 GUI | 使用者不会敲命令、需要拖拽交互 | Web UI（需要说明"打开浏览器访问 localhost"，对财务人员是负担） |
| 壳 | Tauri 2 | 安装包约 8 MB、内存占用低、可离线 | Electron（体积大一个数量级）、Wails（团队不写 Go） |
| 前端 | Vite + React + Tailwind + shadcn/ui | 表格与表单组件成熟，界面质感好 | Svelte（生态略小，招聘资料少） |
| 核心 | Rust 目录：PDF 解析 + 正则字段抽取 | 数据不出本机的硬要求，且能直接被 Tauri 调用 | Python OCR 服务（需要额外运行时，违背轻量目标） |
| 存储 | SQLite 单文件 | 可导出、可备份、支持以后加历史记录 | JSON 文件（数据量上千条后会慢） |

**关键取舍说明**：因为数据不能外传，放弃了"调云端 OCR 精度高"的方案，改用本地版式分析加正则抽取，准确率约九成，靠可编辑表格兜底。**这个妥协必须主动告诉用户**，并给出"如果以后想要更高准确率，可以加一个可选的本地 OCR 模块"的升级路径。

**Step 6 交付**：Windows 的 `.msi` 与 macOS 的 `.dmg`，附 SHA256 校验值；macOS 未签名，文档写明 `xattr -dr com.apple.quarantine` 的处理命令；用 GitHub Actions 三平台矩阵构建；自动更新走 Tauri updater，产物用私钥签名。

**踩坑记录**：Linux 上有同事想用，发现 WebKitGTK 依赖装不上，最终在安装脚本里补了 Debian、Fedora、Arch 三个发行版的安装命令；中文字体在 Windows 的 WebView2 与 macOS 的 WKWebView 上行高不同，把全局行高固定为 1.65 并显式指定中文字体栈后一致。

## 案例共性复盘

| 共性 | 体现 |
| --- | --- |
| 都先复述需求再动工 | 三个案例的第一步都是需求卡片，且都让用户确认过 |
| 只问三个问题 | 其余决定全部由模型做出，并记录理由 |
| 形态决定成本上限 | 脚本最便宜，桌面最贵；能选前面的绝不选后面的 |
| 数据边界改变了技术方案 | 案例三的保密要求直接否掉了云端 OCR |
| 踩坑都集中在跨平台 | 编码、路径、换行、系统依赖、签名，没有一个是业务逻辑问题 |
| 分层让升级免费 | 案例二从 CLI 加 Web UI 零重写 |

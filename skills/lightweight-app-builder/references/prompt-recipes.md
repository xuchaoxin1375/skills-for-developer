# 提示词写法

本篇回答：给 agent 的提示词应该怎么写，以及面向非技术用户该怎么问。用户侧可直接复制的模板见 `assets/prompt-templates.md`。

## 通用提示词骨架

无论哪种形态，提示词都按七段写。**段落顺序本身就是决策顺序**，乱序会导致模型先写代码后想架构。

```text
[目标] 我想要一个{一句话成果}，用来解决{具体重复劳动}。
[用户] 使用者是{谁}，共{n}人，{会/不会}敲命令。
[环境] 主要在{操作系统}上使用，{有/无}网络，数据{能/不能}离开本机。
[规模] 单次处理约{数量}，使用频率约{频率}。
[约束] 必须免费开源；必须跨 Windows/macOS/Linux；界面语言为中文。
[偏好] 优先考虑{安装简单/体积小/易修改}，可以接受{代价}。
[交付] 需要{双击运行/命令行调用/浏览器打开}，并附安装与卸载说明。
```

### 占位符逐项说明

| 占位符 | 含义 | 缺省时建议的默认值 | 常见误用 |
| --- | --- | --- | --- |
| `{一句话成果}` | 交付物的可验证结果，不是功能列表 | 必填 | 写成"一个文件管理工具"这种没有边界的描述 |
| `{具体重复劳动}` | 现在人工是怎么做的、花多少时间 | 必填 | 跳过这一句会让模型自己脑补范围 |
| `{谁}` | 使用者的技术水平与角色 | "作者本人，不懂编程" | 写"开发者"，导致输出过度工程化 |
| `{会/不会}敲命令` | 决定要不要图形界面的唯一关键 | 不会 | 这一项漏掉最容易做出没人用的 CLI |
| `{操作系统}` | 影响打包、签名、路径、依赖 | Windows 11 | 写"跨平台"却不说明主力平台，测试无重点 |
| `{有/无}网络` | 决定离线能力与依赖安装策略 | 有 | 离线场景被忽略，交付后无法安装 |
| `{数据…离开本机}` | 隐私边界，决定是否可调用云 API | 不能 | 唯一一个**不应该默认替用户决定**的项 |
| `{数量}` | 单次处理规模 | 100 以内 | 不写会导致选错存储方案 |
| `{频率}` | 一次性、每日、常驻 | 每周一次 | 常驻程序需要托盘、开机自启、内存约束 |
| `{安装简单/体积小/易修改}` | 三选一的核心偏好 | 安装简单 | 三个都选等于没选 |
| `{代价}` | 愿意接受的成本 | 首次构建等待 1 分钟 | 不写代价会让模型回避取舍说明 |
| `{双击运行/…}` | 交付形式 | 双击运行 | 与"不会敲命令"矛盾时会被打回 |

**写法纪律**：占位符必须填具体值，不要留成 `{...}` 交给模型猜测。**宁可写"我不确定"三个字，也不要留空**——模型会把空白当授权，自行扩权。

## 五个形态变体提示词

在骨架之上追加形态专属段。每段都只加两三行，避免提示词膨胀。

### 自动化脚本

```text
[形态] 这是一个无人值守的本机脚本，不需要界面。
[调度] 由{Windows 任务计划程序/cron}每天{时间}触发。
[失败策略] 出错时{停止并发通知/记录后继续下一项}，日志保留{天数}天。
```

### CLI 命令行工具

```text
[形态] 命令行工具，主命令为{命令名}，包含{子命令列表}。
[输出] 支持人类可读表格与 --json 机器可读两种输出。
[流水线] 需要能作为其他命令的输入源（遵循 stdin/stdout 约定）。
```

### 本地 Web UI

```text
[形态] 本地网页界面，浏览器访问，数据只存本机。
[界面] 核心页面为{页面列表}，需要支持中文与深色模式。
[后端] {需要/不需要}本地小服务；如需，端口默认{端口}且可配置。
```

### 桌面 GUI

```text
[形态] 桌面应用，需要{窗口/托盘/开机自启/全局快捷键}中的哪些。
[体积] 安装包希望小于{体积}MB，启动时间小于{秒}秒。
[更新] {需要/不需要}应用内自动更新。
```

### CLI + GUI 混合

```text
[形态] 同一套核心逻辑，提供 CLI 与 GUI 两种外壳。
[复用] 业务逻辑必须放在独立核心模块，外壳不得写业务判断。
[进度] 用统一的进度结构（百分比 + 当前步骤），由各外壳自行渲染。
```

## 触发词（description）设计要点

`description` 是唯一决定 skill 会不会被启用的字段，写法要求：

- **前半句写做什么，后半句写什么时候用**，并显式列出触发短语和排除场景。
- 中英触发词都要给，因为用户可能中英混说：做个工具、写个脚本、小软件、带界面、cross-platform utility、CLI tool。
- **必须写"不适用"**，否则会把大项目、移动端需求也吸进来，然后输出跑偏的长文。
- 长度控制在 1024 字符以内，一句到底，不要分号套分号。

## 面向非技术用户的提问模板

提问必须带推荐答案，让用户做选择题而不是问答题。

| 场景 | 直接这样问 |
| --- | --- |
| 形态不明 | 你更想要哪种：A. 双击图标打开的窗口程序；B. 浏览器里打开的页面；C. 敲一行命令就跑完。我建议 A，因为你提到要给同事用 |
| 数据边界 | 这个工具处理的数据可以发到网上的服务处理吗？如果不能，我就全部在你电脑上完成，速度可能慢一点但数据不出门 |
| 取舍 | 你更在意"装完就能用"还是"以后自己改起来方便"？前者我选 Go 编译成单文件，后者我选 Python |
| 规模 | 一次大概要处理多少个文件？100 个和 10 万个的做法不一样，后者我会上分批和进度显示 |
| 失败策略 | 如果中间有一个文件坏了，你希望它停下来问你，还是跳过它继续处理，最后给你一份失败清单？我建议后者 |

**上限规则**：一次对话最多问三个问题，且必须一次性列出来，不要挤牙膏式追问。其余一律由模型决策并写入 `docs/DECISIONS.md`。

## 坏提示词与好提示词对照

| 坏提示词 | 问题 | 改成 |
| --- | --- | --- |
| 帮我做一个文件管理工具 | 无边界，模型会做出一个文件浏览器 | 帮我做一个把下载目录里 30 天前的文件按类型归档到子文件夹的脚本 |
| 用最现代的技术栈 | 没有约束条件，无法决策 | 用跨 Windows 和 macOS、安装包小于 20 MB、不需要用户装额外运行时的方案 |
| 做个好看的界面 | "好看"不可验证 | 做一个表格页面，支持按列排序、关键字搜索、深色模式，中文界面 |
| 要跨平台 | 只说了愿望没说验证标准 | 在 Windows 11 和 macOS 14 上各跑通一次安装与卸载，脚本用 LF 换行 |
| 帮我打包 | 缺目标平台与分发渠道 | 产出 Windows 安装包与 macOS 的 `.dmg`，附 SHA256 校验值和未签名的打开说明 |

**共同规律**：好提示词都包含**可验证的数字**和**明确的失败处理方式**。做不到这两点的需求，先用"需求细化十二问"补齐再动工。
